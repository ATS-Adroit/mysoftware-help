Overview
This driver supports the ABB Communications link driver.
The 2nd Generation driver allows for the following features:

Chapter 2

Pages 5-9
Improved performance due to optimizations on mixed I/O to the
same protocol area being transacted only once removing redundant
transactions.
Serial drivers by design don’t benefit from multiple channels thus
only one channel per device is enforced. Up to 247 Multi-dropped
devices are supported per port.
Demand scanning support, where read only I/O that is not on a
mimic / graphic form and not logged or alarmed will be removed
from the scanning system, the applicable tasks will dynamically
reduce is size and merge into fewer scan tasks.
For improved network performance and reliability, it is
recommended to use of industrial USB serial ports or true serial
cards into the machines where applicable. RS-232 and RS-485 and
RS-422 is supported.
Windows traditionally expects COM ports to always be available,
therefore losing contact with Ethernet/serial extenders can cause
lockups. Please contact Adroit support if you suspect this.

Device Configuration
Device Configuration
Enable secondary – Turn this option to have the driver maintain 2
channels of communication, the radio buttons Primary and
Secondary can then be used to toggle between configurations.
Enable shadow scanning from master to standby – NASA specific
function – per device agent level shadow scanning.
If enabled, writes will be sent to the master to be executed on its
corresponding device and reads from master will be replicated to
the standby.
If disabled, writes Parallel scanning is enabled.
Enable standby reads – If disabled, the standby will be considered
cold, no reading will take place on the standby connection, and
neither will any replication from the master occur.
Enable standby writes – If disabled, no writing will take place on
the standby connection, and neither will any request be forwarded
to the master.
PLC Details
Station ID – (Default = 1) PLC station id 1 – 247. Master is always

0.
PLC Model – (Default = ABB CPU) Choose a specific model.
Debug level bitmask – (Default: 480) - This is a bit mask that enable
extra debugging in the datascope output, do not leave it enabled
during normal operation on high-speed drivers as it will slow down
the system depending on speed requirements. In serial drivers this
delay is negligible. (Remember: All NASA drivers one can stop and
start the device to reload these flags.)
960 default is just the protocol messages 40hex + 80hex+ 100hex
+ 200hex = 3C0hex -> 960 decimal in the dialogue.

0x00000008

#define DEBUG_MASK_PROTOCOL_WRITE_DESC 0x00000200
Stale threshold – (Default = 5) Every nth occurrence of an
unchanged item value will be sent to the master. If the value is
different, the value will be sent regardless of this count. This count
reduces unnecessary event within the agent server. Set to report

every poll value regardless of change, where 0 is not a valid option.
Max PDU length – (Default = 32) The overall maximum transaction
length. 1 is the lowest value up to 32 × 16-bit registers or 32 × 16
discrete bits digitals per transaction.
Serial
Com Port – Only insert the number for the port. For example, “4”
for COM4.
Baud rate – (Default = 9600) Select the required baud rate from
the selection provided.
Data bits – (Default = 8) Select the required data bit count from
the selection provided.
Parity – (Default = Odd) Select the required Parity mode from the
selection provided.
Stop bits – (Default = 1) Select the required stop bit count from the
selection provided.
Transaction timeout – (Default =3000ms) Insert the required
timeout for the system in milliseconds.
485 Reflections – (Default = False) Check if reflection detection
and compensation is required on the port [Currently not
implemented].
Purging

The driver will purge TX and RX buffers (data on the port) by
default when required.
However, some systems such as Ethernet to serial port servers can
become overloaded or even lockup if left receiving bytes in its
internal buffer without a driver reading anything for a long period.
For example, when a cluster partner is in standby, use the setting
below to compensate:
Purge port in standby – (Default = False) Check if purging of the
buffers is to be performed in the background while the cluster
partner is in standby.
Purge mode – (Default = SOFT) SOFT cause a simple flushing via
reading any available bytes, HARD sends a system call to tell the
device itself to flush. Some systems have become unresponsive in
HARD mode.
Error handling – Multi-dropped system variables
Retries – Enable this button to have the driver keep the PLC
connection alive. Please see the PLC program and heartbeat sections
below. This option is only useful with the watchdog program
running in the PLC.
Backoff count – (Default = 5) Require 5 full consecutive failures
including retries.
E.g. if 3 retries is configured and the backoff count is 5, the system
will go into a backoff delay period in which this device will not be
polled or written to for the Backoff period, in this example after the
((1 + 3) × 5) consecutive failures.
Backoff period – Specify the millisecond interval the device will

stay silent on the channel. This is very useful in multi-dropped
systems as failing devices do not severely affect online devices.
Disconnect after every transaction – (Default = False) Tell the
channel to close the port after every transaction. This can be useful
on gateways if required.
Disconnect after every error – (Default = False) Tell the channel to
close and reopen the port on every error during retries else it will
only occur after the final retry.
Latency
Inter-PLC latency – The period that the system will wait before
transmitting any read request or write request in multi-dropped
system when a new device is contacted.
Transmission latency – The period that the system will wait before
transmitting any read request or write request for the same PLC
device. Inter message delay.
Tx to RX latency – The period that the system will wait after
transmitting a request and before attempting to read the response.
Data Ranges
P – (Default = 16376) I/O bits area. Bits below 4000 hexadecimal
index is in bits. Example: P 6, P 7, … P n.
PR – I/O bits above 4000 hexadecimal (addressed in octal, index is
in 16-bit registers. Example: PR 0 W, PR 1 W … PR n W)

As of Rev 13 PR area now supports Bits in Registers as well. For
example, PR 1000.0 the bit index is in decimal. 0 -> 15
R – Registers {assumed these are referring to the high registers}
A – Analogue outputs [Currently not implemented]
AI – Analogue inputs [Currently not implemented]
T 0 – Time Sync can be scanned to any agent slot but must be Input
disabled and Output enabled. This is used to send down master time
to the outstation.

Timesync Considerations
Scan address T 0, T 0 W scan to any discreet agent type such as
BOOLEAN, INTEGER or REAL Agent.
Make sure the Input disabled and Output enabled check boxes are
checked, as this type is write-only.
The driver will then send down the system time in UTC time
format.
COMLI - Protocol function supported
0 30H (Write) Transfer Multiple I/O bits ( P 0 ) or register (P 0 W)
1 31H Acknowledge.
2 32H Requests multiple I/O bits or registers groups of at least 8
bits, registers are
groups of 16bits
3 33H (Write) Transfer single I/O bit
4 34H Request a single I/O bit. (Redundant function 2 is used)
J 4AH Transfer date and time in UTC format.

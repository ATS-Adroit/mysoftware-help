1. 
Overview 
 
HLI(High level interface) SDK based driver allows for communication between the Adroit Scada 
server and the Perimeter Patrol server. 
 
 
Live data can be read in the form of discrete I/O communicated in the form of Boolean, Integer, 
Real/Analog , String/Var-String types. 
Live Data can also be read in XML communicated to an Adroit IOT Agent. 
 
Zone statuses can also be issued to the system in the form of an action string, such as “Disarm”, 
“ArmHighPower” see table 4.2 
A writeable bitwise output word if available is also available. 
 
PLEASE NOTE 
The HLI updates all I/O on the channel once every second. Scanning anyfaster than this will not 
affect this rate, scanning slower will just result in a slower retrieval from the internal store of 
changes within the HLI. 
 
 
1.1. Supported Hardware 
 
This driver has been tested on the following hardware: 
 
GPIO board revision xxxx. 
Z18 JVA energiser revision xxxx. 
 
1.2. Supported Software 
 
 Perimeter Patrol version xxxx. 
 
 HLI SDK version 1.0.0.6015. 
 
 PP.HLITransport.dll (version 1.0.0.6015)

3. 
Device Configuration 
 
3.1. Device Configuration 
 
 
 
Enable secondary – Turn this option to have the driver maintain 2 channels of communication, 
the radio buttons Primary and Secondary can then be used to toggle between configurations. 
The Perimeter Patrol HLI interface does provide access for more than 1 channel , so either parallel 
or shadow mode clustering and primary and secondary connections per server is available 
3.1.1. Device details 
 
Enable Secondary – (Default = OFF) Allows enabling of redundant MQTT Broker connections such 
that in case of a failure a switchover will occur. 
 
Primary – Allows configuration setting of the Primary broker connection. 
 
Secondary – Allows configuration setting of the Secondary broker connection.

Enable shadow scanning from master to standby – (Default = OFF) If enabled will stop any 
communication to the MQTT broker when the Agent server is in standby mode. By default, we 
assume parallel scanning. 
 
Enable standby reads – (Default = ON) Allows reading from the MQTT broker when agent server 
is in standby mode. 
 
Enable standby writes – (Default = OFF) Allows writing to the MQTT broker when agent server 
is in standby mode. 
 
 
 
3.1.2. Perimeter Patrol server details 
 
TCP/IP Address – The static IP Address of the Perimeter patrol server machine. 
 
TCP Port – A valid port number is required for the connection to take place. Configured in the 
perimeter patrol system, see Appendix A for details. 
 
Authorization key – An text string used as a seed for the encryption algorithm, used when 
communicating to the Perimeter Patrol system. Configured in the perimeter patrol system, see 
Appendix A for details. 
 
User Name – A username required by Perimeter Patrol. Configured in the perimeter patrol system, 
see Appendix A for details. 
 
User Password – A password required by Perimeter Patrol. Configured in the perimeter patrol 
system, see Appendix A for details. 
 
3.1.3. Datascope details 
 
Debug level bitmask – (Default = 480) This is a bitmask that enable extra debugging in the 
datascope output, do not leave it enabled during normal operation on high-speed drivers as it will 
slow down the system depending on speed requirements. In serial drivers this delay is negligible.

4. 
Supported Addresses 
 
The scan address in Adroit for the JVA system is as follows : 
 
When scanning discrete I/O: 
<Tagname><Space><Type-postfix> 
e.g., Zones.1.FenceAlarm BOOL 
 
When scanning to the IOT agent’s rawValue slot: 
<Tagname><Space><Type-postfix> 
e.g., Zones.1 XML 
 
 
 PLEASE NOTE 
IOT slots cannot have additional ‘.’Dot notations as these are used within Adroit system itself, 
therefor the xml sent from the driver will replace any ‘.’ With ‘_’ 
The Address field when scanning however does allow for ‘.’ Notation, And the dot will be displayed 
in the Description field for clarification purposes. 
Example : IOT agent scanned its rawValue to “Zones.1” where a subsequent slot such as 
AlarmOnStartTime.0 will be renamed to AlarmOnStartTime_0.

1. Overview 
 
Adroit supports communication with the following PLCs: Modicon 84, 884, 184, 384, 484, 584 and 
984 amongst other devices using Modbus RTU and ASCII protocol. 
 
1.1. 
Modbus Emulators 
 
A number of hardware manufacturers have adopted the Modbus protocol to communicate to their 
hardware. These emulations have different maximum number of points that can be retrieved in one 
scan, amongst other variations. Since Adroit creates scan tasks/jobs automatically for you, it is 
important to choose a PLC type that would not result in a scan task requesting more data in one 
scan than that which can be handled by the device. Consult the list below to choose the most 
appropriate PLC model or select the “Custom” PLC type and supply your own from vendor 
documentation. See section: Protocol unit sizes.

Soft Purge (Read from Port) - Continue to read data from the port and just discard it. 
 
3.1.3. 
Handshaking 
 
RTS – (Disable/ Enable/Handshaking). (Default = Enable) Enable means line is always on, disable 
means line is always off, Handshaking means line is on when buffer is less than ½ full and off 
when buffer is over ¾ full. 
 
DTR – (Disable/Enable/Handshaking/Toggle). (Default = Enable) Enable means line is always on, 
disable means line is always off, Handshaking means driver will line is on when buffer is less than 
½ full and off when buffer is over ¾ full. Toggle means the line is high when bytes are being 
transmitted and low when the transmit buffer is empty. 
 
CTS – (Enable/Disable). (Default = Enable) If enabled, the driver will wait for the line to be asserted 
before transmitting any characters. 
 
DSR – (Enable/Disable). (Default = Disable) If enabled, the driver will ignore any characters 
received while the line is not asserted. 
 
3.1.4. 
Network Latency/Delays 
 
Between stations (network) - (Default = Inter-PLC delay) Use this option only if using a 422 
network. A value of zero disables the option. The inter-PLC delay or latency is the delay in 
milliseconds between communicating between different slave devices on the network. This timing 
is needed to allow a slave to detect the end of the communication cycle.

Between Any Transaction (device) - Inter message delay. Use this option to have a delay 
between any two messages even from the same device. 
 
Period in ms - The time in milliseconds to delay. 
A Modbus slave interprets a 2.5 character time delay at the end of a message as a signal that 
communication has been broken off, and thus allows communication to be initiated by the master 
to a new slave. By default, the Adroit driver does not implement this delay. 
To calculate the necessary time use the following formula, we have used 5 characters instead of 
2.5 as this is always good engineering practice. 11 bits per byte have been used. 
1/Baud x 11 x 5. 
e.g. For a baud-rate of 2400, (1/2400 × 11 × 5) = 0.022916. or 23ms. 
 
For a baud-rate of 19200, (1/19200 × 11 × 5) = 0.002863. or 3ms. 
 PLEASE NOTE 
Rounding up of the interval to the nearest 20 ms is used. 
 
3.2. 
Modem Support 
 
Going into the Modem dialog as shown below allows access to modem settings. 
 
The modem support operates on the basis of dialling up an outstation whenever it needs to be 
scanned. When an outstation is scanned, the driver dials the outstation up and connects and 
performs any scanning of that station as may be required. Outstations sharing an identical phone 
number are treated as one connection, but when a station on another number gets scanned, the 
driver drops the line and dials up the new outstation. 
 
The driver will “hold” the line for an inactivity period or until more scanning is done on that line, 
re-setting this period. After the inactivity period the driver will drop the line. 
 
It is suggested that all devices normally be stopped, you can then start a device, causing it to scan 
and be dialled. Stop the device and then start another, in round-robin fashion. A mimic, graphic 
form or a recipe/script easily accomplishes this. Keep the device started for long enough to scan 
all your data. When the device is stopped, the tags go grey to indicates that they are offline. They 
become active again while on-line as you start and run each device.

3.2.2. 
POLAR 3G Modem Support 
 
UsePolar-3G modem – (Default = false) enable the use of Polar 3g units instead of direct serial 
connections. 
 
Https server URL – The connection send URL typically in the following format 
https://polarmonitoring-beta.azurewebsites.net/data/external/Adroit/SerialMessage

occur, typically 30 seconds. Timing information is available on the datascope.

device that has a serial (RS-485 or RS-232) link to any Modbus serial (RTU-Binary) device. The 
SCADA machine will need to have access to the internet. 
Some other settings are not applicable when using polar mode, and dialup modem mode is mutually 
exclusive. 
 
Serial port is not required when using polar mode.

3.3. 
Advanced Settings 
 
Many settings shown here are for advanced users only and were previously only accessible via the 
system registry. 
 
 
3.3.1. 
Backoff 
 
Backoff Period – (Default = 20000ms) A period in time(ms) to allow communication to settle 
when communications is bad and then trying again –(0 Disables function). 
 
Backoff Count – (Default = 2) The number of failures to occur before the backoff is in use ( 0 
Disables). 
 
Mark Bad Tolerance – Will return last known values until consecutive failures match or exceed 
this value. Transaction attempts do not include retries, so if set to 2, and retries set to 3 then only 
after 2 × (1 + 3) = 8 attempts will the job be marked bad. 
3.3.2. 
Byte Ordering 
 
Swap floating-point value ordering – Allows the ordering of all floating point (suffix F) holding-
register I/O to be word-swapped. Required for all genuine Modicon equipment. Checked means it 
is not swopping. 
 
Reverse Modbus coils to integers – If Integers scanned to a coil address appear jumbled, use 
this setting to reverse the ordering.

Swap long value ordering – Allows the ordering of all long (suffix L) holding-register I/O to be

3.3.3. 
General 
 
RS485 wiring with reflections – (Advanced option) When using RS-485 the driver will receive 
and cater for message reflection which occurs because the RX circuit is enabled during the 
transmission of telegrams. (Used with RTS enabled and DTR enabled.) When using an external RS-
232 to 485 converter this option may not be necessary. 
 
Close serial port on fail – (Default = enabled) This setting, when enabled, will do a hard shut 
down and reinitialization of the communications Port. Some Ethernet to serial convertors hang 
under noisy conditions, so we compensate for this by only purging and not closing the port. 
 
Optimize scanning of Coils and relays – turn on this option to prevent the driver from doing 
read-ahead optimization, and instead read only the required number of bits. By default, the driver 
will read all bits packed into a byte, hence the last coil or relay read is always at the end of an 8-
bit multiple. This option prevents incorrect packing by some non-genuine RTUs. 
 
Detailed debugging – (Default = Disabled) This setting will add additional information to the 
datascope. 
 
Use Preset single register (06) func. – (Advanced option) (Default = disabled) Allow the driver 
to use function code 06Hex when writing to any single holding register types. If disabled, the driver 
uses function 10Hex which is more generic. 
 
Integer “I” format is Signed_ magnitude – (Default = disabled) Integers will be expressed as 
signed magnitude if checked. Use, for example, 400001 I 0xFFFF will result in 0x8001 if checked 
else 0xFFFF if not. 
 
Purge Timeout – (0 to disable) Will instruct the communication resource to idle for the specified 
period in milliseconds to wait for incoming noise/corrupted messages to clear from the port, this 
happens when the timeout is too short, and data is still being received. 
 
3.3.4. 
PDU lengths (see section: Protocol unit sizes) 
 
Outputs 000000 , Inputs 100000, Analogue 300000, Holding 400000 , Extended 
600000 – Must be used in conjunction with the “CUSTOM”PLC type, set the appropriate 
lengths here. Length count is in items i.e., 000000, 100000 = 8 items per byte, 300000, 400000 
= 2 bytes per item. 
 
Bit types (Inputs 000000 , Outputs 100000) work optimally in multiples of 8 bits (to a 
byte), i.e. 16 will result in 2 data bytes returned in the data portion of the PDU. Some devices do 
not respond correctly if multiples are not 8.

5. Protocol Definition and Considerations 
5.1. 
Diagnostic Sub-Functions 
 
The function 08 sub-functions are supported as an extension to the driver’s capabilities, and as 
such do not operate as standard scan-points, although they are licensed as such. Data returned 
from a function cannot be read into a tag at this point. 
 
The diagnostic functions are advanced functions, and require special tag configuration for proper

3.3.3.
General
RS485 wiring with reflections - (Advanced option) When using RS-485 the driver will receive
and cater for message reflection which occurs because the RX circuit is enabled during the
transmission of telegrams. (Used with RTS enabled and DTR enabled.) When using an external RS232 to 485 converter this option may not be necessary.
Close serial port on fail - (Default = enabled) This setting, when enabled, will do a hard shut
down and reinitialization of the communications Port. Some Ethernet to serial convertors hang
under noisy conditions, so we compensate for this by only purging and not closing the port.
Optimize scanning of Coils and relays - turn on this option to prevent the driver from doing
read-ahead optimization, and instead read only the required number of bits. By default, the driver
will read all bits packed into a byte, hence the last coil or relay read is always at the end of an 8bit multiple. This option prevents incorrect packing by some non-genuine RTUs.
Detailed debugging - (Default = Disabled) This setting will add additional information to the
datascope.
Use Preset single register (06) func. - (Advanced option) (Default = disabled) Allow the driver
to use function code 06Hex when writing to any single holding register types. If disabled, the driver
uses function 10Hex which is more generic.
Integer "I" format is Signed_ magnitude - (Default = disabled) Integers will be expressed as
signed magnitude if checked. Use, for example, 400001 I 0xFFFF will result in 0x8001 if checked
else 0xFFFF if not.
Purge Timeout - (0 to disable) Will instruct the communication resource to idle for the specified
period in milliseconds to wait for incoming noise/corrupted messages to clear from the port, this
happens when the timeout is too short, and data is still being received.

5.1.6.
Function 08 Registry Entries
The 3 registry entry values can be found in the "Primary" key for each device. e.g.
DWORD startupFn08code = FFFF
DWORD enableFn08 = 1
DWORD startupSF00data = AA55
By changing the "enableFn08" value to zero, reading and writing of the diagnostics points can disabled for security. The values in "Secondary" are ignored if they are different. If the diagnostics
functions have been disabled, the driver addressing options message will no longer show the
explanation regarding the diagnostic scan configuration. The StartupSF00data value can be used
to set an initial value for the sub-function 00 data. e.g.: 0xaa55.
ABB Specific
For proper communication to ABB AC400 series, the diagnostic functions must be enabled, use the
following registry settings. Settings tested with the model AC 450.
DWORD startupFn08code = 0
DWORD enableFn08 = 1
DWORD startupSF00data = AA55
5.2.
Broadcast Support
Broadcast support is achieved by configuring an additional device for station #0. The Modbus
protocol uses a station ID of zero to perform broadcasts. The driver will return zero on scan of any
coils/registers on address zero, and when writing, will not wait for any response from the slave(s).
If you do not want the database to be updated with the zero, you must scan-inhibit the tag while
output enabling it.
All slaves will interpret the command if it is valid. Slaves do not reply to broadcast commands and
only support the following commands in broadcast mode, commands not used by the driver are
not shown.

1. 
Overview 
 
The GSM_SMS protocol driver for Adroit using GSM modems. Messages configured in String or Notify 
Agents may be sent via SMS. Alarms that occur in Adroit can thus be routed to a person via SMS. 
The driver only handles the transmission of the intended message, which can originate as an alarm, 
a message entered by an operator or from programming done in Adroit. This driver is intended for 
easy use with any cellular SMS protocol. No Windows drivers for the modem are needed, this driver 
provides its own interface to the modem via the serial port assigned to it. 
 
All tests and designs were carried out using a ‘WAVECOM WMOD2’ model GSM Modem. 
 
 PLEASE NOTE 
This driver does not currently support secondary ports.

Driver Installation and Setup 
 
Installation of the GSM_SMS protocol driver is done in the standard way in Adroit Setup. After 
installation of the driver, the user may then create and configure devices for the GSM_SMS driver.

At a minimum, you must create at least one GSM_SMS device for each modem. A new device must 
be created per service provider. Currently, the port settings for all devices on a port must be identical. 
In other words, it is not permitted for example to use Vodacom and MTN together.

3.1.5. Using a SIM PIN 
 
The advantage of using a SIM PIN is that if someone on site steals the SIM card, they will NOT have 
full access to making calls. However, this does slow down the initialization process, and may require 
manual PUK unblocking if the wrong PIN is entered more than 3 times. 
 
If using a SIM PIN: 
Enter the required PIN number in the PIN Number edit box, which is stored in the registry, which is 
encrypted. Then when connecting to the modem, the first request carried out is - SIM PIN status and 
if this is required, we use the one provided. 
 
If you want to not specify a SIM PIN: 
In this case, it is necessary to unlock your SIM card, as follows: 
1. Install the SIM card into a mobile phone. 
2. Use the menu functions (which different per phone) to access the security settings and turn 
off SIM checking. 
3. Remove the SIM card from the phone and install it into the GSM modem.

4. 
Supported Addresses 
 
You may only use String type slots. 
 
‘+’ (Read Write) 
For sending and receiving messages, use the international style phone number. For example, 
+27821234567 
 
‘$DR’ (Read only) 
For delivery Reports you must use ‘$DR’ followed by the number as above (no spaces etc.). This will 
give you notification of your SMS when it is delivered to that phone number. 
 
‘$UNKNOWN_MSG’ (Read only) 
Any SMS that is received from an unknown destination (not scanned) will be updated to the String 
slot scanned with this address. 
 
‘$UNKNOWN_NUMBER’ (Read only) 
The sender’s number will be sent to this Sting Slot. 
 
Example: 
If you configure 4 String Agents viz. SHIFT_MANAGER, SHIFT_MANAGER_DR, UNKNOWN_MSG, 
UNKNOWN_NUMBER, and scan them to the addresses…

$UNKNOWN_NUMBER 
 
Messages can be sent and received to and from the Shift Manager, with delivery notification, to 
ensure that the Operator knows that the Shift Manager has received his SMS.

5. Protocol Definition and Considerations 
5.1. 
Using the Notify Agent with GSM_SMS Driver 
 
A very useful feature of the GSM_SMS driver is its ability to route Adroit information (alarms, values, 
statuses, messages etc.) to cellphones. Adroit makes use of the Notify Agent to do this. The 
GSM_SMS driver will receive text messages from Adroit via the Notify Agent and send. The format 
of the text (string) message that the Notify Agent sends the GSM_SMS driver is configurable. It can 
be a simple analogue value, a string, or as is most useful, actual Adroit Alarms. This section explains 
how to set up the routing of an Adroit Alarm to a cellphone, using the Notify Agent. You will create 
on Notify Agent for each user that needs to be sent any messages. 
 
First, we shall assume that we wish to alarm an Analog Tag. This feature is not limited to Analogs; 
any Adroit tag type may be alarmed in its place. 
 
5.1.1. Phase 1: Creating the Agents 
 
Step 1 
Create a new Analog Agent. Edit the Analog Tag and configure High and Low alarms as required. 
 
Step 2 
Create a new AlarmList Agent. Call it something meaningful. 
 
Step 3 
Create a new Alarm Agent. Call it something meaningful. 
 
Step 4 
Create a new Notify Agent. Edit the Notify Agent and ensure that the “User Code” is left empty. 
Check the box entitled “Transmit an Alarm when it is raised”. We shall assume the default alarm 
information is to be transmitted in the text message in this example. If you wish to have control over 
the format of this message, however, you may select which alarm fields you wish to transmit by 
pressing the “Format” button and editing the Alarm Record Structure. 
 
5.1.2. Phase 2: Configuring Alarming 
 
Step 5 
Edit the Alarm Agent. You will automatically be in the “Routes” tab. It is imperative that you select 
a route other than zero. Route 0 is the default route used for general alarms. 
Under Output Destinations, go to the edit box entitled “Alarm Lists”. Select the AlarmList Agent 
you created in Step 2. 
 
Step 6 
Go to the edit box entitled “Output”. Select the Notify Agent you created in Step 4. 
 
Step 7 
Click on the “Types” tab. In the “Agent Type” drop-down box, select the Analog tag. Now in the 
“Available Alarm Types” edit box, remove the “DefaultAlarmAgent” from the box. 
 
Step 8 
Now we add some more types. When you click on the “Add” button, a new dialog will appear. In

5.3. 
Configuring a Notify Agent 
 
The Adroit Notify Agent must be configured in Adroit as above, (see Adroit manual - section: Notify 
Agent) and must be output enabled. In the case of Notify Agents, the slot called “User Code” must 
be left blank when using the GSM_SMS driver. 
 
The Notify Agent can also support User entered messages. Simply type the message into the value 
slot from an Operator Action, “Set value” and the message will be sent when clicking on the OK 
button. 
Note: to re-send an old message, you must change the message content by, for example, adding a 
space at the end of it. 
 
5.4. 
Message Limitations 
 
Limitations may apply to the content of messages; the driver will NOT convert illegal characters in a 
message. Generally, only use keyboard characters. The message length is limited to 79 characters, 
including the device code and a comma added for internal purposes when using the Notify Agent. If 
the Command Agent is being used, then SMS’s will be a maximum of 160 characters.

9.
Appendix B - Unicode (Multi-byte)
Languages (Send only)
When using Unicode languages there are some points to consider.
Due to the Hex mode used on the modem only half the amount of characters can be sent. i.e 70.
The correct code page must be selected, if incorrect the message will likely be garbled. It is
usually best to have the computers local setting match the code page.
English can be sent simultaneously due to the fact that the English alphabet is always
accessible, but again due the use of hex mode the 70 character limit still applies.
If a code page is visible in the Unicode Code page combo box in setup , that means it is a valid
and may be used, the driver will acquire the installed and compatible codepages automatically.
Not all code pages are clearly marked, in those cases an online search may prove use full. For
example : Polish is a Latin based language and its special characters are available on ISO-88592 Latin-2 code page.
When selecting Hex mode, the 4th value of the +CSMP string will automatically be changed to 8
from 0 and vice versa.
The GSM_SMS driver only supports sending of Unicode strings. Reception of Unicode strings will
still be interpreted as single byte strings.
The Command Agent does not recognise Multi-byte strings, so receiving any string in that
format will not be accepted. It is therefore recommended to not use Hex mod when using the
Command Agent in command reception mode.
The Command, Notify or String Agent can be used to send Unicode messages.

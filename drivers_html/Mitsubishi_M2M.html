1. 
Overview 
 
The system allows telemetry functionality for efficient communication to highly distributed systems. 
 
We have attempted to support the most important aspects required for a distributed system, 
namely: 
 
• 
The need for time-stamped data so that events, rather than just register values, can be 
stored. 
 
• 
An event is a register value (16-bit or 32-bit) and a timestamp with second resolution. Time 
of arrival (100ms separation) is attempted to be maintained if change events are registered 
faster than a second. 
 
• 
The need to store in a buffer the events for later retrieval to a SCADA. This is especially 
needed at a time when communication becomes available and/or when the need arises to 
drill down and retrieve most specific data that would not normally require operator 
attention. For example, a temperature reading trend would only be of interest if say a high 
temp alarm were to be received. 
 
• 
Efficient means of communication especially if data costs are an issue. 
 
1.1. 
Supported Hardware 
 
Adroit supports communication with the following PLCs: 
Mitsubishi FX3U with FX3U-ENET using the following “FXM2M613a” Library function block. 
Mitsubishi FX5 PLC using the FX5U_M2M GX Works3 “FX5U_M2M634” program. 
[As of 17/Feb/2022 found in FX5U_M2M_Rev634.gx3] 
 
Mitsubishi QnUDE PLC using the following “QUDEM2M621” Library function block. 
Mitsubishi L-Series PLC using the following “QUDEM2M621” Library function block.

3. 
Device Configuration 
 
3.1. 
Features and Operation: 
 
The system supports the following “Areas” or data types scannable into Adroit: 
 
• 
FX5 DATA Area: 500 data 16-bit WORDs or 250 32-bit WORDs can be mapped or any 
combination making up a total 500 WORDs. This is enforced because of the maximum packet 
size that can be transmitted in one transaction. (ONLY D registers can be monitored) 
 
• 
Q/L DATA Area: 232 data 16-bit WORDs or 116 32-bit WORDs can be mapped or any 
combination making up a total 232 WORDs. This is enforced because of the maximum packet 
size that can be transmitted in one transaction. (ONLY D registers can be monitored) (500 
WORD support still to come) 
 
• 
CONFIG Area: 30 configuration WORDs. 
 
• 
STATISTICS Area: 6 data usage DWORDs and 7 remote side statistical WORDs. 
 
• 
STATUS Area: 3 status 16-bit WORDs, status bits, count WORD seconds to next poll, other 
status bits. 
 
• 
ACTION Area: 2 control 16-bit packed WORDs. 
 
• 
Data area is time-stamped (seconds resolution) data. Devices request time synchronization 
periodically (default is once per day, but this is configurable) but the master can set time at 
any point if required. (Time set is instantaneously, not gradually.) 
 
• 
Manual poll instructions for all Areas, and a periodic DATA Area poll. 
 
• 
Write commands for all Areas except STATISTICS. 
 
• 
Unsolicited support for priority events of DATA Area. 
 
• 
Unsolicited support for historical events of DATA Area. 
 
• 
Logical addresses can be allocated to Priority (Alarmed) or Historical modes, with per logical 
address value deadbanding to reduce risk of chatter. 
 
• 
The driver implements a daemon that will listen for and associate a channel to device link to 
allow incoming and outgoing data to a known device. The PLC is in control of the connection 
attempt and is expected to contact the master periodically via a LINK which the master will 
ACK. This allows for support for fixed and, part of the main design philosophy, dynamic non-
public IPs typically found on public GPRS networks. 
 
• 
FX Systems Historical buffer supporting 1000 (16-bit) events or 500 (32-bit) events. 
 
• 
Q/L Systems Historical buffer supporting 7 500 (16-bit) events or 3750 (32-bit) events. 
 
• 
FX Systems Priority buffer supports 250 (16-bit) events or 125(32-bit) events. 
 
• 
Q/L Systems Priority buffer supports 250 (16-bit) events or 125(32-bit) events.

• 
Historical mode can be enabled/disabled. Automatic retrieval of history can be 
enabled/disabled. Historical buffer can be configured to be kept below a defined threshold. 
 
• 
Any device may be put into reduced communications mode or ‘Economy Mode’ on a per device 
level, and/or per driver level, to allow for reduced comms load during high/peak periods. 
History buffer threshold exceeded reads and periodic interrogates are stopped during this time. 
 
• 
Failover protection in case an invalid IP/port is configured the PLC will eventually timeout and 
go back to the last known “good” configuration (LKG) to reduce the risk of having to manually 
reprogram the configuration. 
 
• 
A standard default configuration is also implemented for first boot-up and connection. 
 
• 
A forced and fixed latency (quiet delay) between consecutive message transmissions from the 
master to the same PLC device is currently hardcoded to 500ms. Retry attempts are also 
hardcoded at 250ms. 
 
• 
The following config data will result in dynamic change and persisted to keep the change valid 
between agent server restarts: 
o Enable priority events. 
o Enable history logging. 
o Keep buffer below %. 
o The actual %. – (this will only accept 25%, 50%, 75% and will automatically select 
the closest valid value.) 
o Periodic Update interval. 
 
Local daemon configuration, however, will remain offline. Changes via Adroit’s setup will 
require an Agent Server restart. Please note that even though station address is 
configurable via the CONFIG Area and can even be changed, this is specifically not 
persisted. The user is forced to manually allocate a new device configuration via setup. 
 
Unknown contacts can thus come in via their default address assuming one at a time come 
alive, then a user can force a new address into the PLC via that same device. The PLC will 
then swing over to the newly provided device, thus freeing up the “unknown device” to 
wait for the next contact and the procedure can be repeated. 
 
If a device does not answer, the PLC will failover back the original address allowing a 
retry. 
 
 WARNING 
Port changes result in an entirely new Daemon being instantiated so devices cannot cross between 
communications Daemon. 
 
• 
STATISTICAL data is available in the statistics area where data such as current daily and the 
last month’s usage is available (this data is persisted and available between Agent Server 
restarts). Other PLC side data such as the number of times the modem has been reset, open 
errors, transactions etc. are also available. This must be manually polled via an ACTION bit. 
 
• 
ACTION and STATUS WORDs are available for information on what modes the M2M is currently 
in, and for control of these functions including manual initiation of functions by toggling these 
bits as required.

• 
The M2M system can be put into “LIVE” mode, where it will send all DATA every 10 seconds. 
If not already on, it will set the “Auto history” to on which will attempt to flush the history 
buffer as well. 
• 
Out of contact alert bit available. 
 
• 
Start-up activity, the driver will time-synchronize the PLC if flagged to do so. A start-up data 
poll (interrogate) is sent, followed by sending a start-up config poll, then sending a start-up 
statistics poll. Enable unsolicited and historical modes if configured. 
 
• 
Offline configuration is refreshed whenever the device is restarted, except that on the PLC side 
there are several latched regions in the file register that will persist between PLC power loss 
and program rewrites. 
 
• 
As of rev620 for the Q-series, the driver has been implemented with a Primary/Secondary 
connection feature for back-up connections to an Adroit Master and Standby Server. In prior 
releases (for Q series, rev619 and earlier) this was referred to as Clustering. This has now 
been replaced by a more customisable dual-port feature mainly used for connection failures, 
allowing the system to connect an alternate Agent Server. The system can be altered to 
operate in Standalone or Dual-Port configuration through the CONFIG Area - CW28. 
 
Refer to Dual-Port and Standalone Mode and Appendix – Standalone and Dual-Port Details 
in this document for more information on how this feature operates. 
 
• 
As of rev35 of the Adroit driver, the M2M connection works with Adroit clustering both in 
Parallel and Shadow Scanning configurations with the new dual-port features. 
 
3.2. 
PLC Performance Considerations: FX5 
 
This system was designed for High Site monitoring where the number of I/O points is low. The 
system has limited buffer space for events so having large I/O DataMaps will cause it to easily 
become overcrowded. Attempting to increase these buffers will make the cycle time of the PLC 
much longer. 
The Q Series PLC’s are a lot faster, with typical cycle times in the low 10’s of milliseconds so it is 
suggested to use a Q PLC when trying to use larger I/O maps, and the Q function block allows for 
larger buffers for event data, ~7500 vs ~1000 on the FX5. 
 
 PLEASE NOTE 
The Q function block still only supports 232 currently. 
 
As of Rev 30b for FX Systems the PLC can support a DataMap size of 500 16-bit (250 32-bit) 
registers.

4.3. 
Addressing Details DATA AREA 
4.3.1. Data area [DW0 – DW(max d-reg)] (READ and WRITEABLE) 
 
The data area is the actual address of the D-Reg as defined in the map in the PLC. 
 
The items defined do NOT need to be consecutive and it is entirely possible to have mixed memory 
16-bit and 32-bit items randomly distributed across the map if the SCADA addressing matches. 
 
From the PLC: 
− 
If the PLC has defined an address size incorrectly as defined in the SCADA, the system 
will still operate normally except it will raise a status SW0, bit 11 MAP_MISMATCHED until 
the discrepancy is resolved. 
− 
If say the PLC sends a DWORD and the SCADA expects a WORD, the SCADA is overridden 
to reflect a DWORD instead, as the compatible agents can accept a DWORD. Writes from 
the SCADA will however be cast to the lower WORD so the mismatch should be corrected 
as soon as possible. 
− 
If say the PLC sends a WORD and the SCADA expects a DWORD, the SCADA accepts the 
data as is. Writes from the SCADA will however be cast to the lower WORD in the PLC so 
the mismatch should be corrected as soon as possible. 
 
 PLEASE NOTE 
Consider the 3rd value in the first stack (DD2:2) - it is a DWORD, and it is logically the third item in 
the stack. It affects the physical address position of the next data point (DW4:3). This fourth data 
points to physical location that starts one value lower because of the DWORD item above it. This is 
very important as an INTERROGATE request will retrieve this whole data area, and if the scanning 
is not defined correctly, it will not unpack correctly.

ForceSwitch (AW0, Bit 14) and CW29 Bit 2 will be set to indicate a pending required switch. 
However, the operator has two choices and does not necessarily have to switch the 
connection. The choices are summarized as follows: 
 
▪ 
A change on the current connection has been sent by the operator but the operator 
wants the connection to re-establish on the same current connection (in terms of 
primary and secondary), then the operator can perform trigger a Reset_M2M. The 
new connection details will be loaded but connection will first try to connect on the 
same dual-port connection. For example, the operator is currently on the secondary 
connection and makes a change on the secondary, but the operator wishes to stay on 
the secondary, then they can perform a Reset_M2M action. Refer to ‘Change 
Connection Details [Maintaining the current connection]: Dual-Port’ in the Appendix 
for reference. 
▪ 
A change on the alternative connection details has been sent by the operator but the 
operator wants the connection to re-establish on the alternative connection (in terms 
of primary and secondary), then the operator can perform trigger a ForceSwitch. The 
new connection details will be loaded, and the connection will then first try to 
connect on the alternative dual-port connection. For example, the operator is 
currently on the secondary connection and makes a change on the primary, but the 
operator wishes to change to the primary to verify a valid connection, then they can 
perform a ForceSwitch action. Refer to ‘Change Connection Details [Applied to 
alternate connection]: Dual-Port’ in the Appendix for reference.

successful connection has been made to it. For example, changing the details on the primary

ForceSwitch flag, since an attempt on the new connection was not attempted. This is the same if 
the new connection details do not result in a valid connection. Refer to ‘Change Connection Details 
[Maintaining the current connection]: Dual-Port’ and ‘Change Connection Details [Applied to the 
alternate connection]: Dual-Port’ in the Appendix for more information.

3.
Device Configuration
3.1.
Features and Operation:
The system supports the following "Areas" or data types scannable into Adroit:
FX5 DATA Area: 500 data 16-bit WORDs or 250 32-bit WORDs can be mapped or any
combination making up a total 500 WORDs. This is enforced because of the maximum packet
size that can be transmitted in one transaction. (ONLY D registers can be monitored)
Q/L DATA Area: 232 data 16-bit WORDs or 116 32-bit WORDs can be mapped or any
combination making up a total 232 WORDs. This is enforced because of the maximum packet
size that can be transmitted in one transaction. (ONLY D registers can be monitored) (500
WORD support still to come)
CONFIG Area: 30 configuration WORDs.
STATISTICS Area: 6 data usage DWORDs and 7 remote side statistical WORDs.
STATUS Area: 3 status 16-bit WORDs, status bits, count WORD seconds to next poll, other
status bits.
ACTION Area: 2 control 16-bit packed WORDs.
Data area is time-stamped (seconds resolution) data. Devices request time synchronization
periodically (default is once per day, but this is configurable) but the master can set time at
any point if required. (Time set is instantaneously, not gradually.)
Manual poll instructions for all Areas, and a periodic DATA Area poll.
Write commands for all Areas except STATISTICS.
Unsolicited support for priority events of DATA Area.
Unsolicited support for historical events of DATA Area.
Logical addresses can be allocated to Priority (Alarmed) or Historical modes, with per logical
address value deadbanding to reduce risk of chatter.
The driver implements a daemon that will listen for and associate a channel to device link to
allow incoming and outgoing data to a known device. The PLC is in control of the connection
attempt and is expected to contact the master periodically via a LINK which the master will
ACK. This allows for support for fixed and, part of the main design philosophy, dynamic nonpublic IPs typically found on public GPRS networks.
FX Systems Historical buffer supporting 1000 (16-bit) events or 500 (32-bit) events.
Q/L Systems Historical buffer supporting 7 500 (16-bit) events or 3750 (32-bit) events.
FX Systems Priority buffer supports 250 (16-bit) events or 125(32-bit) events.
Q/L Systems Priority buffer supports 250 (16-bit) events or 125(32-bit) events.

Historical mode can be enabled/disabled. Automatic retrieval of history can be
enabled/disabled. Historical buffer can be configured to be kept below a defined threshold.
Any device may be put into reduced communications mode or 'Economy Mode' on a per device
level, and/or per driver level, to allow for reduced comms load during high/peak periods.
History buffer threshold exceeded reads and periodic interrogates are stopped during this time.
Failover protection in case an invalid IP/port is configured the PLC will eventually timeout and
go back to the last known "good" configuration (LKG) to reduce the risk of having to manually
reprogram the configuration.
A standard default configuration is also implemented for first boot-up and connection.
A forced and fixed latency (quiet delay) between consecutive message transmissions from the
master to the same PLC device is currently hardcoded to 500ms. Retry attempts are also
hardcoded at 250ms.
The following config data will result in dynamic change and persisted to keep the change valid
between agent server restarts:
o Enable priority events.
o Enable history logging.
o Keep buffer below %.
o The actual %. - (this will only accept 25%, 50%, 75% and will automatically select
the closest valid value.)
o Periodic Update interval.
Local daemon configuration, however, will remain offline. Changes via Adroit's setup will
require an Agent Server restart. Please note that even though station address is
configurable via the CONFIG Area and can even be changed, this is specifically not
persisted. The user is forced to manually allocate a new device configuration via setup.
Unknown contacts can thus come in via their default address assuming one at a time come
alive, then a user can force a new address into the PLC via that same device. The PLC will
then swing over to the newly provided device, thus freeing up the "unknown device" to
wait for the next contact and the procedure can be repeated.
If a device does not answer, the PLC will failover back the original address allowing a
retry.
WARNING
Port changes result in an entirely new Daemon being instantiated so devices cannot cross between
communications Daemon.
STATISTICAL data is available in the statistics area where data such as current daily and the
last month's usage is available (this data is persisted and available between Agent Server
restarts). Other PLC side data such as the number of times the modem has been reset, open
errors, transactions etc. are also available. This must be manually polled via an ACTION bit.
ACTION and STATUS WORDs are available for information on what modes the M2M is currently
in, and for control of these functions including manual initiation of functions by toggling these
bits as required.

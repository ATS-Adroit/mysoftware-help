1. Overview 
 
Adroit supports communication with the Mitsubishi FX PLC range, using the red Beijer RS-232/422 
converter cable and other programming cables. MitFXS is designed to replace the existing MitsuFX 
and MitsuFXS drivers which are discontinued (see Appendix A for compatibility with deprecated 
drivers). 
 
This driver also supports communication using Dial-Up Modem. 
 
This driver also supports communication using “Serial over Ethernet” connection that wraps the serial 
FX extended protocol into the data portion so as to be usable by Ethernet to serial gateways, the 
protocol is not modified.

2. Wiring 
 
2.1. 
Direct 
 
Connect using RS-232 programming cable from Mitsubishi. Red SC09 converter cable 
“RS232/RS422”. 
 
2.2. 
Modem 
 
On the remote PLC side to connect the modem serial output to the SC09 cable, ensure that a cross 
over serial cable is used, because we want to double crossover i.e. MASTER TX to exit out of the 
MODEM TX line to enter the TX input of the SC09.

Retry – The number of attempts that Adroit will try to communicate with a PLC before failing a

Timeout – The time that Adroit will wait for a valid response from a PLC before failing a transaction

ACK transactions, which would otherwise be delayed due to delays produced by the modems.

5. Protocol Definition and Considerations 
 
Communications are fixed at 9600 baud, 7 data, 1 start, 1 stop and even parity. The protocol is 
essentially ASCII, with control codes delimiting portions of the messages. The LRC value is the 8-bit 
SUM of all bytes in a message from after the STX up until and including the ETX. 
 
All PLC Types before the FX2N model uses the FX Protocol, the FX2N and FX3U use the Extended FX 
Protocol.

6.3. 
Troubleshooting 
It is possible that by modifying the default settings, that the watchdog sent by the driver may not 
arrive in the PLC, thus causing the PLC to “intermittently” reset our connection to the PLC. Ensure 
that the timer in the PLC (which runs for 120 seconds by default) is at least double the setting used 
by the driver. If the driver channel is backlogged (i.e. the driver is too busy with polling tasks), the 
watchdog may also be delayed, as it is not a foreground process in the driver. Driver backlogging or 
queuing is easily detectable by setting a value in register in the PLC, and then timing how long it 
takes to receive a feedback via another tag which was scanned to the same register.

7. Appendix A 
 
7.1. 
Compatibility with Previous FX drivers. 
 
 WARNING 
MITSUFXS is not directly compatible with MITFXS therefore the need to change the driver name 
which will prevent problems when upgrading. 
 
A. X and Y regions scanned as INT and REAL will now be correctly addressed starting bit will now 
designate the address i.e. X 0 I – 1st integer in the X region X 20 I is the 2nd integer. The old 
style was X 0 I, X 2 I … 
 
B. S regions scanned as INT and REAL will now be correctly addressed starting bit will now 
designate the address i.e. S 0 I – 1st integer in the S region S 16 I is the 2nd integer. The old 
style was S 0 I, S 1 I … 
This will now bring the addressing standard into line with GX Developer. 
 
Dword support where applicable, is added. 
 
PDU data lengths have been optimized.

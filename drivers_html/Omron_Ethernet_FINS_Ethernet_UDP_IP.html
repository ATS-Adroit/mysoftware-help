3. Device Configuration 
3.1. 
Device Configuration 
 
 
 
3.1.1. 
Config Selection 
 
Enable Secondary – Enables secondary configuration for dual redundant PLCs via Primary and 
Secondary radio buttons. Do not enable if a secondary channel is not configured correctly. 
 
3.1.2. 
PLC Details 
 
PLC Unit no. – The unit number as configured at the front of the Ethernet unit. 
 
PLC Node no. – The node number as configured at the front of the Ethernet unit. The node number 
is the same as the last byte of the IP Address. For example, if the IP Address is 192.168.1.55, then 
the node number should be 55. 
 
PLC Type – The CS/CJ Series is currently supported. 
 
 PLEASE NOTE 
If needed, the CV series will be accommodated.

3.2. 
Registry Settings (BYTE, WORD and DWORD 
Swopping) 
 
There are a few registry settings that allows for compensation when bytes, words or double words 
get swapped around in the receiving protocol message for the different post fixes (as shown below) 
types of namely B, D, I, L, N, R, W and X. 
These registry keys are not accessible from the dialog but can be changed if required from the 
registry by the following steps: 
 
 Open the Registry by going to START-RUN and typing regedit and then press ENTER 
 
 Go to the following key – 
HKEY_LOCAL_MACHINE\SOFTWARE\Adroit Technologies\Adroit\ProtocolDrivers\Omr_Eth\<YOUR 
DEVICE NAME>\Primary 
 
 There is a set of DWORD Keys that can be set to 0 as it is 1 by default. 
The keys are: 
 
“Swap_B_Bytes” 
 
– Swop the bytes of a 16-bit BCD value 
“Swap_D_Bytes” 
 
– Swop the bytes of an unsigned double value 
“Swap_D_Words” 
– Swop the words of an unsigned double value 
“Swap_I_Bytes” 
 
– Swop the bytes of a signed word value 
“Swap_W_Bytes” 
 
– Swop the bytes of an unsigned word value 
“Swap_L_Bytes” 
 
– Swop the bytes of a signed double value 
“Swap_L_Words” 
 
– Swop the words of a signed double value 
“Swap_N_Bytes” 
 
– Swop the bytes of a 32-bit BCD value 
“Swap_N_Words” 
 
– Swop the words of a 32-bit BCD value 
“Swap_R_Bytes” 
 
– Swop the bytes of a 32-bit Float value 
“Swap_R_Words” 
 
– Swop the words of a 32-bit Float value 
“Swap_X_Bytes” 
 
– Swop the bytes of a 64-bit Float value 
“Swap_X_Words” 
 
– Swop the words of a 64-bit Float value 
“Swap_X_DWords” 
– Swop the double words of a 64-bit Float value

6.3. 
Troubleshooting 
6.3.1. 
Problem 1 
 
Problem 
When connected to the PLC and there is communication with device, but my Adroit Tag is still scan 
bad even though I can see in the datascope that I am receiving some sort of data? 
 
Solution 
The first place to look at is in the datascope on ASCII mode. Bytes 13 and 14 of the response 
message will indicate the END CODES. If the 2 bytes are not 00 00 then the tag is “scan bad” as 
there is some kind of error as indicated on image below. 
 
 
Above Image Represents ASCII datascope with end codes returned an error. 
 
 
Above Image Represents ASCII datascope with no errors.

The error codes are available in this document on page 7, but the OMRON Communication 
Commands Reference Manual – Catalogue Number W342-E1-06 goes into more depth with the error 
codes on page 113 – 119. 
 
Example: End Code = 90 05 hex. 
 
Take 9005 and convert to binary, which will give you 10001100101101. Stripping of the MSB (Bit 
15) and in this case was ON which means “Error in Network relay” as shown on pg118 of above 
mentioned OMRON manual. After stripping bit 15 we are left with 0001100101101. Bit 8 to 14 
represent the main end code which will give us value of 10. In the OMRON manual as mentioned 
above on page 114 the value 10 means “Command Format Error”. 
 
If bit 7 is ON it means a “Fatal CPU unit error” and with bit 6 ON it means “Non-fatal CPU Unit Error”. 
In our case we did not have a CPU error. 
 
Bit 0 to 5 represents the sub code which in our case is 05. According to the OMRON manual on page 
114 the sub end code of 5 means “Header Error”. 
This concludes that our errors received is “error in network relay”, ”command format error” and 
“header error” and the problem was solved by correcting the “Unit No” that was specified incorrectly 
in the adroit setup as indicated below the Unit No should have been 0.

1. 
Overview 
 
This driver supports the Mitsubishi 3E Frames protocol, with communication to the Q/QnA/L/R and 
FX5 Series CPU’s. 
 
The 2nd Generation driver allows for the following features: 
a) 
Improved performance due to optimizations on mixed I/O to the same protocol area being 
transacted only once removing redundant transactions. 
b) 
Support for multiple channels, where due scan tasks are balanced over available channels, 
reads and writes are interlaced to prevent starvation. 
c) 
Demand scanning support, where read only I/O that is not on a mimic / graphic form and not 
logged or alarmed and not output enabled will be removed from the scanning system , the applicable 
tasks will dynamically be reduced in size and can merge into fewer scan tasks. 
For improved network performance and reliability, it is recommended that you install 2 network 
adapters into your PC. Use the first adapter for Adroit to Adroit and all other Windows connectivity. 
The first adapter may have all the default installation bindings. Use the second adapter for Adroit to 
PLC connectivity and bind only to the TCP/IP protocol for PLC communications. 
 
1.1. 
Upgrading from classical MITQJE71 Driver 
 
The scanning addresses are identical. 
 
If using the MITQJE71 driver, remove all of the old Device Agents, and create them again with the 
same names using the Q driver. Take care to note settings like the IP, port address and watchdog 
addresses. On the A-Series driver the Decimal or Hex notation used is important and does change 
over in this Q/QnA driver. Names of I/O types stay the same so far possible, this means that scanned 
I/O types existing in the A-Series driver that have different names (prefixes) in the Q Driver are 
promoted automatically to their new names. After saving, the WGP file cannot be loaded on the old 
driver again without the possibility of losing some scan-points.

3. 
Device Configuration 
3.1. 
Device Configuration 
 
Enable secondary – Turn this option to have the driver maintain 2 channels of communication, 
the radio buttons Primary and Secondary can then be used to toggle between configurations. 
 
Enable shadow scanning from master to standby – NASA specific function – per Device Agent 
level shadow scanning. 
 
If enabled, writes will be sent to the master to be executed on its corresponding device and reads 
from master will be replicated to the standby. 
 
If disabled writes Parallel scanning is enabled. 
 
Enable standby reads – If disabled, the standby will be considered cold, no reading will take place 
on the standby connection, and neither will any replication from the master occur. 
 
Enable standby writes -– If disabled, no writing will take place on the standby connection, and 
neither will any request be forwarded to the master. 
 
3.1.1. Error Handling 
Retries - (Default = 3) Number of attempts per transaction. 
 
Disconnect after every transaction – (Default = False) -Tell the channel to close the port after 
every transaction. This can be useful on gateways if required. 
 
Disconnect after every error – (Default = False) Tell the channel to close and reopen the port 
on every error during retries else it will only occur after the final retry. 
 
3.1.2. Latency 
Inter-PLC latency – The period that the system will wait before transmitting any read request or 
write request in multi-dropped system when a new device is contacted. 
 
Transmission latency – The period that the system will wait before transmitting any read request 
or write request for the same plc device. Inter message delay. 
 
Tx to RX latency – The period that the system will wait after transmitting a request and before 
attempting to read the response. 
 
3.1.3. Ethernet 
IP Address – IPv4 address. For example, 192.168.3.50 
 
IP Port – (Default = 1280) For multiple channels a CSV format is supported. For example, say for 
Channels = 3, IP Port = 1280,1282,1289

Max PDU – this specifies the maximum number of words (16-bit) that the driver will allow to be

CPU Number – Enables communication to up to 4 CPU units on the same PLC. Also allows for 
selection of “Redundant” CPU pair and if selected will ensure that all communications is transferred

CPU timeout – The timeout setting to be used internally by the external card for transactions with 
the CPU. The actual value used is rounded up in increments of 250ms. Legal values are 1 through 
63750ms. 
 
Debug level bitmask – (Default = 480) This is a bitmask that enable extra debugging in the 
datascope output, do not leave it enabled during normal operation on high-speed drivers as it will

Ping - (and result) Click the test button on the far left. 
 
3.1.6. Driver Send Watchdog 
This is an internal driver based write to help the PLC program to check if the communications 
between master and PLC is healthy. It can be used to pause operations or cycle the network, etc. 
 
Enable – (Default = OFF) Enable to tell the device to generate an internal write based on Type, to 
a specified bit Address. 
 
Address – (Default = M 100) Any writeable bit Address. 
 
Rate (mSec) – (Default = 2000ms) The period the driver will initiate a new watchdog send.

5. Protocol Definition and Considerations 
5.1. 
PLC software and Heartbeat code 
5.1.1. PLC Side Communication setup 
Two possible configurations are presented, one without a watchdog timer, and one with a watchdog. 
The driver thus supports two modes: one with heartbeat, and one without. PLC logic is required for 
the watchdog. If a watchdog/heartbeat is not used, the AJ must simply be configured using GX 
developer. Sample code using IEC to configure the AJ is not supplied. Any sample programs are 
supplied as-is and are not under any warranty.

1.
Overview
This driver supports the Mitsubishi 3E Frames protocol, with communication to the Q/QnA/L/R and
FX5 Series CPU's.
The 2nd Generation driver allows for the following features:
a)
Improved performance due to optimizations on mixed I/O to the same protocol area being
transacted only once removing redundant transactions.
b)
Support for multiple channels, where due scan tasks are balanced over available channels,
reads and writes are interlaced to prevent starvation.
c)
Demand scanning support, where read only I/O that is not on a mimic / graphic form and not
logged or alarmed and not output enabled will be removed from the scanning system , the applicable
tasks will dynamically be reduced in size and can merge into fewer scan tasks.
For improved network performance and reliability, it is recommended that you install 2 network
adapters into your PC. Use the first adapter for Adroit to Adroit and all other Windows connectivity.
The first adapter may have all the default installation bindings. Use the second adapter for Adroit to
PLC connectivity and bind only to the TCP/IP protocol for PLC communications.
1.1.
Upgrading from classical MITQJE71 Driver
The scanning addresses are identical.
If using the MITQJE71 driver, remove all of the old Device Agents, and create them again with the
same names using the Q driver. Take care to note settings like the IP, port address and watchdog
addresses. On the A-Series driver the Decimal or Hex notation used is important and does change
over in this Q/QnA driver. Names of I/O types stay the same so far possible, this means that scanned
I/O types existing in the A-Series driver that have different names (prefixes) in the Q Driver are
promoted automatically to their new names. After saving, the WGP file cannot be loaded on the old
driver again without the possibility of losing some scan-points.

3.
Device Configuration
Enable secondary - Turn this option to have the driver maintain 2 channels of communication,
the radio buttons Primary and Secondary can then be used to toggle between configurations.
Enable shadow scanning from master to standby - NASA specific function - per Device Agent
level shadow scanning.
If enabled, writes will be sent to the master to be executed on its corresponding device and reads
from master will be replicated to the standby.
If disabled writes Parallel scanning is enabled.
Enable standby reads - If disabled, the standby will be considered cold, no reading will take place
on the standby connection, and neither will any replication from the master occur.
Enable standby writes -- If disabled, no writing will take place on the standby connection, and
neither will any request be forwarded to the master.
3.1.1. Error Handling
Retries - (Default = 3) Number of attempts per transaction.
Disconnect after every transaction - (Default = False) -Tell the channel to close the port after
every transaction. This can be useful on gateways if required.
Disconnect after every error - (Default = False) Tell the channel to close and reopen the port
on every error during retries else it will only occur after the final retry.
3.1.2. Latency
Inter-PLC latency - The period that the system will wait before transmitting any read request or
write request in multi-dropped system when a new device is contacted.
Transmission latency - The period that the system will wait before transmitting any read request
or write request for the same plc device. Inter message delay.
Tx to RX latency - The period that the system will wait after transmitting a request and before
attempting to read the response.
3.1.3. Ethernet
IP Address - IPv4 address. For example, 192.168.3.50
IP Port - (Default = 1280) For multiple channels a CSV format is supported. For example, say for
Channels = 3, IP Port = 1280,1282,1289

3.1.6. Driver Send Watchdog
This is an internal driver based write to help the PLC program to check if the communications
between master and PLC is healthy. It can be used to pause operations or cycle the network, etc.
Enable - (Default = OFF) Enable to tell the device to generate an internal write based on Type, to
a specified bit Address.
Address - (Default = M 100) Any writeable bit Address.
Rate (mSec) - (Default = 2000ms) The period the driver will initiate a new watchdog send.

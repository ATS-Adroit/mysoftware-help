1. Overview 
 
This driver supports the Mitsubishi 3E Frames protocol, with communication to the Q/QnA/L/R and 
FX5 Series CPU’s. 
 
For further information regarding TCP/IP connectivity refer to Windows Networks Help. The SNMP, 
WEB and FTP services on the QJ71E71 are not required for Adroit to Mitsubishi communication. 
 
For improved network performance and reliability, it is recommended that you install 2 network 
adapters into your PC. Use the first adapter for Adroit to Adroit and all other Windows connectivity. 
The first adapter may have all the default installation bindings. Use the second adapter for Adroit to 
PLC connectivity and bind only to the TCP/IP protocol for PLC communications. 
 
1.1. 
Upgrading from original A Series Driver for Q CPU 
 
If using the A-series driver, remove all the old Device Agents, and create them again with the same 
names using the Q driver. Take care to note settings like the IP, port address and watchdog addresses. 
On the A-Series driver the Decimal or Hex notation used is important and does change over in this 
Q/QnA driver. Names of I/O types stay the same so far possible, this means that scanned I/O types 
existing in the A-Series driver that have different names (prefixes) in the Q Driver are promoted 
automatically to their new names. After saving, the WGP file cannot be loaded on the old driver again 
without the possibility of losing some scan-points.

3.1.1. 
Device Configuration 
 
 
 
3.1.2. 
Port Selection 
 
Enable secondary – Turn this option to have the driver maintain 2 channels of communication, 
where the radio buttons Primary and Secondary can then be used to toggle between configurations. 
 
3.1.3. 
PLC Details 
 
PLC Type – Select the relevant PLC CPU model; Q Series CPU, QnA Series CPU, L Series CPU, R 
Series CPU, FX5(iQ-F) Series and Custom. By selecting a CPU, you set the device address range. 
Custom allows you to modify these ranges. 
 
IP Address – Enter the TCP/IP address assigned to the PLC. The default IP address here is your own 
IP, and often it is required that only the last octet be changed. IPv6 is not supported.

Port – The accessible port on the PLC in GX-developer. This value is expressed in hexadecimal; hence 
you can use the drop-box nest to the entry field to toggle between HEX and decimal display modes. 
AJ->CPU timeout (ms) – The timeout setting to be used internally by the external card for 
transactions with the CPU. This value must be less than the communications timeout specified 
below it. The actual value used is rounded up in increments of 250ms. Legal values are 1 through 
63750ms. 
 
CPU Number – Enables communication to up to 4 CPU units on the same PLC. Also allows for 
selection of “Redundant” CPU pair and if selected will ensure that all communications are transferred 
to MASTER CPU in configured redundant system. 
 
Connection Type – Select TCP or UDP connection. 
 
3.1.4. 
MC Protocol 
 
Uses a MELSEC network to access other CPUs remotely through this PLC. 
 
Network No – Network Number of network to be used. 
 
Station No – Remote PLC station number. 
 
3.1.5. 
Heartbeat for Reliable Connection 
 
Use heartbeat – Enable this button to have the driver keep the PLC connection alive. Please see the 
PLC program and heartbeat sections below. This option is only useful with the watchdog program 
running in the PLC. 
 
Heartbeat bit # - Specify the “M” bit number to be turned on by the driver periodically signalling 
SCADA connection as OK. The default heartbeat bit is “M 0” which must be changed if used. 
 
Time between beats – Specify the millisecond interval at which to turn the bit on. The PLC program 
should use a time set to double this value to detect link failure. 
 
3.1.6. 
Local Details 
 
Communications timeout – The interval in milliseconds before the driver assumes the PLC is not 
responding if not response is received, after which the driver will reset and open the connection. As 
in the case with a non-fatal error exception response, the driver will re-attempt the transaction 3 
times. The number of retries is not settable. 
 
Retries – The number of times a specific transaction will be retried before failing the transaction 
completely. 
 
Detailed debugger output – turning this option on forces the driver to provide detailed information 
of activity on the device’s driver diagnostic datascope screen. Use this option when troubleshooting 
problems involving the watchdog/heartbeat, or specific tags not working.

3.1.7. 
Max Device Address Ranges 
 
This section specifies the maximum address that can be validated for each address type. Note, these 
ranges can only be edited manually if the PLC Type is set to Custom. 
 
PDU Length (WORDS) – this specifies the maximum number of words (16-bit) that the driver will 
allow to be transacted in a single transaction. 
 
3.1.8. 
Test Device for Connectivity 
 
Uses a MELSEC network to access other CPUs remotely through this PLC. 
 
Test Address – Type any valid address in here as found under Supported Addresses. 
 
IO Type – Select the base type of read to be performed (Int/Real/String/Bool). 
 
Read Address Button - Press the button to start a direct connection to the plc from this dialog, it 
will open a datascope and attempt a read and display the result. 
 
 PLEASE NOTE 
This must only be executed on the Agent Server machine. If an existing Agent Server connection is 
currently established, it is recommended to not use this method to determine connectivity. Rather 
use the existing methods provided in the Agent Server. 
 
Reply – Simple value result is displayed here. 
 
Ping – Click to perform a “Ping” test which will verify access to the PLC card only. Accessibility to the 
specified port is not verified. For more information in Ping, read the Windows Networking help.

If your PLC’s memory range is smaller than the range supported by the driver, it is possible to 
configure the driver to scan non-existent I/O addresses. Since this can cause unpredictable results, 
please ensure that all scanned I/O are valid for your controller’s current configuration. 
 
 INFORMATION 
Timer/Counter current values are supported, but the contact and coil values are not scanned. T 
and C prefixes are promoted to TN and CN respectively. 
 
Adroit string slots and ASCII type is only supported to Data/File registers and can be scanned as “D/R 
0 Sn” where n is the number of ASCII characters in the string required, which can go up to a maximum 
of 79. 
 
Omitted 
The following I/O types or devices are not supported: 
Device 
Mnemonic 
Function in/outputs 
 
Special relays 
SM, SD 
Timer and counter coils and contacts 
TS, TC, SS, SC, CS, CC 
Step relay 
S 
Direct in/out 
DX, DY 
 
Non-bit device writes 
Bit-writes to items that are not supported in the protocol as discrete (bit devices) will be supported 
using read-mask-write, hence they will be slower.

1. Overview
This driver supports the Mitsubishi 3E Frames protocol, with communication to the Q/QnA/L/R and
FX5 Series CPU's.
For further information regarding TCP/IP connectivity refer to Windows Networks Help. The SNMP,
WEB and FTP services on the QJ71E71 are not required for Adroit to Mitsubishi communication.
For improved network performance and reliability, it is recommended that you install 2 network
adapters into your PC. Use the first adapter for Adroit to Adroit and all other Windows connectivity.
The first adapter may have all the default installation bindings. Use the second adapter for Adroit to
PLC connectivity and bind only to the TCP/IP protocol for PLC communications.
1.1.
Upgrading from original A Series Driver for Q CPU
If using the A-series driver, remove all the old Device Agents, and create them again with the same
names using the Q driver. Take care to note settings like the IP, port address and watchdog addresses.
On the A-Series driver the Decimal or Hex notation used is important and does change over in this
Q/QnA driver. Names of I/O types stay the same so far possible, this means that scanned I/O types
existing in the A-Series driver that have different names (prefixes) in the Q Driver are promoted
automatically to their new names. After saving, the WGP file cannot be loaded on the old driver again
without the possibility of losing some scan-points.

Port - The accessible port on the PLC in GX-developer. This value is expressed in hexadecimal; hence

MC Protocol
Uses a MELSEC network to access other CPUs remotely through this PLC.
Network No - Network Number of network to be used.

3.1.5.
Heartbeat for Reliable Connection
Use heartbeat - Enable this button to have the driver keep the PLC connection alive. Please see the
PLC program and heartbeat sections below. This option is only useful with the watchdog program
running in the PLC.
Heartbeat bit # - Specify the "M" bit number to be turned on by the driver periodically signalling
SCADA connection as OK. The default heartbeat bit is "M 0" which must be changed if used.
Time between beats - Specify the millisecond interval at which to turn the bit on. The PLC program
should use a time set to double this value to detect link failure.
3.1.6.
Local Details
Communications timeout - The interval in milliseconds before the driver assumes the PLC is not
responding if not response is received, after which the driver will reset and open the connection. As
in the case with a non-fatal error exception response, the driver will re-attempt the transaction 3
times. The number of retries is not settable.
Retries - The number of times a specific transaction will be retried before failing the transaction
completely.
Detailed debugger output - turning this option on forces the driver to provide detailed information
of activity on the device's driver diagnostic datascope screen. Use this option when troubleshooting
problems involving the watchdog/heartbeat, or specific tags not working.

6.3.
Troubleshooting Steps
The RUN and INIT lamps on the AJ must be lit.
The COM.ERR lamp indicates a protocol or hardware fault has occurred.
Ping the relevant PLC Ethernet card E.g.
ping 192.168.1.11
The ping should be echoed back.
During a ping, the RD and SD lamps on the external module will flicker together.
Check that the port is not already open, if another device is already connected to the PLC, the OPEN
lamp will be lit. It is possible that multiple pieces of equipment are connected and have an open
port. To see the status of open ports, the "Ethernet diagnostics" menu in GX Developer.

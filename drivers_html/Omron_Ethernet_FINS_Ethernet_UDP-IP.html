Retry - The number of times the driver must retry a connection, or a Transmit/Receive transaction
before returning an indication of failure.
Timeout - The time in milliseconds to wait between each communication retry.
Enable control retries - By checking this box, an interrupted WRITE operation will be retried.
Otherwise, only READ operations will be retries.

Note: There is no CRC field present in the FINS data frame, although the response codes as indicated
in this section provide minimal assurance that the correct data was received.

* The bits for the ICF are laid out as follows:
Bit 7: (1)
Bit 6: (0)
Bit 5: (0)

Bit 0: Response (0=Required, 1=Not required) ,
Bit 1: Always 0

Bit 5: Always 0
Bit 6: Data classification (0=Command, 1=Response),
Bit 7: Bridges (0=Not used, 1=used).
A typical ICF for a command frame would be 0x80, and for a response frame 0xC0.
RSV:
Reserved byte. Always 0.
GCT:
Gateway count. Number of bridges passed through. Currently, the Adroit OMRON Ethernet protocol
driver doesn't support bridging, thus this byte will be 0x00.
DA1:
Destination node address. This corresponds to the last byte of the destination IP Address, which, in
this example is 55 (HEX 0x37)
DA2:
Destination unit address. Corresponds to the unit number as set on the destination unit.

6.3.
Troubleshooting
Problem
When connected to the PLC and there is communication with device, but my Adroit Tag is still scan
bad even though I can see in the datascope that I am receiving some sort of data?
Solution
The first place to look at is in the datascope on ASCII mode. Bytes 13 and 14 of the response
message will indicate the END CODES. If the 2 bytes are not 00 00 then the tag is "scan bad" as
there is some kind of error as indicated on image below.

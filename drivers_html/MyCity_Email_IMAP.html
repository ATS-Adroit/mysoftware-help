3. Device Configuration 
3.1. 
Device Configuration 
 
 
3.1.1. Port Selection 
 
Enable Secondary – Enables secondary configuration for dual redundant Controllers. This setting 
is disabled for this driver. 
 
Primary / Secondary – Select the primary or secondary button depending on which connection 
you wish to configure. 
3.1.2. Common Mail Settings 
 
(The parameters identified by the * define a resource common to all devices that share those 
parameters. Any change to these parameters in this group will cause a change for all Adroit devices 
using this mailbox. Note: this will include other drivers such as the Adroit SMTP Email client driver.) 
 
Resource - An internal ID representing a mailbox configuration in Adroit that cannot be edited. 
When adding a new device, the last added resource will be used to pre-populate the mailbox settings 
(this is used to make the adding of multiple devices easier). To choose another resource, simply 
select it and click OK. To change anything the driver will ask if a new resource is to be created or 
the existing resource be changed for all devices using it. 
 
*Mailbox Type - IMAP is automatically selected (POP is no longer supported). 
 
*Mail Server - The name of the mail server.

*Mail Port - 993 for IMAP (143 is now no longer used), 110 for POP (no longer supported). 
 
Login Name - Username on the server. 
Login Password - User password. 
 
Mailbox Poll Period (ms) - Checking the mailbox for new mails will occur at this interval. 
 
Server uses SSL - [On by default] Some POP and IMAP servers require SLL mode. 
IMAP servers listen on port 143 typically, while 993 is used for SSL/TLS. POP servers listen on 
port 110 typically, while 995 is used for SSL/TLS (no longer supported.) 
 
Detailed debugging to datascope - Each record updated to Adroit will be displayed. 
 
Incoming Mailbox - Incoming account inbox name. 
 
Backup Mailbox - Any emails that are successfully read from the inbox that are for a device that 
is started will be moved to this mailbox. No emails will ever be deleted from this box; therefore, it is 
up to the relevant user to perform manual deletion. (NB – this function is only allowed in IMAP 
mode). 
 
 PLEASE NOTE 
Some servers do not allow multiple mailboxes on one account, but they usually allow subfolders, if 
this is the case: use dot notation. 
For example: 
 INBOX.BACKUPBOX 
 
ToDo Mailbox - When a valid email is received that is for a device that has not been started or is 
currently stopped will move to this mailbox. When a device is 
 
Error Mailbox - When an invalid email is received and Adroit cannot process the incoming mail, the 
email will be moved to this mailbox. Emails here will not be checked again or deleted and must be 
done manually by the user. Any spam that has not been automatically filtered will also be moved 
here. 
3.1.3. Local Device Settings 
 
Station ID - This is the identifier code sent in the subject line of the email. You can use any fixed 
identifiable substring in the subject line. 
 
For example: “Subject: F000001398 : 0082728922419110000100” 
 
The StationID could be the last number including the colon 
“: 0082728922419110000100” or “F000001398” or “F000001398 : 0082728922419110000100” or 
the whole string.

5. Protocol Definition and Considerations 
5.1. 
Datascope Considerations 
 
 
 
When the Adroit Driver Monitor Launcher is examined, all devices will be seen. Note that one of 
them will have indicate more activity than the others. This is usually the top one in the list, which is 
the first one to attach in the agent server on a particular resource (mailbox). This is where all mailbox 
activity will be seen – call it the activity log. If a second mailbox resource is added, the first device 
to attach would be designated the “activity log” for that mailbox. It would not necessarily be at the 
top, so one would have to look for it. 
 
Let’s say we have 2 devices, the first one will show activity of the mailbox, such as checking the 
inbox and displaying empty, etc. We will see updates for that device in white and blue as data. The 
next datascope opened at the same time will only display its own activity, which will become active 
when a valid mail is received, and the driver begins processing the data. Refer to the following 
diagrams for more information:

Now we will receive 3 messages to the inbox: an email for FLOTRON1 (currently started), an email 
for FLOTRON2 (currently stopped) and a spam message. 
 
Note when a message is received for a device how the activity log associated with this device will 
display the data being collected from the email. In this case, an email has been identified for 
FLOTRON1, so the message unpacking is displayed on FLOTRON1’s activity log. Once completed, 
this message is moved to the mailbox listed in the device configuration for the Backup Mailbox (in 
this case BACKUPBOX). 
 
 
 
Now when the message for FLOTRON2 has been detected, it will not attempt to parse the message 
as the device is set to stopped in Adroit. This email is instead moved to the mailbox listed in the 
device configuration for the ToDo Mailbox (in this case TODOBOX).

In summary: 
• 
Any emails that fail to validate due to formatting errors, such as missing the checksum field at 
the end of an email, will be moved to the Error Mailbox. 
 
• 
Any emails that are for an Adroit device that is stopped or does not exist will be moved to the 
ToDo Mailbox. 
 
• 
Any emails that are for an Adroit device that is started, succeeds validation and has been parsed 
to Adroit will be moved to the Backup Mailbox. 
 
5.2. 
Other Considerations 
 
The not-healthy flag on a device will only be cleared once some valid data has been received for it, 
so on Agent server start-up it will show unhealthy until some valid email comes in, if after a while it 
still shows unhealthy then there is a problem. 
 
5.3. 
Datalogging Considerations 
 
Datalogging to Adroit proprietary database (LGD) files require special consideration. 
 
Under normal circumstances, if the value does not change but the timestamp does change the value 
will not be logged if it is newer than the last time on that tag in question. However, historical data 
values will be logged as received even though there is no change. This must be done to allow the 
proper operation of historical logging. 
 
If there is a requirement to log every value for every period you must force this by using Demand 
mode with “self” triggering, A1 triggers itself. This will force ALL values to be logged regardless of 
whether they have changed.

6.3.1. Cannot install the driver (Adroit 10.0.5.2 and earlier) 
 
As of Adroit 10.0.5.2 Update 1, the MyCity Email driver does not have a .inf which is used to add the 
installation of the driver. To install the driver, please go to the following Adroit directory and move 
the mycity.dll from the Drivers folder into the main directory. So, move the mycity.dll from: 
 
C:\Program Files (x86)\Adroit Technologies\Adroit\Drivers 
 
Move into the directory: 
C:\Program Files (x86)\Adroit Technologies\Adroit 
 
6.3.2. Access denied error 
 
Error code according to the device datascope:

[10013] Access deniedCannot do email work! 
 
If you are experiencing this error, please check that the following are correct: 
- 
Login Name and Password 
- 
Mail Server and Mail Port 
If this is still not causing the issue, please make sure that your firewall is not currently blocking the 
port that was provided in the device configuration.

7. Appendix A 
7.1. 
Gmail Setup for Email Drivers using IMAP [New Google 
Security Policy] 
 
This knowledge base article details the steps required in configuring the Gmail IMAP server with the 
mentioned Adroit email drivers, in line with Gmail’s new security policies implemented as of 30 May 
2022. For further information, refer to the following Google Account Help article: 
https://support.google.com/accounts/answer/6010255?hl=en 
The opening article states the following: 
To help keep your account secure, from May 30, 2022, Google no longer supports the use of 
third-party apps or devices which ask you to sign in to your Google Account using only your 
username and password. 
Important: This deadline does not apply to Google Workspace or Google Cloud Identity customers. 
The enforcement date for these customers will be announced on the Workspace blog at a later 
date. 
For more information, continue to read. 
Previously, Adroit email driver’s required full access to your Gmail account, and subsequently your 
Google account, to allow access into your inbox using the Gmail IMAP server. This required adjusting 
a security setting on your Google account to allow 3rd party applications to access your account. 
If you have noticed that Adroit has not been able to successfully connect to the Gmail IMAP server, 
typically stating an authentication error, the problem could be related to this issue.

[AUTHENTICATIONFAILED] Invalid Credentials (Failure) Cannot do email work!]

1. 
Overview 
CANBUS is partially supported by this driver, additions will be added as required. 
 
Using the KVASER canlib API version 5.49.188, simulator is provided by canking version 6.27.701. 
CanDrivers version 5.49.188. 
 
Each Adroit Agent Server can enable tags linked to a CANBUS message provided by a browser that 
will load a dbc file. 
 
Raw 8 bytes , Unsolicited message support, by means of a dbc file that defines one or more CANid 
messages and one or more signal per massage. A CANid range is specified in setup , the driver will 
then not allocate these to a scantask nor attempt to poll for them in anyway. 
 
 
1.1. Supported Hardware 
 
This driver has been tested on the following hardware: 
 
Kvaser simulated ports using CANKING. 
 
 
2. 
Wiring 
 
Not applicable.

3. 
Device Configuration 
3.1. Device Configuration 
 
 
Enable secondary – Turn this option to have the driver maintain 2 channels of communication, 
the radio buttons Primary and Secondary can then be used to toggle between configurations. 
3.1.1. Driver Details 
Enable Secondary – (Default = OFF) Allows enabling of redundant MQTT Broker connections such 
that in case of a failure a switchover will occur. 
 
Primary – Allows configuration setting of the Primary broker connection. 
 
Secondary – Allows configuration setting of the Secondary broker connection. 
3.1.2. Device Details 
Enable shadow scanning from master to standby – (Default = OFF) If enabled will stop any 
communication to the MQTT broker when the Agent Server is in standby mode. By default, we 
assume parallel scanning. 
 
Enable standby reads – (Default = ON) Allows reading from the MQTT broker when the Agent 
Server is in standby mode.

Enable standby writes – (Default = OFF) Allows writing to the MQTT broker when the Agent 
Server is in standby mode. 
 
CANbus details 
 
Channel Index – Channel index as per defined within the CANbus API. Usually exclusive open, all 
channel on the bus “hear” the other channels. Can be thought of as nodes. 
 
Timeout – timeout in millseconds, if polling a specific address. Not applicable for Unsolicited updates 
, see contact exceeded period below. 
 
DBC file– CSV of the full filename and path, multiple dbcs will be supported, currently it is 
recommended to only have one active at a time. Contact Adroit Drivers if this is not adequate. 
 
Bitrate – dropdown combo of applicable bitrate for the bus , the driver must match the CANbus 
hardware. 
 
Use flexible bitrate – opt in to allow for flexible higher than normal rates, the driver must match 
the CANbus hardware. Only one type of bit rate is active at a time so if this is true then Flexible 
bitrate is active. 
 
Flexible bitrate – dropdown combo of additional applicable bitrates for the bus , the driver must 
match the CANbus hardware. 
 
Unsolicited mode 
 
Contact exceeded period (mSec.) Session – (Default = True) This will tell the MQTT broker to 
establish a persistent session or not. If True, the broker will discard any data previously associated 
with the current client ID once successfully connected. Otherwise, when disconnected the broker 
and client will store the session, all subscriptions for the client and all missed messages, when QoS 
1 or 2. 
 
Begin CAN ID (dec) – (Default = 1024dec) if the CANID is between this begin and end value this 
item will not be allocated to a read task , but only available for unsolicited updates, the driver will 
listen on the bus for this item. 
 
End CAN ID (dec) – (Default = 1279dec) if the CANID is between this begin and end value this 
item will not be allocated to a read task , but only available for unsolicited updates, the driver will 
listen on the bus for this item. 
 
Advanced details 
 
Debug level bitmask – (Default = 65535) This is a bitmask that enable extra debugging in the 
datascope output, do not leave it enabled during normal operation on high-speed drivers as it will 
slow down the system depending on speed requirements. In serial drivers this delay is negligible.

7. 
Sparkplug B Notes 
For Adroit 10.0.5.5 onwards Sparkplug B is supported via a SmartUI Server script. 
That usually scans for all expected messaging. 
Input and output Sparkplug B messages are usually scanned to a relatively high-level wildcard “K:#” 
This will allow all Sparkplug messages to be sent to the applicable slots usually a String Agent’s valueex 
slot.

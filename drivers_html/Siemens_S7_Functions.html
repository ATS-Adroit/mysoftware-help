Overview
The S7 Functions driver uses built-in S7 function blocks to communicate with the S7
via L2/MPI, ISO Industrial Ethernet or TCP/IP (if supported on your CP). You will
need to obtain "S7 Functions" or S7 drivers + licences for your CP card from
SIEMENS to enable communication.
Communication to H1 BUS using S7 functions for H1 (to a CP 443-1) has only been
tested for Industrial Ethernet, and not for TCP/IP.
This document will take you through the installation steps for SIMATIC NET, and
then of the Adroit driver. Depending on your version of Simatic and which CP card
you use, instructions will differ. The driver will not appear in the available list in
Adroit Setup until you have completed installation of the Simatic net drivers.
Wiring
L2: Wiring between the card and the stations is standard RS-485. Fibre optic
link modules (OLM's) and copper may be used. No external terminators
as such are required, however it is necessary to set up terminating
switches at the end of cable runs. As physical wiring is not within the
scope of this document, please consult documentation accompanying the
communication modules for details.
H1: Use an AUI to BNC /UTP /Fibre converter to connect to the LAN.

CP Setup
The Sinec setup program can be run directly from this button.
A RSAP is not required, since 00.00 is assumed. When assigning L2 BUS addresses;
remember that an unused address must always be reserved between stations on the
BUS. Only use either odd or even addresses. Address zero should also not be used,
since it is reserved for a PG or diagnostic node. If using MPI, the remote tsap to use
may be 01.00.
Watchdog configuration
Watchdog configuration is optional, and is intended to allow detection of the started
/stopped state of the PLC. Without the watchdog a user has no way of knowing that
the remote CPU has gone into stop mode, since the communications processor, being
separate, continues to function as normal. If not required the watchdog checking
should be disabled.
Watchdog operation
If enabled the watchdog operates by flagging the device as off-line, almost as if there
was a cable fault. The driver then polls the configured 16-bit word at 10-second
intervals. If the PLC variable's value is zero, the driver flags the device as on-line, and
overwrites the zero with a one. If the PLC variable's value is not zero, the driver will
re-test the variable 2 more times, before flagging the device as off-line. The extra 3
tries constitute a grace period, after that all scanning will be bad until the watchdog
variable is zeroed. The driver continues to poll during this time.

The Simatic drivers and the API together manage connections configured in a
database, the database is roughly organized to allow many different applications
(programs) to communicate to PLCs without interfering with each other. At the lowest
level, the database holds a CP card.
This means that each application will have a
number of connections, each connection will be
associated with a single CP. In Adroit, we
associate a connection with a device, since
normally you will sue one connection per PLC
you need to communicate to. Nothing however prevents the configuration of 2
connections whose parameters are for the same PLC. Adroit will still see them as
separate devices. Applications are differentiated by their names. "OPC Server" is an
example of an application with no connections. An application thus only needs to
know the connection name, the connection uses a specific set of parameters, and a CP,
all of which are hidden from the application, allowing the user flexibility to use new
kinds of CP cards and connection parameters freely.

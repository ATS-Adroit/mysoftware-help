Central Station Details (Global affects all 
devices) 
 
Items configured in this group are common to all outstations using the same serial port. What this 
means is if you want to change a parameter such as, say, Link Test Interval, you will need to change 
it for all other devices on that particular communications resource (com port), if not then a new port 
should be used, which implies a different teleRanger RS-232 module, etc. 
Please Note non device specific messages like SM and LT etc will not have a checksum at all, the 
spectrum device will not expect one either. 
 
Central Station Address - The teleRanger central station address, C1 -> C2 
 
Link Test Interval (Sec) - The time (in seconds) between the sending of successive link test (“LT”) 
commands from Adroit to the teleRanger central station. A time of zero disables link testing 
 
Synchronize All Telemetry Clocks (Startup) - When active, this check box will cause all 
outstations to be time synchronized with the SCADA system clock, This will happen once when the 
driver loads. Manual syncs via OSCTL.5 will need to be done when in modem mode … OSHDR.16 
can be driven via an Expression Agent. 
 
Time between “IR” messages The number of seconds to leave between any two stations 
performing an “IR” or interrogate command. 
 
Latency (Sec) - The minimum time delay (in seconds) between the sending of ANY (IR or GL) 
request commands from Adroit to the outstation. Any one will reset the timer to force the other to 
delay. This is NOT global it is only a delay between two IR/GL polls to the SAME station. Manual 
commands (IR and GL) are unaffected and will go out as normal.

3.1.5. 
Outstation Details (Device Specific) 
 
In contrast with the Global Options section, each teleRanger outstation may have a different set of 
outstation details. Generally, the System No. will be common to all outstations, but each outstation 
will have a unique Station Address. 
Station Address - The teleRanger outstation number (“01 to “99”) 
 
System No. - The teleRanger system number (“0” to “9”) that this outstation belongs to 
 
Periodic Update (sec) (Interrogate) Interval - You will be forced to select 0 this when in 
modem mode, manual polling will be required in modem mode. The time (in seconds) between the 
sending of successive update requests (“IR”) commands from Adroit to this outstation. This is NOT 
global it only a delay between two IR polls to the SAME station. 
 
Enable Master Side AKs - Default unchecked. When checked, upon reception of any messages 
of type Change AC/DC etc, Adroit will transmit an AK Acknowledgement back to the originating 
outstation. 
 
Wait For Slave Control AK - Default is unchecked. When checked All controls are checked for 
acknowledgement, i.e. , no new controls will be sent until the pending/current control is completed 
via reception of the ack. This is per device, therefore if an ack for and IA is “pending”, no other 
control will be sent until the IA-Ack is received or the IA timed-out. This will prevent multiple controls 
being sent, but the multiple controls will however be queued for transmission later. Controls will also 
be retried via the timeout mechanism. 
 
IA/IR/WR/TT Pulsed - Default is unchecked. When checked OSHDR.11/12/13 are pulsed on then 
off immediately again (useful for triggers).

OutGoing messages use CRC16 instead of XOR

3.3. 
Master/Standby 
When the Adroit Agent server changes between modes (only if configured as a cluster server), the 
driver is notified, and will not perform any “IR” nor “LT” transmissions when in standby. The input 
data from stations is still processed as normal but is ignored by the Adroit Server. Any queued 
commands (or retries) when the server changes from master to standby will still be sent and are not 
immediately cleared or removed at that time.

4.2. 
Basic Structure of Driver 
Being a Radio Telemetry System, teleRanger poses some special protocol driver development and 
configuration challenges: 
• 
Delayed response. With PLC systems a read request is honoured immediately, whereas with 
a radio telemetry system, several different requests can be sent out before a response to the 
first one is received. Also, the sequence in which responses arrive is totally unpredictable 
• 
Exception-based. Instead of using a poll-response type protocol like most other Adroit protocol 
drivers, the teleRanger driver operates in an exception- or event-based mode. This means 
that messages arrive from the teleRanger equipment in an unsolicited fashion 
• 
Time-tagged. The teleRanger protocol includes the possibility of tagging changes of state and 
other events with the time of occurrence. The protocol driver needs to be aware of time-
tagged information and make sure that this time, as opposed to the current system time, is 
associated with the event 
• 
Even though Adroit directly connects to only a local teleRanger station, it must maintain 
communications, etc., on a per remote station basis. This is to prevent all stations being 
considered bad when only one station may be experiencing communication problems 
 
Given all the above, the following diagram illustrates the context within which the teleRanger protocol 
driver operates:

and Adroit device agents, i.e. a separate device agent is configured for each teleRanger outstation. 
The following diagram shows how the protocol driver connects via an RS232 link to the teleRanger

4.4. 
Addressing Notation 
 
There are four basic items that need to be defined to be able to uniquely identify any point in a 
teleRanger radio telemetry system. These are: 
• 
Station Address - a number (01 - 99) that defines the particular teleRanger station 
• 
Encode/Decode Channel - a number (00 - 99) that defines the particular I/O module. Inputs 
are “encoded” with their channel number as part of message transmission, and outputs are 
“decoded” by teleRanger stations before being recognized 1 
• 
Module - as per above table 
• 
Bit/Channel Number - a number (1 - 32) that defines the particular input or output on a specific 
I/O module 2 
 
Note that, teleRanger stations are mapped directly to Adroit devices. This means that the station 
address field above does not need to form part the Adroit teleRanger addressing notation. 
The addressing notation is therefore: 
<Module >.[<Encode/Decode Channel>].<Bit/Channel Number> 
 
Note that the Encode/Decode channel field is not always required. Specifically, for outstation header 
items, which do not relate directly to I/O points in the field, but rather to DIP switch settings, etc., 
on the outstation, the concept of an encode/decode channel is meaningless and is hence not 
required. A bit number is often supplied where not necessary and will be 1. 
 
Some examples: 
DIO88.04.1[0] 
Input No. 1 of 8-channel digital input/ Output card with encode channel set to 
04 [0..15 pulse factor-Digitals Outputs Only] 
DIN32.04.1 
Input No. 1 of 32-channel digital input card with encode channel set to 04 
AIN412.7.4 
Input No. 4 of 4-channel analog input card with encode channel set to 07 
OSHDR.1 
Outstation header input no. 1 (master/slave mode) 
OSCTL.4 
Outstation header control no. 4 (get dip switch settings) 
 
 
 
 
 
 
 
 
 
 
1 Note that for the dummy counter reset and counter sync modules the encode/decode channel of the 
relevant CIN4 module should be supplied 
2 Note that the maximum bit/channel no. is dependent on the module type, for example: 32 for a DIN32 
module, and 2 for a AOU28 module.

5. Protocol Definition and Considerations 
 
The following protocol document outlines the subset of the Tele-ranger protocol supported and used 
by the Adroit Tele-ranger driver. The outline shows the basic telegram format as a skeleton, and 
then progresses to fill in the components in the data portion of the telegram. The protocol is ASCII, 
i.e. using only printable characters, decimal values appear as “30” for the value 30 and consists of 
the binary characters 33,30. Hex values appear as “0A” which is 10 decimal and consists of the 
binary characters 30,41. 
All values are in ascii decimal except $$ which are ascii hex notation.

4.2.
Basic Structure of Driver
Being a Radio Telemetry System, teleRanger poses some special protocol driver development and
configuration challenges:
Delayed response. With PLC systems a read request is honoured immediately, whereas with
a radio telemetry system, several different requests can be sent out before a response to the
first one is received. Also, the sequence in which responses arrive is totally unpredictable
Exception-based. Instead of using a poll-response type protocol like most other Adroit protocol
drivers, the teleRanger driver operates in an exception- or event-based mode. This means
that messages arrive from the teleRanger equipment in an unsolicited fashion
Time-tagged. The teleRanger protocol includes the possibility of tagging changes of state and
other events with the time of occurrence. The protocol driver needs to be aware of timetagged information and make sure that this time, as opposed to the current system time, is
associated with the event
Even though Adroit directly connects to only a local teleRanger station, it must maintain
communications, etc., on a per remote station basis. This is to prevent all stations being
considered bad when only one station may be experiencing communication problems

7. Appendix A - How to Troubleshoot and
Setup Modems.
This discussion describes landline dialup modem support , but gsm modems are also compatible to
the basic command sets so there is no reason for them not to work either.
Where applicable I will refer to the Hayes (x.2) command set as well as the Duxbury command set.
(*h) - X2 Hayes only (e.g. US robotics)
(*d) - Duxbury only.
Nothing means identical for both command sets.
7.1.
1st Steps
Use HyperTerminal to establish initial communications with the modems , make sure you can
communicate with the modem by creating a hyper terminal session manually to the appropriate com
port. Type in any command and check whether the modem acknowledges it. Try AT(return) you
should see OK. [ATZ, ATI4(*h) or AT&V(*d) for current config info etc)
If no ack is found try a command that will definitely return something ATI4(*h) AT&V(*d).
If no acks are sent but the about info does get sent check result codes are being sent Q = 0. And
the codes must be returned as text V=1.
AT&F will reset the modem factory defaults.
Make sure Carrier detect is enabled &C1. *NB - for driver hang up ability.
Make sure DTR control is enabled &D2. *NB - for driver hang up ability.
If you want the modem to auto-answer make sure S0>0 (i.e. S0=2 for 2 rings then answer)
Make sure Echo is off when you are finished testing E=0. *NB - for driver logic.
Make sure B0(*h). Data baud rate will follow connection train rate.
AT&W(*h) will save the profile , older modems have 2 profiles AT&W0 , AT&W1…
7.2.
For Remote Modem
Make sure the following is set : S0=0, spectrum answers manually.
&D0 spectrum does not control the DTR line and thus must be disabled/ignored!
Recommended ATE0 s0=0 &D2 &C1&W done manually via terminal! Make sure the save went
through by turning off the modem and then doing a ATI4(*h) to check.
7.3.
For Master Modem
S0 = 2 , two rings until auto answer, then the device modem "modem is configured for auto answer"
must be checked , otherwise if its unchecked S0=0, then the driver with do a manual ATA. (It is
recommended to use the modems auto answer feature)

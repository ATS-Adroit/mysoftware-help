Overview
Supports OPTOMUX slave digital and analog controllers. Each
OPTOMUX board consists of a brain board with microprocessor and
an I/O mounting rack. The units communicate over a RS422/485
network which interfaces to the computer via an interface
converter.
This document refers to the microprocessor and I/O rack as the
remote module.

Device Configuration
Device Configuration
Port Selection
Enable Secondary – Enables secondary configuration for dual
redundant Controllers. This setting is disabled for this driver.
Primary / Secondary – Select the primary or secondary button
depending on which connection you wish to configure.
Local Details

Port – The available serial ports on your machine
Baud rate - ????
Retry – The number of times that Adroit will try to gain
communication with a module before failing a transaction.
Timeout (ms) – The time that Adroit will wait for a valid response
from a module before failing a transaction (Read or Write).
Parity – Default to none.
Data bits – Default to 8.
Stop bits – Default to 1.
Moxa Cluster Support - Check this option when running on a MOXA
virtual port in a cluster environment. It will allow to purge the port
when in standby and in shadow mode, as the MOXA unit stops
functioning in this mode. Data keeps filling the buffer seeing that
the driver does not do any reading from the port and eventually
becomes unresponsive!
Hard Purge (Using API) - Does a call to the COM PORT to purge all
the data on it. (Preferred Method).
Soft Purge (Read from Port) - Continue to read data from the port
and just discard it.

Close serial port on fail - With a transaction failure closes the port
and re-opens it by default but for some virtual ports it becomes an
issue so we allow not closing the port in this case.

The Enable Dialog.
Controllers 0 through 255 can be displayed by selecting the visible
range from the range radio button group. The dialog may be used to
enable or disable modules, alternately the same status can be
achieved by scanning Digitals to the enable tags for the modules
and displaying them on a mimic.

changes the driver may have made)
All enabled and All disabled will update the dialog, without saving
the values.

Modules are addresses by ‘M’ for module, followed by the controller
address, the module type, then it’s position from 0(zero) to 15.
Digital I/O can be scanned into a multistate, by specifying the first
digital module in the controller, as input or output, if output is
used, all positions will become outputs. When writing to the value,
only the output modules on the board get updated.
Refresh and controller-enable are header items, i.e. they are not
actual I/O points. They do however count as scan points.
All non-configured positions are assumed by the driver to be inputs.
Header Items
The special address mnemonic for a Boolean or Digital slot is
supplied to initiate configuration refresh on demand: “UPDATE”.
Issuing a digital write with a value of 1 will initiate steps 2 & 3 of
the startup sequence described in Operation. This address will
return zero if scanned. This will refresh the configuration of all the
enabled controllers.
The special address mnemonic “ENABLE n” will allow enabling and
disabling of scanning for a specific module “n”, as an enable tag.
This virtual variable can also be driven from the driver setup dialog.
If the dialog is used to change the value, the digital tag (if scanned)
associated with the variable will also update. A value of 1 =
enabled, and zero (checkbox off) = disabled.
The enable tags get saved in the system registry database for each
device, if the device gets deleted in the setup program, this

information is thus lost.
Operation
The driver scans all input and output variables as required by the
scan agents. When writing, the driver only writes to items
configured as outputs. Digitals are written using read-mask-write.
On the relevant start-up flag the driver will upload all settings, a
dummy force tag is also provided to allow refreshing of the
configuration data. Start-up flags triggered by events are controller
start-up and driver loading, providing 3 ways to refresh the
controller configuration.
The controller configuration is controlled by the driver, which uses
the complete I/O list of scan-points to configure the controller I/O
points. If 2 scanned points for the same I/O module have conflicting
information, the last one’s configuration will be used. Since
whichever scan point is the overriding one is not configurable, this
technique is advised against. The figure below illustrates the
possible ways to initialize the controller configuration.

Driver
Start-up involves 3 steps:
Clear power-on flag (in event of power on).
Set Turn-around delay, watchdog and protocol type parameters.
Send all I/O configuration information to the controller.
All Opto22 controller I/O configuration data will be derived from
actual scanning configured in the adroit database, so as a new scan-
point gets configured it will be down-loaded to the controller.
Already configured scan points all get sent immediately when the
scanning starts (i.e. device starts) as the system loads.
Multiple Devices
Multiple devices may not be assigned to scan the same controller,
else the I/O configuration information which is down-loaded will
conflict. If multiple devices are used to address the boards on a
single line, they must be uniquely assigned to scan the boards.

To scan boards on a separate line, a new device must be assigned to

Tag Scaling Configuration
Opto22 modules provide a raw output range of 0-4095, the actual
value derived to the SCADA is biased with a constant value of 4096,
thus the raw range of an analog is 4096 to 8192. Missing modules
and modules not already configured in the scanning database, will
return 0 (zero). All slots in a module, which are not configured, are
assumed to be inputs.

Power Supply
The power supply requirements are 5V for digital boards with
analog boards requiring a +15v, 0v, -15v supply as well. A
standard 5V TTL supply is recommended to ensure correct
operation of the brain board.
Enabling Stations
If a remote controller is not enabled, the driver will not
communicate with it at all, and the scanned tags for that controller
will remain grayed out. Check the setup dialog to see if the
controller is enabled.
Enable Tag Saving
The enable tags for the modules are saved in the registry, if the
Setup program or the agent server does not have the required
security to change the registry, the changes will not be transferred
and saved. Change the security on the registry key or log-on as a
different user to run Setup or the Agent Server.

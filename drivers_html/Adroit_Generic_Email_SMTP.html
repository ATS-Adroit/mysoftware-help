1. 
Overview 
 
This driver is used to send email messages via Simple Mail Transfer Protocol (SMTP), designed 
specifically for sending alarms or any other information such as Adroit tag values, SV and PV values, 
as well as attachments. 
The driver currently only supports RAWBYTES slots, of which only the Notify Agent currently provides 
a suitable Rawbytes slot. 
 
The Notify Agent allows for manual email sending, and it also exposes the various sub items such as 
TO, CC, FROM, SUBJECT and so forth as individual VARSTRING slots so an email interface could easily 
be crafted onto a mimic. 
 
The subject line and body may contain text macros that are parsed to allow for the additional 
information from Adroit, specifically slot and alarm details, to be sent if required and not just a simple 
alarm text field.

3. 
Device Configuration 
 
3.1. Email Configuration 
 
 
 
3.1.1. Outgoing Mail Settings 
 
Mailbox Resource – A specific resource ID that uniquely identifies an email resource. The relevant 
mailbox settings are saved and remembered for the next time the configuration is brought up. 
Additional Adroit devices can be created and quickly configured with existing mailbox resources. A 
prompt will appear when settings have been changed that do not impact the resource constituents 
whether it must affect all existing devices that use that resource or if it must create a new resource 
to not affect current devices. For this email driver, this only applies to the LOGIN PASSWORD field. 
 
From – The fully qualified email address the email will be sent from. 
 
Login Password – The account domain password. 
 
SMTP Server – The specific SMTP server to contact according to protocol specifications. Usually 
matches the machine name e.g. MAIL.adroit.co.za 
 
SMTP Mail Port – Port required on the mail server for SMTP. Typically, this is 465 for SSL. Other 
ports could include 25 and 587. 
 
3.2. MACRO Usage in Email 
 
This email driver is used in conjunction with the Notify agent. 
<ALM> will insert the alarm string received from the Notify Agent.

 PLEASE NOTE 
The text that will be substituted into the <ALM> macro first needs to be generated by an actual 
alarm. If you see this field as blank in testing, it means an alarm has not been triggered to 
generate it. 
 
<Agent.slot> will insert the result of a string query to the agent slot. For example, an Analog.value 
slot will result in the engineering value being inserted. 
Emails manually sent will contain the macros without the substitution for verification. The macros 
will only be expanded through the traditional Adroit alarming mechanism. Macros can be placed 
anywhere in the text fields of SUBJECT or BODY where duplicates are allowed. 
 
The ATTACHMENT line may only send 1 file at a time, though any file may be sent. For example, 
this can be inserted into the BODY: 
 
Hello Fred 
An alarm for your attention: ( <ALM> ), 
The dam level is at <DAM_LVL.VALUE> meters. 
The pump is <RUN_STATE.TEXT>. 
 
Goodbye from Adroit

4. 
Supported Addresses 
 
4.1. Outgoing Email Rawbytes Slots. 
 
The driver address is “EMAIL.x” where {x >= 0, X <= 250}. When scanning, note the following: 
- 
Must be Output enabled. 
- 
Must be Input disabled. 
- 
Must be scanned to a Notify agent’s Email-rawValue slot. 
The other Notify agent slots are internal and should not be directly scanned to any driver. 
Noting that the FROM field is defined once in the device setup, a system may require more. This can 
be achieved by adding as many mode “devices” as needed. 
 
If the FROM field is not significant, up to 250 Notify agent slots may be scanned to one device by 
incrementing the scan address index.

6.3. Troubleshooting 
 
 When I try send a test email in the Notify agent with an <ALM> macro, I get the following 
printed in my email body: Alarm trigger required to generate ALM message. 
Placeholding 80 characters here. 
 
The reason this message is inserted is because an alarm has not been triggered for the affected 
Notify agent. Only on an alarm is the message generated which can then be substituted into this 
macro. This message is substituted instead to account for the worst-case scenario regarding the 
length of the alarm message macro – maximum size of 80 characters. 
 
 I cannot connect to my Gmail account. (Authentication error) 
Google has updated its security policy regarding 3rd party applications with access to your Google 
account. You will need to setup an App Password with 2-Step Verification to allow the Adroit Email 
Protocol Driver to have access to your Google account. 
 
For more information, please refer to this Adroit Knowledge Base article, which can also be viewed 
in Appendix A: Gmail Setup for Email Drivers using IMAP [New Google Security Policy]: 
 
https://adroittechnologiesautomation.com/t/sending-e-mail-with-smtp-using-gmail/1287 
 
Or visit Google Help Centre for more information: 
https://support.google.com/accounts/answer/185833?hl=en 
 
 I cannot connect to my email account. (Authentication error) 
If you are experiencing issues trying to connect to your email address, please confirm the following is 
correct: 
1. Email address (check formatting, characters used) 
2. Email password 
3. FROM field in the device configuration

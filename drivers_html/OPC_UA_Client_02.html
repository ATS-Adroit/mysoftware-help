1. Overview 
 
OPC UA (OLE for Process Control Unified Architecture) is a standard specification that makes it 
possible for automation/control software applications and field systems/devices to interoperate and 
communicate data between each other. 
 
To learn more about what OPC UA is, visit the OPC foundation website: 
https://opcfoundation.org/about/opc-technologies/opc-ua/ 
 
The OPC UA client driver for Adroit communicates to OPC servers that expose an OPC UA interface. 
 
1.1. 
Connectivity 
The OPC UA client driver communicates with OPC UA Servers in accordance with the OPC UA 
Specification whose details are beyond the intended scope of this document. 
 
1.2. 
Driver Installation and Setup 
If the Adroit OPC UA Client driver is not installed, you will need to install it. Installation of this driver 
for the first time will install the OPC Foundation’s OPC UA redistributable if not already installed on 
your PC. 
The following files will be installed agent server folder: 
• 
d_opc_ua.dll 
• 
d_opc_ua.doc 
• 
opcuabrowser.exe 
 
as well as the following 3rd party dependency files: 
• 
libeay32.dll 
• 
libxml2.dll 
• 
TB5CPP.dll 
• 
TB5OT.dll 
• 
TB5STACK.dll 
• 
TB5UTIL.dll 
If any of these files is not in the agent directory, then the driver did not install properly. 
 
1.3. 
OPC UA Instance Certificates 
The OPC UA specification requires that all UA clients have an instance certificate that positively 
identifies the client to the server. The instance certificate for Adroit OPC UA is automatically created 
on the Agent Server PC when the OPC UA Protocol driver DLL is loaded by PSEXE or AS.EXE for the 
first time. 
 
The instance certificate can also be created manually by executing the %ProgramData%\Adroit 
Technologies\Adroit\certs\create_instance_certificate.bat file which is found in the folder. This will 
be required if the certificate expires. Before executing the batch file, delete the existing certificate

3.1.2. General 
Timestamp source – Local, Server or Source. Default is Local. 
• 
Local – 
If this option is selected, the driver will update values with the timestamp of 
when the driver receives the value. 
• 
Server – When the OPC server sends a value the driver, whether by exception or from 
being polled, the OPC server return two timestamps, the timestamp that the server 
received the value, or the timestamp that the device/source received the value, by 
selecting this radio button, the driver will update values with the server’s timestamp. 
• 
Source – The driver will update values with the device/source timestamp as mentioned 
above. (Important: do not use this timestamp option if the communication protocol 
connecting to the device does not supply a timestamp) 
 
Should you wish to use Server or Source timestamps, you must ensure that the agent server and 
the OPC UA Server and/or the remote device are time synced to the same time source as the agent 
server! 
 
Polled – OPC clients by nature receive data “by exception” from OPC Servers. However, you can 
use OPC for polling data from front end devices. This setting enables polling as opposed to “by 
exception”. This setting should only be used if absolutely necessary. (Default off) 
 
Timeout – The timeout value in msecs. If polled mode is not enabled (which is the norm), you 
must either:

5. Protocol Definition and Considerations 
5.1. 
Scanning Configuration 
The default address is ns=1;s=address. 
 
Each node in the OPC UA address tree is made up of an address tuple which contains the namespace 
index and address of the node. 
 
The OPC UA address format is as follows: 
ns=x;s=y 
 
Where x is the namespace index of the node and y is the address of the node respectively. 
 
A node’s namespace index and address can found/browsed by using the OPC UA Browser. Clicking 
the browse button in the scanning dialog will launch an item browser (not opcuabrowser.exe!) which 
will browse the entire address tree on the connected OPC UA server. The browser dialog looks as 
follows: 
 
If the driver is in polled mode, the update rate of a tag is determined by the scan period specified. 
Please note : 
 This driver does not support dual scanning. In other words should you scan more than one 
tag to a single address, subsequent tags will always remain scan bad. 
 This driver does not support “Output Initialize”. 
5.2. 
Message Protocol 
Datascope messages are displayed in ASCII mode. 
 
The underlying communication protocols to the device is not available to the OPC Client and thus 
not showed, see the troubleshooting section. 
 
This window will however show all validation of tags. If the tag cannot be validated, a message 
indicating the error message will be displayed here. 
 
All item updates (process-data changes) are also indicated here with an offset number of the tag 
that’s being updated.

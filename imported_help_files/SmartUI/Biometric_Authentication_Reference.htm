Biometric Authentication Reference

Biometric Authentication allows operators to log into the Adroit SmartUI Clients (Operator and Designer) using fingerprint scanners or other alternative validation hardware. The feature is implemented via a plugin framework that integrates with the client and server logon controls. While the underlying framework is abstracted to support multiple authentication methods, the default reference implementation supports fingerprint scanners specifically.

Note: Domain credentials are stored in the Windows Credential Manager (WCM) on the Adroit SmartUI Server machine. Fingerprint templates are stored in a proprietary storage file under the server's activeConfiguration directory and are therefore included in standard backup and restore operations.

Configuration Settings

The connection settings listed below are included in the standard configuration files for the Adroit SmartUI Server and the Adroit SmartUI Clients (Operator and Designer). You do not need to add these keys manually. Enable them in each of those configurations using the Adroit Config Editor:

Setting Key Description

AllowCustomLogin

Specifies whether custom authentication providers are allowed to load. Set to true to enable the biometric login option on the server and clients.

Default: false

PreferCustomLogin

Determines whether the Operator or Designer login screen defaults to the custom (biometric) login provider when it is launched.

Default: false

When enabled, the Operator and Designer logon dialogs include a biometric option alongside the standard username and password controls:

Biometric Enrollment

Operators must be enrolled before they can authenticate with a fingerprint. Enrollment uses the Biometric Enrollment.viz graphic, which is available exclusively from the online Asset Library (it is not shipped with the product projects).

  • Deployment: In the Adroit SmartUI Designer, download Biometric Enrollment.viz from the Asset Library and create a navigation link to that page.
  • Enrollment procedure: Open the page in the Adroit SmartUI Operator. Enter the operator's Windows Domain username and password, have the operator scan their finger on the biometric reader, then use the enrollment control to save the credential and template mapping on the connected Adroit SmartUI Server.

Technical Details

Plugin Deployment and Verification

The biometric provider files (BioLogin.dll and its dependencies, including WinBiometricDotNet.dll and MySourceAFIS.dll) are deployed by the product installer into the plugins\LoginProviders\ subdirectory of the application installation path. To confirm the plugin is available, verify these files in both the client and server installation directories.

At startup, if AllowCustomLogin is set to true, the Adroit SmartUI Server loads the plugin and uses the proprietary biometric storage file in the activeConfiguration directory.

Biometric Credential Mapping

Because the Adroit SmartUI Server authenticates users against the Windows Domain, domain credentials must be supplied at enrollment. The biometric provider maps scanned templates to those credentials as follows:

  • Credentials storage: Username and password are stored in the local Windows Credential Manager on the Adroit SmartUI Server, under the context of the service account running the server, and keyed by a unique identifier.
  • Template storage: Fingerprint templates are stored in the proprietary file under activeConfiguration on the Adroit SmartUI Server and associated with the same unique identifier.
  • Authentication flow: When an operator scans their finger, the provider matches the scan against the stored templates. On a match, the associated domain credentials are retrieved from Windows Credential Manager and used to complete the standard logon process.

Companion Capture Service

To avoid Windows privilege isolation issues (where elevated applications running as administrator are blocked from accessing Windows Biometric Framework sessions in the standard user space), the client uses a local tray application (AdroitBiometricCapture.exe). The tray utility runs in the interactive user session, captures the scan, and returns the template to the client over a local named pipe (AdroitBiometricCapturePipe). Enrollment and biometric login both depend on this companion service.

Clustering and Redundancy Constraints

WARNING: Windows Credential Manager entries are local to the operating system instance. If an Adroit SmartUI Server cluster is configured, biometric enrollments completed on the primary node do not replicate to the standby node. Operators must enroll their biometrics on each redundant server separately so that credentials exist in the local WCM on both nodes.

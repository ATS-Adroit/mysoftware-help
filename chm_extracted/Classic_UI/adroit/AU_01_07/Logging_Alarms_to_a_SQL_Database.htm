Logging Alarms to a SQL Database

Tip: the EventLogging agent provides a simpler method for logging incidents to a SQL (OLE DB compatible) database. For details, seeConfiguring EventLogging Agents.

In Adroit, an EventOutput agent can be used to log alarm events to a SQL database. This requires the following main steps:

  1. Creating the SQL database and its associated ODBC data source, which is used by the EventOutput agent to refer to this SQL database.
    1. Create your SQL Database and save it.

    Tip: It is recommended to limit the size of the table and field names as ONLY 80 characters is available to represent the comma delimited list of these names in the EventOutput agent.

    1. Open the Start menu and select Run…
    2. Type “odbcad32.exe” into the Run dialog and click OK.
    3. Click on the System DSN tab in the ODBC Data Source Administrator dialog.
    1. Click the Add... button.
    2. Double-click the SQL Server entry in the Create New Data Source dialog.

    Tip: This should be the last entry in the list.

    1. Specify the name of this ODBC data source in the Name field of the Create a New Data Source to SQL Server dialog. In this example the following name is used: AdrEvtSQL

    Note: This name will be used to specify this Access database, when configuring the EventOutput agent.

    1. Specify the required SQL Server computer in the Server field and click Next to advance to the next configuration page. For more information on configuring the entries on both this and the subsequent pages, click the provided Help button.

    Tip: It is HIGHLY RECOMMENDED to test that the specified data source is able to connect to the specified SQL database. This can be done by clicking the Test Data Source button on the Finish page.

    1. Click OK and OK again to close the ODBC Data Source Administrator dialog.

Note: Please ensure that you are able to add records to the table that these events are to be sent to.

This can be achieved through a simple utility such as Microsoft Query. If you are in doubt as to how to go about this, speak to your SQL administrator.

  1. Adding and configuring an EventOutput agent to log alarms to this SQL database.
    1. Open the Agent Configurator dialog.
    1. Add a new EventOutput agent and click the Edit button.
    1. In the Printer Type field, select the SQL option.

    You will notice that the "Printer Name" and "Setup Data" fields immediately default to a simple form of help.

    These defaults can be re-created by deleting the contents of the respective field, exiting the dialog box and re-entering.

    1. In the Printer Name field, enter the ODBC data source name that refers to the required SQL database, followed by the username and password required to log on to this database as set up in SQL.

    Note: Ensure that commas separate these three items.

    Since no username or password has been specified in this case, this field is simply: AdrEvtSQL,joe,mypassword

    1. In the Setup Data field, enter the table name (specified in the SQL database) followed by a comma delimited list of the required field names.

    Note: The MAXIMUM size of this Setup Data field is 80 characters, therefore ensure that the table and field names are small enough to all fit.

    Tip: It is recommended to add the fields ONE at a time and test that events are added to the SQL database before adding the next field.

    Any problem with any field will prevent records from being added to the database i.e. no warning messages are displayed. Problem areas are the widths of text field; date fields and specific field formatting.

    In this case this field, after three testing iterations is: Evnts,AgtFld,AgtData,EvtTime, where Evnts refers to the table name.

    1. Enable size Printing and disable Demand Printing and Time Printing to prevent duplicate, out of sequence entries in the SQL table.
    2. Type a 1 into the size drop-down list box, so that size = 1, otherwise you will have to wait until the Page is Full or the File is Full before the agent logs to the database.
    1. Click the Format... button and specify the required columns that are to be added to the fields specified in the Setup Data field. For details of these columns, see EventOutput Agent Column Formatting.

    Note1: Ensure that these columns correspond to order of the database fields specified in the Setup Data field (in step e), otherwise records may not be added to the database.

    Note2: Ensure that the specified column widths correlate with the widths of the database fields; otherwise, records may not be added to the database.

    Tip: Ensure that the total number of columns that you have selected is ONE LESS than the comma delimited items of information in the Setup Data field (in step e).

    1. Click the Compress and OK.
    2. In the Activate section select the Yes radio button and click the Update button to activate the EventOutput agent and click OK to close the edit dialog.
  2. Adding this EventOutput agent to the required Alarm agent.
    1. Then edit the required Alarm agent and browse in this newly created Event Output agent in the Event route (global) destinations section.
  3. Testing that alarm events can be successfully logged to this database.
    1. Place an agent into an alarm state and test that the alarm event(s) are added to the specified SQL database.

Note: It is also possible to prevent the EventOutput agent from outputting alarm events when its clustered Agent Server is in standby mode, so that the output destination does not receive duplicate entries, by adding the DisableEventOutputOnStandby value to the registry.

For other uses of this agent, see Configuring the EventOutput Agent.

Scan Bad Indication Methodologies

Each WanClient is able to determine how the scan bad status of all the tags that it communicates is set within its local Agent Server. This is a global setting, in that it applies to ALL the tag values that are communicated by this WanClient, irrespective of the number of WanServers that these values are communicated to and / or from.

This is configured within the Tag bad philosophy group of the WanClient Configurator dialog, which is launched by selecting Open Configurator from the File menu.

Note: Although these are actually ‘scan bad’ indication methodologies, whenever the ‘scan bad’ status bit is set for a tag, this will result in this tag being marked ‘bad’ i.e. its ‘bad’ status bit will also be set. Therefore the terms ‘scan bad’ and ‘tag bad’ can be used synonymously.

The following four events can be used to determine how the scan bad status of these tags are set within the Agent Server that is on the WanClient computer:

  1. On comms start: This event occurs when the WanClient begins communicating the tag values to and / or from the WanClients specified within its tag link database.
  2. On comms fail: This event occurs when the communication of the WanClient to and / or from its listed WanClients is halted unexpectedly.
  3. On comms stop: This event occurs when the communication of the WanClient to and / or from its listed WanClients is stopped.
  4. On client shutdown: This event occurs when the WanClient application itself is exited i.e. the WanClient.exe is shut down. .

For each of these four events, one of the following scan bad indication methodologies can be selected:

  1. Do nothing: This leaves the current status of the scan bad bit for all of the communicated local Agent Server tags unchanged.
  2. Mark bad: This sets the scan bad bit for all of the communicated local Agent Server tags to ON.
  3. Mark healthy: This sets the scan bad bit for all of the communicated local Agent Server tags to OFF.

The Include control tags checkbox, can also be checked or cleared to include or exclude the tags within control groups for each of these scan bad indication methodologies.

However the following needs to be taken cognisance of when this option is enabled: If the tag is currently marked bad, WanClient will mark it healthy (set its scan bad status bit to ON) when it receives a valid value update from the required WanServer.

Since the values of tags within control groups are NOT received from the WanServer, the Mark bad methodology must NEVER be configured for tags within control group, when using the On comms start event, as this will result in the ‘scan bad’ bit ALWAYS being set for these tags.

When the WanClient starts up, control tags are assumed to have dirty values until a value is received from the WanServer.

Updates from a WanServer that fail to putslot in the local Agent Server will also cause values to be "dirty" again. Dirty values are NOT sent to WanServer to prevent "blind" value changes.

Then again, this methodology CAN be used, if these tags are configured as dual mode tags i.e. tags that are members of BOTH a control and a normal group. For further details, see Dual mode tags.

Note: An existing WanLink installation or when the WanLink database files are deleted, will impose the following default scan bad philosophy, that is backward compatible with existing installations, which implements a Mark healthy, for these events: On comms start , On comms fail and On client shutdown and a Mark bad for this event: On comms stop.

Wanlink Quickstart

Wanlink allows data to be replicated over a slow or Wide Area Network (WAN) from one Agent Server to another. In other words, it allows remote Agent Servers to behave as if they were normal remote nodes on a Local Area Network (LAN). For further details, see General Description.

In order to gain access to a local Agent Server from a remote Agent Server across a WAN (Wide Area Network) ensure that the following steps are followed:

Note1: For ease of explanation the local Agent Server will be known as LOCAL and the remote Agent Server, will be known as REMOTE.

Note2: This will assume that the FULL Adroit installation has been installed and that the Agent Servers have already been started on both computers.

  1. On the LOCAL computer, press the Windows key and start typing in Wanlink Server and select it from the list to run the WanServer.
  2. On the REMOTE computer, press the Windows key and start typing in Wanlink Client and select it from the list to run the WanClient.

Note: If the Agent Server is not started, then the WanClient application will wait for it and attach to it when it is opened.

  1. On the REMOTE computer, in the WanClient program, open the File menu and select the Open Configurator command. In the Configurator dialog do the following:
  1. Click the Add Server button to configure the connection settings required to reach the LOCAL computer. (Add as many servers as there are Agent Servers that require data from this computer’s Agent Server.)
  2. Click the Add Group button to configure a tag group, for the Selected Server, that may only contain a subset of the total required Adroit tags, depending upon the requirements of the tags it is to contain e.g. the group type determines if the Adroit tags will be able to be modified by the other Agent Server or not. (Add as many groups as are needed to cater for the Adroit tags that are to be referred to by the selected server i.e. the current Select Server entry.)
  3. Click the New Link button to configure a tag link in which an Adroit tag on this computer’s Agent Server (REMOTE in this case) is linked to which Adroit tag on the Agent Server of the computer on the other side of the WAN (LOCAL in this case). This link is added to the Selected Group and also determines the method by which the data between these two Adroit tags is transferred. (Add all the linked tags that meet the criteria of the currently selected group i.e. the current Select Group entry.)
  4. Once all the tags have been added to their relevant groups and all the groups have been added to necessary servers, then click OK.

Note: This is a once-only configuration, the next time that the WanClient is opened; this step can be skipped, unless alterations or additions need to be made to the configured tag mappings.

  1. On the REMOTE computer, in the WanClient program, after tag mappings have been configured, open the File menu and click on the Repack command and then open the File menu and click on the Reload command, to avoid stopping and restarting the WanClient.
  2. The LOCAL Agent Server will now have access to all the configured tags on the REMOTE Agent Server.

Note1: It is possible to configure the WanServer application to run as a service on the LOCAL computer, so that it start automatically whenever the Agent Server starts up. The WanClient application does not have this facility, as it must be run from within windows.

Note2: If the WanClient is started with the "/start" command-line parameter, then it will automatically start communications.

Tip1: Both the WanClient (if using the "/start" command-line parameter) and WanServer applications can be started before the Agent Servers have started. Therefore once the Agent Servers are started/restarted the applications will resume communications as expected.

Tip2: It is possible to start the WanClient application from an Adroit mimic by using an Execute Command Behaviour, in this case, specify "/start" after wanclient.exe in the "Application name:" field. This will saves the operator from opening WanClient manually each time and because the "/start" command-line parameter is used, will automatically start communicating.

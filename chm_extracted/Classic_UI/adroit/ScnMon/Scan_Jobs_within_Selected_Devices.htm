Scan Jobs within Selected Devices

The Scanning Monitor utility provides information on the scanning (communications) configuration for a particular Agent Server, so this information can be used to manually fine-tune the scanning subsystem to achieve optimal performance. For details, see Monitoring Scanning in Adroit.

The list in the middle of this utility, displays the scan jobs for the selected device or devices within the devices list, directly above this list. For details, see Devices within Selected Agent Server Database.

Note1: Any configured @scans will NOT appear in this utility because scan agents are NOT involved in @scanning functionality - these are simply internal slot-to-slot subscriptions that change in real time mode.

Note2: Scan jobs are automatically created by Adroit to group the scanned tags together in such a way as to minimise scanning load and to maximise throughput. For details on how to assist with this process, see Scanning Optimization Tips.

This list, consists of the following columns:

  1. Scan job: This identifies the name of scan job for the selected device(s) in the devices list. The other columns indicate the following attributes of this scan job:
  2. Started: This is 1 when this scan job has started.
  3. Comms status: This is one of three possible values:
  1. Unknown: scanning has not yet started.
  2. Bad: scanning has started but there are some unsuccessful transactions or bad scan items, if this is the case, check your configuration and cabling.
  3. Healthy: scanning has started and is successful.
  4. Required rate: This indicates the rate at which the scan job is expected to scan the front-end device.

Note: A value of zero means that this scan job is exception based and does not poll or request its front-end device for changes to its data.

  1. Effective rate: This indicates the rate at which the scan job is actually scanning the front-end device. If this value is greater than the required rate then it implies a scanning backlog, which can be avoided by slowing down the current scanning speeds (rates).

Note: This value should only be monitored when the device, to which this scan job belongs, is healthy.

  1. Successful rate: This value should be equal to the Effective rate; otherwise intermittent transaction failures are occurring. If so, check the configuration and cabling.
  2. Driver transaction time: This specifies the amount of time, in milliseconds, taken for the driver to execute the transaction.
  3. Server update time: This specifies the amount of time, in milliseconds, taken for the Agent Server to be updated with the new values.

Supported commands:

When a scan job is right-clicked in this list, the following commands may be enabled:

  1. Start scan job: to start the selected scan job.
  2. Stop scan job: to slop the selected scan job.

The following options are also available for non-exception based (polled) scan jobs:

Note: Do not use these options, unless all communications are healthy for the selected device.

  1. Adjust scan rate: to set the Required rate equal to the Effective rate for the selected scan job.
  2. Manual scan rate: to specify a new Required rate for the selected scan job.
  3. Reset scan rate: to reset the Required rate to the configured rate for the selected scan job.

Note: These commands that change the scan rates are not permanent i.e. saving the database will not save any online changes that are made. In order to make these changes permanent, see How to use the Scan Monitor.

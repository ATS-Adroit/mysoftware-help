To Estimate the Disk Space Required for Data Logging

The user has no direct control over the speed at which the raw data log file will grow.

Therefore, it is important to calculate the maximum space each agent may occupy, before the data log file wraps around and overwrites itself from the beginning. This figure can be compared to the actual free disk space available on the host computer.

Two files are involved in storing historical data: the raw data log file (.LGD) and its index file (.LGI) which uses comparatively little space.

Tip: If you use datalog backups, which create .LDB files, then you can extend the potential amount of logged data without creating larger log files. In this case, while the active log (LGD) file can remain small, the log backup (.LDB) files can store historical data for much longer time periods. For details, see Datalog backup and retrieval.

The amount of disk space reserved for data logging is a function of the rate at which the tag is being logged i.e. the time between each sample and the total logging period specified for each tag, summed for all the tags being logged.

Each log record takes 20 bytes therefore it would be expected that the following formulae would be used to calculate the maximum raw disk space that may be used for each .LGD file:

Raw Buffer size (bytes) = 20 x (Logging Period/Logging Rate)

Raw File size (bytes) = Sum of all Raw Buffer sizes

Example of raw disk space calculations.

However, the original design of datalogging made the assumption that the data would only change 5 times slower than the rate actually configured and therefore Adroit is designed to only reserve 20% of the space calculated above. Hence the following formulae must be used to accurately calculate the actual disk space that will be used for each .LGD file:

PLEASE NOTE: Adroit’s proprietary logging uses an in-built logging factor, which reduces the specified logging period by 80%. UNLESS a clean installation of Adroit is installed, in which case this logging factor is NOT applied. For details, see Adroit Logging Factor.

Actual Buffer size (bytes) = [20 x (Logging Period/Logging Rate)]/5

Actual File size (bytes) = Sum of all Buffer sizes

While the above design assumption can be considered true for faster logging rates such as 1 second, this is definitely not the case for slower rates such as 1 minute or 1 hour where the values (especially analog values) will have definitely changed. In the latter Adroit will only have capacity to log for 1/5th of the configured period necessitating the user to over specify his logging period by a factor of 5.

Note: It is possible to override this 20% data log capacity or the "divide by 5" storage factor, by setting the LogCompressionFactor registry setting.

Each Datalog agent has a maximum of 53 million records, which can provide at least 30 days of logging at a log rate of 50 milliseconds!

For instance: if the log rate is 100 ms, 10 values are logged per second, 36000 values/hour, 864000 values/day, so the total logging length of this datalog file = 53000000/864000 = 61.34 days.

Instead of using one log file for all agents, you can create different log files for agents (values) that require different logging speeds. For example, DAY.LGD, WEEK.LGD, MONTH.LGD and YEAR.LGD.

Note: Adroit allows a slot of an agent to be datalogged once only.

If multiple logfiles need to be created from, for example, an ANA01.value, then this can be done by using an intermediate agent such as an Expression agent called EXP01. Insert the ANA01.value into the Expression Agent’s slots v01, v02 and v03, and configure EXP01 for data logging, such that:

ANA01.value is logged at 1 second intervals for 5 days into logfile DAY.LGD

EXP01.v01 is logged at 15 second intervals for 7 days into logfile WEEK.LGD

EXP01.v02 is logged at 120 second intervals for 31 days into logfile MONTH.LGD

EXP01.v03 is logged at 8 hour intervals for 365 days into logfile YEAR.LGD

Adroit Logging Factor

When Adroit logging was originally developed in 1992 a design criteria was accepted which has come to prove problematic for some installations in the real world. 

Up until 1992 the generally accepted default practice was for users to datalog all points at 1 second. However, due to CPU, HDD speeds and serial protocol speeds, the fastest data could only logged at 4-5 seconds. Therefore the log file created by Adroit was deliberately engineered to always be 20% of the expected size, since Adroit only stores data when it in physically changes.

This logging design started to become a problem when hardware and protocol speeds improved OR where high logging time deadband values (or sample rates) were used especially for Analog agents where one could be assured that its value WAS going to be different at each sample period. In these cases, only 20% of the specified historical data is actually recorded.

The legacy default for Adroit’s proprietary logging of using a 20% datalog compression factor has been REMOVED for all new installations, since it unnecessarily misleads users when configuring logging periods.

However, if a legacy WGP file is opened by a new installation of Adroit, that the logging periods configured for some or all of the Datalog agents will exceed the allowable size limit of 5000000 samples (or 95 MB) per Datalog agent.

This will occur since the legacy method of accommodating this 20% datalog compression factor allowed the required log period to be up to 5 times greater. In these cases these "non-compliant" Datalog agents will display "error load completion" events.

Note: Ensure that you have enabled the logging of Adroit system events in order to identify these non-compliant Datalog agents. For details, see Enabling the logging of Adroit system events.

To remedy these "non-compliant" Datalog agents either set the LogCompressionFactor value in the Adroit registry back to its legacy default of 5 and restart the Agent Server OR reconfigure the logging periods of the affected Datalog agents, which should typically require the currently specified logging period to be divided by 5.

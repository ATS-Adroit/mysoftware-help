Proprietary Data Logging to Disk

Adroit provides extensive proprietary historical data logging facilities . As with scanning, any slot of any agent can be configured to have its values historically logged, subject to the proviso that they are of slot type Real, Integer, Boolean or 79 character String (this length excludes the mandatory zero terminator character).

When logged, the values are time stamped and are made available, via a DataLog agent, to any client. Examples of data log clients would be historical trends, the extract utility, OLE-aware 3rd party applications such as external spreadsheets for reports etc.

Historical values can be stored in one or more data files, each file containing the values of one or more DataLog agents.

Note: If you export and delete Datalog agents that use Adroit's proprietary log files, ensure that you restart the Agent Server before re-importing - so that they can remove the areas that they currently use in the LGD files. Click for more details:

Multiple Datalog agents can potentially use a single LGD file, so when you delete a Datalog agent using proprietary logging all that happens is the area of the file that was used by the deleted Datalog agent is marked as unused and will be compacted at the next Agent Server startup.

Therefore if you re-create the Datalog agent in the same Agent Server session, the LGD resource simply adds the space required for the newly added Datalog to the end of the LGD file i.e. it does not re-use the old area that has been marked as unused.

This can cause the LGD file to become too big, resulting in errors such as an error message asking you to check your Datalog agent configuration (in Agent Server window you may also get a Datalog agent dll exception) and your Datalog agents may not start.

When you restart the Agent Server , the old areas of the LGD file are compacted and room is left to re-create the datalogs.

Previously, when logging to the Adroit proprietary datalog (.LGD) files, the Adroit datalogging system only provided the historical logged data existing in the .LGD file and was unable to provide historical data from the SystemDatalog-created .CSV datalog backup files. Now each Datalog agent can create their own backup (.LGB) files to automatically retrieve this data, if required by trends (charts) or other requests for historical data. For details, see Datalog backup and retrieval.

TWO files are created for each proprietary log, the .LDG file, which stores the raw data and its associated .LGI file, which is the lookup index file.

The total amount of disk space required for data logging depends on the following factors:

  • the number of data files used
  • the number of agents being data logged
  • the total number of values logged per agent
  • the sampling time and length of time each value is logged for.

Note: Any datalogs that cause their .LGD file to be greater than 2 GB will fail to start and user is notified accordingly and an associated eventlog entry is also created.

During logging, each DataLog agent will write to its pre-allocated dynamic buffer area in a data file and will overwrite itself from the beginning after it reaches the end of the buffer.

The Datalog agent allows for a maximum of 53000000 records. This means that the specified datalog Length... (or period) and Time... deadband combination may not exceed 53000000 records. This corresponds to a maximum of 1010.9 MB of data at 20 bytes per record, which means 613 days at 1 second or 30 days at 50 ms.

Note1: The minimum Time... deadband allowed is 10 ms which only provides a maximum Length... (or period) of 6.13 days of logged data.

Note2: When retrieving data from classic (legacy) trends the maximum number of datapoints that can be trended is 99999 therefore, for example, only 27.77 hours of data can be retrieved at 1 second on a classic (legacy) trend.

PLEASE NOTE: Adroit’s proprietary logging uses an in-built logging factor, which reduces the specified logging period by 80%. UNLESS a clean installation of Adroit is installed, in which case this logging factor is NOT applied. For details, see Adroit Logging Factor.

Note: If the logging period is increased ensure that this change is saved and the Agent Server is restarted, at least once, to allow the necessary LGD file compressions to occur. For details, see Increasing Logging Periods.

Tip: If you use datalog backups, which create .LDB files, then you can extend the potential amount of logged data without creating larger log files. In this case, while the active log (LGD) file can remain small, the log backup (.LDB) files can store historical data for much longer time periods. For details, see Datalog backup and retrieval.

A data log file is composed of many buffers, one for each DataLog agent. Being event based, the speed at which each buffer is written depends on how often the value in the agent slot being logged changes, and its deadband.

If necessary, the data log file can be periodically archived by file copy. Historical data can later be retrieved for viewing, used in trends, or exported as comma separated variable (CSV) files, a format recognised by many commercial spreadsheet and database packages.

Adroit supports the merging of external data into existing log files, and logged data is accessible via OLE.

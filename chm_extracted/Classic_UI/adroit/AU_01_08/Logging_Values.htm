Logging Values

"How to effectively log your data" on page 1 : guides you to use the fairly complex logging sub-system effectively.

 

How to Log a Tag (agent.slot): describes the procedure for logging process values in Adroit.

The Datalog agent should ONLY be used for proprietary logging and the datalog period (Length...) should not exceed what is required for operational trending purposes. In other words, should an operator only need to see 24 hours of trend data to properly monitor and control his plant then the datalog period should only be set for 1 day. Historical data (i.e. data outside of the datalog period), if requested, will be retrieved from the backup files, if required.

Therefore the logging to ADO (SQL) databases by the Datalog agent is disabled by default (the SQL... button of the Datasource field is hidden in the Edit Datalog agent dialog). This is to force users to use the DBLog agent instead, which logs data to SQL more efficiently.

Note: The DBLog agent is a bulk OLE DB logging agent for typically logging Analog and/or Digital values to a specific table in a database for later retrieval that supercedes SQL logging via the Datalog agent. For details, see The DBLog Agent.

Although if the Agent Server loads a legacy WGP file that ALREADY contains an ADO datalogging configuration, then the SQL... button of the Datasource field will be visible in the Edit Datalog agent dialog.

Note: Multiple log sets are no longer required as Adroit provides the DBLog agent that should make SQL logging via the Datalog agent redundant. Also you no longer need multiple proprietary sets with increasing periods and larger time deadbands, since Adroit provides a new datalog backup feature with full trend-retrieval support.

Note: The Disable logging on standby setting is now configured PER datalog SET. So you can disable an OLE DB logging set WITHOUT disabling any proprietary logging sets, which typically do not require this setting as each Agent Server logs to their own datalog files.

Proprietary Adroit log files: This logging method has been specifically designed for the needs of the SCADA industry to provide improved logging performance, typically achieving sub-second logging rates.

Previously, when logging to the Adroit proprietary datalog (.LGD) files, the Adroit datalogging system only provided the historical logged data existing in the .LGD file and was unable to provide historical data from the SystemDatalog-created .CSV datalog backup files. Now each Datalog agent can create their own backup (.LGB) files to automatically retrieve this data, if required by trends (charts) or other requests for historical data. For details, see Datalog backup and retrieval.

This method stores original Adroit timestamps (a Windows FILETIME structure which represents the number of 100 nanosecond intervals since Jan 1 1601), which provide millisecond resolution for each recorded value.

Note: When accessing these timestamps by using the OLE automation interface, this millisecond resolution is lost because the data type used to store this value is unable to store milliseconds.

Each log file has a maximum of 53 million records, which can provide at least 30 days of logging at a log rate of 50 milliseconds! This rate is determined by configuring the required Time and/or Value Deadbands.

Note: If the logging period is increased ensure that this change is saved and the Agent Server is restarted, at least once, to allow the necessary LGD file compressions to occur. For details, see Increasing Logging Periods.

Note: If you export and delete Datalog agents that use Adroit's proprietary log files, ensure that you restart the Agent Server before re-importing - so that they can remove the areas that they currently use in the LGD files. Click for more details:

Multiple Datalog agents can potentially use a single LGD file, so when you delete a Datalog agent using proprietary logging all that happens is the area of the file that was used by the deleted Datalog agent is marked as unused and will be compacted at the next Agent Server startup.

Therefore if you re-create the Datalog agent in the same Agent Server session, the LGD resource simply adds the space required for the newly added Datalog to the end of the LGD file i.e. it does not re-use the old area that has been marked as unused.

This can cause the LGD file to become too big, resulting in errors such as an error message asking you to check your Datalog agent configuration (in Agent Server window you may also get a Datalog agent dll exception) and your Datalog agents may not start.

When you restart the Agent Server , the old areas of the LGD file are compacted and room is left to re-create the datalogs.

This logged data can be retrieved for viewing, used in trends, or exported as comma separated variable (CSV) files.

Adroit supports the merging of external data into existing log files, and logged data is accessible via OLE.

In Adroit terminology, a value is referred to as a tagA fully qualified named value in Adroit (agentName.slotName). , therefore ‘to log a value’ is the same as saying ‘to log a tag’. For a brief introduction to Adroit terminology, see Agents, Slots, Tags and their relation to Values.

Note: For further details concerning the agents responsible for managing this logging of data and links to these storage facilities and for other logging functionality, see Logging Agents.

Note: It is also possible to log multiple tags simultaneously i.e. to log multiple agents of the same type, using the most recently specified logging configuration. For details, see Bulk Logging Tags Using the Same Configuration.

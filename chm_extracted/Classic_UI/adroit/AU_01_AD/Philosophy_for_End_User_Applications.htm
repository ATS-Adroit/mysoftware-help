Philosophy for End User Applications

The general philosophy is for the user to create an instance of a coarse grained object, and then instruct the object to create many finer grained objects inside itself.

A coarse grained object corresponds to a connection to a known Agent Server, either running on the same computer as the application, or some other computer on a local- or wide-area network.

In WOSA/XRT terminology, a coarse grained object is a Data Object, and a fine-grained object is a Request Object. A Request object formally describes the pieces of information we require from the Data object. It consists of data that identifies the information we want, plus data which names the specific fields related to that information.

For real time Adroit data this corresponds to an agent and the associated slots we are interested in, whereas for historical data, it corresponds to a time and the associated agent.slots we are interested in. The individual fields of each request are stored as a Properties Collection. A single Request collection can hold many Request objects at once.

Once we have created requests on the Data Object, the easiest way to get at the required data is to ask the object to paste links to the data into our containing application, which needs to be able to process the paste. When the links are pasted onto the application, the application activates the links, and the Data object supplies the application with ongoing updates.

In addition to the basic WOSA/XRT features described above, our OLE server provides a number of Adroit-specific extensions. These include the provision of an output mode that permits the poking of values from a container application to an Agent Server, the ability to fetch values in a one-off fashion from an Agent Server, the ability to connect to a remote Agent Server, the ability to create and remove agents in an Agent Server, etc.

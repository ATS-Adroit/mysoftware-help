Agent Server Master Write Scanning Strategy

This scanning configuration should be used when the Agent Server is required to be the master during normal runtime operations.

This should be used when Agent Server is required to be the master during normal runtime operations.

This is a preferred strategy to Forceoutputs=0, but can cause permanent writes to the process value, if the front-end devices (PLCs) do not accept the Agent Server value. Front-end devices (PLCs) should not overwrite Agent Server values.

For details of all the scanning strategies offered, see Scanning Strategies or for further details on the effect of combining the available global and tag-specific scanning settings, see The Effect of Combining Scanning Settings.

Required global scanning settings:

  1. ForceOutputs = 1
  2. SyncProcessToServerOnFirstScan can be set to 1, if required, in which case, see below as to its effect.

Required tag-specific scanning settings:

  1. Output Enable = 1
  2. Scan Inhibit = 1

Operation of strategy:

  1. When the Agent Server is started, the Agent Server receives the values of these scanned tags from the front-end devices (PLCs).

Note: If SyncProcessToServerOnFirstScan is set to 1, then when the Agent Server is started, each process value, of these scanned tags, is set to the value within the Agent Server i.e. the last saved WGP value.

  1. When a device stops or starts, the Agent Server will write the values of these scanned tags to the front-end device.
  2. When the communications have been restored after a device has failed, the Agent Server will write the values of these scanned tags to the front-end device (PLC).
  3. If a value of one of these scanned tags is changed in the Agent Server, this value is written to the front-end device (PLC).
  4. If a value of one of these scanned tags is changed externally, this value in the front-end device (PLC) is overwritten by the value within the Agent Server.

Secondary Port Enabled

Adroit drivers can make use of a secondary port to cater for the possible failure of some communications hardware component. For this to be effective, the hardware used by the secondary port should be totally separate (e.g. extra serial card and cable).

A device goes into recovery whenever a Read or Write transaction fails. This failure is a 3-step process:

  1. Adroit requests an update from the front-end device.
  2. Timeout Phase : the request is sent to the front end device, and times out or gives an invalid response.
  3. Retry Phase: Step 2 is repeated for the number of retries configured.

If the retries are exhausted and there is still no valid response, the Adroit driver will use the secondary port if it is configured when this step is reached. This involves a port switchover, and only occurs once in any transaction.

The driver then runs through Steps 2 and 3 using the secondary port.

If, at some later time, the secondary port should fail, communications will switch back to the primary port, and will continue through the primary hardware if this has been repaired. After which scanning resumes immediately.

However, there is also an Alternate Secondary Port Enabled scenario where the same PC port / resource is used but with different PLC ports / resources.

The Effect of Combining Scanning Settings

The purpose of this topic is to describe what you can expect to happen when you combine the various scanningthe process of communicating a value (slot), typically to and/or from a front-end device (FED). settings. For details on the various scanning strategies, see Scanning Strategies.

There are two types of scanning settings that can be configured:

  • Global scanning settings – these require the Agent Server to be restarted, before any new setting change takes effect.
  • Tag-specific settings – these require the device(s) used to scan the slot(s) of the configured agent(s) to be restarted, before any new setting change takes effect.

Note: A ‘process value’ of a tagA fully qualified named value in Adroit (agentName.slotName)., is the current value at the front end device (PLC), whereas its ‘Agent Server value’ is the value of the tag in Adroit at runtime since the last read.

PLEASE NOTE: The purpose of Cold start is to set the process value to a pre-configured value on startup and NOT the last saved WGP value!

  1. If a tag’s scan inhibit bit is on there are NO guarantees that its Agent Server value will be the SAME as its process value.
  2. If a tag’s scan inhibit and output enable bits are on, then the Agent Server changes will always be sent out but there are NO guarantees that its Agent Server value will be the SAME as its process value.
  3. Forceoutputs (a global registry setting) always tries to synchronise the process values with the Agent Server values using write instructions if the process value is found not to be equal to the Agent Server value after a process read.

Note: Forceoutputs only has effect if the tag’s scan inhibit bit is on.

  1. Forceoutputs always synchronises the Agent Server with the process on the first scan after Agent Server startup. This can be overridden by setting the tag’s Output Initialise bit or using the global SyncProcessToServerOnFirstScan (a global registry setting), whereupon the saved tag’s value will be sent to the process on the first scan.

Note: SyncProcessToServerOnFirstScan should NOT be used without using the Forceoutputs setting and therefore also requires the scan inhibit setting to be used.

  1. If a tag’s scan inhibit and output enable bits are on and Forceoutputs is on, see the Agent Server Master Write Scanning Strategy as to its effects, which also shows the effect of using SyncProcessToServerOnFirstScan.
  2. If a tag’s scan inhibit and output enable bits are on and Forceoutputs is off or not used, then see the Write Only Scanning Strategy as to its effects, which also shows the effect of using SyncProcessToServerOnFirstScan.

Note: This scanning configuration is NOT RECOMMENDED.

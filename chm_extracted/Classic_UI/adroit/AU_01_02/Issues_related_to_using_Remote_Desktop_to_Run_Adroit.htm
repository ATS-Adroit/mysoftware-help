Issues related to using Terminal Clients (Remote Desktop) to Run Adroit

Problems running the Agent Server

You cannot start the Agent Server as an application by using the Windows Remote Desktop (a terminal client). This is because Windows does not support USB ports when you use the Remote Desktop application, so any USB HASP is effectively invisible to the Agent Server.

Note: This is not a problem when starting the Agent Server as a service from within a Remote Desktop.

The resources (e.g. printer etc) of the computer used to remote desktop into the Agent Server computer are used by the Agent Server NOT the resources on the Agent Server's computer. This means that when you terminate the remote desktop session, these resources become unavailable which causes problems.

 

Problems running AdroitClient Applications

Adroit has terminal client (remote desktop) connection licencing rules whereby every Adroit client application takes a (remote node) connection licence regardless. 

An Adroit client is ANY application that makes a connection to an Agent Server, for instance:

  • Classic User Interface
  • Agent Configurator
  • Adroit utilities, such as the Agent Browser
  • Any AdroitOLE Automation (MISSRVR) or ActiveX client application.

If the Classic User Interface is started from within a remote deskop session, and the Configurator is opened – then TWO connection licenses are required; otherwise either the Configurator and/or UI will be unable to connect to the Agent Server. Since BOTH the UI and the Configurator require their OWN connection licences when started using remote desktop.  

This change ALSO prevents the use of remote desktop for perform maintenance especially on stand-alone (no remote connection licences) installations. Since UIs cannot be restarted via Remote Desktop and/or the Configurator is unable to connect to the Agent Server. 

For this reason, Adroit has attempted to redress this limitation by NOT enforcing connection licences for the console user’s session. Typically when a user logs onto a computer, this user, known as the “console user”, always gets:

  • Session 0 (on Window Server 2003 or Windows XP operating systems or older) or
  • Session 1 (on Windows Server 2008 or Windows Vista operating systems or newer).

When a remote desktop user logs on with the same user credentials as the console user, this remote desktop user inherits the same session number.

When Adroit clients are launched via a remote desktop using the session of the console user (either session 0 or 1 depending on the operating system), then these Agent Server connections are treated as legacy local connections which do NOT require connection licences.

Note: The resources (e.g. printer etc) of the computer used to remote desktop into the Adroit client computer are used by the Adroit client NOT the resources on the Adroit client's computer. This means that when you terminate the remote desktop session, these resources become unavailable which causes problems.

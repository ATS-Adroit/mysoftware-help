Active Link Monitoring

WARNING: Registry settings are recorded as ADVANCED information and should not be used unless you understand exactly how these will affect the operation of your Adroit  installation, IF YOU HAVE ANY DOUBTS, PLEASE CONTACT Adroit SUPPORT, BEFORE CHANGING THE REGISTRY.

PLEASE NOTE: When working on a 64 bit operating system, remember to add "\Wow6432Node" to the path of each registry setting after "\SOFTWARE", for instance: "HKEY_LOCAL_MACHINE\SOFTWARE\Wow6432Node\Adroit Technologies".

The following Active Link Monitoring registry settings can remedy or troubleshoot slow (or unresponsive) Agent Servers and/or clients, which may occur when:

  • there are a large number of clients connected to an Agent Server AND/OR
  • there is a misbehaving network and/or clients resulting in an inability to effectively send subscriptions to the Agent Server.

These (REG_)DWORD registry settings need to be added to the HKEY_LOCAL_MACHINE\SOFTWARE\Adroit Technologies\Adroit\Workgroup\WG.INI registry key:

ActiveLinkMonitor: when set to a value of 1, this enables an Agent Server’s link manager to actively monitor connections to remote Agent Servers instead of simply relying on broadcasts from the remote Agent Server to assume that the connection is healthy.

This setting works hand in hand with the KillSlowClients registry setting, for instance, if the remote Agent Server has KillSlowClients enabled, then the remote Agent Server will force a disconnection to the local (this) Agent Server should the remote Agent Server be unable to send subscriptions to the local (this) Agent Server.

The ActiveLinkMonitor setting allows the local Agent Server to recognise this closed channel within 5 seconds - instead of the legacy 30 to 45 seconds that potentially causes secondary issues with the local Agent Server and any clients connected to it. The default value is off (0).

KillSlowClients: when set to a value of 1, this instructs the Agent Server to close the channel to the remote client if it is unable to send a subscription to the remote client. If this happens, an Agent Server side debug event message is generated.

This setting has the effect of disconnecting misbehaving clients and thereby keeping the local server free of delays and lockups that have the potential to cause failures in the local Agent Server. The default value is off (0).

This setting is typically used in conjunction with the ActiveLinkMonitor setting.

 

The following registry settings can provide related informative/warning events:

Note: These events are only displayed if you have checked the Enable logging of agent server system events checkbox in the Advanced Agent Server Configuration dialog of the Config Editor or PSEXE.

ShowSlowClientEvents: when set to a value of 1, this will display Agent Server side system events when slow clients are detected, which simply means that the remote client is unable to deal with the speed of subscriptions being sent to it by the Agent Server. The default value is off (0).

MonitorSubsChannelsize: we suggest setting this to a decimal value of 100000, in this case an event is generated by an Agent Server client every time the number of bytes differs by 100,000 from the previously displayed event, whether the number of bytes is increasing or decreasing. These client side system events provides client side monitoring of the incoming subscription pipe showing how full this pipe is.

WARNING: Improper use of this setting could overload the event system thereby further crippling the ability of the client to deal with subscriptions!

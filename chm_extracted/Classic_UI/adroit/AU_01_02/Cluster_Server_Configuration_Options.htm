Cluster Server Configuration Options

For more details on addressing the important issues that affect the operation and configuration of clustered Adroit Agent Servers, see Important Points to consider when Clustering Agent Servers.

Using the Adroit Configuration Setup:

Press the Windows key and start typing in Classic Setup and select it from the list.

Click the Agent Server tab.

Using the Adroit Config Editor:

Launch the Adroit Config Editor.

Click Agent Server Configuration in the right hand pane.

Click Agent Server Configuration again in the right hand pane.

Ensure that the Agent Server Type list, is set to Cluster Server, then click on the Options… button to display the following cluster-specific settings:

Note: If your Agent Server has a cluster partner that is on a DIFFERENT domain or on DIFFERENT sides of a router/switch, then ensure that you are using an explicit connection to connect to this remote agent server. See Agent Server Connection Methods.

  1. Cluster Name: Enter the name of the cluster to which this Agent Server is assigned, in this edit box.

  2. Enable client runtime transaction shadowing: Check this checkbox to copy (shadow) all the transactions initiated by a client on a server to the other server in the cluster to provide total data replication. More details: For instance, if, from within a picture, an operator modifies the value of any non-scanned tag in a cluster server, it's cluster partner would not normally receive this new value via the PLC I/O scanning. So the cluster server needs to replicate these operations to its cluster partner immediately and transparently.

    Note: This option is on by default and it should typically not be disabled.

  3. Server I/O options: This involves selecting one of the following options:
  1. Shadow scanned data from master to standby nodes: This is the default mode of operation, in which only the master server communicates with the front-end devices and all the I/O changes from scanning are shadowed (copied) to the standby server.

Note: Be aware of the implications of implementing shadow scanning when using drivers, especially telemetry drivers such as OPC or DNP3 in an asynchronous or non-polling mode. For details, see The Effect of Using Shadowed Cluster Servers with Drivers.

  1. Parallel scanning: In this mode of operation each cluster server is configured to replicate the scanning tasks to provide scan task replication, that is, each server performs scanning as if it were a normal Agent Server. This mode provides the following additional options:
  2. Enable writes in standby mode: If not selected, all outputs or writes to the PLCs by the Standby servers are turned off.

Note: When a server is configured to disable writes when in standby mode, and a point that is scanned out is changed on the standby computer, this operation will be shadowed to the master computer (if Enable client runtime transaction shadowing is enabled), and thereby scanned to the PLC.

  1. Enable reads in standby mode If not selected, all incoming data or reads from the PLCs by the Standby servers are turned off.

Note: These two modes of data acquisition via scanning when Cluster modes are used are susceptible to the type of the communication hardware used, as explained in the Communication Hardware and Cluster Server I/O modes table.

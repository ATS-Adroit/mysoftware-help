Configuring Analog Agents

You can configure an Accumulator agent to calculate the difference in value (or delta) of an ever increasing or accumulating process value between successive events or over a specific time period (interval), as follows:

Note: You can also calculate statistics from the value slot every second, for a specific rolling period (specified in minutes). For details, see Calculating statistics from Analog values.

If necessary, open the Edit Analog Agent dialog, as follows:

  1. If necessary, add an Analog agent. For details, see To Add a New Agent.
  2. Select the name of this agent. For details, see To Select an Agent.
  3. Right click and select the Edit... menu item to display the Edit Analog Agent dialog.

Note: To reduce the loss of accuracy in scaling caused by IEEE conversion issues, the Analog agent bypasses the scaling calculation, when the scaling is 1:1.

To edit or view the current value: to view or change this value manually.

  • The Engineering field (the value slot) of the Value section, displays the last refreshed value, which is scaled within the specified Engineering Span.
  • The Raw field (the rawvalue slot) of the Value section, displays the corresponding value that is specified within the Device Span.

If you edit either value manually click the Update or OK button to save the changes BEFORE clicking the Refresh button; otherwise this value change is lost.

Note: This value will ONLY be changed to the specified value if it is NOT being scanned.

Tip: Use the value slot to display this value, so the tag would be AnalogAgentName.value.

To scale this value: typically specified when using a value contained in a front-end device that needs to be scaled to an engineering or display value.

IMPORTANT CHANGE FOR ANALOG AGENTS: Changed the default method of handling what happens when the rawvalue slot goes out of range (either exceeds the rawMax value or is lower than the rawMin value), from now this causes the Analog agent to set the new OutOfRange status bit (which can be alarmed if needed).

This is to prevent the entire agent from being marked at as being bad, as happened previously, which causes all the instances of this value to be greyed out (disabled) on the mimics which display them.

Note: If you prefer the legacy method of marking the agent bad (setting the statusAgentBad condition bit) when the rawvalue slot goes out of range, then you need to add the OutOfRangeEqualsAgentBad registry setting.

  • Device Span: use this section to specify the Minimum (the rawmin slot) and Maximum (the rawmax slot) limits of the Raw value (the rawvalue slot) that will be scanned (communicated) from the front end device. Please ensure that the correct span is specified for this value in the device, otherwise the value may be truncated to fit within this value range. 

Check the Sqrt Extraction checkbox (the sqRoot slot) if you want this agent to apply square root conditioning to the raw value.  For instance, this can be used to make flow inputs linear. 

  • Engineering Span: use this section to specify the Minimum (the engmin slot) and Maximum (the engmax slot) limits of the Engineering value (the value slot), which is typically the value that is displayed on mimics and trended etc. These limits correspond to the limits specified in the Device Span section and are used to scale the raw value, received from the device, into an engineering or display value.  

Note: If you require reverse polarity for ALL Analog agents , so that the Maximum limit of the Engineering Span is LOWER THAN its Minimum limit, then you need to add the AnalogRawComms value to the registry. For details, see AnalogRawComms.

If necessary specify the Unit (the unit slot) in which this value is measured. This unit is displayed when this value is trended or charted.

Tip: The default scaling values correspond to the settings required for 12 bit A to D water temperature signals from a PLC, so the Maximum values for the Device Span and Engineering Span are 4095 and 100 respectively.

To specify the engineering units to use for this value: these units are displayed when this value is trended or charted.

Edit the Unit field (the unit slot) in the Engineering Span section of this dialog.

To configure alarm limits and/or deadbands for this value: to specify one or more alarm limits and/or their deadbands for the Engineering value (the value slot) of this agent.

The following alarm limits can be defined in the Alarms section of this dialog:

  • The High-high alarm limit (the hiHi slot) specifies the second alarm limit for a high Engineering value (the value slot), which if reached should require urgent and immediate corrective action. More details:When the value reaches or exceeds this alarm limit the High-high status bit is set to 1 (enabled), which can be alarmed using the High-high default alarm type. If necessary, you can also specify this alarm limit for the Raw value, by using the rawHiHi slot, that is NOT displayed by this dialog.

Note: The High alarms engineering deadband value (the hiDeadBand slot), specified in the Deadbands section, is used to de-sensitise this alarm limit.

WARNING! This deadband value does NOT work with alarm time deadbanding (configured by using the Delay setting when alarming this agent). Therefore if you are using alarm time deadbanding then you must SET this deadband value to 0.

  • The High alarm limit (the hi slot) specifies the first alarm limit for a high Engineering value (the value slot), which if reached should require corrective action as soon as possible. More details:When the value reaches or exceeds this alarm limit the High status bit is set to 1 (enabled), which can be alarmed using the High default alarm type. If necessary, you can also specify this alarm limit for the Raw value, by using the rawHi slot, that is NOT displayed by this dialog.
  • The Low alarm limit (the lo slot) specifies the first alarm limit for a low Engineering value (the value slot), which if reached should require corrective action as soon as possible. More details:When the value lower or equal to this alarm limit is reached the Low status bit is set to 1 (enabled), which can be alarmed using the Low default alarm type. If necessary, you can also specify this alarm limit for the Raw value, by using the rawLo slot, that is NOT displayed by this dialog.

Note: The Low alarms engineering deadband (the loDeadBand slot), specified in the Deadbands section, is used to de-sensitise this alarm limit.

WARNING! This deadband value does NOT work with alarm time deadbanding (configured by using the Delay setting when alarming this agent). Therefore if you are using alarm time deadbanding then you must SET this deadband value to 0.

  • The Low-low alarm limit (the loLo slot) specifies the second alarm limit for a low Engineering value (the value slot), which if reached should require urgent and immediate corrective action. More details:When the value lower or equal to this alarm limit is reached the Low-low status bit is set to 1 (enabled), which can be alarmed using the Low-low default alarm type. If necessary, you can also specify this alarm limit for the Raw value, by using the rawLoLo slot, that is NOT displayed by this dialog.
  • The Rate of change alarm limit (the roc slot) specifies the maximum difference between any two consecutive Engineering values (the value slot) in one second. More details:When the rate of change of this value reaches or exceeds this alarm limit the Rate-of-change status bit is set to 1 (enabled), which can be alarmed using the Rate-of-change default alarm type. If necessary, you can also specify this alarm limit for the Raw value, by using the rawRoc slot, that is NOT displayed by this dialog.

Note: If this field is set to 0 this effectively disables this alarm limit.

IMPORTANT: If you want to configure these alarm limits externally, such as from a front-end device, then you need to add the AnalogRawComms value to the registry. For details, see AnalogRawComms Registry Value. 

The deadbands for the low-low, low, high and high-high alarm limits can be specified in the Deadbands section of this agent as follows:

WARNING! These value deadbands do not work with alarm time deadbanding (configured by using the Delay setting when alarming this agent). Therefore if you are using alarm time deadbanding then you must SET these value deadbands to 0.

  • The High alarms field (the hiDeadBand slot), specifies the engineering value used to de-sensitise the High and High-high alarm limits. In other words this specifies the ‘band’ (size of) the ‘dead’ area below these alarm limits, which the level must reduce by before the alarm becomes inactive (is cleared). This can prevent unnecessary alarms if the level wavers up and down as it is stabilised. 
  • The Low alarms field (the loDeadBand slot), specifies the engineering value used to de-sensitise the Low and Low-low alarm limits. In other words this specifies the ‘band’ (size of) the ‘dead’ area above these alarm limits, which the level must increase by before the alarm becomes inactive (is cleared). This can prevent unnecessary alarms if the level wavers up and down as it is stabilised.

Note: Deadbands can be specified to reduce the sensitivity of these alarm limits, so that you do not create unnecessary alarms.

WARNING! These value deadbands do not work with alarm time deadbanding (configured by using the Delay setting when alarming this agent). Therefore if you are using alarm time deadbanding then you must SET these value deadbands to 0.

For a detailed description of how these alarm limits and their deadbands are used when monitoring a process value, see Using Analog Agent Alarm Limits.

To monitor this value for changes: if enabled, any change in value instantaneously sets the Changed specific status bit of this agent and records the previous value.

To enable and specify a default (cold-start) value: to specify the default value to use when the Agent Server is started and it does not have a value specified for this agent. If enabled, this value is sent to the front-end device when the Agent Server starts up.

  1. Check the Enable checkbox in the Cold start section.
  2. Specify the required default engineering value in the Value field (the initValue slot).

This value is sent to the scanned front-end device for this Analog agent when the Agent Server is first loaded.

The Accumulator agent

The Accumulator Agent gets its name from the type of process values that it monitors and operates in three ways:

  1. It retrieves an input value that normally accumulates over time and is always increasing in value.
  2. It uses this value to calculate the difference, or its change in value, between successive events or over a specific time or interval.
  3. Finally, it calculates the total for a period based on a predefined trigger or time interval.

Operation

When the agent is first enabled, it works as follows:

  • If the intervalMode slot property is set to 4, a new period will commence immediately.
  • If the intervalMode slot property is set to 3, the period will commence immediately but will end at the next synchronised period.
  • At the end of every period, the value is saved as lastValue and the new value is calculated as inputValue minus startValue.
  • If a SQL Server connection is configured, a new record is added to the history table (see History below) containing the period end time, the value for the period as well as the current inputValue.
  • A new period commences immediately and the startValue (=inputValue) is recorded.

Configuration

The minimum required configuration for the Accumulator agent:

  1. Define an inputTag OR scan the inputValue and then enable the agent.
  2. Define a triggerTag and triggerMode OR a method of driving the trigger slot.

Trigger event

When a trigger event occurs:

  • The agent subtracts the previous interval input value from the current input value to determine the value differential for the current period.
  • This results in a value which represents “the total production for the last hour or shift or day and so-on”.
  • It then calculates the rate of change in value, which is the differential value for the current period divided by the interval of this period (value per hour).

Alarming

You can also configure alarm limits for both the differential value and rate of change in value for the current period, which will monitor the current value or rate against these alarm limits:

  • high-high
  • high
  • low
  • low-low

Any infringement of these alarm limits causes the agent to set its corresponding status bit, which can also be alarmed.

History

To maintain a history of these periodic counts/totals, you should connect the Accumulator agent to a SQL Server database:

  • Each record captures the start and end times of the period, the start and end values and the differential value for the period.
  • To provide automatic management of this data, then a housekeeping period can be defined to ensure that it keeps the most relevant or most recent records only.
  • If a valid connection and table is specified, the History table is created as follows:
    Column name Type Description
    idx Int Auto incrementing index
    dt datetime Period end date and time
    value float Calculated value for period
    accumulator float The accumulator reading (inputValue) at the end of the period

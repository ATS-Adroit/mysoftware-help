MultiState Data Model

The MultiState agent models a logic table or truth table, which can be used to define the operating and control sequence for equipment and is typically used to control drive groups. Its logic or truth table has the following properties:

  1. Up to a maximum of 16 discrete states, such as, for example, Group Auto Ready and OFF, Group in hold, etc. Each state can have a description text up to 64 characters long.

  2. A maximum of 16 inputs, various unique combinations of which are used to define the discrete states.

    These inputs can originate from any Boolean, Integer, or Real data, but will be converted to Boolean TRUE/FALSE indications on being stored in a MultiState agent. MultiState inputs can be sourced either from agents, such as existing Digital agents or directly from PLC registers. This latter option is facilitated by the ability to scan directly into MultiState agent’s inputs (.rawValue slot) without going through an interposing conditioning agent like a digital, and can yield some very substantial benefits in terms of reducing the total number of agents that need to be engineered for a project.

  3. Any number of Boolean outputs, can be set TRUE or FALSE on attainment of a particular state.

  4. A current state variable, containing the agent’s currently active state. Because there are a maximum of 16 states, 16 agent- Specific Status Bits are used to hold the current state.

    This approach, namely having a separate bit dedicated to each state, leads to a smooth integration with the Classic user interface multicolor Behaviour, by allowing a different text, line and/or background color for each discrete state. In addition, these bits can be individually alarmed using existing Adroit alarming mechanisms, which means a wide variety of alarm strategies can be developed.

  5. If a Multistate input bit is driven by a Digital agent in addition to being scanned to the field, then this input bit will reflect the state of this Digital agent, ignoring any changes made to this Multistate agent’s "rawValue" slot from the field.

Note: It is recommended that the Marshal agent be used for this type of application instead.

  1. A current state string, containing the state description text for the MultiState agent’s currently active state.
  2. Each state therefore has the following properties:
  1. A state number (1 -16), corresponding to the state’s bit position in the MultiState agent’s status word.
  2. A state description text string up to 64 characters long.
  3. A 16-bit input-true mask, defining which, if any, of the 16 inputs need to be TRUE for the state to be active (see Common Status Bits).
  4. A 16-bit input-false mask, defining which, if any, of the 16 inputs need to be FALSE for the state to be active.
  5. An output-true list, comprising any number of Boolean agent.slots that are automatically set TRUE on attainment of the state.
  6. An output-false list, comprising any number of Boolean agent.slots that are automatically set FALSE on attainment of the state.

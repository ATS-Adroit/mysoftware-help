The IOT agent

The term Internet of Things (IOT) is an abstract concept that refers to an ever-growing network of physical objects that use an Internet Protocol (IP) address for Internet communication between these objects and other Internet-enabled devices and systems. This implies connecting any device with an interface to the Internet and also possibly to each other.

IOT is expected to offer advanced connectivity of devices, systems, and services that goes beyond machine-to-machine (M2M) communications and covers a variety of protocols, domains, and applications. The interconnection of these embedded devices (including smart objects), is expected to support automation in many technological fields.

Creating a specific IOT Agent

As an example, let’s create an IOT agent called 2KVAPUMP.

  • All that is required is to first copy the default Adroit IOT agent x_iot.dll to a new file called t_2KVAPump.dll in the Adroit system folder, which is typically found at C:\Program Files (x86)\Adroit Technologies\Adroit.
  • The newly copied agent type is then available to Adroit.
  • A newly created IOT agent can represent any object containing multiple properties or slots.
  • Currently, the IOT agent does not support real-time catch-up.

Management slots

By default,

  • The IOT agent in itself does not contain any useful slots that are usable for end-user process purposes.
  • It does, however, contain four management slots that may be used to build up the structure of the IOT agent after it has been created.
  • Select the Agent Specific Slots option below to view more information.

The xmlSlots slot

When this agent is created, it only contains the management slots, one being the xmlSlots slot which is used to create and configure the user-defined slots.

  • This agent does not have any default status slots.
  • The structure of this agent is defined only once in XMLstands for Extensible Markup Language, which defines a set of rules for encoding documents in a format that is both human-readable and machine-readable. format after the agent instance is created and saved in the Agent database (.WGP) file.

Expression slot

The IOT agent provides a multi-line expression engine to calculate the defined slot values and status bit conditions, which are saved in the expression slot.

  • The expression engine is similar to the expression engine used by UDP-Based Protocol (UDT) agents for manipulating status slot values (See the “Creating UDT Status Bit Expressions” topic).
  • However, the IOT agent lets users create multi-line expressions where each unique expression is used to drive a single IOT slot or a single status slot.

Configuration

This agent does not possess any default status slots and is required to be configured externally.

  • The IOT agent is basically not usable until it’s configuration is defined by using either the addSlot or the xmlSlots slot.
  • Configuration of the agent slots is not currently supported by the agent dialog, however, you may import a XML slot definition file that defines the slots for any single IOT agent.
  • It is typically called from an external source, for example, a browser or 3rd party application.

Creating the structure of an object

You should provide an appropriate name and then add the required IOT agent, which will enable the code that interfaces to the IOT device to identify it.

As only this code knows the identification of the IOT device, it should use the addSlot OR xmlSlots slots of this agent to programmatically create the slots as required.

Using the addSlot

The format for this slot is as follows:

slottypeidx,slotname[,slotdescription[,slotvalue]]

Where:

slottypeidx : is a slot type index as follows:

0 : boolean (1/0)

1 : integer (4 byte signed integer)

2 : real (8 byte float)

3 : string (79 characters)

4 : time

5 : tagname (67 chars) (see “Use of Tagname type slots” below)

10 : varstring (any number of characters)

slotname : any valid slotname not exceeding 15 characters and not containing the characters $ @ , \ & % * ?

slotdescription : any 79 character description describing the agent (object) instance

slotvalue : any suitable slot value conforming to the slot type index above

Using the xmlSLot

This XML structure requires that you always specify:

  • the name and description of the IOT agent in the <IOT> section.
  • the name, description and values of each slot that you require in the <Slots> section, where:
    • The slot name is any valid slot name not exceeding 15 characters and does not contain the characters $ @ , \ & % * ?
    • The slot description is any 79 character description that describes the purpose of this property.
    • The slot type is one of the following (case sensitive) values:
      • Boolean : a 1 or a 0
      • Integer : a 4 byte signed integer
      • Real : an 8 byte floatString : 79 characters
      • Time : Win32 64-bit FILETIME Type
      • Name : 67 chars. For more details, see How to use Tagname type slots.
      • VarString : any number of characters
  • Status bits, you can specify status bits in the <HeaderSlots> section, where only the status bit name is required.

Note:  You should note, however, that you do not need to specify a name for the status bits of an IOT agent for them to be used.

Example of the XML structure

The following is an example of the required XML structure for the xml slot of the IOT agent with custom text shown in blue for ease of reference:

<IOT Name="Fridge1" Description="Fridge in kitchen"><Slots><Slot Name="value" Description="Temperature" Type="Real">20</Slot></Slots><HeaderSlots><Slot Name="hi"/></HeaderSlots></IOT>

Alternatively, with Revision 7 or later of iot.dll, you should use

<IOT><SlotDefinitions><Slot Name="value" Description="Temperature"Type="Real">20</Slot></SlotDefinitions><HeaderSlots><Slot Name="hi"/></HeaderSlots></IOT>

Important:  This is the expected format when saving the XML structure to the xml slot.

To facilitate easier reading, the expanded view of this XML structure is shown as follows:

<IOT Name="Fridge1" Description="Fridge in kitchen">

<Slots>

<Slot Name="value" Description="Temperature" Type="Real">20</Slot>

</Slots>

<HeaderSlots>

<Slot Name="hi"/>

</HeaderSlots>

</IOT>

Any number of <Slots> may be defined. A maximum of 16 <HeaderSlots> (status bits) may be defined. The first specified header slot represents status bit 16 and subsequent header slots will represent status bits 17 to 31.

The XML code above can be saved to an XML file as a template and loaded in the IOT agent dialog.

An example of IOT values XML packet for rawValue is a simplified version of the xmlSlots schema as follows with custom text shown in blue:

<IOT><Slots><Slot Name="value">20</Slot></Slots></IOT>

Alternatively, with Revision 7 or later of iot.dll, you should use

<IOT><SlotValues><Slot Name="value">20</Slot></SlotValues></IOT>

For improved reading, the expanded view of this XML structure is shown as follows:

<IOT>

<SlotValues>

<Slot Name="value">20</Slot>

</SlotValues>

</IOT>

Important:  This is very important!! – To send a Time slot type value within the rawValue XML … you MUST first convert the value to a UCT time.

Expressions

Once the slots have been defined, you create expressions to specify the value of one or more of the specified IOT agent slot and the required condition that needs to be met to enable each of the specified status bits by using the expression slot.

The expression slot is a multi-line expression engine, where multiple expressions are separated by blank lines.

For more information, see Creating IOT Expressions.

Using Tagname Type Slots in an IOT Agent to subscribe to external tags

Tagname type slots are used in an IOT agent when the IoTThe Internet of Things (IoT) is the concept of connecting any device with an on and off switch to the Internet (and/or to each other). device needs to subscribe to external tags, such as systeminfo.second.

When using Tagname type slots, there is a rule that must be applied:

  • The Tagname slot must be immediately followed by the IOT agent slot that will ultimately contain the value of the specified tag.
  • If the Tagname slot contains a valid tag name, the IOT agent will automatically subscribe to the specified agent and will place any values received for this tag into the next slot.

For example, to subscribe to systeminfo.second then the XMLstands for Extensible Markup Language, which defines a set of rules for encoding documents in a format that is both human-readable and machine-readable. slot value would look something like this:

<IOT Name="SecsInMinute" Description="The second time value">

<Slots>

<Slot Name="source" Description="Source of value" Type="Tagname">systeminfo.second</Slot>

<Slot Name="value" Description="Seconds" Type="Integer">0</Slot>

</Slots>

<HeaderSlots>

</HeaderSlots>

</IOT>

In the above sample,

  • the Slot Name “source” defines the tag to which we want to subscribe.
  • the Slot Name “value” defines the slot where the subscribed tag value will be stored.

Important:  The slot names "source" and "value" used in the example above are merely placeholders to make this example clearer, you may use any names you choose.

Creating IOT Expression creating expressions to drive the value of defined slots and status bits

The IOT agent provides a multi-line expression engine to allow you to calculate the defined slot values and status bit conditions. These expressions are saved in the expression slot.

Note:  You need to insert empty lines to separate multiple expressions.

The following example shows two separate expressions as they are displayed in the Expression edit box of the IOT agent dialog:

Z=slot(x) + slot(y)

status16 = slot(z) > 100

As a side note, the expression slot of the IOT agent would actually be saved as follows:

Z=slot(x) + slot(y)\r\n\r\nstatus16 = slot(z) > 100

How to define IOT expressions

Note:  Any status or controlling IOT slot can be alarmed by creating an IOT Alarm agent to alert the user of an anomaly.

Expression Conditions

Your expressions can contain one or more of your defined slots, such as:

Logical expressions Condition for success
Slot(value) > 95 SUCCESSFUL if the Value slot is greater than the value of 95
Slot(Open) & (Slot(value) > 95) SUCCESSFUL if the Open tag is On and the Value slot is greater than the value of 95

Templates

You can build your XML structures in an external text editor and save as an XML file template.

  • The Load template button allows you to load an XML file defining the slot structure of the IOT agent.
  • The Save template button allows you to save the slot structure of the IOT agent to an XML file.

 

Creating an IOT agent using expressions in the XML slot

If you want to create an x+y=z agent with alarming when the z value exceeds 100 then the xml slot of this agent would have the following structure:

<IOT Name="AddingTwoNumbers" Description="This adds two real values together"><Slots><Slot Name="x" Description="X value" Type="Real">0</Slot><Slot Name="y" Description="Y value" Type="Real">0</Slot><Slot Name="z" Description="Z value" Type="Real">0</Slot></Slots><HeaderSlots><Slot Name="hi"/></HeaderSlots></IOT>

And the expression slot of this agent would saved as:

Z=slot(x) + slot(y)\r\n\r\nstatus16 = slot(z) > 100

Which, appears in the Expression edit box in the configuration dialog of this IOT agent as follows:

Z=slot(x) + slot(y)

 

status16 = slot(z) > 100

Note:  The use of the empty line between these expressions, indicates that they are separate independent expressions.

Expressions using external tag values

Expressions can also use external tag values in the format value(tag) e.g. value(“systeminfo.second”). The following example of the xml

The following example provides the xml slot that defines an IOT agent that obtain the value of the systeminfo.second tag and stores this in a secs Integer slot. Then it provides the expression slot that enables the status bit 16 when the number of seconds exceed 30.

SecsInMinute.xml=<IOT Name="SecsInMinute" Description="Alert when the seconds exceed 30"><Slots><Slot Name="source" Description="Source of the seconds value" Type="Tagname">systeminfo.second</Slot><Slot Name="secs" Description="The actual seconds" Type="Integer">0</Slot></Slots><HeaderSlots></HeaderSlots></IOT>

SecsInMinute.expression=status16=slot(secs)>30

Note:  This example also shows that you do not need to specify a name for the status bits of an IOT agent in order for them to be used, in this case they need to be referred to using the convention statusnn in any expressions that you create (where nn is the required status bit number from 16 to 31).

Expressions using status slots

However, when you provide names for your status slots, such as in the first example where the status16 was named as "hi", then you can also refer to the named status slot in any expressions that you create, in addition to using the statusnn numbering convention.

So when you use:

status16 = slot(z) > 100

You can also use:

status(hi) = slot(z) > 100

 

In addition to referring to the status slots as the statusnn or the named status(slotname) convention, interchangeably, you can also use these on the right hand side of the equation, if needed.

As a result, you could have the following expression:

status17 = if(status(enabled), slot(abc) > 100

Alarming status slots

These status slots used in expressions can be alarmed using IOT Alarm agents.

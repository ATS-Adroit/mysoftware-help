Ignoring Delayed SET Commands

Once SET commands are enabled for a Command agent, additional restrictions can be imposed on these commands to further ensure that they are not misused to create a serious security and/or operational risk. For details, see Specifying Permitted Commands or Additional SET Command Restrictions.

One of the additional restrictions is to specify the period for which these commands are of valid for, which is calculated from the time the message is originally sent.

Any SET commands, whose SMS messages are received after this period has elapsed will not be processed by the Command agent. This is to prevent SMS messages that have been lost or delayed by the network from being inappropriately acted upon.

To specify the period of validity for SET commands:

  1. If necessary, add a Command agent. For details, see Adding Agents.
  2. Edit the required Command agent. For details, see Editing Agents.

This will display the Edit Command agent dialog.

  1. If necessary, select the General tab, the default selection.
  2. Under the Commands group, ensure that the Enable commands and Allow ‘Set’ commands checkboxes are checked to allow this Command agent to perform SET commands.
  3. Under the Extended ‘Set’ Configuration group, specify the required period of validity, in minutes, in the Time (in minutes) edit box beneath the Ignore ‘Set’ commands older than title, the default is 0 minutes.

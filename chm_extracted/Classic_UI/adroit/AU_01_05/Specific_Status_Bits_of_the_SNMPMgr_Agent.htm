Specific Status Bits of the SNMPMgr Agent

Each SNMPMgr agent can manage a single device, by getting, setting and/or trapping its OIDSNMP managed Object IDentifier, which describes the exact location of this value in the SNMP structure for its device. values.

The following status bits of this agent can be used for diagnosing the status of its connection to the device it is required to manage and the status of the managing process, as follows:

  • statusBit16
    Invalid Connection

On if the agent is UNABLE to connect to the specified device. To troubleshoot this, see Connecting to the Managed Device.

Note1: This will ALWAYS be On if the agent is loaded in the Stopped state and is only validated when the agent is Started or Updated.

Note2: An invalid connection will delay the closing and opening the Edit dialog of this agent, as the agent attempts to establish this connection.

Note 3: This is On, by default, for new agents.
  • statusBit17
    Stopped

On if the agent is ABLE to connect to the device BUT not getting, setting and/or trapping OID values.
  • statusBit18
    Started

On if the agent is ABLE to connect to the device AND getting, setting and/or trapping OID values.

For details on stopping or starting the managing of the device, see Device Management Settings.
  • statusBit19
    Unlicensed

On if:

  • the Started (statusBit18) is set
  • Agent Server license does NOT contain the required OEM license and
  • it is NOT the first SNMPMgr agent that was added.

For details regarding the licensing and use of this agent, see SNMPMgr Agent Usage Requirements.
  • statusBit21
    Error

On when a non connection-related error has occurred, while the errorMsg slot can be used to determine the reason why this status bit is being set. This specifies that one of the following errors have occurred:

Note: If this Error status bit is alarmed, using the default Error alarm type, then the contents of the errorMsg slot appears in the "Reported data" field of the alarm entry.

  1. If Started (statusBit18) is set and any agent assigned to an OID value is not found. For instance, when an agent is removed from the Agent Server after it was assigned.

Note: In this case the errorMsg slot contains the name of the missing agent. However, if multiple agents are not found, usually only the last agent that is "not found" will be displayed by this slot.

  1. If Started (statusBit18) is set and one or more of the polled, written and/or trapped OID values cause the number of licensed scan points for this Agent Server to be exceeded.

Note: In this case the errorMsg slot contains 'Not enough scan points'.

WARNING! This immediate disables the polling, writing and/or trapping of ALL the OIDs, even if this agent only attempts to consume one scan point more than the total number of licensed scan points for this Agent Server.

  • statusBit22
    Traps

On when this agent receives 1 or more SNMP traps from the device and the trapCount slot is >= 1.

These traps are stored in the trap queue for this agent, so that you can process them, typically by means of a script. For more details, see About SNMP Traps.
  • statusBit23
    Healthy

On if the agent is UNABLE to connect to the specified device.

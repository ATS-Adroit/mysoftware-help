Using Analog Agent Alarm Limits

The Analog agent provides extensive monitoring and alarming of its engineering value (the value slot), by providing low-low, low, high, high-high and/or rate of change alarm limits, which when reached set the relevant specific status bit, which can be alarmed. You can use these alarm limits and their deadbands, where applicable to monitor a process value, as follows:

Using alarm limits and their deadbands:

  • The Low (the lo slot) and High (the hi slot)  inner alarm limits are the first warning that a process value has moved outside its acceptable range, and implies that corrective action must be taken as soon as possible.
  • The Low-low (the loLo slot) and High-high (the hiHi slot) outer alarms are the second warning that the process value has moved further from its acceptable range and reached the second alarm limit. This implies that the first warning has been ignored and urgent and immediate corrective action is now required.

Note: That whenever the Low-low alarm is on, the Low must by definition already be on. Similarly, whenever the High-high limit is reached, the High limit will already have been passed.

The alarm will become inactive (be cleared) once the process value goes past the limit AND through its deadband, if configured. Click here for an illustration:

 

Using the Rate of Change alarm limit:

The Rate of Change status bit is set when the difference between any two consecutive engineering values in ONE second exceeds the defined Rate-of-Change limit. Click here for an illustration:

 

In other words, if this is set to 100, the default value, then if the engineering value (the value slot) of this Analog agent changes from 1 to 101 in 1 second then the Rate of Change status bit is set. But if the engineering value takes 2 seconds to change from 1 to 101 then the effective rate of change is (100/2 =) 50 so the Rate of Change status bit is NOT set.

This rate of change measurement is independent of the condition of the low-low, low, high and high-high limits. The value change could be the result of a scan (from the front-end device), operator action or an output from another agent.

Factors affecting OEE or KPI calculations

Calculation duration

The OEE agent uses a background engine to update the monitored KPI or OEE in real-time.  Any changes made to the input slots, determines how this background engine does its calculations.

Note: Ensure that your Adroit license has specified the required number of OEE agents, which are specified in groups of 10. WITHOUT specifying the licensed number of OEE agents, only one instance of an OEE agent has its background engine enabled. All other agents will appear not to be running.

By default, the agent records the OEE or KPI based on shift numbers, which are determined by the Shift agent specified by the Shift tag field of the edit dialog ( shiftAgent slot). For details, see Configuring the Shift agent.

At the end of each shift the OEE or KPI is recorded and automatically reset for the start of the next shift. 

If you want to use the agent for recording the OEE or KPI on a “per batch” basis, then:

  • Disable the autoReset slot of the agent (uncheck the Shift auto-reset checkbox of the edit dialog) and
  • Programmatically reset the agent at the end of every batch. 

Note: The action of resetting the agent, automatically creates an OEE data snapshot entry before resetting the data.

Tip: If the KPI or OEE is affected by the type of product being produced, then use different OEE agents for the different products.

Running time

KPI calculations are performed against runtime.  Therefore the OEE agent uses the BOOLEAN running slot (or the optional BOOLEAN tag reference runningTag) that informs the agent whether the process (or machine) is running.

Running time is typically automatically incremented by the agent while this BOOLEAN value is ON.

IMPORTANT: The OEE agent only supports BOOLEAN tags - so you cannot use an expression value tag.

Note: The OEE agent expects that this slot will be OFF if the available slot is OFF.  If not, runtime will continue to increment even though availability is OFF.

However, it is possible that the process/machine is running but there is no physical production because, for example, a gear has stripped.  This causes the measurement variable (the input1slot) to remain static or go to zero i.e. inactive.  

If the measurement variable (the input1slot) remains inactive for a configurable amount of time then the OEE agent will stop incrementing the running time and will raise a downtime alarm status. 

As long as the input1slot is changing AND is not zero, the agent assumes that the process/machine is active and increments the running time.

Therefore the actual production time is determined by a combination of the running slot and an active input1slot.

Available time

Whereas KPI calculations are performed against runtime, OEE calculations are calculated against the time that the process/machine is available for production. 

The OEE agent therefore uses the BOOLEAN available slot (or the optional BOOLEAN tag reference availableTag) to determine the maximum available time. 

  • This slot should be ON when the machine/process is supposed to be running. 
  • If the process/machine is under maintenance or operators are at lunch/tea, this slot should be OFF. 

Tip: This slot can be controlled by the output of a Scheduler agent that is configured with the applicable maintenance/lunch/tea times etc. For details, see Configuring the Scheduler agent.

Complex mode and KPI calculation

To allow for KPIs that have one measurement divided by another measurement (other than time), such as kWh/ton- the OEE agent supports a second measurement input slot (input2). 

For normal OEE and KPI calculations,input2 is not used and the input type is set to Unused (0), by default. In this case the input1 slot is divided by time.

In this case:

KPI% = (Total for the Shift for input1/Run time)/Target KPI

 

If the Input type 2 field (the type2 slot) is NOT set to Unused(0), then the OEE agent is said to be in complex mode.

Note: OEE agents operating in complex mode CANNOT calculate OEE.

In this case:

KPI% = (Total for the Shift for input1/Total for the Shift for input 2)/Target KPI

OEE calculations

The OEE agent performs OEE calculations using the following formula:

OEE% = Quality% * Performance% * Availability%

Where:

 

Quality% = Quality factor(%) * ((Total for the Shift - Reject Count)/Total for the Shift)

 

Performance% = Total for the Shift/(Design capacity (per hour) * Run time)

 

Availability (hours)% = Run time/Available time

 

Availability

Percent of scheduled production (to measure reliability) or calendar hours 24/7/365 (to measure equipment utilization), that equipment is available for production.  Calculated as the equipment uptime (actual production – see 2.5 above) divided by the time that the equipment was available (see 2.3 above) for use.

Performance

Percent of total parts produced against the design capacity (optimal production rate) per time frame. 

Quality

Percent of good sellable parts out of total parts produced per time frame multiplied by the Quality factor % value.

Quality factor

Quality can be calculated in many ways, depending on the type of process and the variables/information available to calculate quality. 

Therefore, the OEE agent calculates the quality using the reject and total counts for the shift, which is multiplied by an external quality factor, expressed as a percentage.

This Quality factor % value (the qualityFactor slot) is the external quality factor whose value (0 to 100) must be driven externally.  The default value is 100%.

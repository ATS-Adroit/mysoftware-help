Accumulator Agent - Slot Details

The Accumulator agent requires an input value that accumulates over time. The Accumulator agent uses this value to calculate the difference between successive events or over a specific time period (interval).

Slot List for the Agent

  • Red slot names indicate configuration slots.
  • Blue slot names indicate operator/process driven slots.
  • All other slots are driven/controlled by the agent.
Slot Name Type Function
connection VARSTRING

This slot contains an optional connection string to the SQL Server database that is required for this agent to maintain a history of the differential values for each period.

Note:

If you specify global, the Global OLE DB connection string of the Agent Server is used, which is specified in the Adroit Config Editor.

  • Typically, you can launch this tool from the Desktop shortcut.
  • Select the Agent Server Configuration Welcome menu item.
  • Select the Advanced Agent Server Configuration option.
  • At the bottom of the dialog, the Global OLE DB connection field is available for you to specify this connection string.
deadband REAL

The deadband slot is used to desensitise the value alarm limits to prevent unnecessary alarms if the value is oscillating.

  • This slot is optional and specifies the ‘band’ (size of) the ‘dead’ area outside these alarm limits.
  • The deadband value must reduce before the alarm becomes inactive and is cleared.

Important:  This deadband slot ONLY applies to the alarm limits for the differential value and NOT for the rate of change alarm limits!
disableOnStandby BOOLEAN

Set this slot on [1] to disable SQL Query transactions on the standby clustered partner to prevent the standby Agent Server from logging duplicate records.

  • By default this slot is set to on [1].
elapsedTime REAL This slot captures the amount of time, in minutes, that has passed from the start of the current period.
enable BOOLEAN

Set this slot on [1] to enable this agent.

  • You must enable this agent before it can start analysing the accumulating process value and calculating its differential value for each period and its rate of change.
  • If necessary, log the values of each period to the specified history table in the specified SQL Server database.
housekeepDays INTEGER

Set this slot value, if you want to provide automatic management of the database history table.

  • If this agent is logging records, then use this slot to specify how many days of data you want this table to retain, to ensure that only the most recent records are kept.

Note:  The default value of 0 disables this functionality.
inputTag TAGNAME This is an optional tag that defines the accumulating process value. If used, the value of this tag will be transferred to the inputValue slot.
inputValue REAL

This slot contains the ever increasing process value.

  • If an inputTag is not used, then you need to drive the inputValue slot.
  • You do this by scanning this slot value to the required accumulating process variable stored on the front end device or by means of a script or expression.
interval INTEGER

The number of minutes that define the duration of each period.

Note:  This slot is ONLY applicable if you are using an intervalMode of 3 or 4.

Important:  ONLY when you use intervalMode 3 must you ensure that the specified interval is divisible into 60 or is a multiple of 60, if not, period timing errors will occur.
intervalMode INTEGER

Use this slot to determine how you want to specify the constant interval of time over which the differential increases in value will be calculated.

The selected mode determines which additional slots are used to determine this period.

The first three intervalMode options make use of the intervalTag, which is a tag that you can monitor to determine when the end of an interval has occurred, as follows:

  • 0=Interval tag value goes to zero.
    • In this case the end of the interval occurs when the value of the intervalTag changes from any non-zero value to a value of zero [0].
  • 1=Interval value goes (from zero) to non-zero.
    • In this case the end of the interval occurs when the value of the intervalTag changes from zero [0] to any non-zero value.
  • 2=Any interval tag value change.
    • In this case the end of the interval occurs when the value of the intervalTag changes in value to any other value (a different value from its current value).

The next option allows you to define the required interval duration using the system time (the time of the Agent Server computer) and the interval slot, which specifies the number of minutes for the duration of each period:

  • 4= Not synchronised (to clock)
    • In this case the agent sets the starting time of the periods to the exact time that this agent is enabled and calculates all the successive periods by adding the specified interval number of minutes to this starting time.
    • For example, if the agent is configured to use this intervalMode 4 with an interval of 10 minutes and this agent is enabled at 10:02, then the first period will end at 10:12 for this mode (a full interval from the starting time) and the next period will end at 10:22 etc.

For the final option, you typically need to devise a method of driving the triggerNow slot via a script or an expression. or alternatively, this agent can calculate the differential value whenever you choose to.

  • 5=Manual trigger

Note:  The rate of change and its alarm limits only applies when using periods that have regular intervals.
intervalTag TAGNAME

A tag that defines the value that will indicate the end of an interval.

Note:  This slot is ONLY applicable if you are using an intervalMode of 0, 1 or 2.
lastValue REAL The differential value of the previous period.
periodCount INTEGER Number of elapsed periods for the current agent server session.
rate REAL The rate of change of the differential value for the last period, specified as a value per hour.
rateHiHi REAL

The optional second alarm limit for a high rate, which if reached should typically require urgent and immediate corrective action.

  • When the rate reaches or exceeds this alarm limit, the RHighHigh status bit is set to 1 (enabled).
  • This slot can be alarmed using the RHighHigh default alarm type.

Note:  The deadband slot does NOT apply to these rate alarm limits.

rateHi REAL

The optional first alarm limit for a high rate, which if reached should require corrective action as soon as possible.

  • When the rate reaches or exceeds this alarm limit, the RHigh status bit is set to 1 (enabled).
  • This slot can be alarmed using the RHigh default alarm type.

Note:  The deadband slot does NOT apply to these rate alarm limits.

rateLo REAL

The optional first alarm limit for a low rate, which if reached should require corrective action as soon as possible.

  • When the rate lower or equal to this alarm limit is reached, the RLow status bit is set to 1 (enabled).
  • This slot can be alarmed using the RLow default alarm type.

Note:  The deadband slot does NOT apply to these rate alarm limits.

rateLoLo REAL

The optional second alarm limit for a low rate, which if reached should typically require urgent and immediate corrective action.

  • When the rate lower or equal to this alarm limit is reached, the RLowLow status bit is set to 1 (enabled).
  • This slot can be alarmed using the RLowLow default alarm type.

Note:  The deadband slot does NOT apply to these rate alarm limits.

startTime TIME The start time of the current period.
startValue REAL The inputValue as recorded at the start of the current period.
tableName STRING

The table name of the database that will store these records, if one has been specified via the connection slot.

  • By default, this table name is set to the name of this Accumulator agent.
triggerNow BOOLEAN

Performs a manual end of period, which is effective in any mode selected by the intervalMode slot.

  • The differential value for the current period, i.e. inputValue minus startValue.
  • This value would obviously be equal to 0 at the beginning of each period.
value REAL

The differential value for the current period, which is inputValue minus startValue.

  • This value is always equal to 0 at the beginning of each period, since startValue = inputValue.
valueHi REAL

The optional first alarm limit for a high value, which if reached should require corrective action as soon as possible.

  • When the value reaches or exceeds this alarm limit, the VHigh status bit is set to 1 (enabled).
  • This slot can be alarmed using the VHigh default alarm type.

Tip:  The deadband slot, can be used to desensitise this alarm limit to prevent unnecessary alarms if the value is oscillating.

valueHiHi REAL

The optional second alarm limit for a high value, which if reached should typically require urgent and immediate corrective action.

  • When the value reaches or exceeds this alarm limit, the VHighHigh status bit is set to 1 (enabled).
  • This slot can be alarmed using the VHighHigh default alarm type.

Tip:  The deadband slot, can be used to desensitise this alarm limit to prevent unnecessary alarms if the value is oscillating.

valueLo REAL

The optional first alarm limit for a low value, which if reached should require corrective action as soon as possible.

  • When the value lower or equal to this alarm limit is reached, the VLow status bit is set to 1 (enabled).
  • This slot can be alarmed using the VLow default alarm type.

Tip:  The deadband slot, can be used to desensitise this alarm limit to prevent unnecessary alarms if the value is oscillating.

valueLoLo

REAL

  • When the value lower or equal to this alarm limit is reached, the VLowLow status bit is set to 1 (enabled).
  • This slot can be alarmed using the VLowLow default alarm type.

Specific status bits list 

Note:  These are of type BOOLEAN.

Bit Number Name Function

status bit 16

endofperiod

Pulsed (set to ON [1] momentarily and then set back to OFF [0]) at the end of each period.

status bit 17

sqlerror

ON if there is a problem connecting to the database, when the connection to this SQL database has been specified.

status bit 18

VHighHigh

ON when the differential value is GREATER THAN OR EQUAL to the valueHiHi alarm limit.

status bit 19

VHigh

ON when the differential value is GREATER THAN OR EQUAL to the valueHi alarm limit.

status bit 20

VLow

ON when the differential value is LESS THAN OR EQUAL to the valueLo alarm limit.

status bit 21

VLowLow

ON when the differential value is LESS THAN OR EQUAL to the valueLoLo alarm limit.

status bit 22

RHighHigh

ON when the differential rate of change is GREATER THAN OR EQUAL to the rateHiHi alarm limit.

status bit 23

RHigh

ON when the differential rate of change is GREATER THAN OR EQUAL to the rateHi alarm limit.

status bit 24

RLow

ON when the differential rate of change is LESS THAN OR EQUAL to the rateLo alarm limit.

status bit 25

RLowLow

ON when the differential rate of change is LESS THAN OR EQUAL to the rateLoLo alarm limit.

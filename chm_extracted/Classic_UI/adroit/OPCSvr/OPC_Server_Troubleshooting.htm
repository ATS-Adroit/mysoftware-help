OPC Server Troubleshooting

 

See OPC Server Security Issues,since these are the most prevalent issues relating to the use of OPC.

 

If for no obvious reason:

  • You are losing OPC communications when running Adroit (or any OPC client application) on a Windows XP computer.
  • It takes 30-45 seconds to connect to a remote OPC Server

This is caused by a problem on Windows XP operating systems that allows you to add datagram DCOM protocols, even though these operating systems do not support datagram protocols for DCOM.

To resolve this, remove the datagram protocols from the DCOM protocols, so that ONLY connection-orientated protocols are listed, as follows:

  1. Launch the Component Services Administrative tool.
    For Windows 2000: From the Start menu, select Programs, Administrative Tools and then click Component Services OR run DCOMCNFG and the refer to step 4.
    For Windows XP: From the Start menu, select Settings, Control Panel, Administrative Tools, then click Component Services.
  2. In the console tree of the Component Services Administrative tool, right-click the computer on which you want to configure the protocols to display the menu.
  3. Click the Properties menu item to display the Computer Properties dialog box.
  4. Click the Default Protocols tab.
  5. If any Datagram protocol (UDP/IP or IPX) are listed, then select each one and click Remove.
  6. If you do not have any of the connection-orientated protocols in the list, click Add to display the Select DCOM Protocol dialog box.
  7. Choose Connection-orientated TCP/IP Protocol as the protocol sequence, and then click Ok.
  8. Repeat step 7 to add other connection-orientated protocols to the default protocol.
  9. Move the Connection-orientated TCP/IP Protocol to the top of the list.
  10. Restart the computer for these changes to take effect.

For more information on this subject refer to http://support.microsoft.com/default.aspx?scid=kb;EN-US;q245197 and/or http://support.microsoft.com/default.aspx?scid=kb;EN-US;q242022

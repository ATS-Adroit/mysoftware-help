OPC Definitions

  1. OPC is short for OLE (Object linking embedding) for Process Control, it is a software technology designed, like OLE to allow different applications to exchange data, more specifically allowing an I/O server developed by a 3rd party to communicate to any SCADA.

    This allows a SCADASupervisory Control And Data Acquisition, used to monitor and control an industrial plant or process and its related equipment. such as Adroit to use the same I/O server as any other SCADA, eliminating the need for each SCADA to have its own drivers or I/O server for a device. The technology allows for an OPC item (scan pointa scan point licence that is consumed from your Adroit license when information is being manipulated.) to be read by a SCADA and, if enabled to do so, to also write to the OPC item.

  2. An OPC Item: is a string, uniquely describing an individual data element residing in an OPC server. It may be up to 80 characters long, and structured hierarchically typically using a period "." to separate each level.

  3. OPC Data Types: OPC is based on OLE, which uses Variants for all data transferred in transactions. A Variant is basically a block of data preceded by some information indicating the actual type of data in the block.

    A program will automatically convert Variants received to a data type that it is familiar with. Conversions are standardised, and automatically occur in high-level programming languages.

  4. An OPC Server is a data source or I/O Server, conforming to the OPC Data Access Specification e.g. the Adroit OPC Server.
  5. An OPC Client is an application, which uses the data provided by an OPC server, such as HMI software.

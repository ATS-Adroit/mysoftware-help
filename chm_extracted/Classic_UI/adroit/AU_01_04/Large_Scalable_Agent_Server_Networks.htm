Large Scalable Agent Server Networks

This network configuration typically contains a large number of Agent Servers that are required to share information as if they were part of the same project so that any one Agent Server can directly gain access to any of the other Agent Server.

However, maintaining a grid of fully connected Agent Servers can potentially be resource intensive, for the following reasons:

  • Many Agent Servers within a network all broadcasting their presence - many IT administrators do not like this.
  • Many Agent Servers within a network all on the same project causing large agent tables to be transmitted in a "one to many" relationship. Large agent tables are generally created when agents are added or deleted.

Note: This is a problem for slower (10MB, WLAN) networks where bandwidth was at a premium especially if the network is not dedicated to SCADA operations. However, 100MB networks handle this easily.

In this case, we recommend that you use the method, in which you can divide these Agent Servers into their own projects (or have each Agent Server in its own project if necessary), then use the list method for connecting these Agent Servers and/or projects together. For further details of this and the other methods of connecting Agent Servers together, see Agent Server Connection Methods.

If these Agent Servers are in different domains then you need to use explicit Agent Server connections. Click for details:

For instance, consider this situation in which each section in a plant has its own Agent Server and its own local Classic UI and where all of these plant section Agent Servers are connected to a central gateway computer (known as a proxy server), which also has its own local (or remote) Classic UIs. In this case

  1. The central gateway computer requires explicit Agent Server connections to be created for each of the plant section Agent Servers.
  2. Each plant section Agent Server, will only require explicit Agent Server connections to those servers from which data is required i.e. if its local Classic UI refer to tags, which are located on other plant section Agent Servers.

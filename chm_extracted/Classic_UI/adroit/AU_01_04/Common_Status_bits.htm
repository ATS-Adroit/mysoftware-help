Common Status bits

The overall status of an agent can be determined from its status slot, which is a 32 bit word containing configuration and run-time status information about the agent, each bit of which is also exposed as a slot. For details, see Agent Status.

The first 16 bits (0 to 15) are known as the Common Status bits as they are common across all agent types, each bit has a fixed purpose.

Their equivalent slots each have unique slotname, which follows the naming convention of statusXxxxxxXxxxxx. e.g. statusScanBad.

These Common Status bits are further classified into control, condition and configuration groups, as follows:

Note1: These are NOT contiguous groupings of bits, for instance the first bit statusBit00 is a condition bit NOT a control bit!

Note2: The first bit in the status word, statusBad, is the only bit an application needs to monitor to determine the integrity of an agent or slot. For details, see Agent or Slot Integrity Monitoring (Bad Handling).

  1. The first group is called Control bits, which can be modified by the user. Each bit can therefore be set or reset by the user, to control an agent’s operator, logging, alarming, and scanning functionality.
  2. The second group is called Condition bits, which are not directly modifiable by the user, and may only be viewed. They report on an agent’s integrity and alarm state, etc.

Note: All agent Specific Status bits are also Condition bits, since they are not directly modifiable by the user.

  1. The third group is called the Configuration bits, which are also not directly modifiable by the user, since they only provide configuration information about an agent, namely whether or not it has been scanned and/or alarmed.

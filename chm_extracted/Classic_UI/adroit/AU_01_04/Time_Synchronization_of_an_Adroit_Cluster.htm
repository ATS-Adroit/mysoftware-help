Time Synchronization

It is essential that both the cluster Agent Servers and their clients have their system time synchronised, for clustering to work effectively.

This is ALSO critical in a distributed Adroitinstallation (where there are multiple user interfaces and/or Agent Servers on different computers) that the system times of all of the computers are synchronised to a common source. Adroit will behave unpredictably on a system which system time is not synchronised with the computer it’s connecting to.

Time synchronization is typically managed by the Windows Time service that is installed by the default installation of Windows XP and later operating systems.

The following are symptoms of unsynchronised times:

  • The User Interface does not seem to be updating with the most recent information.
  • The Trend displays odd Behaviour: either the data seems to be inserted into the middle of the trend, or a strange unexplainable sudden change in the values being trended when pressing F5 to refresh the trend.
  • The data logs of the two unsynchronised Agent Servers in a cluster seem to get corrupted (as a result of the data being inserted into the wrong place) after doing a Datalog catch-up with the SystemDatalog agent. This corruption is most notable in a trend.

Agent Servers generate an event every minute if remotely connected Agent Servers have a time difference of more than two seconds. To indicate that there is a time synchronization issue. This feature does NOT affect Adroit clients (UIs) that connect to a remote Agent Server. In this case time synchronization issues are not reported.

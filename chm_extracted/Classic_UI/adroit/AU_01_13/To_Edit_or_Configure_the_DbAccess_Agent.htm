Configuring the DbAccess Agent

The DbAccess agent.

NB Read through the usage guidelines of this agent first.

  1. Edit an agent of type: DbAccess.

The Edit DbAccess Agent dialog box is displayed

  1. Click the browse button to the right of the Connection string to specify the connection details to the OLE DB database that you want to transact on. For details, see Connecting to an OLE DB database.

If remote User Interfaces are to configure these agents then the database folder must be shared and the location to the database file must be expressed in the UNC (Universal Naming Convention) format: \\ComputerName\ShareName\dataBaseFileName

The DbAccess Agent only establishes one connection per database; so many DbAccess Agents may share the same connection if they transact with the same database.

IMPORTANT: If you are connecting to a database across the network and your Agent Server is running as a service, then ensure that the user profile that the Agent Server service uses to log onto the computer HAS the necessary rights to browse the network and connect to the remote database. This should NOT be the default Local System account. See Configuring Agent Server Service User Profile. 

  1. Check Connect to database, to allow the table to be selected from the database, in general use, this is used to determine whether the transactions between Adroit and the database can occur.
  2. Then click the Update button, which updates the agent with the configuration changes.
  3. In the Table name edit box, specify the name of the table in which the transactions are to occur, by:
  4. Entering the name of the table directly into the edit box.
  5. If there is at least one connection to the database identified in the connection string, then the browse button can be used to select the required table, from the list of tables available in the selected database.
  1. If you have clustered Agent Servers that both access the same database then check the Disable on standby checkbox to prevent double entries for "Insert" transactions. The default state is unchecked.

Note: If enabled, the master Agent Server will perform the Retrieve transaction and shadow the result to the standby Agent Server tags.

If this option is NOT enabled and client runtime transaction shadowing is also enabled, then any Retrieve transactions performed by this DbAccess agent will be performed by both cluster nodes (Agent Servers). For details on enabling client runtime transaction shadowing, see Cluster Server Options.

  1. Check Eventlog errors, to enable the event logging of any errors generated while connecting or transacting with the database.

All events will be logged under the category DbAccess in the event log. Alternatively, monitor the information slot of the agent on a mimic.

  1. Under Transaction Type , select the type of transaction that is required to be performed. The available transactions are: Insert row, Update row, Delete row and Retrieve row.
  2. Enter the tag to field mapping i.e. the mapping of tags to the specific fields within the table of the database. These mappings are required for every transaction type, except for the delete transaction.

Note1: When connecting to an Oracle database, after the tag to field mappings have been made, add the name of the required database to the Table name edit box, as follows: OracleDataBaseName.SelectedTableName e.g. DB1.Table1

Note2: Support has been added for databases, which require square brackets around the field names otherwise their SQL transactions fail. If required, add the ForceJet registry value.

  1. Use the Identify row edit box, to identify the row in the table of the database, in which the transaction is to occur.

This is required for every transaction type, except for the insert transaction.

To delete all records in a table, leave this field blank, when using the delete transaction.

  1. Under Transaction scheduling and triggering , either click the Edit… button to configure the scheduling and/or triggering of the transaction or click the Trigger Now button to force the transaction to occur immediately.
  2. The Details… button , displays the Details dialog box, which gives the status of the transactions, by showing any database connection errors and the SQL statement that is being sent to the database.

The DbAccess Agent

The DbAccess Agent provides a link between Adroit and various external databases such as Access, SQL Server, FoxPro and Oracle, by using OLE DB technology, supported by Microsoft. OLE DB connectivity means that Adroit can connect to any OLE DB provider, unlike ODBC that was only created to provide access to relational databases.

The DbAccess Agent allows Adroit to share its information with 3rd party applications that use databases to store information. These 3rd party applications may be responsible for optimised control, reporting, MES, ERP or many other enterprise solutions.

As each DbAccess agent is responsible for a transaction on a row in a database, it allows the user to specify how and where he wants the data to be stored which is ideal for reporting.

Note: If a connection fails, due to network problems etc. the DbAccess agent will recover and continue transacting.

The DbAccess agent allows the following transactions to be performed: new rows can be added to an existing table; existing rows can be updated with current information; specific rows or the entire table can be deleted and data can be retrieved from the table inserted into tags inside the Agent Server. These transactions can be done on demand, they can be scheduled and (or) they can be triggered.

IMPORTANT: If you are connecting to a database across the network and your Agent Server is running as a service, then ensure that the user profile that the Agent Server service uses to log onto the computer HAS the necessary rights to browse the network and connect to the remote database. This should NOT be the default Local System account. See Configuring Agent Server Service User Profile.

The DbAccess agent is ideally used in applications where data inside the Agent Server is periodically written to a database (such as at the end of a batch job) for reporting reasons. It is not suited for fast logging of data.

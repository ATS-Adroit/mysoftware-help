Connecting to the Managed Device

The SNMPMgr agent must connect to the required device and specify the required level of access to its values (SNMP managed objectsmanagement data exposed by SNMP managed devices that might be hardware, configuration parameters, performance statistics, and any other data that directly relates to the operation of this device.) before you can monitor and/or manage this device.

IMPORTANT: Since the SNMPMgr agent supports up to SNMP version 3 and SNMP version 3 supports additional connection settings, therefore you need to know beforehand which SNMP version the device requires before you can connect to it.

To connect to a SNMP device:

Specify the following settings in the Connection settings section of the Edit SNMPMgr Agent dialog:

  1. IP address (STRING ipAddress slot): Type in the IP address of the device that is to be monitored and/or managed by this SNMPMgr agent. For details on the requirements and guidelines regarding the use of this agent to monitor and/or manage devices, see Usage Requirements.

Tip1: Use the LEFT and RIGHT arrow keys to quickly move to each number separated by the periods.

  1. Port address: (INTEGER ipPort slot) this allows SNMP devices to be addressed via a gateway where the IP addresses are not unique and so a unique port address is required. By default this is 161 the port that is used for SNMP communications.

    IMPORTANT: Ensure that the specified port is unblocked (enabled) in any firewalls that may exist.

  2. Timeout (INTEGER timeout slot): If necessary, specify the maximum time (in seconds) to establish a connection to this device. This is 1 seconds, by default.
  3. Version (INTEGER version slot): Select which SNMP version this device supports. This is version 1, by default.
  4. Read comm. (STRING readCommunity slot): If you ONLY want to retrieve (poll) values from this device then specify its read-only SNMP Community String. For further details, see SNMP Community Strings.

Tip: Since most equipment ships from the factory with a read-only community string that is set to "public", this is its default value.

  1. Write comm. (STRING writeCommunity slot): If you want to write (set) values for this device then specify its read-write SNMP Community String.
  2. Username (STRING userName slot): SNMP version 3 ONLY: the required user name.
  3. Authentication (STRING authPassword slot): SNMP version 3 ONLY: the required password for authentication on this device.
  4. Encryption (STRING encrPassword slot): SNMP version 3 ONLY: the required encryption password for this device.
  1. Retries (INTEGER retries slot): If necessary, specify the number of attempts to connect to the device, before deeming this device to be unavailable. This is 3 times, by default.
  2. Only check the Enable traps checkbox (BOOLEAN trapEnabled slot): if you want to receive SNMP trapsunsolicited SNMP messages sent by a device to notify an SNMP manager of significant events. from this device. For more details, see About SNMP Traps.

Note: If the Update button is clicked after modifying the IP address or Read comm. or WriteRead comm. settings, the agent will attempt to reconnect to the device using these new settings.

TheInvalidConnectionstatus bit (Invalid connection checkbox) indicates if this agent CAN (if empty) or CANNOT (if checked) connect to the specified device. BUT this checkbox is ONLY validated when you press the Update button or select the Enable polling option for this agent, so it will ALWAYS be CHECKED when the Disable polling option is selected.

Note1: If you are monitoring a computer and have NOT installed the SNMP service, then this Invalid connection status bit will be set.

Note2: An invalid connection will delay the closing and opening the Edit dialog, as the agent attempts to establish this connection.

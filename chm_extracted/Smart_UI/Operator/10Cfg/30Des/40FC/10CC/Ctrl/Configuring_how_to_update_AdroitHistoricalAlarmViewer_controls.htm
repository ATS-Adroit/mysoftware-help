Configuring how to update AdroitHistoricalAlarmViewer controls

The available method used to update the grid of the AdroitHistoricalAlarmViewer control with recent alarms depends upon how the Alarm Management database (specifically the Adr_AM_HistoricalIncidents table) has been connected to the AdroitHistoricalAlarmViewer control, as follows:

Typically, the DataSource tab Initial Configuration and/or General Configuration Settings and/or Configure DataSource Connection configuration dialogs, connect the AdroitHistoricalAlarmViewer control via an OLE DB datasource, as follows:

In the DataSource tab of the Initial Configuration dialog, the Server should already specify your current Smart UI Server, if necessary select the required one; if you already have an OLEDB Datasource for your AlarmManagement agent SQL Server database, select the name of this datasource from the list box or click the New button to create this OLEDB datasource. For details, see Creating a new OLEDB datasource.

Tip: The advantage of this method is that you do not have to explicitly create the OLEDB datasource first, you can do this during the configuration process.

In this case, you can use the Historical Data Update Settings section of the DataSource tab of the relevant configuration dialog and/or the Refresh Mode list box provided by the tasks menu to select the following methods for this control to refresh the grid with more recent alarms:

  • Manual Refresh Mode (the default) in this case the user needs to manually click the Manual Refresh tool at runtime to update the grid with more recent alarms.
  • Auto Refresh Mode, specify the required Auto Refresh Interval in Minutes, to update the grid by refreshing the grid with new data at this specified interval, however users can still click the Manual Refresh tool.

 

However, you can also manually drag the Adr_AM_HistoricalIncidents table from the OLEDB datasource (that connects to your Adroit Alarm Management SQL database) onto the AdroitHistoricalAlarmViewer control, and then select To Control Property... > AdroitHistoricalAlarmViewer control > DataSource.

Then click Finish in the displayed Filter DataSet configuration dialog.

Note: This method requires you to explicitly create the OLEDB datasource that connects to your Adroit Alarm Management SQL database and DISABLES the Server and OLEDB Datasource fields in the DataSource tab of the relevant configuration dialogs.

In this case, subscription updates are used by this control to refresh the grid with new data.

The advantage of subscription updates is that as an alarm is added to the Historical Incidents table it is immediately displayed by this control.

However, the PROBLEM with subscription updates is that if you are busy configuring this control to search or filter it and a new alarm is added to the grid then the entire contents of this control will automatically refresh itself, which will LOSE ANY CONFIGURATION made since the last save in design time and at runtime it will ALWAYS cause this configuration to be lost!

For this reason the initial setting is set to Ignore, which ignores all subscription updates.

In this case, you can use the Historical Data Update Settings section of the DataSource tab of the relevant configuration dialog and/or the Subscription Update Mode list box provided by the tasks menu to select the other subscription updating methods:

  • When set to Prompt, then the control displays a confirmation dialog, to allow you to choose if you want to receive the update or not - this is useful when configuring the control, if you choose No then you can continue configuring and if Yes then it will update the entire control with the latest data.
  • When set to Auto, then whenever a historical alarm is added to the table then it will be added to this control, refreshing the entire contents of the grid in the process.

Therefore, this setting should only be enabled is your operators will not be creating filters and searching and it is imperative that it displays the latest alarms as soon as they are added to the Historical Incidents table.

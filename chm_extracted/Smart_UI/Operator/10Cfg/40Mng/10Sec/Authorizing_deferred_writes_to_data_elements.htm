Authorizing deferred writes to data elements

This is only required when:

  • you have changed a data element, whose data element security settings require authorization and
  • you are unable to have this data element write authorized, on the spot, in the Authorize Data Element Writes dialog.

In this case click the Defer button of this dialog to add this write to the list of deferred writes, so that it can be authorized later.

This list of deferred writes:

  • is not persisted (saved) so any changes to values that are waiting for deferred authorization are lost, if there is a power failure or the Smart UI Server computer is shut down.
  • is automatically maintained on a most recent change basis so that “old” changes are removed when a newer change is entered. Therefore, only the last (newest) change made to each value will be authorized.

Currently the System Information project, provides the sample Authorize Deferred Writes graphic form (in the Data Element Authorization folder), to obtain a list of the currently deferred changes made to data elements, so that these can be authorized by the applicable user.

The authorizing user:

  • needs to be an allowed user (or a member of an allowed user group) of the Smart UI Server
  • requires write access to a data element to authorize its change in value.
  • CANNOT be the initiating user (the user who made the change)

If necessary, click the Refresh button to populate the list with all the currently deferred data element writes (changes to values).

Select which value change/s you want to authorize in the list.

Specify the User Name and Password and, if required a Comment , typically the justification for granting the requested change/s.

Click the Authorize button.

Note1: Only the last change made to the value is authorized, when more than one deferred change is made or requested for the same value (data element),

Note2: Any data elements that the authorizing user does NOT have write access to will remain in this list.

Repeat this as often as needed.

In future versions, deferred authorizations will also be performed by a control.

For details on configuring the authorizing of value changes, see Configuring the auditing and/or authorizing of value changes.

Implementing SNMPManager Agents

Each SNMPManager agent can manage a single device, by getting, setting and/or trapping its OID values.

PLEASE NOTE: It is very important to set up Windows firewall, or any other similar network security product, correctly to allow SNMP traffic. Failing to do this will result in the inoperability of the SNMPManager agent. For further details on the requirements and guidelines regarding the use of this agent, see Usage Requirements.

To implement SNMPManager agents to monitor a physical industrial network:

  1. Before setting up the SNMPManager agent, decide which devices you need to monitor. In other words determine the (SNMP) network topology.

Tip: It is recommended to create a mimic to visualize the network, because this also assists in quickly detecting of the source of network bottlenecks too.

It is recommended to create a mimic to visualize the (SNMP) network topology, not only because it helps in deciding which devices are going to be monitored but more importantly, because the source of bottlenecks can then easily be detected on such a mimic.

Consider the example mimic below, where the different lights indicate whether a computer is deemed ‘healthy’ in terms of its bandwidth use or not. For instance a red light might indicate high bandwidth usage on a certain computer running an important network-driven process.

  1. In the case of the network described by this mimic, it would be necessary to configure seven SNMPManager agents on the computer running the Agent Server.

In other words one SNMPManager agent is required for each networked device that you need to manage. For details of the issues concerning the monitoring of computers by SNMP, see Usage Requirements.

Note: Each networked device must have its own fixed IP Address.

  1. Configure each of these SNMPManager agents to get and/or set the required OID values of their devices. For details, see Configuring SNMPManager Agents.

Note: In addition to browsing the device for its SNMP objects, the SNMPManager agent also provides a collection of commonly used statistics for device management, known as General objects. For details, see Selecting General SNMP Objects.

Some of these statistics are calculated from two or more OIDs, which are common to all devices. For instance, in this example, the ‘Bandwidth’,‘Unicast Packets/s’ and ‘Errors/Min’ are all examples of such calculated statistics.

  1. Once the monitoring process has begun, the SNMPManager agent will start:
  2. Polling : to receive values from the device and copy them into the associated tags.

Which you can then trend, alarm or log in Adroit: For instance, it is possible to trend object information such as bandwidth; alarm certain conditions on the network, such a computer becoming unavailable and log information, which allows you to determine at which point in history an error or certain condition of the network has occurred, such as its degree of congestion etc.

  • Writing: to change values of the device when the value of their associated tags change.
  • Trapping: to receive events from the device, which are placed in a queue that you will typically interrogate by means of a script and respond to the important ones.

Tip: If an SNMP trap identifies an OID that is not in the list then you can manually poll and/or manually write to it too.

Advanced Scanning Settings

Launch the Adroit SmartUI Config.

  1. Click Agent Server Configuration in the right hand pane.
  2. Click Driver Configuration in the right hand pane.
  3. Click the Advanced Driver Options button in the bottom right of this page.

This replaces the Installed Drivers and Devices list with the Advanced driver options list, which allows the following commonly used global settings that affect scanning, to be added or modified:

  • Demand scanning enabled: checkbox, which is enabled by default, to allow any NASAThis stands for New Adroit Scanning Architecture and describes a sub-class of protocol drivers that are specifically written to take advantage of the scanning improvements and enhancements provided by NASA, such as demand scanning and highly optimized scan tasks. protocol driver to provide demand scanning. For more details, see Demand Scanning.
  • Halt agent server on startup if device/s fail to load: By default this is disabled.
  • Mark tags bad if device agent stopped: If this checkbox is cleared then Adroit will NOT gray scanned tags once their device has stopped. This is enabled by default.
  • Allow changes in scan-inhibit and output-enable to affect tags immediately: If this checkbox is ticked, then the scanning sub-system will create an extra subscription to each tag that is being scanned to detect changes made to their output-enable and scan-inhibit statuses, so that they take affect immediately.

Note: For details concerning the scanning strategy in which this setting can be used, see Read Only Scanning Strategy.

By default, when this checkbox is cleared, the scan-point must be re-added or the device re-started for the scanning sub system to detect a status (output-enable or scan-inhibit) bit change.

This setting will also allow "read only" scanned tags to display the correct values if the values are manipulated from within the Agent Server or from a mimic.

However, this is not generally a problem because "read only" scanned tags should not normally be configured with operator actions that allow their values to be changed unless they are configured to be output enabled i.e. to be read/write scanned tags.

PLEASE NOTE: Turning on this setting will increase the number of subscriptions (1 for each scanned tag) within the server, this will have a small effect on device stopping and starting times because each subscription, for tags scanned by a device, is destroyed when stopping the device and recreated when starting the device.

  1. Text agents convert bit strings into status bits: If this checkbox is ticked, then a Text agent will convert a string of up to 16 1's and 0's into the corresponding status bits (16 thru 32). By default this is cleared.

Note: This setting will affect all the Text agents in the system.

PLEASE NOTE: The following marshalling functionality of the Multistate agent has been superceded by the Marshal agent, which is specifically designed to do this task and is more powerful and easier to use.

  1. Multistate agent status bits 16-31 are equal to the rawValue slot: Tick this checkbox, if you intend using some of your Multistate agents as marshalling agents. Then any Multistate agent that does not have states defined, will result in its value slot and status bits reflecting the rawValue slot directly and its states will NOT be processed. By default this is cleared.

  2. Multistate bits are reversed: Tick this checkbox, if you are using your Multistate agents as marshalling agents and are using large endian ordering when scanning its I/O to the PLC.

    This reverses the rawValue slot and places this value into the value slot of the agent. By default this is cleared.

Note: This setting will affect all the Multistate agents in the system.

  1. Outputs are sent before values are read on device start: Tick this checkbox, to enable the resending of the Adroit value to the front-end device when a tag that is output enabled receives a value from the front-end device that is different from the value currently in Adroit. By default this is cleared.

Note1: This setting ONLY has effect if the tag’s scan inhibit bit is on.

Note2: For details of the scanning strategy, in which this setting should be used, see Agent Server Master Write Scanning Strategy or for further details on combining the various scanning settings, see The Effect of Combining Scanning Settings.

  1. Check for Comm port availability: Tick this checkbox to allow the device configuration dialog to check the availability of each COM port. Each ports’ availability is represented in the port selection box, by a green icon if available and a red icon if unavailable.

But when you are connecting to virtual ports, such as MOXA, you should DISABLE this setting, because if these virtual ports are unavailable it takes a LONG time to determine this, which delays the loading of the device configuration dialog.

  1. Interval (ms) between starting any 2 devices during Agent Server startup: When the Agent Server starts up, all the devices are started one at a time with a 2 second delay between each device.

    If a huge amount of traffic is generated during this time, secondary failures can be caused in the scanning subsystem. If so, change this delay, it is recommended to set this value to 5000 ms instead of its default setting of 2000 ms.

Note: This value can also be set to 1000 ms to speed up the starting of devices if you are happy that the system can handle it.

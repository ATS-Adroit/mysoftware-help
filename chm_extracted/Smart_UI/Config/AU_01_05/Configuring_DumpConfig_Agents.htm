Configuring DumpConfig Agents

You can configure a DumpConfig agent to specify which agents' configurations you want to save to the OLE DB database and at what time or events their configurations should be saved, as follows:

If necessary, open the Edit DumpConfig Agent dialog, as follows:

  1. If necessary, add an DumpConfig agent. For details, see To Add a New Agent.

    Note: You can only add ONE DumpConfig agent.

  2. Select the name of this agent. For details, see To Select an Agent.
  3. Right click and select the Edit... menu item to display the Edit DumpConfig Agent dialog.

 

Specify which agents' configurations you want to save to the OLE DB database, as follows:

  • Click the plus (+) button to add a row to the Agent type configuration table.
  • Type in the name of the required Agent Type, ensuring that you spell this name correctly.

  • By default all the Agent slots of the specified agent type are included in each configuration that is saved to the database (*), although you can specify a comma delimited list of slots to explicitly specify the slots that you are interested to reduce the size of each configuration.

    When using the * to specify all the agent slots, you can also specify a comma delimited list of the header slots that you also want to save, in the following format: *,agentName.headerSlot1,agentName.headerSlot2, agentName.headerSlot3 etc.

  • By default configurations for all the Agent instances of the specified agent type are saved to the database (*), although you can specify a comma delimited list of only those agent instances that you are interested to further reduce the amount of logged data and therefore the time taken to log this data.

IMPORTANT: The optional comma delimited list of Agent slots or Agent instances for the specified Agent type cannot exceed 79 characters!

 

Specify what time interval or which event will cause the specified agent configurations to be dumped to the database, as follows:

  • If necessary, specify the required Dump interval (in hours, 0 to disable). If this is set to a number greater than 0, then this number specifies the hourly interval that will be used to trigger this agent to dump the specified agent configurations to the database but if set to 0 this disables this method of triggering this agent.
  • And/or specify the required Dump trigger tag by typing or browsing in the required tag (agent.slot) with a Boolean, integer or real value so that whenever the value of this slot changes to a non-zero value, the specified agent configurations are dumped to the database.
  • Alternatively, you can manually dump the specified configurations to the database by clicking the Dump now button.

 

Specify which OLE DB database you want to save the specified agent configurations to, as follows:

Type or browse in the connection details of the required OLE DB database in the Connection string field.

Typically use an existing (or create) a SQL database to dump your agent configurations to.

Note: In this case, if you need to configure this DumpConfig agent from remote computers, it is safer to use SQL authentication (Use a specific user name and password) when creating this connection and NOT Windows authentication (Use Windows NT Integrated Security) unless you are sure that the logged on users at the remote computers have the necessary access rights to this SQL database. More details:

If the SQL connection string configured in the DumpConfig agent has been configured using Windows authentication and you then try and connect from a remote UI to configure, it will more than likely not work (in other words the agent configurations will not be dumped to the database).

This would happen if the Windows User on this remote computer has not been given access rights to the SQL database.

Click the browse button to the right of this field and use the Data Link Properties dialog to create the required connection string to your SQL Server database, as follows:

IMPORTANT: If the computer on which SQL was installed was renamed, then SQL may need to be re-installed. More details:

If the computer is renamed AFTER installing SQL, then SQL must be re-installed, in order to function.

Do the following check:

  • Run the following T-SQL script in SQL Server Management Studio: SELECT @@SERVERNAME
  • If the result is different to the actual name of the computer, then the name of the computer has been changed AFTER SQL Server was installed, so you need to reinstall SQL.

This Data Link Properties dialog specifies the location and the security credentials required to connect to this database.

Note: If you need to configure or view this database and its data from other computers, like remote User Interfaces, then use a UNCUniversal Naming Convention (UNC) is used to specify the location of servers, printers, files and other shared resources on a local area network (LAN). UNC names begin with \\ (two backslashes) and take the form: \\Computer_name\Share_name path and not a local file paththis path, as opposed to a UNC path, can ONLY be accessed from the computer that it refers to, this path adopts the following general format: <driveletter>:\directories\filename.to specify the location of this database.

  1. Double click the Microsoft OLE DB Provider for SQL Server item in the Provider tab of the Data Link Properties dialog.
  2. Either type in the computer name of the SQL Server that you want to connect to, in the Select or enter a server name field.

Tip: This is the fastest method, if you know the name of the SQL Server.

  1. Or click the button to the left of the Select or enter a server name list box and select the name of the required SQL Server from the list.
  2. Specify the required security credentials to connect to this SQL Server, as follows:

IMPORTANT1: If you need to connect to a remote SQL database and want to run the Agent Server service using the Local System account, then use SQL Server Authentication.

IMPORTANT2: If you need to connect to a remote SQL database and want to Use Windows NT Integrated security, then ensure that the user profile that the Agent Server service uses to log onto the computer HAS the necessary rights to browse the network and connect to the remote database. This should NOT be the default Local System account.

  • Use Windows NT Integrated security: this option uses the username and password of the currently logged on Windows user.

Tip: We recommend that you configure your SQL Servers to use this option to avoid requiring additional database security.

  • SQL Server Authentication: this option uses the User name and Password configured within the SQL Server you are attempting to connect to.

Note: In this case it is recommended to check the Allow saving password checkbox.

  1. Select the name of the required database from the Select the database on the server list box.
  2. Click the Test Connection button to ensure that you are able to connect to this database using these details. Only proceed once 'Test connection succeeded' is displayed.
  3. Click the OK button.

Your connection string will be created.

Note1: The Advanced tab of this dialog allows you to specify access permissions for this connection string. If you are unsure about these settings NEVER set these permissions to Read otherwise this connection string will fail.

Note2: These security credentials are database specific and should not be confused with application security.

Note3: You can edit this string directly, once it has been created, if necessary.

 

Configurations will be dumped to tables named Adr_Dump_AgentTypeName in the specified database, for instance: Adr_Dump_Analog. The available agent slots that are saved to these tables depend upon whether table exists or not in the specified database, as follows:

  • If the Adr_Dump_xxxxx table does not exist it will be created with the specified Agent slots in the Agent type configuration table for this Agent type.
  • If the Adr_Dump_xxxxx table already exists then the configurations will be saved using the existing slots specified by this table, to allow users to manually remove columns of unwanted data from this table.

 

Lastly, ensure that the Enable checkbox (the enable slot) is checked, to start dumping the specified agent configurations to the selected database.

 

The status bits of this agent can be used for diagnosing the status of its connection to the database and/or the process of dumping agent configurations to this database. For details, see Specific Status Bits of the DumpConfig Agent.

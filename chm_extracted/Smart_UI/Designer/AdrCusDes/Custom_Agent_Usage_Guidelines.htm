Custom Agent Usage Guidelines

Since the introduction of the Custom agent a number of customers have put this agent to good use, which is what it is there for.

But as with all tools there is both a proper and improper way of using them and the method used directly affects the achievable results.

Therefore the following points or guidelines are recommended concerning the prudent use of this agent:

  1. If the Custom agent is used purely as a pure container agent i.e. no scripting attached, this should not cause any problems.

  2. When using large numbers of intelligent Custom agents (those containing scripts):

  3. Always monitor the virtual memory usage of the AS.EXE (Agent Server) process (from startup) during the design and commissioning phase - typically by using the Windows Performance Monitor.

    Since Adroit is a 32 bit application, if you have installed a 64 bit operating system then when you run the default Performance Monitor (PERFMON.EXE) all the counters for Adroit will be missing, because the 64 bit version of PERFMON is being run which can only load 64bit counter dlls! Therefore, in order to force Windows to load the 32 bit version of PERFMON, open the Command Prompt and specify the following statement: mmc /32 perfmon.msc

    As this KPI determines when you should convert your intelligent Custom agents into properly written C++ agents, as follows:

    For 32-bit operating systems, which allocate a maximum of 2 GB per process, when the virtual memory used by the AS.EXE process:

    • exceeds 1.0 GB then you SHOULD convert your intelligent Custom agents to C++ agents.
    • approaches 1.5 GB then you MUST convert your intelligent Custom agents to C++ agents.

    For 64-bit operating systems, which allocate a maximum of 4 GB per process, when the virtual memory used by the AS.EXE process:

    • exceeds 2.0 GB then you SHOULD convert your intelligent Custom agents to C++ agents.
    • approaches 3.0 GB then you MUST convert your intelligent Custom agents to C++ agents.

  4. Always monitor the CPU usage of the AS.EXE process.

    Natively, the AS.EXE process runs at about 1-2% CPU load, very rarely over 5%.

    If your custom agent configuration causes the CPU load to exceed 10-20%, then you should ALSO consider converting your intelligent Custom agents into properly written C++ agents.

  1. Ensure that the code used to create an intelligent Custom agent is optimised.

    Since EACH instance of this agent uses the SAME CODE to perform its functions. So when the code is poorly written, EVERY error is exacerbated, which can reduce the performance of the entire Adroit system.

  2. Custom agents normally have multiple slots scanned, which is no problem in itself. But please ensure that ONLY the required INDIVIDUAL slots are output enabled and NOT the ENTIRE Custom agent. Click for more details:

    Note: The scan dialog does this by default.

    Historically, users have simply output enabled the whole agent and this practice was acceptable because, typically, only one slot was scanned in the analog, digital or marshal agents.

    However, when an agent has multiple slots scanned AND is globally output enabled, any changes to ANY of this agent’s slot values will cause a write message to the scanning subsystem resulting in scan degradation.

    In the case of Custom agents the extent of this scanning degradation depends on the number of Custom agents being used and the level of activity on these agents.

Note: This rule also applies when configuring scan inhibit.

About Agent Servers

The Agent Server is the storage facility for all real time and historical data.

  • The real time data resides within intelligent objects, known as agents, which exchange messages with other agents or picture objects either from their local host computer or from remote computer nodes elsewhere on the network.
  • Historical data is written to disk where it is available for rapid retrieval and on-line analysis.

Note: Redundancy can be provided by configuring the Agent Server as a cluster server, which is a set of two Agent Servers running a replicated database. For details, see About Active Clustering and Important Points to consider when Clustering Agent Servers.

Agents are described as intelligent because they store live data as well as providing methods of manipulating that data. Agents can be both clients and servers at the same time, by operating on, and being operated upon, by other agents. For details, see About Agents.

The interaction of the agents with each other as well as with the Classic User Interface and its picture objects, provides a powerful and dynamic monitoring and control capability which reflects the status of your process in real-time. For further details, see What you can do in Adroit.

Agents are classified by function into a number of agent types, which can be used to implement a wide variety of system related, as well as application-specific tasks. For details, see About Agent Types.

Note: An instance of an agent type is usually referred to as an agent.

The Agent Server is therefore a collection or container of the supported agent types and stores and manages the instances of their created agents, in an agent database (.WGP) file. For further details regarding the storage of agents, see About Adroit Database Files (Agent Storage).

Note: The Agent Server is the only component in Adroit that needs to be licensed. For details, see Adroit Licensing.

Adroit OEMs, distributors, and even power end-users can create their own custom agent types programmatically by using the Adroit agent interface. However, it is also possible to use the Custom agent type and its associated Custom Agent Designer utility. For details, see How to Use the Custom Agent Designer.

Due to the way in which Adroit has been designed, there are no theoretical limits to the number of different agents that can be contained within an Agent Server.

In addition, multiple Agent Servers can be distributed across many physical computers, in a local or wide area network, by using the concept of a Project. For this reason, the total number of agents that can exist in an Adroit installation is effectively unlimited. For further details concerning Projects in Adroit, see About Adroit Projects.

Furthermore, because 32 bit Windows supports multi-threaded applications, Adroit Agent Servers can concurrently interact with as many client workstations as may be required. This feature is facilitated by Adroit agent level locking which ensures orderly access to any instance of an agent.

Adroit provides consistent mechanisms for creating and deleting agents, as well as efficient means of accessing information contained within them, making it easy to manage these agent collections. The Agent Server is typically configured by means of the Configurator dialog in the Classic UI or by means of the Project Explorer. For details, see Configuring the Agent Server or The Project Explorer.

Adroit Agent Servers, provide two basic methods of accessing the data within agents:

  1. The first allows a user to get a data value from or put a data value into an agent.
  2. The second allows a user to register as a subscriber to another agent, and then to be notified whenever the relevant value changes. These subscriptions make for significant reductions in processor load, since changing values will not be communicated to a subscriber until necessary.

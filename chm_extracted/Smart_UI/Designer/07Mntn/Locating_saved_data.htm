Locating saved data

The following topic describes how to locate all the data that is saved to disk:

Note: Each Configuration is completely separate or insular, containing its own files, application settings and/or registry keys. For details, see Working with Configurations.

Tip: The Adroit Config Editor provides a System Backup and Restore feature that can backup and restore your SmartUI and/or Adroit user-configuration. For details, see System Backup and Restore.

Server data files:

Note: It is necessary to backup all of this data to completely backup the Server. For details, see Backing up Server data.

  1. Server-specific configuration: This contains all the SmartUI Server configuration that only has meaning for this Server, such as its security configuration and the added datasources and their configuration.
  1. This data is saved to the ‘ServerData’ files. For details, see Saving data files.
  2. By default, these files are located in the Data subfolder of the Default configuration folder (typically C:\ProgramData\Adroit Technologies\Adroit\SmartUI\Configurations\Default\Data), although this location can be customised. For details, see Server directory settings.

Note: If these files are removed then all the security configuration and added datasources will be removed for this Server. However the profiles and projects may still exist.

  1. Profiles: This contains all the profiles created for this Server and their configuration, which is saved separately so that these profiles can be easily replicated to other Servers, if necessary. For details, see Locating saved profiles.
  1. Projects: Each project that is created is saved in separate folders, with the exact structure of the project being maintained, to easily locate your graphic forms, so that they can be backed up, copied and/or moved. For details, see Locating saved projects.  

 Client data files:

  1. Each Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. is also able to save or cache data that it requests from the SmartUI Server, however unlike the SmartUI Server this data does not need to be saved and is saved voluntarily to improve its response time from the Server.
  1. This data is saved to the ‘CACHE’ and 'CACHEINDEX' files.
  2. These files will always be located in the Caching sub-folder of the SmartUI ProgramData folder (typically C:\ProgramData\Adroit Technologies\Adroit\SmartUI\Caching), if the (Caching) DataElementCachingEnable setting is enabled (set to True) for the Client. For details on accessing this setting, see Advanced Designer settings or Advanced Operator settings as applicable. 
  3. Currently this only applies to graphic forms for SmartUI Operators. By default, if a graphic form that has already been requested from the SmartUI Server remains unchanged when it is opened again, then this graphic form is opened locally on the SmartUI Operator, which greatly improves the response time.

If you enable (set to ‘true’) the (Caching) DataElementCachingRetrieveRegardless setting, then the SmartUI Operator will ALWAYS load a cached graphic form from the local cache REGARDLESS of the subsequent changes that have been made to it, since the cache was last updated.

This greatly improves the user experience but requires the additional administrative overhead of ensuring that the local cache is updated to include any changes made to the graphic forms of the project/s that it displays. For details, see Updating cached graphic forms.

Note: This data cannot be used for backing up purposes.

Exported files:

  1. Graphic forms: In addition to being saved within a project, graphic forms can also be manually saved to disk for reuse in other projects. For details, see Exporting graphic forms and Importing graphic forms.

Note: Each saved graphic form, is entirely self-sufficient, containing all the data that it requires, such as spiders, levels and layers and translations.

When a graphic form is saved to disk, it adheres to the following file format:

ServerName.ProjectName.[Folder(s)Name(s)].GraphicFormName.VizData

For instance, [IAN] Server.MyProject.MyFolder.GFNO2.VizData

  1. Graphic elements: To speed up the process of creating a graphic form, it is possible to export graphical objects that have been created from one or more configured graphic elements for reuse in other graphic forms. For details, see Exporting and Importing graphic elements.

When one or more graphic elements are saved to disk, the file can have any file extension although typically a .XML file extension is used.

  1. Datasources: It is also possible to export the datasource and its configuration to a file to facilitate the replication of datasources from one Server to another. For details, see Exporting datasources and Importing datasources.

Each datasource that is saved to disk consists of two files, which have the same name as the selected datasource and the following extensions: .DSINFO and .DSINFOINDEX.

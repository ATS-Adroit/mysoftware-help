Backing up Server data

By default, the SmartUI Server backups ALL of the data that it saves, which includes the profiles, projects and the other data that it stores to guard against its possible corruption, accidental deletion etc.

Tip: The Adroit Config Editor provides a System Backup and Restore feature that can backup and restore your SmartUI and/or Adroit user-configuration. For details, see System Backup and Restore.

  1. For details on configuring this backup setting and also how long the backed up data should be stored before it is deleted, see Server saving and backup settings.
  2. These backups are stored in a subfolder called BACKUP, which is created in the folder in which the various data items have been configured to be saved. For details on specifying these storage locations, see Server directory settings.
  3. Each backup consists of two files, namely the FileName file, which depends on the type of data that is being backed up and the FileNameINDEX file, both of which have the current date and time appended to their names.

Backing up and Server performance

Normally backing up the Server data will not affect the performance of the Server, since this operation only briefly affects the CPU usage and the backup does not consume a large amount of the hard drive space.

However, the larger the data files become, the more carefully one should configure the frequency of these backups.

Restoring a Server data backup

When restoring a back up, both of these files, need to be copied to the parent folder and must be renamed so that the specified date and time is removed from their file names.

Then when the SmartUI Server is launched, it will obtain this data item from these files instead.

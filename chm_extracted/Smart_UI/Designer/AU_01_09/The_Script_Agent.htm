The Script Agent

The Script agent provides a way for the user to execute complicated tasks such as batching, reporting or complex mathematical operations through a Visual basic script or Java script.

IMPORTANT: If your Agent Server is running as a service and you create a script that needs access to protected network resources or that launch other Windows programs or perform any other function that requires a logged on user. Then ensure that the user profile that the Agent Server service uses to log onto the computer HAS the necessary rights to perform these functions. This should NOT be the default Local System account. See Configuring Agent Server Service User Profile. 

Note: This agent does not replace the expression agent, as the expression agent can execute simple calculations far more efficiently and faster than the Script agent.

Each Script agent can be configured to have an associated list of module files that contain user-defined variables, functions and subroutines. The Script agent allows the user to interact with the Agent Server, in order to access and manipulate data within the Agent Server.

A script is compiled after the Agent Server has started up or whenever the script agent is modified from within the Agent Configurator. The script agent executes a single subroutine, or "main" subroutine, in one of four different ways. For details, see Running the Main Subroutine.

PLEASE NOTE: There is no way for the Agent Server to protect itself from badly written or buggy scripts and Adroit Technologies does not take responsibility for badly written or buggy scripts written by users.

Users also have the ability to launch other applications, or manipulate other applications via OLE automation, for example to configure reports in Microsoft Excel or Microsoft Word. The Script agent may also be used as an alternative to using the Recipe agent and it can be used to perform simple scheduled tasks.

Note1: If you are using scripts to obtain datetime tags such as systeminfo.currenttime – the time is now returned as a local time, therefore NO time CONVERSIONS are REQUIRED.

Note2: An event is logged if a script is executed that contains compilation errors, preventing it from being run. However, this event could result in the event log from being flooded, therefore ensure that the event log is closely monitored and that any buggy scripts are either fixed or disabled ASAP!

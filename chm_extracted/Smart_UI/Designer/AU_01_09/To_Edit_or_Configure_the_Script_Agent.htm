To Edit or Configure the Script Agent

The Script agent.

NB Read through the usage guidelines of this agent first.

See Also: List of Script Functions (with usage examples).

  1. Edit an agent of type: Script.

The Edit Script Agent dialog box is displayed.

  1. Use the Select Language, list box, to choose the programming language, in which the script is written in. The two options are:
  2. VBScript: refers to the Microsoft Visual Basic scripting language, the default selection.
  3. JScript: refers to the Microsoft Java scripting language
  1. Leave Disable scripting. in its default unchecked state. If checked, then the script will not run when the Script agent is triggered.
  2. Check Eventlog errors, to enable the event logging of any script errors. Any compilation and run time errors will appear in the Adroit eventlog.

Note: An event is logged if a script is executed that contains compilation errors, preventing it from being run. However, this event could result in the event log from being flooded, therefore ensure that the event log is closely monitored and that any buggy scripts are either fixed or disabled ASAP!

  1. Use Modules to add, delete or edit the list of modules that constitute the script. Each module may contain variable declarations, subroutines and functions.
    If you use the Adroit search path you need only specify the module name.

Note1: When using a remote User Interface, modules can only be edited and their sub-routines selected, if the script files have been browsed in using the UNCUniversal Naming Convention (UNC) is used to specify the location of servers, printers, files and other shared resources on a local area network (LAN). UNC names begin with \\ (two backslashes) and take the form: \\Computer_name\Share_name file notation i.e. \\ComputerName\ShareName\scriptPath&FileName, otherwise it will use the path on the respective local drive of the remote computer, to locate the file.

Note2: If you are using scripts to obtain datetime tags such as systeminfo.currenttime – the time is now returned as a local time, therefore NO time CONVERSIONS are REQUIRED.

  1. Under Main subroutine: browse the name of the subroutine that will be executed (when the script is run), from the list of all the subroutines contained within the specified module files. Only input parameters (ByVal) may be passed to this subroutine. click in order to run the main subroutine immediately.

Note1: Input parameters must be comma delimited, text input parameters must be enclosed in double quotes e.g. "TextParameter" and tags may not be used as input parameters.

Note2: The name of this main subroutine CANNOT be the name of the Script agent.

  1. Specify how this "main" subroutine is to executed. For details, see Running the Main Subroutine.
  2. Click the Advanced… button, to display the Advanced Script Agent Properties dialog box, to specify a script initialization and /or cleanup subroutine.
  3. Click the Updatebutton, which updates the agent with the configuration changes. Usually this is done before clicking the Details… button.

Note: If script modules are unchanged and unedited they will NOT be recompiled UNLESS you click the Update button.

  1. The Details… button, displays the Details dialog box, which gives the status of the main subroutine, by showing any compilation or run time errors that occur.

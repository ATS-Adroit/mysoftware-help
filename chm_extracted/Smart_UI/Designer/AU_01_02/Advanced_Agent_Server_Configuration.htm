Advanced Agent Server Configuration

Using the Adroit Config Editor:

Launch the Adroit Config Editor.

Click Agent Server Configuration in the right hand pane.

Click Advanced Agent Server Configuration in the right hand pane.

This displays a page of grouped advanced Agent Server settings.

  1. Agent Server Parameters: settings affecting the configuration and saving of the Adroit database (.WGP) file and the location of the Adroit system folder.
  2. Distributed Event Routing: settings that allow you to route distributed error reports to a particular route number. For each event type: Connected, Connection lost, Tag not found, or Duplicate tagname, a route number may be specified. It is RECOMMENDED to NOT CONFIGURE these settings.
  1. WGP Versioning: settings that configure the automatic backup of WGP files and its versioning.
  • The Delete WGP backup files older than # days to and a maximum limit of # files edit boxes are used to configure the optional automatic backup of WGP files, for details, see Configuring Automatic WGP File Backups.

  • The Enable WGP version description entries checkbox, is used to enable or disable the appearance of the Save WGP file pop-up dialog when the WGP file is manually saved - so that a description of the changes made to it since its previous save can be entered.

    For details of this and the other versioning information saved to each WGP file, see Versioning WGP Files.

  1. Server Auditing: allows you to audit the Agent Server, in other words to log each Agent Server sessioneach time an application is started and stopped on a computer constitutes a single session of this program. and selected activities performed during these sessions to an OLE DB database. For details, see Agent Server Auditing.
  2. Debug Flags: settings used primarily by Adroit support engineers, for diagnosing system problems.

WARNING! Turning these on SLOWS the Agent Server down. For details, see Adroit About Debug Flags.

  1. Processor affinity: allows you to select which processors the Agent Server runs on simultaneously, for computers that have more than one physical processor, by checking the required checkboxes. By default ONLY the first processor is selected.

The following items are only provided by Adroit Config Editor:

  1. Event Logging: check the Enable logging of Agent Server system events checkbox, to enable the logging of such events as: when time-stamped data is rejected by a mimic for being to old etc.
  2. Agent Server Connectivity: From Adroit 10 Agent Servers allow clients to connect to them by using sockets over and above the legacy named pipes.
  3. Sockets give you better performance when a remote client (running on another computer) connects to an Agent Server.
  4. Named pipes gives you better performance when a local client (running on the same computer) connects to an Agent Server.

Therefore Adroit client software need to specify which of the following mechanisms they want to use when connecting to local and remote Agent Servers:

  1. Uncompressed Named Pipes (UNP) both locally and remotely: this is the legacy default.
  2. UNP locally, and Sockets (TCP) remotely: this provides the best performance for LAN/WAN applications and where network traffic needs to be controlled across switches etc.
  3. Compressed Named Pipes (CNP) both locally and remotely: this provides the best performance for LAN/WAN applications with restricted connectivity.
  4. TCP both locally and remotely: TCP is slower for local connections when compared to UNP.

IMPORTANT: Please ensure that all Adroit computers across your enterprise are configured for either named pipes or sockets, but not a mixture thereof!

  1. Legacy UI Parameters: When converting your existing Classic UI mimics and/or trends into SmartUI graphic forms, then check the Enable Xaml Saving checkbox.

    Note: You need to RESTART the Classic UI after changing this setting.

    This enables the “secondary” xaml saving functionality in the Classic UI. So when saving a mimic (with this setting enabled) in the Classic UI, you will be prompted to save the mimic as a .xaml file as well as a .mim file. This .xaml file is used to import this mimic document into the SmartUI.

    This also enables the “secondary” xml saving functionality in the Classic UI. So when saving a trend (with this setting enabled) in the Classic UI, you will be prompted to save the trend as a .xml file as well as a .trn file. This .xml file is used to import this trend document into the SmartUI.

Working with the SmartUI

The primary purpose of the SmartUI is to provide a web enabled, data visualization tool that is able to collaborate with data from a number of sources. 

The data can be accessed and manipulated from one or more local, LAN or Internet clients. The data can be secured at the data element level on a per user basis for read/write/no access. 

CAD type tools are provided for the design of graphic forms (mimics) that contain a mixture of vector drawing and windows components for visualizing and manipulated the data. 

Stand-alone operator environments then allow access to these graphic forms via a smart client application.

Overview of the SmartUI architecture:

The SmartUI consists of three main components:

  1. The Server: this is the "data portal" - it aggregates data from a number of disparate sources via "datasource plug-ins" which convert data from the outside world into a generic SmartUI format called a "data element". The Server also contains datasources designed to hold all user information and configured graphic forms.
  2. The Designer: this is used to configure datasources and data elements in the Server and allows for the design of graphic forms to visualise and interact with the data.
  3. The Operator: this is a “smart client”, which allows access to the configured graphic forms for the viewing and manipulation of data, over a LAN or over the Internet.

The Click Once Operator allows a user to use a fully fledged Operator, which is downloaded via Internet Explorer and runs normally, as a separate application.

The reasons for having two Client applications:

  • The Operator has been designed to be able to provide across the Web reporting
  • The future Win CE version of the Operator
  • Ability to combine both when designing

The real world problems that SmartUI solves:

  • It’s a real time data portal
  • Real time data over the Internet
  • Secure open client architecture (OEM extensibility)
  • Roaming user profiles
  • Internationalization (translation) of mimics
  • Full UI and Server scripting
  • Containment of ActiveX, .NET & 3rd-party controls in mimics
  • Web Service compatible - both as a consumer and provider

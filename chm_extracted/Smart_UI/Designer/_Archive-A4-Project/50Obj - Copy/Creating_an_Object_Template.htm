Creating or Editing an Object Template

When creating an object template typically use a wizard instance on a graphic form that you have already configured, which is working EXACTLY the way you want it to work and for which you have already configured the necessary SCADA configuration (the scanning logging and alarming etc.) and any other agents that this object needs configured.

IMPORTANT: You need to ensure that the required SCADA configuration of this wizard instance is EXACTLY what you require, since this will be copied exactly; in other words: garbage in = garbage out!

More details:

Tip: If you keep the SAME substitution names as those used in the wizard, this will make it easier to implement your instances, since you will only need to configure these substitutions ONCE, otherwise you will need to specify substitutions both during the SCADA Configuration and Graphical Substitution stages.

Then create a template from it, which incorporates the graphical components of the wizard (and any substitutions that it uses) along with SCADA configuration that you specify, from which you can create numerous instances each of which will create their own unique tags, which will be scanned, logged and/or alarmed, as specified by the template.

To create an object template:

Open a graphic form that contains an instance of a wizard for which the necessary SCADA configuration (the scanning logging and alarming etc.) and any other agents that this object needs has been created and is working well.

Right click this wizard instance in the Designer and select Create Object Template .

IMPORTANT: if you Cancel the configuration dialog then you will lose any configuration that you have done. However, you can use the Previous and Next buttons to navigate back and forward between the steps, which retains the current configuration of each step.

Step 1 of 12: Validate Wizard Data Elements

By default the Template Name is the name of the wizard that the selected wizard instance is an instance of, prefaced by "TPL_". This wizard is further described by the Path edit field of the Primary wizard tab, which displays the exact path to this wizard when the mouse hovers over its name and/or representation.

You can also specify a Template Descriptor, which is the last portion of the default deployed object name, that relates to the object itself and not its context. Typically, this is a standardised abbreviation for this object, such as PMP for pump, after which you typically need to provide the unique, detailed name for this object e.g. PMP_SUMP_01.

By default a number of predefined descriptors have been created for you. However you can add a custom descriptor:

To add a custom template descriptor: click the list button to the right of the Template Descriptor field and then click the Add new descriptor... button at the bottom of this dialog, in which case you need to specify their required Category and Description, in addition to the required Descriptor - so that they can be easily identified in this list of predefined descriptors.

The Wizard Data Elements table should contain the valid names of the specified data elements used for the substitutable values of this primary wizard, so no further configuration should be required.

This displays all the data elements from all the datasources that apply to the specified wizard, however only the Adroit-specific data elements will be processed, since the purpose of a template is to specify the necessary SCADA configuration for this primary wizard.

If necessary, click the Associated wizards tab to specify related wizards that use the SAME substitutable values as this primary wizard (or LESS of these substitutable values).

Note: Another wizard can ONLY be associated when it has the SAME or LESS substitutions as the Primary wizard.

Examples of valid Associated wizards:

  • if you have created different graphical orientations for the same item of equipment like a left or right or top or bottom view, which use the SAME substitutable values
  • if you have a simpler view of the primary wizard, in other words a wizard that uses LESS of the substitutable values

Click Next, once you are happy with the template name and have specified any associated wizards.

Step 2 of 12: Select Agents

By default the Agents tree displays the list of Adroit tags directly referenced by the wizard.

If an agent is used by (referenced within) another agent, such as an expression, these agents are added to the Related Agents list.

Note: Only DBLog agents that have been enabled will appear in this list, when they reference one of the selected agents.

Then the template designer needs to decide which of the agent relationships are required by the template, as these intra-agent relationships may become complex depending upon how nested they are. By default only the first level of agents are linked to by default.

This task is best suited to a user who has an in-depth knowledge of how their SCADA system (Agent Server) has been designed.

You may also need to manually add any agents not directly linked to the agents in this wizard, which are also required. Such as Script agents or an AlarmManagement agent etc, by clicking the Add agent button and selecting these agents. Any added agent, both existing or created at this time, is displayed in blue.

IMPORTANT: Currently the Object Model only supports the following agent types: alarm, alarmmanagement, alarmlist, analog, beeper, counter, dblog, digital, eventoutput, expression, icmp, integer, marshal, maxdemand, oee, pid, real, shift, snmpmgr, statistical, string, stringlist, text and timer.

Note: Do NOT include the agents used to directly alarm, log or scan the agent.

Tip: You can also create agents at this stage, if necessary.

Click Next, once all the relevant agents have been specified.

Step 3 of 12: Assign Agent Substitutions

This step is where you decide which portions of the agent name you want to be substitutable or which may need to be variable when creating instances of this object. So that they adhere to any tag naming conventions that are applicable.

Typically the substitutions for all the values used within the referenced wizard are listed here, prefixed by the Adroit datasource name.

Tip: If you keep the SAME substitution names as those used in the wizard, this will make it easier to implement your instances, since you will only need to configure these substitutions ONCE, otherwise you will need to specify substitutions both during the SCADA Configuration and Graphical Substitution stages.

Unless the substitution included the datasource name, in which case and for any manually added agents, the tag name is used instead and you need to manually add the required substitutions. You can also modify the existing substitutions at this point too, if needed.

IMPORTANT: Any tag that is NOT substituted will be referenced by ALL the instances of this template.

Note: Templates do not support the obtaining of tags from two different Adroit datasources - all the specified tags need to exist on the same Agent Server.

In this case, double click the row containing the required agent and then specify each required substitution within curly brackets {...} in the Substitutions dialog.

For instance, if there is a plant area code and an equipment code : {PlantAreaCode}_{EquipmentCode}.value

Alternatively you can use a single substitution for both the agent name and slot value, such as {AnalogTag}

Note: It is not possible to substitute the Adroit datasource name, however you can specify which Adroit datasource (Agent Server) you want to use when creating an instance of this template.

Tip: When you click the Remove Substitution(s) button, this removes all the specified substitutions of the current row (only if one has been selected) replacing these substitutions with the name of the specified agent.

Click Next, once all the relevant substitutions have been specified.

Step 4 of 12: Configure Slots

Typically each agent that is selected for use in this template, provides a filtered list of values (slots) that a user can configure.

Select the row containing an agent whose values (slots) you want to configure, which displays this filtered list in the Slots table below.

Note: Any agent used to scan, log or alarm this agent are NOT configured at this point, such as the DBLog agent.

However, since the purpose of the object template is to create specific objects to simplify the lives of your users, you need to decide how informed each of your users will be i.e. complex your objects need to be and therefore which of these values should be configured by selecting one of the following four configuration modes:

  • Agent Default (Not displayed): these values are pre-configued for this object and are hidden from your users.
  • User Default (Read-only): these values are pre-configued for this object and are also displayed for information purposes so that your users can still see them, even though they cannot edit them (like alarm limits or set points).
  • Editable with a default value: a recommended or suggested value is provided, which a user can change when adding an instance if they want to. This is the DEFAULT option.
  • Editable with NO default value: in this case users MUST specify these values when creating each instance.

Note: This ONLY applies to values are NOT of type String (since a blank string can be valid).

Click Next, once you have appropriately configured the slots of EACH agent referenced by this object.

Step 5 of 12: Configure Scanning

This step lists all the slots (values) of the selected agents that are being scanned and some of their commonly configured scanning settings, such as the device and the scan address in this device, along with the scan rate and deadband and the four scanning IO settings that affect how this value is scanned. For more details, see "IO Flags" on page 1.

Note: If you want to make changes to these scanning settings, then ensure that the Update all devices on edit checkbox is checked

Click Next, once you are happy with how each of these slots are being scanned.

Step 7 of 12: Data Logging Summary

This step lists all the slots (values) of the selected agents that are being datalogged and some of their commonly configured logging settings that affect how this value is being logged.

If necessary, you can modify one or more of these logging settings.

Click Next, once you are happy with how each of these slots are being logged.

Step 8 of 12: DBLogging Summary

This step allows you to configure each of the selected DBLog agents and view which of the slots of the other selected agents have been allocated to each DBLog agent.

Select the row containing the DBLog agent you want to configure in the DBLogs list, which displays the slots of the other selected agents in the Tags table below, for information purposes only.

Click Next, once you have appropriately configured the DBLog agents.

Step 10 of 12: Add Attributes

This step allows you to add one or more attributes or searchable strings or identifiers that you can use to filter or classify the objects that you create in the Context View window.

Each specified attribute will apply to all the object instances and requires both a Name and a Value.

Note: You cannot edit the Name once you create it, if you need to change it then delete this attribute and add it again.

In other words these provide user-friendly terms that can be used to identify this object, such as equipment Type, whose value is motor or valve etc. or perhaps the power specification, such as 'kWh' and then specify the required value for each object.

Step 11 of 12: Add Child Templates

This step allows you to define logical parent-child relationships between this template (the parent) and any other related object model templates (the children), for example, by adding a PLC template to a Plant Area template.

These template relationships are only defined and viewable in the SmartUI and only affects Adroit as to which tags and their configuration to create when this template is deployed.

IMPORTANT: Even though these child templates are deployed along with the parent template, you still need to separately drag them onto the required graphic forms in order to display them.

Note: You need to create your lower-level or commonly used object templates first as you can only select existing templates as child templates.

To add a template, simply click the Click here to add child template link and select the required template from the Templates list.

This template is added to the root User folder of the Templates folder of the Object Model datasource in the Datasources category of the Enterprise Manager.

Step 12 of 12: Run A Script

This step allows you to define a script for this Object Model Template, so that when deploying an instance users can run this script (only if it compiles successfully).

Note: Currently only the script defined for the template can be run. Therefore any scripts defined for child templates will be ignored, even if no script is defined for the parent template.

By default, the Include script in this template checkbox is unchecked.

If this option is checked, then click the Launch Script Editor button to launch the Script Editor with the default (sample) script.

Then edit and ideally compile this script and then close the Script Editor window to save this script.

Note: A warning is displayed when the current script has not been compiled yet or has not compile successfully (so in this case click the Launch Script Editor button to edit and compile the script).

However, this does not stop you from clicking the Finish button, but when an instance of this template is deployed it will NOT run this script (unless it has been edited in the interim to successfully compile).

When deploying an instance of a template, a new checkbox is provided called Run Script, which is unchecked by default and will be greyed out if a script was not specified or when the specified script does not successfully compile.

Click Finish, once you are happy with the configuration of this object template.

Tip: You can use the Previous and Next buttons to navigate back and forward between the steps, to edit any of the steps before clicking Finish.

Creating contextually sensitive object instances

Creating an object instance from a node in the Default context can be particularly useful when its name and substitutions use a predefined naming convention that specifies the context in which the instance is created.

Tip:  If you drag an existing Object Model template from the Enterprise Manager directly onto the applicable node, then you can skip the step where you need to specify the required template.

To make the best use of this feature, you need to:

  • Define the necessary hierarchy of Nodes, which typically represent each specific contextual area and specify each Node descriptor, typically a 3-character reference code for each contextual area.
  • For more information about naming details, see Configuring Node names and descriptors.
  • Define the process variable names if your object employs multiple substitutions. You should ensure that these substitutions are specified in the template and are in the logical order of the defined contextual areas.

When an object instance is created in a node, then each defined Node descriptor, up to the current level, are used to define its name and its substitutions, as follows:

  • The Map Descriptors to Substitutions dialog lets you do one of two things:
    1. Assign the Descriptor path, a string that assigns all the Node descriptors that are separated by 'underscore _' characters to a specific substitution.
    2. You can specify which Node Descriptor in the Descriptor path is used for each of these substitutions, if you have created multiple substitutions that are combined to specify the required contextual naming convention, such as {site}_{area}_{section}_....,
    • By default, this dialog immediately assumes that the first substitution maps to the first defined Node descriptor, and the second substitution maps to the second defined Node descriptor and so on, up to the current node level of the displayed object instance.
    • It is most useful when the order of the first substitutions matches the order of the Node Descriptors meaning no further configuration is required.
    • You can, however, manually select the required substitution values, if required.
    • Tip:  The Template Descriptor (if one was specified for this template) the last portion of the default deployed object name, that relates to the object itself and not its context, is also specified as an available option in this list.
    • Note:  This step is optional and can be skipped by clicking the Skip button at the bottom of this dialog.
  • In the Create New Instance dialog the default New instance name uses the Descriptor path, a string that specifies all the Node descriptors that are typically separated by '_' characters, and appends the Template Descriptor (if one was specified for this template) the last portion of the default deployed object name, that relates to the object itself and not its context.

Note:  Typically you will need to edit this default name to provide the unique, detailed name for this object.

For detailed steps to create an object instance, see Creating an Object Instance.

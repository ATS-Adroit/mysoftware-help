Properties tool window

This tool windowtool windows are dockable windows, which provide several arrangement options to increase the size of the Design workspace window used for designing graphic forms. displays and allows you to manually configure the properties and events exposed by the graphic form and/or its form componentsa general term encompassing all the controls, components and / or graphic elements that can be added to graphic forms, to provide the required user interface for its end-users. See control; component; graphic element; graphic form. that is currently opened and displayed in the Design workspace.

Note:  Each tool window is a dockable windowa window that can be either be attached to a docking area or that can float anywhere on the screen. See floating mode; docked mode; docking area. whose location can be customised to increase the viewing and editing space provided by the Design workspace.

For more information, see Arranging tool windows.

This tool window consists of the following features, which are listed in order from the top of this tool window to the bottom:

Note:This tool window only displays the properties of the currently selected graphic form or its form component(s).

Example:

  1. A list box appears at the top of this window, which lists each namespaceone or more names separated by periods (or dots), where each name represents an individual item and the entire namespace indicates the relationship or lineage of the leftmost term i.e. grandparent.parent.child. of the form components of the currently edited graphic form. This is provided as an alternate means of viewing and/or configuring their properties.

Note: The default entry of "[ ... ]" indicates that multiple form components are currently selected or that the currently selected component cannot be retrieved.

  1. This tool window provides a toolbar below the list box at the top of this tool window, which can be used to display the exposed properties or events of the selected item(s) and which also determine how these properties or events will be displayed, as follows:

Note1:Certain properties are always expandable or collapsible, when they contain more than one sub-parameter. Typically these sub-parameters are used when animating graphic forms. For details, see Animating graphic forms.

Note2:If more than one control, component and/or graphic form is currently selected, this will only expose the events of the last item selected, known as the primary controlwhen a group of controls are selected, the sizing handles of this control are white and its attributes will be used if this group of controls are formatted. See control.. For details, see Selecting multiple controls.

  1. Categorised: This groups the properties or events of the selected item(s) into a number of expandable and collapsible categories, each category representing an attribute of the selected item. The available categories depend upon which item(s) is currently selected, as follows:

Note1:Any properties or events that do not have a default category are placed into the Misc (miscellaneous) category.

Note2:When properties are listed in this display mode, they can be further classified according to the data types of each property, by selecting the Property by Type toolbar button.

Tip1:These categories can be expanded or collapsed to display or hide the relevant properties or events, by clicking the grey plus box or minus box to the left of the category name respectively.. 

Tip2:This display mode is recommended if you are unfamiliar with the item, whose properties or events you are configuring as this makes it easier for you to know which properties or events affect or belong to the required attribute of the selected item.

The categories that are displayed, differ for properties and events as follows:

  • Properties: Properties are listed in differing categories, depending on the selected item.
    1. Accessibility: properties that configure Windows Accessibility profiles, where supported.
    2. Appearance: properties that determine the display of the item e.g. colors, cursors, fonts etc.
    3. Behaviour: properties that manipulate the Behaviour of the control e.g. its visibility, enabled state etc.
    4. Data: properties that enable data binding for Database functionality.
    5. Design: properties that assist in the designing of the graphic form itself e.g. the drawing grids.
    1. Focus: this specifies the events that are raised when the control requires validation, focus being set, etc…
    2. Notes: this contains the property that designers can use to specify any extra information about the control, such as changes made etc.
    3. Layout: properties that determine the layout of the item e.g. size, position, docking, etc.
    4. Security: this contains the property that allows graphic form security to be applied to this control. For details, see Securing graphic forms.
    5. VizNET Extended: properties that provide additional information or more functionality, when designing graphic forms.

     

Note: Whenever a property requires the name of a data element, simply drag the required data element to this property and its name will be automatically extracted to specify this property at runtime.

  • Events: Events are always listed in the following categories, regardless of the selected item.
    1. Action: events produced through interaction from a user input device.
    2. Appearance: events related to the ‘look and feel’ of the item.
    3. Behaviour: events produced from environmental actions (system/regional/ settings).
    4. Data: events produced by the data related to the control or graphic form.
    5. Drag Drop: events produced by the mouse drag/drop functionality, this allows data transfer between controls/form on drag-drop events.
    6. Focus: events which are related to validation (usually on ‘lost focus’ event) of textboxes or combo boxes and other input fields.
    7. Key: events produced by the keyboard.
    8. Layout: events produced by movement and re-positioning of the control or graphic form.
    9. Mouse: events produced by mouse input i.e. its movement and the mouse button(s) being clicked etc.
    10. Property Changed: event produced when some, but not exclusively all properties are being set.
  1. Alphabetic: This displays the properties or events of the selected item(s) in an alphabetical listing, except for the parenthesized properties, which are added to the top of the property grid.

Note: Parenthesized properties provide extra information or more functionality when designing graphic forms. For instance the Security option provided to all controls on the graphic form, or when you add a tooltip component to the graphic form.

Tip: This display mode is recommended if you are familiar with the item, whose properties you are configuring as this makes it easier to locate the required properties by name.

  1. Properties: This displays the properties of the selected item(s) in the currently selected display mode, either Categorised or Alphabetic.
  2. Events: This displays the events of the selected item(s) in the currently selected mode, either Categorised or Alphabetic.
  3. Properties by Type: This can be used, when listing properties to further sort and classify the displayed properties according to the type of the individual properties. For instance, the Visible property has a Boolean type (true/false) and this will be grouped with all other Boolean property types.

Note: Properties by Type is only applied when the Categorised listing mode is selected.

  1. Beneath the properties or events list, is an information pane, which displays the name and if supported a brief description of the selected property or event. This is separated from the properties or events list by a splitter bar which can be used to adjust the relative size of this pane or to hide it altogether.

To access the Properties tool window:

  1. Click the Properties tab, which is on the right of the Designer application window, by default. For details, see Accessing tool windows.

Working with scripts

Scripts are usually created and edited in the SmartUI Designer using the generic Script Editor, however, users can also use Visual Studio 2010 (and later).

These scripts can either be written in Microsoft Visual Basic.NET or Microsoft C# (CSharp) scripting languages. Click for more details:

Both the default scripting and debugging environment and the default scripting language and other scripting settings are specified by the profile associated with the currently logged in user. For details, see Customizing default script editor or Customizing default scripting language.

Note1: Graphic form scripts can also be created and edited in the Graphic Form Script tool window. For details, see Graphic form scripting.

Note2: The onus rests upon the user to be familiar with these programming languages, since assistance with these languages is beyond the scope of this documentation. Articles related to scripting and converting scripts to the .NET Framework, are available on: http://msdn.microsoft.com; http://msdn.microsoft.com/netframework/ and http://www.codeproject.com.

Each script is seamlessly encapsulated in a script object, which provides the self-contained environment within which the script is run. For details on writing scripts, see Writing scripts.

For instance, the script object is responsible for managing the list of external assembliesformerly known as a dynamic linked libraries (.DLL files), which is externally compiled and contains a collection of properties or methods that can be implemented within a script. that are referenced by each script, so that their properties and methods etc. can be used within the script. For details, see Managing references.

The following three types of scripts can be implemented:

  1. Scripts that interact with and run on the SmartUI Server, these are added to the Script Server datasource. For details, see Script datasources.
  2. Scripts that interact with and run on the SmartUI Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. (the Designer / Operator), these are added to a Script Engine spider. For details, see Script Engine spiders.
  3. Scripts that run on the SmartUI Server, but which interact with the SmartUI Client (the Designer / Operator) these are added to the Script Server datasource and connected to the required Script Engine spider.

Note1: Scripts are able to interact with the SmartUI Server and/or the Client through INeed interfaces, which provide programmatic access to their various components. For details, see Working with INeed Interfaces or INeed interfaces object reference.

Note2: Running a script object from the SmartUI Server or a Client, should not affect its speed of execution. Typically, the script execution speed is dependent on the script source, the utilization of external references and correct programming techniques and other system-dependent factors such as CPU load etc.

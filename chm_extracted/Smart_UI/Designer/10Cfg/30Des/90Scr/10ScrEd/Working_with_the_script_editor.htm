Working with the Script Editor

Scripts are typically written within the scripting language and the script editor specified by the profile of the currently logged in user. Click for more information:

Only if this profile associated with the currently logged in user specifies the Built-in script editor, is the generic Script Editor displayed; otherwise Visual Studio 2010 or later will be used. For details on configuring this profile setting, see Customizing the default script editor.

Note: When debugging your scripts in Visual Studio, the scripts are exported to the ScriptsExport subfolder of the SmartUI ProgramData folder (typically C:\ProgramData\Adroit Technologies\Adroit\SmartUI\ScriptsExport) in a Visual Studio-compatible format.

The default language of the Script Editor is usually C# (CSharp), although it also supports Visual Basic.NET. For details on changing the scripting language, see Changing scripting languages in the Script Editor.

Note1: Profiles can be used to specify the default scripting language used when creating scripts in the Designer. For details, see Customizing default scripting language.

Note2: The Script Editor will not successfully compile your script unless it has been set to the correct language. The selected scripting language is saved in the script object of the script, so that it does not need to be selected again.

Note3: If the language has been changed, the default text of the script can also be changed to the new language too.

This script editor provides standard programming functionality, such as bookmarks, commenting lines of text, indenting lines of text, compiling the script, compiling and running the script etc.

Note: These commands can either be accessed from the toolbar, the menus or by right-clicking in the Editor workspace window.

The script editor consists of the following windows:

  1. Editor workspace: this is the main work area, which contains all the scripts that are currently open in the Script Editor.

    Only one script can be displayed and edited within this window at a time. Scripts are displayed by selecting its tab, at the top of this window.

Note1: Only the script indicated by the leftmost tab will be saved to the script object.

Note2: All the other windows are dockable tool windows, which can be arranged and interacted with in a similar fashion to the tool windows within the Designer application window itself. For details, see Working with tool windows.

  1. Solution Explorer: This displays a file-centric, physical view of your script and any referenced assemblies.

    This tree view will always display the name of the script object and beneath this its References, if any, will be displayed. For details on references, see Managing references.

  2. Class View: This displays a programmatic view of language elements within your script and any referenced assemblies, denoted by , for example, classes, methods, and functions.

Within each , the contents are shown in a hierarchical tree view, indicating the containment relationships between the language elements.

This logical view enables you to better understand the structure of the code and the interrelationships between its various language elements.

Each language element, within a script or assembly, is also represented by an icon. For details, see Available Language Element Icons.

Note1: This view is populated after the script has been compiled, with only the contents that are externally accessible. The script itself or a referenced assembly, is denoted by: 

Note2: Since the script is in memory this will always be seen as an “Unknown” assembly.

Note3: An icon is expandable if it contains other language elements.

  1. Output: This displays any errors that occur when compiling or running the selected script. If a compiler error is located, double-clicking on it, will open the script at the line that it occurs and highlight this error.

Note: Due to the nature of logic and runtime errors, it is not possible to predict where these occur, therefore the information that will be displayed may not be too helpful in locating the cause of the problem.

Close the Script Editor to choose whether to save changes made to the edited script object and its associated script, as follows: either click Yes to save the changes made to the script and script object or click No to lose the changes that have been made.

Note1: Once the Script Editor is displayed, you are unable to perform any other tasks in the SmartUI Designer, until the editor is closed.

Note2: You can only edit ONE script object in the Script Editor. Therefore while you can open additional script files, you can ONLY save changes made to their text and not their lists of references.

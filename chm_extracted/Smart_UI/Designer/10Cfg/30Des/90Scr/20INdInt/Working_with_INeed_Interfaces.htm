Working with INeed Interfaces

INeed interfaces are made available to scripts to provide them access to the various components of the SmartUI Server and/or the Clientrefers to either the Designer or the Operator, both of which are client applications of the Server.. Click for more information:

The INeed interfaces required by a script will depend upon whether it is required to interact with either the Server or the Client or both of them. For details of the exposed objects, see INeed interfaces object reference.

Note1: Each INeed interface has a required abstract virtual definition that if not present in the script, will cause a compiler error. These definitions are included in the default source code. For details, see Changing scripting languages.

Note2: These INeed interfaces are populated after the script has been successfully compiled, before the script is run.

Note3: The INeed interfaces will be added to, as necessary.

Client–specific INeed interfaces

Note: These INeed interfaces are specific to scripts used within Script Engine spiders. For details, see Script Engine spiders.

  1. INeedSpiderInfo: Provides the script access to any custom input or output variables e.g. var 1 etc. that have been added to the associated Script Engine spider. In this way the script is able to retrieve and/or alter these values as required.

  2. INeedGraphicObject: Provides the script access to the graphic form associated with its Script Engine spider, its graphic form components and their properties.

    In addition it also provides access to the spider workspace, associated with this graphic form, by means of the MyController.

    This exposes all the spiders that have been added to this spider workspace and the graphic form’s graphic form components, by name.

  3. INeedApplication: Provides the script access to the Client, by means of the IObjectManager, which allows the script to retrieve, alter and in some cases delete items, such as standard dialogs and environmental settings, associated with the Client.

    Scripts are also able to store temporary variables in the IObjectManager, so that they can be retrieved later from another script, if necessary.

    It is also possible to use the IObjectManager to store variables within the currently active profile, so that their values can be remembered between login sessions of users belonging to this profile. For details on profiles, see Working with profiles.

  4. INeedConnection: Provides the script access to the SmartUI Server through the Client, by means of an IConnection object.

    This object can be used to perform low-level communication with the Server, such as subscribing to data elements.

    Since this connection to the SmartUI Server is via the Client, all the security settings of the SmartUI Client are imposed upon this IConnection object too.

Server–specific INeed interfaces

Note: The INeedConnection above, is the only INeed interface currently implemented for scripts which interact with the SmartUI Server, and this ONLY provides access to data available to the SmartUI Server on which the script is executing.

About datasources and data elements

The SmartUI Server is a "data portal" which integrates data from a number of disparate sources.

Each source of data requires a datasource plugin before it can be associated with the SmartUI Server. This provides the ability to expose its data as data elements to the Server and, if necessary, provides special functions or methods to further interact with its data. Click for more details:

For instance, the OLEDB datasource plugin exposes data within OLEDB databases to the Server as data elements.

While the datasource plugin behaves as a datasource template, it is the datasource itself, which is the actual connection to each source of data wherever it is physically located.

By using its datasource plugin, the datasource is able to expose the connected data to the Server as data elements. It also provides any special functions so that users can further interact with this connected data.

For instance, an OLEDB datasource connects to an OLEDB database (e.g. Database1.mdb), by using the OLEDB datasource plugin to expose the tables and fields within this database as data elements to the Server.

A data element is essentially a finite component of data contained within a datasource that behaves in a generic manner.

In other words, although data elements may contain disparate data, they all possess generic attributes so that they can be similarly interacted and worked with.

For instance, a data element would be a specific field within an OLEDB datasource e.g. Database1.mdb.

Note1: In addition to making its data available as data elements, a datasource plugin may also or may only provide additional functionality for interacting with each datasource and/or its data, known as special functions.

Note2: Each data element contains a number of internal properties, one of which monitors the status of the veracity or accuracy of its data. If this is set to anything other than GOOD, then any controls that displays this data element in a graphic form will become disabled (greyed out). For details on associating data elements with controls, see Animating graphic forms.

Note3: Access to data elements and special functions need to be controlled separately for each datasource that is created. For details, see Working with data element security or Working with special function security.

Generally speaking, the SmartUI Server connects to data using two different types of datasources, which are distinguished by the relation of the data to the SmartUI Server, itself, as follows:

  1. External datasources that link to data from the outside world, for instance, the OLEDB datasource. For details, see Working with datasources.
  1. Internal datasources that link to Client-specific data managed by the Server.

The following is a list of some internal datasources and their data elements:

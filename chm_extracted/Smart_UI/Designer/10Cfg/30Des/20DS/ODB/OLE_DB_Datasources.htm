OLE DB datasources

An OLE DB datasource exposes the data contained within an OLE DB compliant database or data store. This data is contained within fields in one or more tables.

For a practical example of using Select queries one of which uses parameters, which are supplied by controls on a graphic form, see How to chart and/or report data from a database.

For an example of using a DataBinder to read and/or write data in a database to and/from a control on a graphic form, see How to write and or read database data from a control.

Click for more details:

OLE DB is an open standard for accessing data from a variety of sources — both relational and non-relational data including: mainframe and hierarchical databases; e-mail and file system stores; text and graphical data and custom business objects etc.

An OLE DB data or service provider is required, before a database or data store can become OLE DB compliant. This data provider ensures that the database shares its data in a uniform or consistent manner using OLE DB.

This datasource is added to and configured within the Datasources category of the required Server connection in the Enterprise Manager. For more details, see Adding OLE DB datasources.

Click for advanced OLE DB datasource usage information:

  • This datasource can be updated, locked or removed, if necessary. For details, see Updating datasources, Locking datasources or Removing datasources.
  • Instead of manually duplicating an OLE DB datasource from one Server to another, especially when many queries and/or stored procedures have been configured, it is possible to export and import the required datasource. For details, see Exporting datasources.
  • When connecting to a SQL database, the table, view, stored procedure and user function names support schemas. Click for more details:The default schema 'DBO' is NOT displayed. But if a table, view, procedure or function has a different schema name, then this is indicated in brackets after the name of the table, view, procedure or function. This means that you can now have a table, view, procedure or function with the same name as another table, view, procedure or function as long as it belongs to a different schema.

Note1: This datasource provides the following as its data elements: its tables, their fields and any queries which have been created.

Note2: Currently both the Client and Server computers need the required OLE DB data provider to be installed. Both computers also need access to the required data store in order to establish a connection to it.

Note3: If necessary, the access to this OLE DB datasource, its data and/or queries can be controlled. For details, see Securing datasources.

Note4: Each table is monitored at an individually configurable interval for new or updated data by the Server.

Note5:Queries can be executed, by using Special Function spiders. Also, if using SQL, please ensure that all time based queries adhere to the universal date time standard for SQL, which is yyyy-mm-dd. For details, see Executing queries and stored procedures.

An OLE DB datasource is identified in the Datasources category in the Enterprise Manager, which can be identified by its specified name or icon . When this datasource is opened, it displays the following main branches:

  1. Tables : contains all the data exposed by this data store, within its tables and their fields. Click for advanced usage information:
  1. The tables are listed alphanumerically, which specify all the tables which have been configured for this data store.

Note1: Only the tables with a plus box to their left actually contain fields.

Note2: The rate at which each table is monitored by the Server for new or updated data can be individually configured. For details, see Specifying the table polling interval.

Note3: Tables return their last 1000 records, by default, although you can adjust this number, see Specifying the maximum number of records to return for a table.

  1. The fields are listed alphanumerically beneath their applicable table.
  2. Fields which are configured as primary keys are indicated by the following icon: .
  1. DataBinders : allow your users to view and/or modify the data within your database. Click for advanced usage information:

For more details about how to use DataBinders, see About DataBinders.

  1. The DataBinders that have been configured are listed alphanumerically beneath the DataBinders folder.

Note1: The rate at which each DataBinder is monitored by the Server for new or updated data can be individually configured. For details, see Specifying the databinder polling interval.

Note2: Databinders return their last 1000 records, by default, although you can adjust this number, see Specifying the maximum number of records to return for a databinder.

  1. The tables and their fields are listed alphanumerically beneath their databinder .
  1. Queries : queries can also be created for this OLE DB datasource to perform common tasks for managing and/or obtaining data from your database. Click for advanced usage information:

For more details about creating and using queries, see About queries.

Note1: Queries can be queued so that they are not lost when the connection to their OLE DB database fails.

Note2: The data obtained by a query is not updated by the Server and remains as current as the last time that it was executed.

Note3: Queries display ALL the records that match the specified criteria.

  1. Views : contains any stored (pre-defined) queries in an Access and/or SQL database. These views can be used and interacted with in the same way as the listed Tables . For instance they can also be dragged onto DataGrid controls etc. Click for advanced usage information:

The applicable fields are listed alphanumerically beneath their associated view .

Note1: The rate at which each View is monitored by the Server for new or updated data can be individually configured. For details, see Specifying the view polling interval.

Note2: Views return their last 1000 records, by default, although you can adjust this number, see Specifying the maximum number of records to return for a view.

Note3: Views do not have primary keys.

Note4: If necessary, you can view the associated SQL Script, see Viewing the associated SQL Script.

  1. Procedures : lists the predefined stored procedures or user-functions of the database, which can be performed by using a Execute Statement query. Click for advanced usage information:

For details on how to run stored procedure , see Execute Statement queries.

Each stored procedure and/or user function display the following elements when expanded:

  • One or more input parameters : these provide the stored procedure/user-defined function with values.
  • One Output/Result parameter : these values are returned when the stored procedure/user-defined function is executed.

Note1: Currently these procedures can ONLY be viewed.

Note2: System stored procedures and functions are not displayed.

Note3: If necessary, you can view the associated SQL Script, see Viewing the associated SQL Script.

To display the connection details of an OLEDB datasource:

Right click the OLEDB datasource in the Enterprise Manager and select the Connection Details option.

Note: If the connection string for this OLEDB datasource contains a password, it is hidden in *'s for security reasons.

Tip: When editing an OLEDB datasource connection, the Data Link Properties dialog uses the previously supplied details, so you only need to specify the changed details NOT all of them.

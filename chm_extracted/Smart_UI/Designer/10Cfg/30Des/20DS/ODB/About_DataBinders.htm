About DataBinders

After connecting your database to an OLE DB datasource, you can add DataBinders to allow your users to view and/or modify the data within your database.

Each DataBinder can create a sub-set of your data to select only the data that meets a specific need.

In addition to selecting the required tables and their fields, you can also create relationships between the selected tables and/or add parameterised constraints and/or specify how the displayed data should be sorted.

Typically relationships are only defined within the database program itself. This facility is provided to allow you to comprehensively configure your data by ONLY using SmartUI. 

For an example of using a DataBinder to read and/or write data in a database to and/from a control on a graphic form, see How to write and or read database data from a control.

The main difference between a Select query and a DataBinder

Although this seems similar to the function performed by a Select query, the main difference between a query and DataBinder is that:

  • Select queries (and the queries in previous versions) only return static snapshots of the selected data that are only current at the time at which the query is performed.

  • DataBinders remain in constant communication with the database and so can provide a ‘live’ view of your data, if necessary.

    This makes it possible for DataBinders to modify the data within the database, so that instead of merely viewing the existing records, additional records can be added or existing records can be removed.

To access the data within a DataBinder, create a graphic form and add a VIZNETDataBinder component.

This launches a configuration dialog to select the required DataBinder and which of its tables and their fields to display on this graphic form.

The controls and components to view and/or modify the selected fields for each of the selected tables can be automatically generated and added to this graphic form.

Note: Please ensure that the DataBinder contains all the primary keyA primary key is one or more fields in the table of a database that uniquely identify each record stored in this, so they can locate records. Therefore, the primary key column/s must have unique values for each their rows. column/s for a table, if you require your users to add or remove records from this table.

These primary key column/s, however, do not need to be displayed on the graphic form.

More advanced users can:

  • Add additional controls to this graphic form and link them to the required database fields by binding the required BindingSource component to their DataBinding property.
  • Configure the DataBinder control to specify which controls will be used to provide the values of any parameters.
  • Configure the DataBinder control to specify the maximum number of records to be retrieved from the database.
  • Report the data within a DataBinder using a charting control. Typically one would use a Bar, Column or Pie charting control.

  • Configure the navigator controls to determine which functions are available to a specified user.

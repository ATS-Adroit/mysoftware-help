Adding DataBinders

After connecting your database to an OLE DB datasource, the DataBinders folder appears beneath this datasource in which DataBinders can be added. Click for more details:

Adding a DataBinder allows you to create or define a sub-set or selection of the data contained within your database, required to achieve a certain outcome or purpose.

Therefore, instead of your users wading through every record in your database, they can access a tailored set of records containing exactly the data they need to perform a particular task.

PLEASE NOTE: Databinders, themselves are unable to view or modify your data, they merely allow you to select the data (tables, views and fields) that they are to contain.

Each DataBinder requires an associated VIZNETDataBinder component on a graphic form to display and/or modify this data. For details see, Accessing data within DataBinders.

Note: To see if a specific DataBinder contains the required data, simply expand the required DataBinder in the Enterprise Manager to reveal its selected tables, views and their fields.

To add a DataBinder:

  1. In the Enterprise Manager expand the required OLE DB DataSource.
  2. Right click the DataBinders folder and select Add DataBinder.
  3. Specify the required DataBinder Name in the Add DataBinder configuration dialog:

    WARNING! Once a DataBinder has been named, it is NOT possible to rename it later.

    Note:The specified name cannot be the same as any other DataBinder that has been already been specified.

    Tip: Give this DataBinder a meaningful and concise name so that its purpose can be clearly identified. Try not to use all 50 characters.

  4. Click Next, once the name has been specified.
  5. Select the fields that this DataBinder should contain:

    Select the required Tables by clicking the checkbox next to each table’s name in the tree view. By default, this selects all the fields of the table, clear the checkboxes of the undesired fields.

    If necessary, expand the Views node and check the checkbox of each view and their field/s that you would like to be queried, by clicking on it.

    Note1: The default View includes all the specified fields.

    Note2: Selecting a table, view or field does not necessarily mean that it needs to be displayed.

    Note3: Each selected table or view has its own Select statement in the Select Statements (lower) list.

    The Preview button, provides as easy way to debug your DataBinder as you create it.

    Simply select the required view or table in Select Statements (lower) list before clicking this button.

    This returns all the records that the currently configured DataBinder will return for this table or view, in the pane at the bottom of the configuration dialog. In this way you can ensure that your DataBinder provides the required data.

It is important to select BOTH the fields that you want the DataBinder to display and those that are needed to configure the DataBinder.

So select the fields you want to use to create relationships between, define constraints for and use to sort the displayed results.

IMPORTANT: If you will require users to add or remove records or update data from a table then select all the primary key fields defined for this table.

Tip: The primary keyA primary key is one or more fields in the table of a database that uniquely identify each record stored in this, so they can locate records. Therefore, the primary key column/s must have unique values for each their rows. fields are highlighted in the table and field tree, so that they appear in brown unlike the other fields and table names that appear in black.

Note: If there are relationships between tables, select BOTH of the related tables to represent the relationship.

  1. Click Next, once the required tables, views and/or fields are selected.
  2. If necessary, add or remove relationships between the selected tables and/or views in the Table Relationships Setup dialog:

    In this case a relationship is simply a pair of selected fields, usually in different tables or views, whose values are required to be identical in order for a record to be returned.

    Tip: Select the required view or table in Select Statements (lower) list and press the Preview button to test your defined relationships, since an exception will be displayed if any of the data types of the related fields are NOT identical.

    To add a relationship:

    1. Click the Add Relationship button to create a relationship between two of the selected fields, as follows:

    2. Click the drop-down list box button at the right of each Field list and select the required field from both tables or views.

      This list only displays the fields selected in the previous dialog, in the following syntax: [Tablename].[Fieldname] or [Viewname].[Fieldname].

    To delete a relationship:

    Click the Delete Relationship button to remove the last relationship from the Relationships list.

    WARNING! This will ALWAYS delete the relationship at the bottom of the list, regardless of the currently selected item.

     

Note: These do not affect the relationships that you may have already created within your database.

Typically, you create relationships between tables in order to perform lookups on fields between different tables, such as between a primary key s of two tables.

  1. Click Next, once the required relationships have been defined.
  2. If necessary, add or remove constraints for the values of one or more of the selected fields in the Constraints dialog:

    To add a constraint:

    1. Specify the main View or the name of the table or view you want to constrain in the top list box.
    2. Click the Add Constraint button.
    3. If this constraint is NOT the first for the selected View or Table, specify how to relate this constraint to the previous constraints, as follows:
    4. AND: This is the default option, which makes this constraint mandatory. For instance, if there are two constraints with an AND between them, then the data will be restricted by BOTH constraints.
    5. OR: Use this option, to make the specified constraint optional. For instance, if there are two constraints with an OR between them then the data can be restricted with EITHER of these constraints.
    6. AND NOT: This makes the INVERSE of this constraint mandatory
    7. OR NOT: This makes the INVERSE of this constraint optional.
    1. Select the field, whose values you want to limit, from the Field drop-down list box.

    Note1: This list only displays the selected fields.

    Note2: Only if the main View is selected is the syntax for the fields [Tablename].[Fieldname] or [Viewname].[Fieldname] , otherwise this is simply [Fieldname].

    1. Select the method by which the values of this field are to be constrained or limited from the Constraint drop-down list box. For details, see Available constraint operators.
    2. Specify the constraining value or parameter in the Value field.

    Specify a value if your users will not need to change this criterion, otherwise specify a parameter if your users will need to change this criterion, for instance, if different users require different values. For details, see Adding parameters.

    Note1: If you use parameters, then you must add controls to the required graphic form so that your users can specify these values and link these controls to each parameter. For details, see Linking DataBinder parameters to controls.

    Note2: Ensure that the specified Value has the same data type as the specified Field, otherwise the DataBinder will not work.

    Tip: Click the Preview button to test your defined constraints, since an exception will be displayed if any of the data types of the related fields are NOT identical for the currently selected View or Table.

    When previewing constraints containing parameters, a dialog box will appear so that you can provide a temporary value for each of them.

    To delete a constraint:

    1. Specify the View or the name of the Table you want to constrain in the Select View/Table list box.
    2. Click the Delete Constraint button to remove the last constraint from the Constraints list.

    WARNING! This will ALWAYS delete the constraint at the bottom of the list, regardless of the currently selected item.

     

    As you define the constraint(s), the appropriate SQL query commands are added to the Select Command field, which cannot be edited.

Note: You need to constrain the View and each selected table separately.

Typically, you constrain or limit the values of a field to only return those records that you require. This is why it is a good idea to use parameters instead of hard-coded values since your users’ fields of interest may vary.

  1. Click Next, once the required constraints have been created.
  2. If necessary, define the sorting order of the resultant records in the Ordering dialog:

    To add a sorting order:

    1. Specify the main View or the name of the table or view you want to sort in the top list box.
    2. Click the Add Order button.
    3. Select the field, whose values you want to sort, from the Field drop-down list box.

    Note1: This list only displays the selected fields.

    Note2: If the main View is selected the syntax for the fields is [Tablename].[Fieldname] or [Viewname].[Fieldname], otherwise this is simply [Fieldname].

    1. Select the method by which the values of this field are to be sorted from the Constraint drop-down list box, as follows:
    2. ASC: The default value, which sorts the values of the specified field in ascending order. The method used to sort the values,depends on the data type of the specified field, as follows:
      1. String: This displays records beginning with non-text characters such as ‘_’ or ‘!”, then records from 0 to 9, then records from A to Z, with lowercase letters preceding uppercase letters e.g. for text like fgfd and Fgfd, the ASC order is fgfd and then Fgfd.
      2. Numeric: This displays records from 0 to 9.
      3. Date Time: This will display the records in this field from newest to oldest.

       

    3. DESC: This sorts the values of the specified field in descending order, which is the reverse of the ASC order.

     

    To delete a sorting order:

    1. Specify the required View or the name of the Table in the Select View/Table list box.
    2. Click the Delete Sort Order button to remove the last sort order from the Sort Orders list.

    WARNING! This will ALWAYS delete the sort order at the bottom of the list, regardless of the currently selected item.

    As you define the sort order(s), the appropriate SQL query commands are added to the Select Command field, which cannot be edited.

Note: You need to sort the View and each selected table separately.

Typically, you sort a view or table to ensure that the records are displayed in order of importance or relevance.

Although more than one field can be used to sort the data, the closer the field is to the top of the list, the greater the impact it has upon the sorting process.

Typically multiple fields are used to sort tables, when their entries are related – for instance can be used when sorting by surnames and then sorting by their first names. It may also be useful to sort by identity (ID) fields or by Country, when viewing a list of orders etc.

  1. Click Next, once the required sort orders have been set up.
  2. The Custom View dialog allows you to customise the main View that is created for this databinder. Only check the Use Custom View checkbox, if you do not want the default main View and have the SQL know-how to create your own customised view in the SQL editor.

When creating a customised view, parameters can be added so that their requirements can be specified before the main View is displayed. For details on specifying and using parameters, see Adding parameters.

Note1: The Preview button, provides as easy way to debug your main View as you manually edit it.

Clicking this button will return all the fields, in the pane at the bottom of the configuration dialog, that the current main View would return. In this way you can ensure that your main View returns what you want it to.

Note2: When previewing a main View containing parameters, a dialog box will be displayed for each parameter, allowing you to provide a temporary value for them.

  1. Click Next, if you do not require a custom main View or have finished creating it.
  2. The Final Select Commands dialog allows you to preview the Views and Table/s that you have created to ensure that you are happy with their results and if not to alter them as required.
    1. Select the required View or Table in the Select Commands list.
    2. Click the Preview button.
    3. If the selected View or Table contains parameterised constraints, a dialog box will appear so that you can provide a temporary value for each of them.

    This displays the records that comply with the configured relationships, constraints and/or sorting orders in the pane at the bottom of the configuration dialog.

    Note: If the required records are not displayed or an error is returned, then press the Previous button to locate the required page to rectify this problem.

Only click the Finish button when you are satisfied that the View and or Table/s return the correct data.

Note: Once you click the Finish button the configuration dialog ends and you will need to edit this DataBinder manually in order make any further changes.

Tip: The rate at which each DataBinder is monitored by the Server for new or updated data can be individually configured. For details, see Specifying the databinder polling interval.

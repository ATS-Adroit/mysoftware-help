Utilizing data with VIZNETBindingNavigator controls

If you selected the Create Controls option, when linking a VIZNETDataBinder component to the required DataBinder, then each displayed table or View has a VIZNETBindingNavigator control and other controls that display the values of the selected fields.

The VIZNETBindingNavigator control provides a toolbar of commands that allow users to interact with its associated table or View. Click for more details:

Note: By default the VIZNETBindingNavigator control displays all the available commands, although unnecessary commands can be hidden, if required.

Note: If you did not select the Create Controls option, then you need to create controls that provide this functionality for your users.

PLEASE NOTE: All changes made to a table (records that are added, edited or deleted) can ONLY be reversed by pressing the Undo All Changes button BEFORE the Update Changes button is pressed. This is because you do not working directly on the database itself, but on records that are retrieved from the database. Therefore, It is only when the Update Changes button is pressed that the actual data in the database is updated

This toolbar allows you to do the following:

To initially obtain the records from the table or View to populate the associated controls:

Typically when the graphic form opens all the controls associated with a specific table or view are empty, such as the TextBoxes and DataGridViews. In this case, press the Load Data button to retrieve the first page of records from the associated table or View.

This will also cause the count to specify the number of records that are retrieved.

Note1: The MaxRecords property of the associated VIZNETDataBinder component, determines how many records are retrieved.

Note2: If the AutoLoad property of the associated VIZNETDataBinder component is set to True, then this button is not required, as the data is automatically fetched when the graphic form is displayed.

PLEASE NOTE: If a relationship exists between two tables, so that another table’s column also appears in the DataGridView control associated with the current table, then you need to load the data of the related table first.

To navigate the required record of this table or View:

Note: This requires the data for the associated table or View to be initially retrieved (Load Data button).

This toolbar allows you to move to the records on the boundaries of the following three ranges:

The currently displayed Record:

Note: The Current Position field specifies the number of this record, if this field is displayed.

The Move to Previous Record button displays the record before the current record, if possible.

The Move to Next Record button displays the record after the current record, if possible.

Note1: If the current record is the last record in the page, then a delay may occur as the next page of records are retrieved from the database.

Note2: The number of records that are fetched at a time are specified by the MaxRecords property of the associated VIZNETDataBinder component.

The Page, which is all the retrieved records of the table or View:

Note: The “page” that is referred to are ALL the retrieved records and NOT the individual pages of records that are retrieved when a user specifies a record that exceeds the MaxRecords property of the associated VIZNETDataBinder component. 

The Move to First Record in Page button displays the first record retrieved from the database.

The Move to Last Record in Page button displays the last record retrieved from the database.

Tip: When used in conjunction with the Move to Next Record button, this will obtain the next page of records.

The Database, which is all the records within this table or View:

The Move to First Record in Database button displays the first record retrieved from the database.

Tip: This will always display the same record as the Move to First Record in Page XXX button.

The Move to Last Record in Database button displays the last record retrieved from the database.

Note1: The Total Number of Items (Records) XXX field specifies the number of this record, if this field is displayed.

Note2: You may experience a lengthy delay when using this method, especially if there are a large number of records in the database and the database is accessed over the Internet.

 

Note: These are listed in order of increasing scope.

To locate a specific record within this table or View:

Note: This requires the data for the associated table or View to be initially retrieved (Load Data button).

  1. Specify the column that contains the data that you want to find in the Lookup drop-down list box.

Note: The Lookup drop-down list box lists all the column names of the associated table or View.

  1. If necessary, specify what the required record/s should contain in the Filter edit box.

Note: By default the Filter is a LIKE filter for STRING data - returning all the records containing the specified string. Use the Custom Filter button to create your own filtering criteria.

Tip: If Filter is blank then all the records in this column are returned.

  1. Locate the required record in the Find drop-down list, which contains all the records of the column specified by the Lookup that match the specified Filter criterion, if one was specified.
  2. The Find Next button finds successive records that match the predefined Filter in the Lookup column.

To specify a custom Filter:

Filters help you to refine your results by only displaying the records that match specific criteria.

By default the Filter provided by the toolbar, is a LIKE filter for STRING data that returns all records containing the specified string.

To specify another filter:

  1. Click the Custom Filter button.

This launches the Custom Filter configuration dialog, so that you can define the required filtering constraints, as follows:

  1. Check the Use Custom Filter checkbox.

Note: Unchecking the Use Custom Filter checkbox uses the default (LIKE) filtering.

  1. Click the Add Filter button.
  2. If this filtering constraint is NOT the first, specify how to relate this constraint to the previous constraints, as follows:
  • AND: This is the default option, which makes this constraint mandatory. For instance, if there are two constraints with an AND between them, then the data will be restricted by BOTH constraints.
  • OR: Use this option, to make the specified constraint optional. For instance, if there are two constraints with an OR between them then the data can be restricted with EITHER of these constraints.
  • AND NOT: This makes the INVERSE of this constraint mandatory
  • OR NOT: This makes the INVERSE of this constraint optional.
  1. Select the field, whose values you want to limit, from the Field drop-down list box.

Note: This list only displays the fields displayed by the VIZNETBindingNavigator control.

  1. Select the method by which the values of this field are to be constrained or limited from the Constraint drop-down list box. For details, see Available constraint operators.
  2. Specify the constraining value in the Value/Expression field.

Note1: Ensure that the specified Value has the same data type as the specified Field.

Note2: You can also type in the SQL expressions (SQL functions and operators and fields), such as GETDATE().

To add a record to the associated table:

Note: This requires the data for the associated table or View to be initially retrieved (Load Data button).

Note: This can only be performed on a table and not a View.

Note: The DataBinder MUST contain all the primary key column/s for this table, before your users can add records from this table. These primary key column/s, however, do not need to be displayed on the graphic form.

  1. Click the Add New Record button.
  2. If a DataGridView control is associated with this table, then a new row is added to the bottom of this control.
  3. If selected fields of this table are displayed in separate controls, then these become blank so that new data can be entered into them.

WARNING! You can only undo (remove) added records if you have not pressed the Update Changes button.

Note1: Any fields that are not displayed on this graphic form will NOT have values specified for them unless they are auto-numbered?

Note2: If you make a mistake when adding a field, press the Undo All Changes button to undo all changes made since the Update Changes button was pressed.

To edit a record of the associated table:

Note1: This requires the data for the associated table or View to be initially retrieved (Load Data button).

Note2: This can only be performed on a table and not a View.

Note3: The DataBinder MUST contain all the primary key column/s for this table, before your users can edit records from this table. These primary key column/s, however, do not need to be displayed on the graphic form.

  1. If necessary, navigate to or locate the required record first.
  2. If a DataGrid control is associated with this table, then change the edit the fields in the required columns for this record in this control.
  3. If selected fields of this table are displayed in separate controls, then edit the required controls.

WARNING! You can only undo editing changes to records if you have not pressed the Update Changes button.

To remove a record from the associated table:

Note1: This requires the data for the associated table or View to be initially retrieved (Load Data button).

Note2: This can only be performed on a table and not a View.

Note3: The DataBinder MUST contain all the primary key column/s for this table, before your users can remove records from this table. These primary key column/s, however, do not need to be displayed on the graphic form.

  1. If necessary, navigate to or locate the required record first.
  2. Click the Delete Record button.
  3. If a DataGrid control is associated with this table, then a new row is added to the bottom of this control.
  4. If selected fields of this table are displayed in separate controls, then these become blank so that new data can be entered into them.

WARNING! You can only restore deleted records if you have not pressed the Update Changes button.

 

To undo all the changes that have been made to the associated table:

  1. Click the Undo All Changes button.

PLEASE NOTE: All changes made to a table (records that are added, edited or deleted) can ONLY be reversed by pressing the Undo All Changes button BEFORE the Update Changes button is pressed. This is because you do not working directly on the database itself, but on records that are retrieved from the database. Therefore, It is only when the Update Changes button is pressed that the actual data in the database is updated.

To save all the changes that have been made to the associated table:

Note: The DataBinder MUST contain all the primary key column/s for this table, before your users can save changes made to this table. These primary key column/s, however, do not need to be displayed on the graphic form.

  1. Click the Update Changes button.

WARNING! Changes to this table CANNOT be reversed AFTER pressing this button.

 

Miscellaneous features:

  • The Current Position field indicates the number of the currently selected record in the associated table or View.
  • The Total Number of Items (Records) field indicates the total number of records within the associated table or View.

About queries

After connecting your database to an OLE DB datasource, a Queries folder appears beneath this datasource, which provides the following categories or common tasks for managing your database:

Note: For backward compatibility, the Select Queries category contains any query created in a previous version, regardless of its actual function.

  1. Select Queries: Selects a sub-set of your data by tailoring your data to suit specific uses or requirements. Click for more details:

    Select the required tables and/or views and their fields. If necessary, refine this data by create relationships between fields in these tables and/or adding criteria that must be met by values in one or more fields.

    Note: If necessary, parameterise the criteria values to specify them before performing the query.

    Tip: Use a DataBinder instead if you want users to modify this data or have it dynamically updated. For details, see About DataBinders.

For a detailed description on how to add, configure and perform this query, see Select queries.

  1. Insert Queries: Inserts records into a specific table or view, by specifying the values of selected fields. Click for more details:

    Note: If necessary, parameterise one or more of these values to specify them before performing the query.

    Tip: You can also specify calculations instead of single values. These calculations can involve numeric parameters. For instance ‘<!!param!!>*4’ multiples the value of this parameter by four.

For a detailed description on how to add, configure and perform this query, see Insert queries.

  1. Update Queries: Updates the values of specific fields of a database table or view. Click for more details:

    If necessary, limit this updating by defining criteria for fields that must be met first.

    Note: If necessary, parameterise both the field and/or criteria values to specify them before performing the query.

For a detailed description on how to add, configure and perform this query, see Update Queries.

  1. Delete Queries: Deletes records from a specific table or view. Click for more details:

    If necessary, limit this deletion by defining criteria for fields which must be met before a record is deleted. Otherwise all the records will be removed.

    Note: If necessary, parameterise the criteria values to specify them before performing the query.

For a detailed description on how to add, configure and perform this query, see Delete Queries.

  1. Execute Statements: Runs predefined stored procedures or user-functions of the database. Click for more details:

    Note: If these statements include input parameters, these can be specified before performing the query.

For a detailed description on how to add, configure and perform this query, see Execute Statements.

  1. Create Table Queries: Creates tables in the database with specific structures. Click for more details: 

    This allows you to take the tedium out of creating similar tables, by creating a library of common table configurations, in which you only perform the laborious configuration once for all.

    If necessary specify primary keys and lookup columns (foreign keys) for fields.

    Note: If necessary, parameterise both the table and field names to specify them before performing the query.

For a detailed description on how to add, configure and perform this query, see Create Table queries.

  1. Drop Table Queries: Deletes a table or view from the database. Click for more details:

    Note: If necessary, parameterise the table or view names to specify them before performing the query.

For a detailed description on how to add, configure and perform this query, see Drop Table queries.

Note: The Custom Query provided by the Query spider allows your users to perform on-the-fly queries, see Performing Custom queries.

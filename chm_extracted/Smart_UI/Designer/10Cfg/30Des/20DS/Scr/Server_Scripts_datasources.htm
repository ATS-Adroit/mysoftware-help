Server Scripts datasources

The Server Scripts datasource provides a repository for scripts that can either be run on the SmartUIServera "data portal" which exposes data from a number of disparate sources. or the Clientrefers to either the Designer or the Operator, both of which are client applications of the Server..

Click for advanced Server Scripts datasource usage information:

This datasource essentially manages one or more script objectthis contains a script and provides its self-contained environment within which it is run., each of which contain a script that is run on the Server. For further details on scripts, see Working with scripts. These script objects can be added and edited from this Server Scripts datasource. For details, see Adding script objects or Editing script objects.

If necessary, you can schedule the script objects to run at specific times, see Scheduling script objects.

For details on specifying where these scripts are saved, see Server directory settings.

Note: Access to both the Server Scripts datasource and its script objects can be controlled, if necessary. For details, see Securing datasources. 

This datasource is added within the Datasources category of the required SmartUI Server in the Enterprise Manager. For details, see Adding Script datasources.

A Server Scripts datasource is identified in the Enterprise Manager by its specified name and its icon .

When this datasource is opened any script object added to it are displayed immediately below it.

Advantages of adding a script object to a Server Scripts datasource:

  1. Due to the self-contained nature of script objects, it is possible to create and store script objects, which will interact with either the Server or the Client or both of them, if necessary.

Note: Scripts are able to interact with the Client and/or the Server through the use of INeed interfaces. For details, see Working with INeed Interfaces. In addition to this functionality, you are also able to provide additional functionality, by referencing external assemblies (.DLL files). For details, see Managing references.

  1. Each script object is able to be used within a Script Engine spider. For details, see Script Engine spiders.

Note: Scripts which are used within Script Engine spiders are run from the Client and not the Server.

  1. Each script object is immediately accessible by all the Clients connected to its SmartUI Server.
  2. Each script object becomes a data element and can therefore be secured, if necessary. Unlike a script object created within a Script Engine spider, which cannot be secured directly and instead relies upon the security applied to the graphic form with which this spider is associated.

Note1: Running a script object from the Server or a Client, should not affect its speed of execution. Typically, the script execution speed is dependent on the script source, the utilization of external references and correct programming techniques and other system-dependent factors such as CPU load etc.

Note2: When running a script object of the Server Scripts datasource, within the Script Editor, the script will be executed slower than if it was run normally. For details, see Working with the script editor.

Note3: Scripts which are not used within Script Engine spiders can either be executed manually Running script objects or by using the ExecuteScriptObject special function provided by the Script datasources.

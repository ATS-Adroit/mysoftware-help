Execute Command Behaviours

This Behaviour can be applied to controls and graphic elements (vectors) to perform the following commands:

Note: You CANNOT test Execute Command behaviour that perform graphic forms operations (opening, closing etc.) in the SmartUI Designer in Run mode, this functionality is only available in the SmartUI Operator. If you try to do so, an alert informing you of this is displayed.

Tip: If necessary, more than one Execute Command Behaviour (command) may be assigned to perform additional commands.

To add a command to a control or vector:

  • Add or edit an Execute Command Behaviour to display its configuration dialog.
  • Select the required command from the Command list and configure it as follows:

Start application: to launch an application and specify any required parameters, you configure this command as follows:

  • Application Name: browse in the required application.
  • By default this specifies an absolute path.
  • Check the Exclude path checkbox to specify a relative path, from the folder in which the Client executable is being run from, which is typically the installation folder.

IMPORTANT: You need to ensure that this application is located in the specified path of your Operators and/or Web Operators.

  • Parameters: specify any parameters required by this application.

Open graphic form: to open a specific graphic form, you configure this command as follows:

  • Graphic Form: click the browse button to launch the Graphic Form Selection dialog to select the required graphic form from the configured projects on the available SmartUI Servers.
  • Open As: specify how the graphic form opens, as follows:
  • Modal Form: the graphic form opens as a separate window that requires the user to interact with it or close it before being able to continue using the application. This is the default selection.
  • Modeless Form: the graphic form opens as a separate window that allows the user to interact with it and also return to a previous task without closing it.
  • Tab Page: the graphic form opens as a another tabbed page within the workspace.
  • Replace: the graphic form replaces the currently displayed graphic form.

  • Template Graphic Object: the graphic form is opened within a specific Template Graphic Object control.

    This option displays the TemplateGO field to specify the name of the required TemplateGO or TemplateGONavToolbar control, from the list - assuming that one or more of these controls have been added to the graphic form on which this Execute Command Behaviour is on.

  • Position: specify where, on the screen, the graphic form opens, as follows:

    • Center of Screen: opens the graphic form in the center of the screen (the default setting).
    • Location: uses the Location settings to specify the required X and Y position of the top left hand corner of the graphic form.
    • Mouse cursor: opens the graphic form at the current position of the mouse cursor
  • Template Set: specify which pre-configured template set to activate, when this graphic form opens.
  • Level : specify which pre-configured level to show, when this graphic form opens.
  • size: specify the dimensions of the opened graphic form, as follows:
  • By default, this conforms to the size of opened graphic form.
  • If you check the Custom checkbox then specify the required Width and Height dimensions of the opened graphic form.

Note1: The Advanced View provides an Aliases tab for this Open Graphic Form command, which lists any configured aliases of the specified graphic form, so that these values can be set either by specific data elements or by static values. This tab can be used to Drive alias values with wizard substitutions or Pass alias values from parent to child SmartUI Templates.

Note2: If the specified graphic form does not exist (for instance if it was typed in incorrectly or if this Behaviour was copied from another project), then when this Behaviour is performed in the SmartUI Operator, it opens the specified graphic form containing the text 'graphic form not found'.

IMPORTANT: The default action for values entered into the Aliases tab of the Advanced View has been changed to always specify the text that is either manually entered or browsed in, unless the Use Tag Value checkbox is checked, at which time it will try to resolve the required data element value from the entered (typically browsed in) text.

Therefore when passing substitutions or aliases, in curly {} brackets, ensure that the Use Tag Value checkbox is NOT checked, which is its default setting.

Tip: If necessary this graphic form can be opened within a specific TemplateGOa Template Graphic Object control that displays a graphic form and connects data elements to any aliases of this graphic form. control on this graphic form.

Close graphic form: to either close a specific graphic form or the currently open graphic form, you configure this command as follows:

  • Either specify the required graphic form to close, as follows:

Graphic Form: click the browse button to launch the Graphic Form Selection dialog to select the required graphic form from the configured projects on the available SmartUI Servers.

  • Or check the This form checkbox to close the graphic form that is currently open, when this command is performed.

Print graphic form: to send the currently displayed graphic form to the default printer.

If you check the Show Print Dialog option, then your users can choose which printer is used to print this graphic form and/or which print settings are used when printing this graphic form, such as the required page orientation.

Otherwise you the currently displayed graphic form will be sent to the default printer.

Log off: to log off the current Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. user, you configure this command as follows:

  • No further configuration is required to simply log off the current user.
  • If you have configured an auto-login account for this Client, then you can check the Auto login checkbox to automatically log in again using the specified auto-login user credentials.

This, in effect, performs a “switch user” operation for the pre-configured auto-login user.

Log on: to perform a “switch user” operation by logging in another user, you configure this command as follows:

  • Username: either type in the name of the required Allowed or Impersonated user or use the browse button to use the User Browser to specify this user name.
  • Password: type in the required password of the selected user.

 

If necessary, click the Advanced View button to specify some or all of the following additional configurable options:

Confirmation: provide pre and/or post confirmation for this command, by selecting one or both of the following checkboxes:

  • Log action: logs (records) this command in the Application event log for forensic or audit trail purposes.
  • Confirm action: pops up a yes/no confirmation message box before the command is performed.

Security: ensure this action is only performed when the designated user/s and/or group/s are logged on, as follows:

  • Either click the browse button to specify a String data element, which contains the names of the required users and/or groups.

Note: The user and group names in this string must be delimited by semi colons “;”.

  • Or click the Security button to open the Security configuration dialog to select the required users and/or groups.

Tip: Instead of using the buttons to move users and groups from the Available and Selected lists, you can simply double click them.

Event Trigger: specify which event of this control or graphic element (vector) triggers this Behaviour, as follows:

  • Either select the required event from the list of common or frequently used events.
  • Or click the browse button and use the Event Selector to select the required event.

Tip: Click the Simple View button to hide these advanced options, if necessary.

 

Tip1: When adding a Behaviour to a SmartUI TemplateA graphic form that has one or more configured aliases and is therefore designed to be displayed within a TemplateGO control. , you can use {} notation to automatically create an alias for any data element field. For more details, see Working with SmartUI Templates.

Tip2: When adding a Behaviour to a wizardA pre-drawn and/or pre-configured skeleton of graphical objects and their assigned Behaviours (if any), which has placeholders (substitutions) for data elements., you can use {} notation to automatically create a substitution for any data element field. For more details, see Working with wizards.

To add a Behaviour to a control or graphic element:

Ensure that you have added the required control or graphic element to the graphic form.

  1. Select the required control or graphic element.

  2. If necessary, select the Behaviours tab from the SmartUI Designer ribbon.

    Note: Any Behaviour that cannot be applied to this control or graphic element will be greyed out.

  3. Select the required Behaviour from the relevant group.

Tip: You can also select its glyph to display its task menu and then select the required Behaviour from the New Behaviour drop down list.

This displays the configuration dialog of this Behaviour.

Tip: When you add or edit a Behaviour you can name it, which makes it easier to identify the spiders and their regions associated with your Behaviours.

To edit a Behaviour of a control or graphic element:

  1. Right click the required control or graphic element to the graphic form.
  2. Select the required BehaviourName# menu item, where BehaviourName is the name of the added Behaviour and # usually only appears if more than one of same type of Behaviours have been added. For example: Execute Command1

Tip: You can also select its glyph to display its task menu and then select the required link beneath the Behaviours heading.

This displays the configuration dialog of this Behaviour.

Tip: The Behaviours tab of the SmartUI Designer ribbon provides the Edit Behaviour list box that lists all the Behaviours configured for the currently selected form component. Clicking its browse button displays the configuration dialog of the currently selected behaviour.

To remove one or more added Behaviours from a control or graphic element:

  1. Select the required control or graphic element.

  2. If necessary, select the Behaviours tab from the SmartUI Designer ribbon.

  3. Select the Remove command from the Remove group.

Tip: You can also select its glyph to display its task menu and then select the Removelink beneath the Behaviours heading.

This displays the Behaviour Removal configuration dialog.

  1. Select (check the checkboxes) of the Behaviour/s that you want to remove from this list in the Behaviour Removal configuration dialog.

WARNING! Ensure that ONLY the Behaviour/s you do not require is selected, since no deletion confirmation dialogs are displayed.

  1. Click the Finish button to remove the selected Behaviour/s or Cancel to abort.

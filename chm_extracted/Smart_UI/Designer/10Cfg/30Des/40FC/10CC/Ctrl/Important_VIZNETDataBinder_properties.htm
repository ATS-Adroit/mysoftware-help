Important VIZNETDataBinder properties

The VIZNETDataBinder component provides the following properties that manage how the data of its associated DataBinderDataBinders allow you to create a sub-set of the data contained within an OLE DB datasource to provide constant bi-directional communication with this database. This means that unlike the data returned by Select queries, this data can be viewed and/or modified and updated if it changes. is accessed:

Note: All of these settings are in the Settings category.

AutoLoad: Determines whether the associated VIZNETBindingNavigator controls initially fetch their data or not.

If this is set to True, then when the graphic form is opened all the VIZNETBindingNavigator controls, associated with this component (as specified by the BindingNavigatorList property) immediately fetch the first page of records for their associated table or View (BindingSource component).

Note1: In this case, all the parameters of the associated DataBinder, must have default values configured.

Note2: The number of records fetched by each VIZNETBindingNavigator control is specified by the MaxRecords property.

Note3: The AutoLoadList property allows you to select which tables you want to be automatically loaded.

If this is set to False, the default value, then the user must press the Load Data button of each VIZNETBindingNavigator control individually.

Note: This setting ONLY applies if you selected the Create Controls option when adding the VIZNETDataBinder component.

AutoLoadList: Allows you to select which tables you want to be automatically loaded (by using the AutoLoad property).

By default all the associated tables are selected, but if there are one or more tables that you do NOT want to AutoLoad, simply uncheck the checkbox of these tables, so that their data will NOT be automatically fetched.

MaxRecords: Determines the maximum number of records retrieved from the database at any one time.

By default this is 100. Configure this property to ensure that your users do not experience sizable delays when requesting further records. Since the larger this property the greater the potential delay that users could experience in waiting for this amount of records to be returned.

The recommended size of this property is therefore dependant upon the average bandwidth of your users’ connection to the database. Click for more details:

The default of 100 works well for both LAN and Internet usage.

If you using Internet we recommend using less than or equal to 100.

If you are using LAN then you may use more than 100, but this depends on how busy your network is.

 

RefreshData:Determines what happens when external changes are made to the retrieved records.

The following options are provided:

• Manual: The default option in which a message box is displayed when the database is modified externally, asking whether the user wants the data updated to reflect the new changes.

Use this option when you require the Operators of the system to be aware of any changes and want to ask them if they want to get the newest changes or not.

• Auto: The data is immediately updated with the new changes.

Use this option when there is only ONE client that changes the data in the database; while the other clients only view the data. You can also use this option if the VIZNETDatabinder is purely used for viewing the data.

• Ignore: The data is NEVER updated with new changes.

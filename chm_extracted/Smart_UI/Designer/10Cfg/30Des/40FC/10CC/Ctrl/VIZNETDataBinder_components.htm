VIZNETDataBinder components

This componenta hidden form component that provides additional functionality to this graphic form and some or all of its form components. See form component. makes the data of a DataBinderDataBinders allow you to create a sub-set of the data contained within an OLE DB datasource to provide constant bi-directional communication with this database. This means that unlike the data returned by Select queries, this data can be viewed and/or modified and updated if it changes. accessible to other controls and components on a graphic form. For details, see Accessing data within DataBinders.

Note1: The VIZNETDataBinder component provides a number of properties that manage how the data of its associated DataBinder is accessed. For details, see Important properties.

Note2: If necessary, other controls can access the data of the View and/or tables by being linked to the respective Bindingsource component. For details, see Linking controls to BindingSource components.

This is made possible by creating BindingSource components for each of the tables and View of this DataBinder, which provide other controls and components on this graphic form with access to their data.

Created BindingSource-specific components and their naming conventions:

Note: These components do not require further configuration.

  • A single View BindingSource component, which only allows its data to be viewed and not modified, which adheres to the following naming convention: viewDataBinderNameBindingSource. For instance, if the DataBinder is called 'MyDtBndr': viewMyDtBndrBindingSource. 
  • A BindingSource component for each table within this DataBinder, which allows both viewing and modification of its data and adheres to the following naming convention: TableNameBindingSource. For instance if the table name is 'SalesPerson': SalesPersonBindingSource.
  • A DataSet component that provides communication between the BindingSource components and the DataBinder's database. This component adheres to the following naming convention: OLEDBDatasourceNameDataBinderNameDataSet. For an OLEDB datasource called 'North Wind' and a DataBinder called 'MyDtBndr': north_WindMyDtBndrDataSet.

Note1: If the component name already exists then its name will be appended by a unique number starting from 1.

Note2: Any spaces or other illegal characters are replaced with underscores, when naming these components.

Although BindingSource components provide access to the data, they do not provide direct access to this data. Instead they retrieve records from the database in pages or set quantities. It is these retrieved records that they provide to the other controls and components on a graphic form. This has a number of advantages:

  • Since you do not working directly on the database itself, you have the ability to undo changes that are made, before they are actually made.
  • Since you only receive pages or set quantities of records, you do not experience the potential performance lags associated with receiving all the records from the database at once.

Note: Since all the controls that require data from the same table receive it from the same BindingSource component, when a specific record is selected this record is selected in ALL the associated controls.

Configuration options:

  • A configuration dialog to select the required DataBinder : Launched when adding a VIZNETDataBinder component to a graphic form. This configuration dialog also provides the option to Create Controls, where you select which of the tables and their fields you want displayed and specify which controls should be used to display them.

    Use one or both of the following options of controls for your data:

    • labeled TextBoxes to display the value of the selected fields. This method is recommended when you require information about a specific item such as a particular user or asset.
    • a DataGridView containing the selected fields. This method is recommended when the associated table contains large amounts of data that you want to view in a spreadsheet environment.

    A toolbar ( VIZNETBindingNavigator control) is also added for each of the selected tables, which allows your users to view, navigate and modify your data, by communicating to the associated BindingSource component.

Most notably, the Create Controls option adds a toolbar ( VIZNETBindingNavigator control) for each of the selected tables, which allows your users to view, navigate and modify your data, by communicating these requests to the associated BindingSource component.

Note: If you do not use the Create Controls option, then you must implement your own method of communicating to the BindingSource components. For instance, use the DataBinderTrigger spider to load (fetch) and update their data.

  • A Tasks menu, which provides a list of important properties and configuration options for this component.. The configuration dialog, however, should still be used to select the required DataBinder and, if necessary create the required controls.
  • Important properties, this describes the functions of the important properties that can configure this component.

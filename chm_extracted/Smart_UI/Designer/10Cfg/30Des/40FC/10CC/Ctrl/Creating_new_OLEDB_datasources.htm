Creating new OLEDB datasources

When connecting an AdroitHistoricalAlarmViewer control to an Adroit AlarmManagement agent SQL Server database, you can create the required OLEDB datasource on the fly.

To create a new OLEDB datasource to connect to an AdroitHistoricalAlarmViewer control:

Typically in the DataSource tab of the of the Initial Configuration dialog and/or General Configuration Settings or the dedicated Configure DataSource Connection configuration dialogs:

Click the New button to the right of the OLEDB Datasource field.

Specify the name of this datasource in the OLEDB Datasource Name field.

Typically if your Adroit Agent Server is offline and you know the connection details of the AlarmManagement agent SQL Server database, then click the New Connection Settings option.

Click the browse button to the right of this field and use the Connection Properties dialog to create the required connection string to your SQL Server database, as follows:

Important:  If the computer, on which SQL Server was installed, was renamed, then SQL Server may need to be re-installed.

If the computer was renamed after installing SQL Server, then SQL Server must be re-installed, to function correctly.

Run the following check:

  • Execute the following T-SQL (Transact-SQL) script in SQL Server Management Studio: SELECT @@SERVERNAME
  • If the resulting server name is different to the actual name of the computer, then the name of the computer has been changed after SQL Server was installed, so you need to reinstall SQL Server.

This Connection Properties dialog specifies the location and the security credentials required to connect to this database.

Note: If you need to configure or view this database and its data from other computers, like remote User Interfaces, then use a UNCUniversal Naming Convention (UNC) is used to specify the location of servers, printers, files and other shared resources on a local area network (LAN). UNC names begin with \\ (two backslashes) and take the form: \\Computer_name\Share_name path and not a local file paththis path, as opposed to a UNC path, can ONLY be accessed from the computer that it refers to, this path adopts the following general format: <driveletter>:\directories\filename.to specify the location of this database.

  1. Typically do NOT change the Data source from the default of .NET Framework Data Provider for OLE DB, unless you are connecting to a SQL Compact database. More details: in which case, click the Change... button and choose the datasource that corresponds to the correct version of SQL Compact and then the dialog will change so that you only need to browse in the required database file and specify the required password, if any.
  2. Select the required OLE DB Provider from the list, for instance to connect to SQL Server, select the Microsoft OLE DB Provider for SQL Server
  3. Type in the name of the computer name of the SQL Server that you want to connect to, in the Select or file name field.
  4. Specify the required security credentials to connect to this SQL Server, as follows:
  • Use Windows NT Integrated security: this option uses the username and password of the currently logged on Windows user.

Tip: We recommend that you configure your SQL Servers to use this option to avoid requiring additional database security.

  • Use a specific user name and password: this option uses the User name and Password configured within the SQL Server you are attempting to connect to.

Note: In this case it is recommended to check the Allow saving password checkbox.

  1. Select the name of the required database from the Initial catalog list box.

Tip: This list box is only populated with the available databases, if you have been able to successfully connect to the database, so there is no need to click this Test Connection button.

  1. Click the OK button.

This should create your connection string, although click the Test Connection button provided by this dialog to check.

Note1: The Advanced... button of this dialog allows you to configure Advanced Properties, which should ONLY be modified if you know what you are doing.

Note2: The Data Links... button of this dialog, opens the Data Link Properties dialog, which allows you to configure both these advanced properties via the All tab and may allows you to specify access permissions for this connection string via the Advanced tab. Once again ONLY modify these settings if you know what you are doing.

Note3: These security credentials are database specific and should not be confused with application security.

Note4: You can also edit this connection string directly, once it has been created, if necessary.

If you have an Adroit datasource that connects to an Agent Server containing this AlarmManagement agent and this Agent Server is running, then click the Adroit Alarm Management Agent Connection Settings option and specify the required Adroit datasource and the name of the AlarmManagement agent.

Click the Test Connection button to ensure that the specified SQL Server database can be accessed by this control and then click the Finish button.

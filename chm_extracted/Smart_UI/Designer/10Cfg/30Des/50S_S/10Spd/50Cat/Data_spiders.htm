Data spiders

These are a special subset of spiders, which provide the entry and exit points of data into and out of the spider workspace. Data spiders are typically added automatically and cannot be renamed.

Available Data spiders

  1. Data Element spider: responsible for communicating Data Elements between the Server and its inputs and outputs. When triggered, its input value is written to the Server. For details, see Data Element spiders. 
  1. Property spider: responsible for communicating data between its inputs and outputs and the property that it is linked to. When triggered, its input value is written to the property of the connected control. For details, see Property spiders. 

Note: If the property is connected to a data element that contains more than one value i.e. of type dataset, then a number of additional inputs which are made available and the Filter Dataset configuration dialog is displayed to select which of these value(s) are required. For details, see Additional dataset configuration or Filtering datasets.

Note1: The namespaceone or more names separated by periods (or dots), where each name represents an individual item and the entire namespace indicates the relationship or lineage of the leftmost term i.e. grandparent.parent.child. of the Data spider is typically the name of the associated item, which can be used to locate it in its tree.

Note2: A Data spider is also automatically removed if it no longer has no silks attached to it, when the spider workspace is saved. For details, see Saving spider workspaces.

Tip: Although these spiders cannot be renamed, you are able to edit their descriptions. For details, see Annotating spiders. Both this description and the spider’s name is displayed by the tool-tip text whenever the mouse pointer hovers over the title bar of a spider. For details, see Spider title bars.

When a Data spider is added to the spider workspace, a silk appears adjacent to the node within the respective tree, to indicate that a spider is linked to this node. However, the start and end points of the silks to or from the Data spiders are specified, by the direction of their arrows within the spider workspace.

Data spiders also behave differently within the spider workspace, when their configuration views are hidden or displayed, as follows:

  1. In Expanded mode, in addition to displaying its configuration view the Data spider also graphically indicates its associated data element or property. This is denoted by a light-purple ray, which expands from the position of the data element or property tree node to the appropriate side of the configuration view. If the associated node is collapsed, then the ray points to the topmost collapsed branch hiding this tree node. For details on closing its configuration view, see Hiding spider configuration views.

In Collapsed mode, Data spiders may disappear from view in the spider workspace and are located in their respective tree nodes and cannot be further configured, although, silks can still be dragged to and from these tree nodes. For details on displaying its configuration view, see Displaying spider configuration views.

Note: Like other spiders, whenever a Data spider is added to the spider workspace, by default it is displayed in Collapsed mode.

Script Engine spiders

The Script Engine spider allows users to create scripts to perform advanced customised operations. These scripts can use both input and output variables, if necessary.

Configuration

Spider menu: This describes the available menu items and their default settings for this spider. 

Note:Menu items that are enabled will have a tick mark to the left of them.

  1. Detail View: This can be used to display the configuration view of this spider, so its name, description, inputs and outputs can be configured. For details, see Working with spider configuration views.

Tip: Double-click the title bar of the spider to display or hide the configuration view of the spider.

  1. Delete Spider: This can be used to remove this spider from the spider workspace. For details, see Removing spiders.
  2. Trigger Spider From Event: This enables the spider to be triggered (which will run its script) by means of an event. For details, see Triggering a spider from an event. This is disabled by default.
  3. Enable Silk Triggering: This enables the spider to be triggered (which will run its script) by any silks that are attached to the inputs of this spider. For details, see Triggering spiders. This is disabled by default.
  4. Propagate Outputs At Startup: This enables the spider to supply the silks connected to its outputs with values as soon as its spider workspace enters into running mode. For details, see Working with spider workspaces or Sending spider outputs at startup. This is disabled by default.
  5. Trigger Now!: This will cause this spider to immediately be triggered - usually used for testing.

 

Inputs and outputs: This describes the available inputs and outputs displayed by the default configuration view of this spider.

This default configuration view of this spider, contains the following sections:

  1. Inputs, this section contains the inputs to this spider.
Input Data Function
Enable Boolean If Enable = True (the checkbox is checked), then the associated script object will execute whenever this spider is triggered. Otherwise it will not.

Thread based

Boolean

If Thread based = True (the checkbox is checked), then whenever the script is triggered, providing Enable = True, the script will be run using a separate thread. Otherwise it will be run using the Client’s thread.

Note1: It is only recommended to set this input for scripts that perform their processing in the background and do not require user input to allow this processing to execute faster.

Note2: The thread-based execution of the script object will not halt other processing of the Client.

Script Object 

Script Object

This can accept a script object from the Script Server that has been written to interact with the Client and if necessary the Server. For details, see Creating script objects or Adding script objects.

Script Source 

Text 

This contains the raw text content of the specified script object.

Note: This is an optional input that can be used to change the script text within the script object, specified by the Script Object input.

Tip: When creating a script within this Script Engine spider, it is recommended to launch the Script Editor instead, so that the script and its references can be appropriately configured. For details, see Working with the script editor.
  1. New Input, this section contains the input types configured for this spider.
New Input Function

+ input var

This will add a variable called var # to the Inputs section, where # is a unique number starting from 1, which can be used within the script of this Script Engine spider. For details, see Adding input variables.

Note1: In order to use input variables within your script, ensure the IneedSpiderInfo interface has been implemented. For details, see Working with INeed Interfaces.

Note2: You must create the required input variables that the script requires before the script is run, otherwise a runtime error will result.

Note3: Input variables can also be removed from this spider. For details, see Removing input and output variables.
  1. Outputs, this section contains the outputs from this spider.
Output Data Function

Runtime errors

ArrayList

A list of the errors that occurred when the script was last executed. This list is updated after the script is run.

Errors

ArrayList

A list of errors that occurred while the script was being compiled. This list is updated before the script is run.

Note: Whenever the script is run, it is first compiled and only if there are no compilation errors, is it executed, after which any run time errors are identified.

These outputs record both the compilation (Errors) and run time errors (Runtime errors) that occur when the script is last run. But only display the number of each type of error, within this configuration view. For details, see Debugging the script object.

Tip: It is recommended to launch the Script Editor to view the descriptions of these errors in its Output window so that you may be able to locate and rectify them.

Do this by clicking the Launch Script Editor button, within the Inputs section. For details, see Working with the script editor.

  1. New Output, this section contains the output types configured for this spider.
New Output Function

+ output var 

This will add a variable called var # to the Outputs section, where # is a unique number starting from 1, which can be used within the script of this Script Engine spider. For details, see Adding output variables.

Note1: In order to use output variables within your script, ensure the IneedSpiderInfo interface has been implemented. For details, see Working with INeed Interfaces.

Note2: You must create the required output variables that the script requires before the script is run, otherwise a runtime error will result.

Note3: Output variables can also be removed from this spider. For details, see Removing input and output variables.

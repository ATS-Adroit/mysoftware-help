Variable Data Element spiders

The Variable Data Element spider can dynamically change a portion of or the entire names of data elements and if necessary configure their values.

Example of usage:

A typical example of usage would be for a redundant server system or process; where only the datasource portion of the datasource name changes between the common setups. In this case, this spider can be used for all the relevant data elements, instead of creating an entirely redundant set of spiders.

Through the creation of named inputs, the Variable Data Element spider allows you to combine (concatenate) these inputs to dynamically specify several components of a data element name at runtime.

Example:

In this example a variable data element concatenates the {AgentServer}.{PUMP} inputs to dynamically specify the value of any pump on any Agent Server, which are specified via graphic form aliases.

  1. To add this spider to the spider workspace.
  2. To create one or more variable data elements and if necessary configure their values.

Note: You can create one or more named inputs, instead of or in addition to using the default {0}, which can specify the variable portion/s of the required data element name(s) that are dynamically driven by spiders or string type inputs, at runtime.

  1. To remove unnecessary variable data elements.

Configuration

Spider menu: This describes the available menu items and their default settings for this spider. 

Note: Menu items that are enabled will have a tick mark to the left of them.

  1. Detail View: This can be used to display the configuration view of this spider, so its name, description, inputs and outputs can be configured. For details, see Working with spider configuration views.

Tip: Double-click the title bar of the spider to display or hide the configuration view of the spider.

  1. Delete Spider: This can be used to remove this spider from the spider workspace. For details, see Removing spiders.
  2. Trigger Spider From Event: This enables the spider to be triggered (which will run its script) by means of an event. For details, see Triggering a spider from an event. This is disabled by default.
  3. Enable Silk Triggering: This enables the spider to be triggered (which will run its script) by any silks that are attached to the inputs of this spider. For details, see Triggering spiders. This is enabled by default.
  4. Propagate Outputs At Startup: This enables the spider to supply the silks connected to its outputs with values as soon as its spider workspace enters into running mode. For details, see Working with spider workspaces or Sending spider outputs at startup. This is disabled by default.
  5. Trigger Now!: This will cause this spider to immediately be triggered.

 

Inputs and outputs: This describes the available inputs and outputs displayed by the default configuration view of this spider.

This default configuration view of this spider, contains the following sections:

  1. Inputs, this section contains the inputs to this spider.
Input Data Function

{0}

String

This input can be used as a placeholder when specifying the other variable data elements inputs.

The value of this input can specify the variable portion of the required data element name(s) at runtime or you can create other named inputs and use these instead. For details, see Creating variable data elements.
  1. New Input, this section contains the input types configured for this spider.
New Input Function

+ New Input 

This allows you to create one or more named inputs, instead of or in addition to using the default {0}.

When clicked this displays a dialog to specify the required name for this input.

The specified name is added to the list of Inputs, enclosed in {} braces.

Tip: You can manually type in and/or concatenate one or more named inputs in the vde #[DE Name (Segment)] inputs to replace one or more portions of a data element name.

Note: To remove an unnecessary named input, right click it in the Inputs section and select Delete.
  1. Outputs, this section contains the outputs from this spider.
Output Data Function

BusySubscribing

Boolean

Set to True when the values of data elements connected to the VDE inputs are being fetched from their datasources. Set to False once all the values have been fetched.

For instance, this can be used to control the display (visibility) of a message informing users that the system is waiting for values - when using a slow (low bandwidth) connection to/from the Server Status of a read By default this is False.

UpdateComplete

Boolean

Set to True when the VDE outputs write their values to whatever they have been linked to. Set to False once all the output values have been written.

For instance, this can be used to control the display (visibility) of a message informing users that the system is currently writing values - when using a slow (low bandwidth) connection to/from the Server.
  1. New Output, this section contains the output types configured for this spider.
New Output Function

+ Variable DE 

This will add 2 inputs, namely vde #[DE Name (Segment)] and vde # [Return DE] to the Inputs section and an output called vde # to the Outputs sections, where # is a unique number starting from 0.

The vde # [DE Name (Segment)] input should specify the variable data element name using the {0} input. For details, see Creating variable data elements.

The vde # [Return DE] input can be used to specify the value that will be written to the dynamically modified data element, specified by the vde # and {0} inputs.

The vde # output should be used wherever this dynamically modified data element is required.

Note: Variable data elements can removed. For details, see Removing variable data elements.

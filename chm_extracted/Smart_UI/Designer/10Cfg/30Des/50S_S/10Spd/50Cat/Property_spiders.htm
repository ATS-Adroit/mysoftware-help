Property spiders

The Property spider is a Data spider, which is responsible for communicating data between its inputs and outputs and the property that it is linked to, so that the value of this property can be determined by its connected data element(s).

In other words, this spider allows you to connect a data element or another property to the required property of the selected graphic forma document that belongs to a project, which can be designed to graphically display data to the user and to accept input from the user when it is being operated. or form componentsa general term encompassing all the controls, components and / or graphic elements that can be added to graphic forms, to provide the required user interface for its end-users. See control; component; graphic element; graphic form..

Adding:For details, see Quick linking or Methods of linking data to properties within a graphic form. This spider is added automatically when a data element is connected to property of a graphic form or one of its form component or vice verse or when the Show Property Spider menu item is selected.

Naming: The namespaceone or more names separated by periods (or dots), where each name represents an individual item and the entire namespace indicates the relationship or lineage of the leftmost term i.e. grandparent.parent.child. of this spider is typically the name of its associated property i.e. controlName.propertyName.

Note: This name cannot be changed.

Triggering: When a Property spider is triggeringthe process by which spiders perform their specific operation, which usually involves communicating and / or manipulating data from their set of inputs to their set of outputs. See spider., its input value is written to the property of the control that this spider is connected to, so that this control is updated accordingly.

By default, this spider is triggered by means of silks. Triggering methods can be configured via its spider menu, see Configuration below.

Note: Triggering only occurs when the spider workspace is running i.e. this only occurs for graphic forms when they are loaded in Run mode or opened in the Operator. For details, see Working with spider workspaces.

WARNING! If the event triggering method is used this spider is NOT triggered, instead it is forced the read the value of its property and update its output.

Configuration

This depends upon the data being connected and the property type, as follows:

General configuration: The following GENERAL menu options and inputs and outputs, are ALWAYS provided by this spider, for instance when connecting a property to a data element that contains a single value.

Spider menu: This describes the generally available menu items and their default settings for this spider. 

Note1: This menu can be accessed by selecting the spider and right-clicking its title bar. For details, see Selecting spiders.

Note2: Menu items that are enabled will have a tick mark to the left of them.

  1. Detail View: This can be used to display the configuration view of this spider, so its name, description, inputs and outputs can be configured. For details, see Working with spider configuration views.

Tip: Double-click the title bar of the spider to display or hide the configuration view of the spider.

  1. Delete Spider: This can be used to remove this spider from the spider workspace. For details, see Removing spiders.
  2. Trigger Spider From Event: When this triggering method is enabled, this spider is NOT triggered, instead it is forced the read the value of its property and update its output.
    Any silks that are attached to the output of this Property spider transmit this value to their associated spider(s). For details, see Triggering a spider from an event. This is disabled by default.
  3. Enable Silk Triggering: When this triggering method is enabled, a silk triggers this spider, after it has set this spider’s input value. For details, see Triggering spiders. This is enabled by default.

Note: A silk is only able to trigger this spider in this way, if its Trigger Output Spider setting is enabled. For details, see Disabling silk triggering of spiders.

  1. Propagate Outputs At Startup: This enables the spider to supply the silks connected to its outputs with values as soon as its spider workspace enters into running mode. For details, see Working with spider workspaces or Sending spider outputs at startup. This is disabled by default.
  2. Trigger Now!: This will cause this spider to be triggered immediately.

Note: Triggering only occurs when the spider workspace is running. For details, see Working with spider workspaces.

  1. Add Properties: This displays the Properties configuration dialog, which exposes one or more of the sub-properties of this property as additional inputs and/or outputs for this spider. For details, see Adding properties.

 

Inputs and outputs: This describes the generally available inputs and outputs displayed by the default configuration view of this spider.

Note1: Before the spider can be configured, its configuration view needs to be displayed. For details see Displaying spider configuration views.

Note2: For details on using the general fields and sections of the configuration view, see Working with spider configuration views.

This default configuration view of this spider, contains the following sections:

Note: The name of this input and output is dependant upon the property that is being connected to.

  1. Inputs, this section contains the inputs to this spider.

Note: These inputs can either be configured within the spider itself and/or may require their values to be supplied by other spiders or Data spiders (e.g. properties or data elements). For details, see Creating silks.

Input Data Function

PropertyName

DE

Enables a data element or another property to connect to this property.

Format

String

Allows the String property value to be formatted, without needing to use a String Format spider. For details on the required formatting syntax, see Working with value formatting.
  1. Outputs, this section contains the outputs from this spider.

Note: Some or all of these outputs can be used to supply the inputs of other spiders or Data spiders (e.g. properties or data elements).

Output Data Function

PropertyName

DE

Contains the value of this property, including any modifications made to this property on the graphic form, when triggered, for instance, by an event specified in the event object and event source inputs.

If this property is connected to a data element, then it is also possible to connect this output back to this data element to update it with any changes made to its value(s) by the user. For details, see Creating silks.

Note: This assumes that this data element can be written to. Also if this data element contains more than one value, then it needs to be able to be updated by means of a dataset. For details, see Updating datasources with datasets.
 
 

Data containing more than one value: The following ADDITIONAL menu options and inputs and outputs, are provided when a property has been connected to a data element that contains more than one value i.e. of type datasettabular data or data that is contained within one or more tables; each table contains one or more columns and each column consists of one or more rows..

Spider menu: This describes the additional menu item that is displayed.

Note: This can be accessed by selecting the spider and right-clicking its title bar. For details, see Selecting spiders.

  1. Filter DataSet: This can be used to display the Filter Dataset configuration dialog to specify the required columns and tables, constraints and/or sorting. For details, see Filtering datasets.
  2. Apply Table Style Formatting: When enabled, this displays the Table Style Date Time Format input, which can be used to customise the display of all the date time fields in this dataset. This is enabled by default.

 

Inputs and outputs: This describes the additional available inputs displayed in the default configuration view of this spider.

Note: Before the spider can be configured, its configuration view needs to be displayed. For details see Displaying spider configuration views.

  1. Inputs, this section contains the inputs to this spider.

Note: These inputs can either be configured within the spider itself and/or may require their values to be supplied by other spiders or Data spiders (e.g. properties or data elements). For details, see Creating silks.

Input Data Function

Filter String

String

This can be used to specify a string that is used to filter a data table’s rows and apply sorting.

Note: It is also possible to specify the required filtering and sorting using the Filter DataSet configuration dialog. For details, see Filtering datasets.

Table Style Date Time Format

String

This input can customise the display of all the date time fields. For details on specifying the required formatting string, see Date and Time formatting syntax.

Note: This input is only displayed when the Apply Table Style Formatting menu item is enabled. 

Append Data Updates

Boolean

By default, when this checkbox is cleared, all the existing data is read initially and thereafter only the newly added or changed data will be displayed.

Check this checkbox, if the data updates from the Server needs to be merged with the data from previous updates. For details, see Displaying both existing and updated dataset data.
For instance, typically data updates from the Event Log datasources only send changed data after each poll period. If you need to show all the historical data as well as any new events that come through, then tick this checkbox.

Note: This input is NOT configured within the Filter DataSet configuration dialog.

Column

List

This displays a list of available columns and can be used to specify which column of the specified data table is to be communicated to its connected property.

Note: It is also possible to specify the required column using the Filter DataSet configuration dialog.

Table

List

This displays a list of available tables and can be used to specify which table is to be communicated to its connected property.

Note1: It is also possible to specify the required column using the Filter DataSet configuration dialog.

Note2: If there is only one table in the dataset then it is not necessary to specify this input.

Note1: Dataset data should typically only be connected to properties that are able display and/or communicate more than one value, such as, the DataSource property of the DataGrid control and any Windows Forms control, which has an 'Items' property of type (Collection), such as: ComboBox, ListBox, CheckedListBox, ListView and DomainUpDown.

Note2: The Filter Dataset configuration dialog is also displayed to select which of the table(s), column(s) and row(s) provided by this data element are to be assigned to this property. For details, see Filtering datasets.

Note3: Although the Filter Dataset configuration dialog configures most of these additional inputs, it does not configure the Append Data Updates setting.

Tip: For a detailed step-by-step procedure of using ListBox and ComboBox controls to display and interact with databases (data elements of type datasettabular data or data that is contained within one or more tables; each table contains one or more columns and each column consists of one or more rows.), see How to use ComboBox (and ListBox) controls to interact with databases.

 

String Properties: When connecting to a property of type String:

  • This spider also provides the Format input, so that this value can be formatted before it is displayed. For details on the required formatting syntax, see Working with value formatting.
  • This spider also provides a right click option for its value input called Maintain Type, which when enabled forces the value to be displayed as a string value regardless of its actual data type. In other words it maintains the type of data that the input expects, which is a string.

Note: When the Maintain Type option is enabled, the input value can only be formatted as a string, as any non-string formatting will be ignored.

To display the configuration view of a particular Property spider:

  1. Open the required spider workspace. For details, see Working with spider workspaces.
  2. In the spider workspace, locate the silk that is connected to the required property and navigate along the silk until you reach its associated node in the property tree pane at the left edge of the spider workspace. For details, see Working with spider workspaces.

Tip1: If necessary, display the required pane by using the required pane display bar. For details, see Working with pane display bars.

Tip2: If the required silk is currently grouped with other silk(s), select this silk first to assist you in located its connected Data spider. For details, see Selecting silks.

If a dotted line is displayed, next to the silk in the property tree pane, this indicates that the associated node is currently hidden within this node of the tree.

  1. If necessary, expand the tree node(s) until a solid line is displayed, next to the silk in the property tree pane, indicating that this is the required property.

Note: Whenever a branch is expanded the associated silk(s) will also move down to and either indicate where the required tree node is hidden or displayed.

Example:

  1. Right-click this property (tree node) adjacent to this solid line and select Show property spider.

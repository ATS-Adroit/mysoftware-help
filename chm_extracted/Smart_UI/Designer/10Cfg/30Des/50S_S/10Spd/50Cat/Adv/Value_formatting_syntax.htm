Value formatting syntax

When you can format the appearance of a value, this formatting is defined as a string, which adheres to the following syntax: 

{#[,alignment][:dataFormat]}

 

General syntax information:

Note1: Only the matching curly brackets ("{" and "}") and the number '#' are compulsory. 

Note2: Any text or numbers typed into the format string, which are not in curly brackets will be displayed as-is.

Note3: Because opening and closing curly brackets are interpreted as starting and ending a format item, you must specify two opening curly brackets ("{{") in order to display one opening curly bracket ("{"), and, similarly, two closing curly brackets ("}}") to display one closing curly bracket ("}").

Note4: It is only possible to use one set of curly brackets when formatting a value.

Where:

  1. The compulsory #, is the unique number, starting from 0, which denotes the input that is being formatted. Typically this will be 0, unless more than one value has been added.
    Specific syntax information:

    Note1: The same # can be formatted multiple times in the same format string. For example, if the value is numeric, this can be formatted in hexadecimal, scientific, and number format, in the same format string, as follows: "{0:X} {0:E} {0:N}".

    Note2: The order in which the # values are formatted is unimportant. For example, if there are three values, you can format the second, first, and third value by specifying a format string like this: "{1} {0} {2}".

    Note3: A # value that is not referenced within the format string it will NOT be displayed.

    Note4: If you specify a # that designates an input which has not been added yet, the Format input cell will prevent you from entering this format string until either a valid # is specified or it is removed.

  1. The optional alignment component is a signed integer indicating the preferred formatted field width, which can be specified for any value, irrespective of its data type.
    Specific syntax information

    Note1: The comma (,) is required if alignment is specified.

    Note2: If padding is necessary, white space is used.

    Note3: The examples specified in this table assume that a String value of ABCDEFGHIJ is assigned to input 0.

    DescriptionFormat String = Example

    If the value of alignment is less than the length of the formatted string, alignment is ignored and the length of the formatted string is used as the field width.

    ->{0,5}<- =

    ->ABCDEFGHIJ<-

    If the value of alignment is positive, the formatted data in the field is right-aligned.

    ->{0,15}<- =

    ->    ABCDEFGHIJ<-

    If the value of alignment is negative, the formatted data in the field is left-aligned.

    ->{0,-15}<- =

    ->ABCDEFGHIJ    <-

  1. The optional dataFormat component, consists of one or more data type specific format specifiers to customise the display of values.

The following types of data can be formatted:

  1. Numeric Format Specifiers: This provides both the commonly used and custom numeric formats, along with examples.

    Commonly used numeric format specifiers: These produce standard numeric formats.

    These numeric format strings, take the form Axx, where:

    • A: is a single alphabetic character called the format specifier.

    Note: If the format specifier is not found in the table below, the Format input cell will prevent you from entering this format string until this incorrect format specifier is removed.

    • xx: is an optional integer called the precision specifier, which ranges from 0 to 99 and controls the number of significant digits or zeros to the right of a decimal.

    Note: If the format string is longer than a three characters (even if the extra characters are white spaces), the format string is interpreted as a custom format string.

    The following table describes these standard numeric format strings.

    Note1: The output produced by these format specifiers is influenced by the current Regional Options settings. Computers using different settings will generate different results.

    Note2: These format specifiers can be typed in both upper and lower case.

    Note3: The example outputs specified in this table assume that a Double value of 1.42 is assigned to input 0 and an Integer value of -12400 is assigned to input 1.

    Format SpecifierNameDescriptionFormat string = Output

    C or c

    Currency

    The resultant string is formatted according to the current currency settings.

    Note1: The currency format may vary.

    Note2: If the precision specifier is omitted, the default currency precision is used.

    {0:c1} = $1.4

    {1:C} = ($12,400.00)

    D or d

    Decimal

    The resultant string is a series of decimal digits (0-9), prefixed by a minus sign if the number is negative. The precision specifier indicates the minimum number of digits desired in the resulting string, if required, the number is padded with zeros to its left to produce this number.

    Note: This format is only supported for whole numbers.

    {0:D} = Not allowed.

    {1:d8} = -00012400

    E or e

    Scientific

    The resultant string is of the form "-d.ddd...e+ddd", where each 'd' indicates a digit (0-9). The string starts with a minus sign if the number is negative.

    Note: One digit always precedes the decimal point.

    {0:e} = 1.420000e+000

    {1:E3} = -1.240E+004

    F or f

    Fixed point

    The resultant string is of the form "-ddd.ddd..." where each 'd' indicates a digit (0-9). The string starts with a minus sign if the number is negative.

    Note: If the precision specifier is omitted, the default numeric precision is used.

    {0:f4} = 1.4200 

    {1:F} = -12400.00

    G or g

    General

    The number is converted to the most compact of either fixed-point or scientific notation, depending on the type of the number and whether a precision specifier is present.

    Note: If the precision specifier is omitted or zero, the type of the number determines the default precision.

    {0:g5} = 1.42 

    {1:g1} = -1e+04

    {1:G} = -12400

    N or n

    Number

    The resultant string is of the form "-d,ddd,ddd.ddd...", where each 'd' indicates a digit (0-9). The string starts with a minus sign if the number is negative. Thousand separators are inserted between each group of three digits to the left of the decimal point.

    Note: If the precision specifier is omitted, the default numeric precision is used.

    {0:N} = 1.42  

    {1:n3} = -12,400.000

    P or p

    Percent

    The resultant string represents a percent, which has been multiplied by 100 first. If the number is negative, the string starts with a minus sign.

    Note: If the precision specifier is omitted, the default numeric precision is used.

    {0:p} = 142.00 %  

    {1:P0} = -1,240,000 %

    R or r

    Round-trip

    The round-trip specifier guarantees that a numeric value converted to a string can be parsed back into the same numeric value. Any precision specifier appended to the round-trip format specifier is ignored.

    Note: This format is supported by floating-point types only.

    {0:R5} = 1.42  

    {1:r} = Not allowed.

    X or x

    Hexadecimal

    The resultant string is a series of hexadecimal digits. The case of the format specifier indicates whether to use uppercase or lowercase characters for the hexadecimal digits greater than 9. The precision specifier indicates the minimum number of digits desired in the resulting string, if required, the number is padded with zeros to its left to produce this number.

    Note: This format is supported for whole numbers only.

    {0:x} = Not allowed.    

    {1:x} = cf90

    {1:X7} = 000CF90

    Custom numeric format specifiers: If the commonly used numeric format specifiers do not provide the type of formatting you require, use these custom format strings to further enhance your output.

    Note: A commonly used format string consists of a single alphabetic character optionally followed by a sequence of digits that form a value between 0 and 99; all other format strings are custom format strings.

    The following table shows the characters you can use to create custom numeric format strings and their definitions.

    Note1: The output produced by some of these characters is influenced by the current Regional Options settings. Computers using different settings will generate different results.

    Note2: The example outputs specified in this table assume that a Double value of 1500.42 is assigned to input 0.

    Format SpecifierNameDescriptionFormat string = Output

    0

    Zero placeholder

    If the value being formatted has a digit in the position where the '0' appears in the format string, then that digit is copied to the resultant string.

    Note: The position of the leftmost '0' before the decimal point and the rightmost '0' after the decimal point determines the range of digits that are always present in the resultant string.

    {0:00.0000} = 1500.4200

    #

    Digit placeholder

    If the value being formatted has a digit in the position where the '#' appears in the format string, then that digit is copied to the resultant string, otherwise, nothing is stored in that position in the resultant string.

    Note: This specifier never displays the '0' character if it is not a significant digit, even if '0' is the only digit in the string.

    {0:(#).##} = (1500).42

    .

    Decimal point

    The first '.' character in the format string determines the location of the decimal separator in the formatted value; any additional '.' characters are ignored.

    Note: The character used as a decimal separator may vary.

    {0:0.0} = 1500.4

    ,

    Thousand separator

    If the format string contains a ',' character between two digit placeholders (0 or #) and to the left of the decimal point if one is present, then the output will have thousand separators inserted between each group of three digits to the left of the decimal separator.

    {0:0,0} = 1,500

    ,.

    Number scaling

    If the format string contains one or more ',' characters immediately to the left of the decimal point, then the number will be divided by the number of ',' characters multiplied by 1000 before it is formatted.

    Note1: The character used as a decimal separator may vary.

    Note2: Use of the ',' character to indicate scaling does not include thousand separators in the formatted number.

    {0:0,.} = 2

     

    Note: To scale a number by 1 million and insert thousand separators you would use the format string "#,##0,,".

    %

    Percentage placeholder

    The presence of a '%' character in a format string causes a number to be multiplied by 100 before it is formatted.

    {0:0%} = 150042%

    ;

    Section separator

    The ';' character is used to separate sections for positive, negative, and zero numbers in the format string.

    Note: The second section might be left empty (by having nothing between the semicolons), in which case the first section applies to all nonzero values.

    {0:$#,#;($#,#);Zero} = $1,500

    Note: It will output the same format but in parentheses if the number is negative, and will output the string "Zero" if the number is zero.

    E0

    E+0

    E-0

    e0

    e+0

    e-0

    Scientific notation

    If any of the strings "E", "E+", "E-", "e", "e+", or "e-" are present in the format string and are followed immediately by at least one '0' character, then the number is formatted using scientific notation with an 'E' or 'e' inserted between the number and the exponent. The number of '0' characters following the scientific notation indicator determines the minimum number of digits to output for the exponent. The "E+" and "e+" formats indicate that a sign character (plus or minus) should always precede the exponent. The "E", "E-", "e", or "e-" formats indicate that a sign character should only precede negative exponents.

    {0:00e+0} = 15e+2

    'ABC'

    "ABC"

    Literal string

    Characters enclosed in single or double quotes are copied to the result string literally, and do not affect formatting.

     

    Other

    All other characters

    All other characters are copied to the result string as literals in the position they appear.

     

  2. Date and Time Format Specifiers: This provides both the commonly used and custom date and/or time formats, along with examples.

    Commonly used date and time format specifiers: These produce standard date and time formats.

    These date and time format strings, consist of a single format specifier character from the following table.

    Note: If the format string is longer than a single character (even if the extra characters are white spaces), the format string is interpreted as a custom format string.

    The following table describes these standard date and time format strings.

    Note1: The output produced by some of these format specifiers is influenced by the current Regional Options settings. Computers using different settings will generate different results.

    Note2: The example outputs specified in this table assume that a DateTime value of 8/20/2004 11:12:45 AM is assigned to input 0.

    Format SpecifierNameNotesFormat string = Output

    d

    Short date pattern

    This formatting may vary.

    {0:d} = 8/20/2004

    D

    Long date pattern

    This formatting may vary.

    {0:D} = Friday, August 20, 2004

    t

    Short time pattern

    This formatting may vary.

    {0:t} = 11:12 AM

    T

    Long time pattern

    This formatting may vary.

    {0:T} = 11:12:45 AM

    f

    Full date/time pattern (short time)

    Displays a combination of the long date and short time patterns, separated by a space.

    {0:f} = Friday, August 20, 2004 11:12 AM

    F

    Full date/time pattern (long time)

    This formatting may vary.

    {0:F} = Friday, August 20, 2004 11:12:45 AM

    g

    General date/time pattern (short time)

    Displays a combination of the short date and short time patterns, separated by a space.

    {0:g} = 8/20/2004 11:12 AM

    G

    General date/time pattern (long time)

    Displays a combination of the short date and long time patterns, separated by a space.

    {0:G} = 8/20/2004 11:12:45 AM

    M or m

    Month day pattern

    This formatting may vary.

    {0:m} = August 20

    R or r

    RFC1123 pattern

    This formatting always adheres to the following defined standard pattern: "ddd, dd MMM yyyy HH:mm:ss G\MT".

    Note: The time displayed is for local, rather than universal (GMT) time.

    {0:R} = Fri, 20 Aug 2004 11:12:45 GMT

    s

    Sortable date/time pattern; conforms to ISO 8601

    This formatting always adheres to the following custom pattern "yyyy-MM-ddTHH:mm:ss".

    {0:s} =2004-08-20T11:12:45

    u

    Universal sortable local date/time pattern

    This formatting always adheres to the following defined standard pattern: "yyyy-MM-dd HH:mm:ssZ".

    Note: The time displayed is for local, rather than universal (GMT) time.

    {0:u} = 2004-08-20 11:12:45Z

    U

    Universal sortable GMT date/time pattern

    Note: The time displayed is for the universal (GMT), rather than local time.

    {0:U} = Friday, August 20, 2004 9:12:45 AM

    Note: This currently non-sortable format is caused by .NET.

    Y or y

    Year month pattern

    This formatting may vary.

    {0:y} = August, 2004

    Custom date and time format specifiers: If the commonly used date and time format specifiers do not provide the type of formatting you require, you can use custom format strings to further enhance your output.

    Combine one or more of the following custom format specifiers to construct a format that yields the output you prefer.

    The following table describes the custom format specifiers and the results they produce.

    Note1: The output produced by some of these format specifiers is influenced by the current Regional Options settings. Computers using different settings will generate different results.

    Note2: The example outputs specified in this table assume that a DateTime value of 8/20/2004 1:14:48 PM is assigned to input 0.

    Format SpecifierNameNotesFormat string = Output

    d

    Single or double digit day

    Displays the current day of the month, as a number between 1 and 31, inclusive. If the day is a single digit only (1-9), then it is displayed as a single digit.

    Note: If this single 'd' format specifier is used alone, without other custom format strings, it will be interpreted as the standard short date pattern format specifier.

    {0:%d} = 20

    dd

    Double digit day

    Displays the current day of the month, as a number between 1 and 31, inclusive. If the day is a single digit only (1-9), it is formatted with a preceding 0 (01-09).

    {0:dd} = 20

    ddd

    Abbreviated day name

    Displays the abbreviated name of the day.

    {0:ddd} = Fri

    dddd (or more d's)

    Full day name

    Displays the full name of the day.

    {0:ddddd} = Friday

    f, ff, fff, ffff, fffff, ffffff, fffffff

    Second fractions

    Displays seconds fractions represented by a number of digits, which are determined by the number of f's that are used (up to 7 digits).

    Note: If this single 'f' format specifier is used alone, without other custom format strings, it will be interpreted as the full (long date + short time) format specifier.

    {0:%f} = 7

    {0:ffff} = 7724

    g (or more g's)

    Era

    Displays the era (A.D. for example) .

    Note: If this single 'g' format specifier is used alone, without other custom format strings, it will be interpreted as the standard general format specifier.

    {0:gg} = A.D.

    h

    Single or double digit hour

    Displays hours in the range 1-12, representing whole hours passed since either midnight (12)  or noon (12). If this format is used alone, then the same hour before or after noon is indistinguishable. If the hour is a single digit (1-9), it is displayed as a single digit.

    Note: No rounding occurs when displaying the hour. For example, a time of 5:43 returns 5.

    {0:h} = 1

     hh (or more h's)

    Double digit hour

    Displays hours in the range 1-12, representing whole hours passed since either midnight (12) or noon (12). If this format is used alone, then the same hour before or after noon is indistinguishable. If the hour is a single digit (1-9), it is formatted with a preceding 0 (01-09).

    {0:hhh} = 01

    H

    Single or double digit hour, 24hr format

    Displays hours in the range 0-23, representing whole hours passed since midnight (0). If the hour is a single digit (0-9), it is displayed as a single digit.

    {0:H} = 13

    HH (or more H's)

    Double digit hour, 24hr format

    Displays hours in the range 0-23, representing whole hours passed since midnight (0). If the hour is a single digit (0-9), it is formatted with a preceding 0 (01-09).

    {0:HHHHH} = 13

    m

    Single or double digit minute

    Displays minutes in the range 0-59, representing whole minutes passed since the last hour. If the minute is a single digit (0-9), it is displayed as a single digit.

    Note: If this single 'm' format specifier is used alone, without other custom format strings, it will be interpreted as the standard month day pattern format specifier.

    {0:%m} = 14

    mm (or more m's)

    Double digit minute

    Displays minutes in the range 0-59, representing whole minutes passed since the last hour. If the minute is a single digit (0-9), it is formatted with a preceding 0 (01-09).

    {0:mmmm} = 14

    M

    Single or double digit month

    Displays the month, as a number between 1 and 12, inclusive. If the month is a single digit (1-9), it is displayed as a single digit.

    Note: If this single 'M' format specifier is used alone, without other custom format strings, it will be interpreted as the standard month day pattern format specifier.

    {0:%M} = 8

    MM

    Double digit month

    Displays the month, as a number between 1 and 12, inclusive. If the minute is a single digit (0-9), it is formatted with a preceding 0 (01-09).

    {0:MM} = 08

    MMM

    Abbreviated month name

    Displays the abbreviated name of the month.

    {0:MMM} = Aug

    MMMM (or more M's)

    Full month name

    Displays the full name of the month.

    {0:MMMM} = August

    s

    Single or double digit second

    Displays seconds in the range 0-59, representing whole seconds passed since the last minute. If the second is a single digit (0-9), it is displayed as a single digit only.

    Note: If this single 's' format specifier is used alone, without other custom format strings, it will be interpreted as the standard sortable date/time pattern format specifier.

    {0:%s} = 48

    ss (or more s's)

    Double digit second

    Displays seconds in the range 0-59, representing whole seconds passed since the last minute. If the second is a single digit (0-9), it is formatted with a preceding 0 (01-09).

    {0:sss} = 48

    t

    Abbreviated A.M./P.M. designator

    Displays the first character of the A.M./P.M. designator. If the total number of whole hours passed is less than 12, then the P.M. designator is used. Otherwise, the P.M. designator is used.

    Note: If this single 't' format specifier is used alone, without other custom format strings, it will be interpreted as the standard long time pattern format specifier.

    {0:%t} = P

    tt (or more t's)

    Full A.M./P.M. designator

    Displays the full A.M./P.M. designator. If the total number of whole hours passed is less than 12, then the P.M. designator is used. Otherwise, the P.M. designator is used.

    {0:ttttt} = PM

    y

    Single or double digit year

    Displays years, by omitting the first two digits of the year. If the year is a single digit (1-9), it is displayed as a single digit.

    Note: If this single 'y' format specifier is used alone, without other custom format strings, it will be interpreted as the standard short date pattern format specifier.

    {0:%y} = 4

    yy

    Double digit year

    Displays years, by omitting the first two digits of the year. If the year is a single digit (1-9), it is formatted with a preceding 0 (01-09).

    {0:yy} = 04

    yyyy

    Four digit year

    Displays years, including the century. If the year is less than four digits in length, then preceding zeros are appended as necessary to make the displayed year four digits long.

    {0:yyyy} = 2004

    z

    Single or double digit time zone offset in hours.

    Displays the time zone offset for the system's current time zone in whole hours only.
    The offset is always displayed with a leading or trailing sign (zero is displayed as "+00"), indicating hours ahead of Greenwich mean time (+) or hours behind Greenwich mean time (-). The range of values is –12 to +13.
    If the offset is a single digit (0-9), it is displayed as a single digit with the appropriate leading sign.
    The displayed offset is affected by daylight savings time.

    {0:z} = +2

    zz

    Double digit  time zone offset in hours.

    Displays the time zone offset for the system's current time zone in whole hours only.
    The offset is always displayed with a leading or trailing sign (zero is displayed as "+00"), indicating hours ahead of Greenwich mean time (+) or hours behind Greenwich mean time (-). The range of values is –12 to +13.
    If the offset is a single digit (0-9), it is formatted with a preceding 0 (01-09) with the appropriate leading sign.
    The displayed offset is affected by daylight savings time.

    {0:zz} = +02

    zzz (or more z's)

    Full time zone offset (hours and minutes)

    Displays the full time zone offset for the system's current time zone in hours and minutes.
    The offset is always displayed with a leading or trailing sign (zero is displayed as "+00:00"), indicating hours ahead of Greenwich mean time (+) or hours behind Greenwich mean time (-). The range of values is –12:00 to +13:00.
    If the offset is a single digit (0-9), it is formatted with a preceding 0 (01-09) with the appropriate leading sign.
    The displayed offset is affected by daylight savings time.

    {0:zzzz} = +02:00

    :

    Time separator

    Separates the components within a displayed time.

    {0:hh:mm:ss} = 01:14:48

    /

    Date separator

    Separates the components within a displayed date.

    {0:dd/mm/yyyy} = 20/14/2004

    %c

    Standard format specifier usage override for identical custom format specifier characters.

    Where 'c' is both a standard format specifier and a custom format specifier, this will display the custom format pattern associated with the format specifier. Otherwise 'c' would be interpreted as a standard format specifier.

    {0:%d} = 20

  3. String: Although no additional format specifiers are specifically supported for strings:
  • Characters enclosed in single (') or double quotes (") are copied to the output literally, and do not affect formatting.
  • Any text or numbers typed into the format string, which are not in curly brackets {} will be displayed as-is in the output.
  • Any value that is manually entered into the input of the String Format spider, will ONLY be interpreted as a String value.

Note1: The colon (:) is required if dataFormat is specified.

Note2: This dataFormat is read from left to right.

Note3: If this dataFormat is not specified, the general ("G") format specifier is used.

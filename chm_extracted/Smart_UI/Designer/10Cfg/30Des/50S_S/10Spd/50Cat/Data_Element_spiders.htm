Data Element spiders

The Data Element spider is a Data spider, which allows you to connect a data elementa finite component of data contained within a datasource that behaves in a generic manner; typically a value. See datasource. or a placeholder for a data element to or from another data element or a property of a graphic forma document that belongs to a project, which can be designed to graphically display data to the user and to accept input from the user when it is being operated. or one of its form componentsa general term encompassing all the controls, components and / or graphic elements that can be added to graphic forms, to provide the required user interface for its end-users. See control; component; graphic element; graphic form..

This spider has the following two modes of creation and operation:

  • Automatic: this is the typical usage, in which this spider is added automatically whenever the user drags a data element of an existing datasource onto the associated graphic form or directly onto another spider in the spider workspace. More details:

In this case the namespaceone or more names separated by periods (or dots), where each name represents an individual item and the entire namespace indicates the relationship or lineage of the leftmost term i.e. grandparent.parent.child. of this spider should be the EXACT name of its associated data element, which is typically: ServerName.datasourceName.dataElementName.

Note: It is also possible to alter this ServerName, at any time, for all of its data elements used within a spider workspace. For details, see Changing data element referencing. 

  • Manual: this spider can be manually added to the spider workspace to create either a data element substitution for a wizardA pre-drawn and/or pre-configured skeleton of graphical objects and their assigned Behaviours (if any), which has placeholders (substitutions) for data elements. or a place holder for a data element of a datasource that is currently unavailable. More details:

  • For details on creating a data element substitutiona placeholder for a data element in a wizard. for a wizard, see Working with substitutions.

    IMPORTANT: These substitutions ONLY apply to wizards and NOT to graphic forms!

  • When creating a place holder for a data element of a datasource that is currently unavailable or will be added later:

In this case the namespaceone or more names separated by periods (or dots), where each name represents an individual item and the entire namespace indicates the relationship or lineage of the leftmost term i.e. grandparent.parent.child. of this spider should be the EXACT name of its associated data element, which is typically: ServerName.datasourceName.dataElementName.

Note: It is also possible to alter this ServerName, at any time, for all of its data elements used within a spider workspace. For details, see Changing data element referencing. 

When the spider workspace (engine) is started, an initial bulk read of all the data elements is performed and their initial values are retrieved. After this, Data Element spiders only receive changes made to their data elements from the Server.

 

Triggering: When you triggerthe action of causing a spider to perform its specific operation, which usually involves communicating and / or manipulating data from its set of inputs to its set of outputs. See spider. a Data Element spider its input value is written to the Server:

Although, this assumes that its datasource and its security configuration allows the value of this data element to be modified.

By default, this spider is triggered by means of silks, although it can also be triggered by events. These triggering methods can be configured via its spider menu, see Configuration below.

Note: Triggering only occurs when the spider workspace is running i.e. this only occurs for graphic forms when they are loaded in Run mode or opened in the SmartUI Operator.

Configuration: This describes the available menu items and inputs and outputs of this spider:

Spider menu: This describes the available menu items and their default settings for this spider. 

Note1: This menu can be accessed by selecting the spider and right-clicking its title bar. For details, see Selecting spiders.

Note2: Menu items that are enabled will have a tick mark to the left of them.

  1. Detail View: This can be used to display the configuration view of this spider, so its name, description, inputs and outputs can be configured. For details, see Working with spider configuration views.

Tip: Double-click the title bar of the spider to display or hide the configuration view of the spider.

  1. Delete Spider: This can be used to remove this spider from the spider workspace. For details, see Removing spiders.
  2. Trigger Spider From Event: When this triggering method is enabled, this spider is triggered after the specified event is raised. For details, see Triggering a spider from an event. This is disabled by default.

  3. Substitutions: To create either a data element substitution for a wizardA pre-drawn and/or pre-configured skeleton of graphical objects and their assigned Behaviours (if any), which has placeholders (substitutions) for data elements. or a place holder for a data element of a datasource that is currently unavailable. For details, see the details provided for the manual creation method above.

    Tip: The Substitutions dialog is also displayed by clicking the Substitutions spider toolbar button.

  4. Enable Silk Triggering: When this triggering method is enabled, a silk triggers this spider, after it has set this spider’s input value. For details, see Triggering spiders. This is enabled by default.

Note: A silk is only able to trigger this spider in this way, if its Trigger Output Spider setting is enabled. For details, see Disabling silk triggering of spiders.

  1. Trigger Now!: This will cause this spider to immediately be triggered.

 

Inputs and outputs: This describes the available inputs and outputs displayed by the default configuration view of this spider.

Note1: Before the spider can be configured, its configuration view needs to be displayed. For details see Displaying spider configuration views.

Note2: For details on using the general fields and sections of the configuration view, see Working with spider configuration views.

This default configuration view of this spider, contains the following sections:

  1. Inputs, this section contains the inputs to this spider.

Note: These inputs can either be configured within the spider itself and/or may require their values to be supplied by other spiders or Data spiders (e.g. properties or data elements). For details, see Creating silks.

Application spiders

The Application spider can interact with a graphic form within the SmartUI Operator when this spider is triggered.

For instance, opening, closing or printing a graphic form when an event occurs, such as by clicking a button or logging the current user on or off.

Note: Each action or command can be confirmed and/or logged to the event log - see the spider inputs for more details.

Note: You CANNOT test this spider in the SmartUI Designer in Run mode, when performing graphic forms operations (opening, closing etc.) - this functionality is only available in the SmartUI Operator. If you try to do so, an alert informing you of this is displayed.

  • To add this spider to the spider workspace.

  • To open a graphic form from an event.

    Note: If the specified graphic form does not exist (either was typed in incorrectly or this spider was copied from another project), then when this spider is triggered in the SmartUI Operator, it opens the specified graphic form containing the text 'graphic form not found'.

    Tip: If necessary a graphic form can be opened within a specific TemplateGOa Template Graphic Object control that displays a graphic form and connects data elements to any aliases of this graphic form. control on this graphic form.

  • To close a graphic form from an event.

Tip: To close the current graphic form, either set the Action input to Close this form action, which does not require or provide the Graphic Form input or set the Action input is Close and do not specify the Graphic Form input (leave it blank).

This spider can perform the following additional commands:

  1. Print this form: This sends the currently displayed graphic form to the default printer and therefore does NOT provide the Graphic Form input.

  2. Log off: to log off the current Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. user, you configure this command as follows:

    • No further configuration is required to simply log off the current user.
    • If you have configured an auto-login account for this Client, then you can check the Auto login checkbox to automatically log in again using the specified auto-login user credentials.

    This, in effect, performs a “switch user” operation for the pre-configured auto-login user.

  3. Log on: to perform a “switch user” operation by logging in another user, you configure this command as follows:

    • Username: either type in the name of the required Allowed or Impersonated user or use the browse button to use the User Browser to specify this user name.
    • Password: type in the required password of the selected user.

Configuration

Spider menu: This describes the available menu items and their default settings for this spider. 

Note: Menu items that are enabled will have a tick mark to the left of them.

  1. Detail View: This can be used to display the configuration view of this spider, so its name, description, inputs and outputs can be configured. For details, see Working with spider configuration views.

Tip: Double-click the title bar of the spider to display or hide the configuration view of the spider.

  1. Delete Spider: This can be used to remove this spider from the spider workspace. For details, see Removing spiders.
  2. Trigger Spider From Event: This enables the spider to be triggered (which will run its script) by means of an event. For details, see Triggering a spider from an event. This is enabled by default, since this is the preferred method for performing this spider's function.
  3. Enable Silk Triggering: This enables the spider to be triggered (which will run its script) by any silks that are attached to the inputs of this spider. For details, see Triggering spiders. This is disabled by default.
  4. Propagate Outputs At Startup: This enables the spider to supply the silks connected to its outputs with values as soon as its spider workspace enters into running mode. For details, see Working with spider workspaces or Sending spider outputs at startup. This is disabled by default.
  5. Trigger Now! : This will cause this spider to immediately be triggered.
  6. Add Alias Inputs: If the graphic form that you open contains aliases, then use this option to expose these aliases as additional inputs.

 

Inputs and outputs: This describes the available inputs and outputs displayed by the default configuration view of this spider.

This default configuration view of this spider, contains the following sections:

  1. Inputs, this section contains the inputs to this spider.
Input Data Function

Graphic Form

DE

This specifies the graphic form used by the Action input. For details, see Methods of specifying graphic forms.

Action

List

The graphic form actions, which determines the other available inputs , as follows:

  1. Open : This will open the graphic form specified by the Graphic Form input, and display it in a manner specified by its Open Graphic Form As input, as follows:
  2. ModalForm : This will open as a separate window that requires the user to interact with it or close it before being able to continue using the application. This is the default selection.
  3. ModelessForm : This will open as a separate window that allows the user to interact with it and also return to a previous task without closing it.
  4. TabPage : This will open, normally, as another tabbed page within the workspace.
  5. Replace : This graphic form will replace the currently displayed graphic form.
  6. Template Graphic Object: the graphic form is opened within a specific Template Graphic Object control.

This option displays the Template Graphic Object input to specify the name of the required Template Graphic Object control, from the list - assuming that one or more TemplateGO controls have been added to the graphic form on which this Application spider is on.

The TemplateSet input can specify which template set to activate when this graphic form is opened.

The Level input can specify which level should be visible when this graphic form is opened.

The Location input can specify the location of the opened graphic form at runtime - preferably as a Point data typethe format of this data type are two integer values separated by a comma e.g. 34,56. or a String in the format: 'X,Y' that represents the X and Y coordinates of the upper left corner of the graphic form e.g. 50,50.

Note: If empty (default) the location property of the specified graphic form is used.

The size input can specify the size of the opened graphic form at runtime - preferably as a Point data type or a String in the format: 'Width,Height' that represents the width and height of this graphic form in pixels e.g. 800,600.

Note: If empty (default) the size property of the specified graphic form is used.

For example, open the graphic form on the mouse Click event, then pass the mouse location and the desired size which can vary on where the user clicked.

  • Check the Center Screen checkbox (this is checked by default) to open this graphic form in the center of the screen.
  • Uncheck the Center Screen checkbox and use a Click event to trigger this spider and open this graphic form where the user clicks.

Confirm Action?

Boolean

This enables or disables the display of a confirmation dialog before the action specified by the Action input is performed.

Confirmation message

String

The informative text that is displayed by the confirmation dialog, which depends upon the action that is being performed, as follows:

  1. Open: Open the graphic form {0}?
  2. Close: Close the graphic form {0}?
  3. Close this form: Close the graphic form {0}?
  4. Print this form: Print this graphic form {0}?
  5. Log off: Log off the current user {1}?
  6. Log on: Log on with the user {2}

When specifying this text, the following placeholders can be used:

{0}: The name of the specified (or currently selected) graphic form.

{1}: The user name, of the currently logged in user, typically specified for the log off and log on actions

{2}: The user name specified by the Username input when performing a Log on action.

 
Log Actioned Event? Boolean

This enables or disables the logging of an event to an event log when the action specified by the Action input is performed.

For details on configuring or viewing the location of the Server event log where this event will be logged, see General Server settings.

EventLog message

String

The text that is displayed by the logged event, which depends upon the action that is being performed, as follows:

  1. Open: [{1}] has opened the graphic form {0}
  2. Close: [{1}] has closed the graphic form {0}
  3. Close this form: [{1}] has closed the graphic form {0}
  4. Print this form: [{1}] has printed this graphic form {0}
  5. Log off: [{1}] has logged off
  6. Log on: [{1}] has logged on with the user {2}

When specifying this message, the following placeholders can be used:

{0}: The name of the specified (or currently selected) graphic form.

{1}: The user name, of the currently logged in user, typically specified for the log off and log on actions

{2}: The user name specified by the Username input when performing a Log on action.

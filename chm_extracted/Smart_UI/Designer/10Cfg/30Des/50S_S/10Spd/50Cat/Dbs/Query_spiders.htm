Query spiders

The Query spider can perform queries and execute statements provided by any OLE DB datasource. For details on queries in general, see About queries.

 

To add this spider

 

For a practical example of using Select queries one of which uses parameters, which are supplied by controls on a graphic form, see How to chart and/or report data from a database.

Note: Ensure that the Success output is True (i.e. the query ran successfully), if this is False then there is either a problem with the query syntax or another problem preventing this query from running.

Tip: The Rows Exist output is only True when the query returns data and is False if an empty dataset is returned.

To perform a Select query : to select a sub-set of your data for specific uses or requirements.

To perform an Insert query : to insert records into a specific table or view.

To perform an Update query : to update the values of specific fields of a database table or view.

To perform an Delete query : to delete records from a specific table or view.

To perform an Execute Statement : to run predefined stored procedures or user-functions of the database.

To perform an Create Table query : to create tables in the database with specific structures.

To perform an Drop Table query : to delete a table or view from the database.

 

To perform an Custom query : to allow users to perform their own queries 'on-the-fly'.

 

Configuration

Spider menu: This describes the available menu items and their default settings for this spider. 

Note: Menu items that are enabled will have a tick mark to the left of them.

  1. Detail View: This can be used to display the configuration view of this spider, so its name, description, inputs and outputs can be configured. For details, see Working with spider configuration views.

Tip: Double-click the title bar of the spider to display or hide the configuration view of the spider.

  1. Delete Spider: This can be used to remove this spider from the spider workspace. For details, see Removing spiders.
  2. Trigger Spider From Event: This enables the spider to be triggered by means of an event. For details, see Triggering a spider from an event. This is enabled by default, since this spider will usually be triggered by this method.
  3. Enable Silk Triggering: This enables the spider to be triggered by any silks that are attached to the inputs of this spider. For details, see Triggering spiders. This is disabled by default.
  4. Trigger Now!: This will cause this spider to immediately be triggered.

 

Inputs and outputs: This describes the available inputs and outputs displayed by the default configuration view of this spider.

This default configuration view of this spider, contains the following sections:

  1. Inputs, this section contains the inputs to this spider.
Input Function

Server

A drop-down list of the names of all the connected Servers that are available.

Tip: Use the Default Server selection, where possible, when referring to datasources on the login Server to simply the importing of this spider. Otherwise this Server input will need to be reconnected after this spider has been imported.

OLEDB Data Source

A drop-down list of the names of all the OLE DB datasources that have been configured on the Server that has been selected in the Server list box.

The OLE DB datasource that was first added to this Server is selected by default.

Note: This displays all the OLE DB datasources, whether they have queries configured or not.

Query Type

A drop-down list of the names of all the query categories or tasks provided by the OLE DB datasources.

The Select Query category is selected by default.

Query Name

A drop-down list of the names of all the queries of the query category specified by the Query Type input for the specified OLEDB Data Source.

Note: If the selected query contains parameters, the names of these parameters will be added as additional inputs to the Inputs section.

Confirm Action

If enabled, this displays a confirmation dialog before this query is performed. Typically this should be used when inserting, updating or deleting records and/or tables.

This is enabled by default.
  1. Outputs, this section contains the outputs for this spider.
Output Data Function

Return Object

Boolean

If the query produces an output, then this contains the this result when the query is successfully performed.

For instance for the Select query this contains the DataSet of records that can be displayed by a control on a graphic form.

Return Information

String

This displays additional feedback concerning the status of the Success output, such as how many rows were returned, updated or removed or this describes the cause of any errors.

Success

Boolean

This is True when the query is successfully performed. If this fails (False) then there may be a problem with the query syntax or another problem preventing the running of the query.
Rows Exist Boolean

This is True when the query returns data (one or more records) and False when an empty dataset is returned.

Tip: This can be used to hide or show a control depending upon whether it contains data or not.
  1. Event Trigger, this section is used to specify the event that is used to trigger this spider. This is typically a control added to the graphic form, such as a Button control, which uses its Click event to perform the query. For details, see Triggering a spider from an event.

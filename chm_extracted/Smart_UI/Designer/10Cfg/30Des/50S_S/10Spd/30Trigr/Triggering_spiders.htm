Triggering spiders

Spiders need to be triggered so they can perform their functions.

Spiders can be triggered using a variety of methods, choose the method that best suits your purpose:

  1. Silk triggering: The default triggering method, where each silk connected to the input of a spider can trigger this spider.

    In other words a silk will trigger its destination spider, after the output value of its source spider changes. 

    Note: Certain spiders disable this triggering method by default.

    For instance, if spiderA is connected to spiderB, by silkA, then whenever the specified output value of spiderA changes, silkA will update spiderB’s input and then trigger spiderB to perform its operation.

    Note1: It is recommended to use silk triggering when transferring data between spiders instead of event triggering.

    Note2: It may be necessary to disable this default triggering of some or all of the silks connected to a spider, for instance, when using another means of triggering. For details, see Disabling silk triggering of spiders.

  1. Event triggering: This involves triggering the spider after a specific event or action is performed:
  2. by a spider, which has already been added to this spider workspace e.g. if an input of the specified spider is changed.
  3. upon a control, which has already been added to the currently edited graphic form e.g. if the specified button control is clicked.

Typically used to trigger spiders based on user input. For configuration details, see Triggering a spider from an event.

Note: Title bars contain icons that indicate the status of the Trigger Spider on Event and Propagate Outputs At Startup spider properties respectively. For details, see Spider property indicators.

  1. Manual triggering: This involves immediately triggering the spider, by manually selecting its Trigger Now! menu item to simplify the process of testing spider functionality.

    This method of triggering allows a user to easily trigger any spider, as and when is necessary. For details, see Configuring spiders.

  2. Spider triggering: The Trigger spider, allows users to tailor the triggering of their existing spiders to their own requirements.

    This spider is able to trigger one or more spiders at the same time, whenever it is itself triggered. For details, see Trigger spiders.

Note1: Triggering is supported by all spiders that are have inputs.

Note2: Triggering only occurs when the spider workspace is running i.e. this only occurs for graphic forms when they are displayed in Run mode or within the SmartUI Operator.

Available spiders

Spiders and their links (silks) are essentially a visual programming language, which allows data to be transferred and/or manipulated, typically by means of drag and drop. Click for more information:

For an overview, see Introduction to spiders and silks.

Spiders are usually only manually added to the spider workspace, to perform additional manipulation or formatting of data. For details on how to add a spider to the spider workspace, see Adding spiders.

Tip: In addition to manually configuring spiders and silks, it is also possible to perform bulk configuration, by exporting and importing this configuration. For details, see Importing spiders and silks.

Spiders are organised into the following categories to make it easier to selected the required spider:

  • Advanced: Spiders that perform advanced functionality or configuration, such as, providing scripting functionality, adding performance counters, executing special functions, formatting string values or changing the visible level of a graphic form or dynamically changing the names of data elements and if necessary configuring their values.

    This briefly describes the operation performed by each of its spiders:

    1. Levels And Layers: To change the visible level of a graphic form at runtime. For details, see Levels And Layers spiders.
    2. Performance Counter: To add performance counters to monitor the performance of your system. For details, see Performance Counter spiders.
    3. Script Engine: To create script objects that interact with the Client and if necessary with the Server, to perform customised functionality. For details, see Script Engine spiders.
    4. Special Function: To execute any special function provided by any of the configured datasources. For details, see Special Function spiders.
    5. String Format: To format one or more values, if necessary, and display them as a single formatted string. For details, see String Format spiders.
    6. Variable Data Element: To dynamically change a portion of or the entire names of data elements and if necessary configure their values. For details, see Variable Data Element spiders.
  • Animation: Spiders that animate graphic forms, for instance, by varying the colors displayed by color properties of components within the graphic form.

    This briefly describes the operation performed by each of its spiders:

    1. Blinking: To start and stop a color alternating between two pre-defined colors at a specified interval and to display another pre-defined color when this blinking is stopped. For details, see Blinking spiders.
    2. Multi-state color: To define colors that provide a visual indication of the current value/s of either String, Double or Integer value/s. For details, see Multi-state color spiders.
  • Application: Spiders that perform application-level tasks, such as opening or closing graphic forms within the Operator application or that display dialogs to enter data values or that launch other applications and command files.

    This briefly describes the operation performed by each of its spiders:

    1. Application: To open or close a graphic form in the SmartUI Operator. For details, see Application spiders.
    2. Data Entry: To enter a data value by displaying a dialog for this purpose at runtime. For details, see Data Entry spiders.
    3. Execute Command: To run an application (.EXE), command file (.CMD) or a batch file (.BAT) and, if necessary, specify any command-line parameters. For details, see Execute Command spiders.
  • Databasing: Spiders that perform database-specific tasks, such as performing queries or interacting with DataBinders.

    This briefly describes the operation performed by each of its spiders:

    1. DataBinder Trigger: To display or to save changes made to the data of a table in a DataBinder. For details, see DataBinder Trigger spiders.
    2. Query: To perform queries and execute statements provided by any OLE DB datasource. For details, see Query spiders.
  • Extended Type: Spiders that can configure or expose properties, such as specifying color or font properties that can dynamically change, splitting a data row into its column values, exposing hidden properties of objects, displaying the properties of data elements or mapping inputs to outputs to simplify the configuration of reusable graphics.

    This briefly describes the operation performed by each of its spiders:

    1. color: To select a color using a color edit box or define a color by individually manipulating its color constituents. For details, see color spiders.
    2. Data Row Splitter: To filter out a row from datasettabular data or data that is contained within one or more tables; each table contains one or more columns and each column consists of one or more rows. data and expose the values of its columns as outputs of this spider. For details, see Data Row Splitter spiders.
    3. Extended Data Element: To either display the properties of an existing data element or to create a data element from any input. For details, see Extended Data Element spiders.
    4. Font: To select a new font using the standard font dialog or to modify an existing font by independently adjusting certain of its attributes. For details, see Font spiders.
    5. Hidden Property: To expose and/or manipulate properties of the specified object that are normally hidden. For details, see Hidden Property spiders.
    6. Mapping: To map (connect) inputs to outputs, so that each input has an associated and identically named output.
      This spider is intended to act as a connection interface for reusable graphics to connect its necessary data easily i.e. without needing to configure its individual properties and/or spider inputs again. For details, see Mapping spiders.
    7. Multi-State: To create more than one “state” for a specific String, Double or Integer value, so that when this value falls within a defined state, the spider returns the value associated with this state. For details, see Multi-state spiders.
    8. Tooltip: To add a tool tip to a form component, to display additional information, which can include values. For details, see Tooltip spiders.
  • Logic: Spiders that construct logic expressions to perform various tasks by triggering one or more spiders, as an alternative to writing script.

    This briefly describes the operation performed by each of its spiders:

    1. AND: To create a logical expression and, if necessary to AND its result with another Boolean input. For details, see AND spiders.
    2. IF: To either create a logical expression. For details, see IF spiders.
    3. Logic Trigger: To create list of spiders that are triggered in order from top to bottom, when its Boolean Logical Result input becomes TRUE after having been FALSE. For details, see Logic Trigger spiders.
    4. OR: To create a logical expression and, if necessary to OR its result with another Boolean input. For details, see OR spiders.
    5. NOT: To NOT (inverse) its Boolean Logical Result input. For details, see NOT spiders.
  • Mathematical: Spiders that perform mathematical calculations, such as providing constants, creating custom expressions, scaling values, summing values, multiplying or dividing values.

    This briefly describes the operation performed by each of its spiders:

    1. Constant: To create user-defined constants and/or use the existing (standard) constants within other spiders. For details, see Constant spiders.
    2. Expression: To implement user-defined calculations, which can make use of variables. For details, see Expression spiders.
    3. Multiply and Divide: To multiply and divide multiple numerical values to produce the result. For details, see Multiply and Divide spiders.
    4. Operator Action: To perform various operations on an numerical or Boolean input. It is possible for this change in value to be confirmed and/or logged to an event log. For details, see Operator Action spiders.
    5. Scaling: To convert raw (unscaled) values into engineering (scaled) values. For details, see Scaling spiders.
    6. Summation: To add and subtract multiple numerical values to produce the result and to total all the values that are added and all the values that are subtracted. For details, see Summation spiders.
  • Simulation: Spiders that produce customizable simulated data, this is especially useful when the Designer is not connected to any datasources.

    This briefly describes the operation performed by each of its spiders:

    1. Simulation: To create simulated data. For details, see Simulation spiders.
  • Spider Workspace: Spiders that are used to perform spider-specific functionality, such as changing the active template set or triggering selected spiders.

    This briefly describes the operation performed by each of its spiders:

    1. Template Set: To change the active template set at runtime. For details, see Template Set spiders.
    2. Trigger: To create list of spiders that are triggered in order from top to bottom, whenever it is itself triggered. For details, see Trigger spiders.
  • Statistical: Spiders that perform statistical operations, such as counting on and off events or calculating statistical functions from an analog value.

    This briefly describes the operation performed by each of its spiders:

    1. Counter: To record the number of On and Off events that occur, for a Boolean value, and the individual and total time of these events. For details, see Counter spiders.
    2. Statistical Functions: To collect data from an analog (floating point) value and calculate statistical information (maximum, minimum, mean, standard deviation and total) from this collected data. For details, see Statistical Functions spiders.
  • XML: Spiders that either operate on or produce data in the XML format.

    This briefly describes the operation performed by each of its spiders:

    1. Extended XML: To expose XML properties defined within an XML document as outputs so they can be used individually, as required. For details, see Extended XML spiders.
  • Data Elements: Spiders that represent a data elementa finite component of data contained within a datasource that behaves in a generic manner; typically a value. See datasource..

    This briefly describes the operation performed by each of its spiders:

    1. Data Element: To create either a data element substitution for a wizardA pre-drawn and/or pre-configured skeleton of graphical objects and their assigned Behaviours (if any), which has placeholders (substitutions) for data elements. or a place holder for a data element of a datasource that is currently unavailable. For details, see Data Element spiders.

Note: Data spiders (data elements and/or properties) are a special 'hidden' subset of spiders, which are typically added automatically to the spider workspace.

These are called Data spiders as they manage the transfer of data to and from the spider workspace. For details, see Data spiders.

Working with template sets

The PRIMARY function of template sets, is to connect DIFFERENT sets of data to the SAME graphic form.

In this case create the Template sets connecting each of them to the SAME properties; then the currently active template set determines which set of data is displayed. Click for more information:

PLEASE NOTE: Spider template sets have nothing to do with TemplateGOs or SmartUI Templates and should not be confused with them!

Tip: If you need the SAME graphic form to connect to DIFFERENT data, then use TemplateGO controls to display the SAME graphic form the required number of times.

For more information and detailed procedures for this and other methods of re-using graphical components to speed up the process of creating graphic forms, see How to reuse graphical components.

Template sets are essentially sets of silks, which are used to control the transfer of data between spiders, by determining which of the silks are enabled or active as only one template set can be active at a time.

Note: The name of the currently active template set is specified in the top left corner of the spider workspace.

Once a template set is activated, its associated silks are enabled and the silks not associated with it are disabled. Only when a silk is enabled, are the spiders it connects able to transfer their data and therefore perform their functions. For details on silks, see Working with silks.

In this way, it is possible to vary the information and even its means of calculation, which is either displayed on a graphic form or mapped to a virtual data element. For details, see Animating graphic forms.

Tip: In addition to manually configuring spiders and silks and template sets, it is also possible to perform bulk configuration, by exporting and importing this configuration. For details, see Importing spiders and silks.

An example of its use:

Consider the case where a graphic form is constructed to represent a pump, which displays its status, its flow rate, its pressure and flow, by linking this data to the necessary properties by means of silks. Now consider the case where a battery of similar pumps are required, each requiring this same information to be displayed.

Instead of redrawing this pump and replicating in on multiple graphic forms graphic form and then attaching the correct data to each of these pumps individually, template sets can be used.

In this case the silks required to supply each individual pump with its required data could be created to this single pump graphic form and then associated with its own template set.

Then when the spider workspace is running, the active template set can be dynamically changed, as required, to display the correct information for each pump.

 

Template sets can be implemented in the following manner:

Click for more information about each step:

  1. One or more template sets can be added to a spider workspace. For details, see Adding template sets.

Note1: Every spider workspace has a template set called ‘Default’, which cannot be removed.

Note2: Each template set is specific to the spider workspace in which they are added.

  1. If necessary, specify which of these template sets is to be the active set. For details, see Activating template sets.

    This will enable all the silks associated with this template set are enabled and any silk(s) not associated with it is will be disabled.

Note1: Any silk associated with the Default template set will ALWAYS be enabled, irrespective of the currently active template set.

Note2: Any silks that are created are immediately associated with the currently active template set.

Note3: The active template set can be changed using a Template Set spider. For details, see Template Set spiders.

  1. Silks can be associated with as many template sets as is required. These associations can also be removed, if necessary. For details, see Associating silks with template sets.

WARNING! Any silk not associated with any template set will never be enabled.

Note1: If a template set is removed which had silks associated with it, then only their association to this template set will be removed and not the silks themselves. For details, see Removing template sets.

Note2: If a silk is only associated with a single template set, which is removed then it will remain deactivated until it is associated with an active template set.

Troubleshooting importing of spiders and silks

The Import Configuration spider workspace menu item, can be used to import the configuration of spiders and/or silks from a Microsoft Excel XML file into the selected spider workspace. This will re-configure the spider workspace to the configuration specified in this file.

Note: Importing can be used to re-configure and create spiders and silks and will not delete any spiders or silks that are not configured in the imported file.

Tip: It is highly recommended that close attention be paid to the Import Results dialog of the Import Wizard.

This is because it provides detailed information concerning the MANUAL configuration that still needs to be performed and all the spiders and/or silks that could not be imported.

To troubleshoot the importing of spiders and silks:

The troubleshooting of this wizard, is displayed per dialog, as follows:

The Import Configuration dialog:

On clicking Next the specified XML file is opened, so that the spider and/or silk configuration contained within it can be imported into this spider workspace.

Note: Microsoft Excel locks spreadsheet files that are currently open, which prevents them from being imported from.

Therefore ensure that the specified file is closed in Microsoft Excel before importing the spider and/or silk configuration into this spider workspace.

If the specified file could not be opened, any error(s) preventing this will be displayed in bold within this dialog, such as:

  • an invalid or nonexistent path or file
  • the file is read-only
  • the file has an incorrect format
  • the file was locked by another application
  • the file denied reading from to it 

 

The Map Worksheets dialog:

On clicking Next the necessary spreadsheet name(s) are processed. Therefore:

  • If the Silk Linking spreadsheet name is incorrectly specified the "Silk linking worksheet in incorrect format" error will be displayed in this dialog.
  • If the Spider Definitions spreadsheet name is incorrectly specified the "Spider Definitions worksheet in incorrect format" error will be displayed in this dialog.

Note: If ONLY importing silk or spider configuration, then ensure that the BLANK spreadsheet name is selected as the specified name for the OTHER spreadsheet, to prevent this incorrect format error.

 

The Spider Configuration dialog:

This displays the results of the comparison of the spiders referenced within the XML file with those present within this spider workspace, as follows:

Note: This dialog will be displayed even if ONLY the SILK configuration is being imported, so that any referenced spiders that do not exist can be created.

  1. The top list, displays the spiders that are ONLY referenced within the XML file and which need to be created. This list contains four columns, which provide important information concerning the success of importing these spiders, as follows:
  1. Name: Only spiders that have DIFFERENT names than the existing spiders in this spider workspace will appear in this list. Therefore any spider that has the same name as an existing spider will NOT be appear in this list EVEN if it is of a DIFFERENT type.
  2. Type: If spiders of Type 'property' are listed in this list, they will ONLY be created if the appropriately named control and its specified property exists in the graphic form associated with this spider workspace. For instance, textBox.text will only be imported if a control with the name of 'textBox', which has a property 'Text' exists.

WARNING! All names are case-sensitive, therefore ENSURE that the correct case is provided otherwise the specified items may NOT be recognised when they are imported. This includes the names of the spider types, data elements and controls, components and graphic elements and their property names.

  1. Configured Inputs and Configured Outputs: These columns give an indication of how many inputs and outputs have configurations that need to be imported from the spider configuration spreadsheet.

Note: Even if an input or output is specified as having been configured, this does not mean that it is actually connected to a silk.

  1. The middle list, contains any duplicate spiders or the spiders referenced in the XML file that ALREADY exist in this spider workspace, which can be selectively imported, as required.

WARNING! If any of these existing spiders are imported, they may MODIFY the existing configuration of these spiders, however they will not delete any existing inputs or outputs.

Note: ALL spiders that have the SAME name as an existing spider in this spider workspace will appear in this list EVEN if it is of a DIFFERENT type.

  1. Name: Empty the checkbox of each spider that should NOT be imported i.e. for each spider whose existing configuration should not be lost. By default all the checkboxes are ticked.

Tip: Double-clicking on the name will check or empty the checkbox. 

  1. Type: This ONLY specifies the type of spider that is to be imported. However if an existing spider has the same name, but a different type, this spider will not be imported. 
  2. Configured Inputs and Configured Outputs: These columns give an indication of how many inputs and outputs have configurations that need to be imported from the spider configuration spreadsheet.

Note: Even if an input or output is specified as having been configured, this does not mean that it is actually connected to a silk.

  1. The bottom list, displays any spider-specific errors that have been detected that will prevent them from being successfully imported into this spider workspace.

Note: If there is something missing from the importing spreadsheet, for instance, the spider type is not specified anywhere, then the spider and the reason for not being able to import is reported here.

 

The Silk Configuration dialog:

This displays the results of the comparison of the silks referenced within the XML file with those present within this spider workspace, as follows:

  1. The top list, displays the silks that are ONLY referenced within the XML file and which need to be created. This list consists of the following four columns, each of which can provide important information concerning the success of importing these silks, as follows:

Note: If only the silk configuration is being imported, this will list every spider connected by a silk that does not currently exist in the spider workspace.

  1. Source: The name of the spider whose output provides the source of this silk i.e. the spider whose value is transferred by this silk to another spider.
  2. Destination: The name of the spider whose input provides the destination of this silk i.e. the spider which receives values from this silk.
  3. Trigger Output: This column specifies whether this silk is used to trigger the Destination spider once the value provided by the Source spider changes. If this is False then the spider can be triggered from an event or by means of a Triggering spider etc.
  4. TemplateSet(s): This specifies the name(s) of the template sets that this silk is associated with.
  1. The middle list, contains all the duplicate silks or the silks referenced in the XML file that ALREADY exist in this spider workspace, which can be selected imported, as required.

WARNING! If any of these existing silks are imported, they may MODIFY the existing configuration of these existing silks, such as their associated template set and their Trigger Output setting.

  1. Source: The name of the spider whose output provides the source of this silk. Empty the checkbox in this column, of each silk that should NOT be imported i.e. for each silk whose existing configuration should not be lost. By default all the checkboxes are ticked. 

Tip: Double-clicking on the required Source name will check or empty the checkbox. 

  1. Destination: The name of the spider whose input provides the destination of this silk. 
  2. Trigger Output: This column specifies whether silk triggering has been enabled for this silk.
  3. TemplateSet(s): This specifies the name(s) of the template sets that this silk is associated with.
  1. The bottom list, displays any syntactic errors that have been detected in the silk import worksheet that will prevent them from being successfully imported into this spider workspace.

Logging in to a SmartUI Server

A SmartUI Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. must login to a SmartUI Server, which provides the roaming user profiles and other user-specific settings and default data sources.

During the login process a 'connection' is created to transfer data between this Client and Server.

Note: When a touch screen is detected, a button appears to the right of the Login Name and Password edit boxes, which if pressed, launches a virtual keyboard for users to type in the required value.

However when the Boolean Designer and Operator ForceShowTouchKeyboard config setting is enabled (set to TRUE), then the touch keyboard is always available in all Touch Textboxes, whether the computer uses a touch screen or not.

 

To login using existing login settings or a login profile:

  1. Launch the Client to display the User Login configuration dialog.

Note: If automatic login enabled this configuration dialog is greyed out as the configured login settings are used - press or hold down the SHIFT key to disable this.

  1. If necessary, select the required profile from the Login Profile list box.

The [Default] login profile is initially selected, which specifies the default login settings as specified by this Client.

  1. If necessary, provide the required Login Name and/or Password.

    Note: If security is not an issue for you, you can bypass the login process by using an automatic login, by checking the Automatically login with these settings next time checkbox (if it is visible).

  2. Click the Finish button.
  3. If this login attempt is successful, then the work environment of this Client will be displayed.
  4. If this login attempt is unsuccessful, see Troubleshooting a failed login attempt.

 

To modify the existing login settings and/or to create a new login profile:

  1. Launch the Client to display the User Login configuration dialog.

Note: If automatic login enabled this configuration dialog is greyed out as the configured login settings are used - press or hold down the SHIFT key to disable this.

  1. Click the Change button

This launches the Create Connection configuration dialog. For details, see Creating connections.

Note1: If either of the login details are modified within this configuration dialog, both the Login Name and Password fields will be correctly updated with these changes once this configuration dialog has been completed.

Note2: This configuration dialog can create a login profile out of these new settings too.

  1. Click the Finish button to create this new connection to the Server.
  • If this login attempt is successful, then the work environment of this Client will be displayed.
  • If this login attempt is unsuccessful, see Troubleshooting a failed login attempt.

 

The Current Environment Information fields displayed by the Advanced View of the User Login configuration dialog provide advanced information about this connection. Click here to view these fields:

This first group of fields describe the Client computer that is being connected to, as follows:

  1. User Name: The name of the user account that is currently logged in to this Client computer.
  2. Machine: The network name or IP address of this Client computer.
  3. Domain: The domain in which this Client computer resides.

The second group of fields describe both the Server computer and the mechanism used to connect to this computer, as follows:

  1. Host Name: The network name or IP address of the Server computer that will be connected to.

Note: If this Server uses a port other than 9000 (the default), this becomes: 'HostName:PortNumber'.

  1. Type: The physical connection between this Client computer and the required Server computer i.e. via the LAN or the Internet.
  2. Mode: The method of communicating data between the Client and Server computers, which depends upon the selected Type. For details, see About connection communication methods.

 

Troubleshooting failed (unsuccessful) log in attempts.

 

Click for more information:

Tip: To save time when launching a Client, it is possible to use an automatic login. For details, see Automatically logging into Servers.

Note1: In order to login, a user must either be an allowed user or a member of an allowed group on this Server and have a password. 

Note2: One or more high-level groups and/or users can be specified on a Server computer that are always able to login and have unrestricted access to this Server. For details, see Global security groups and users.

Note3: Although you only login to a single Server, a Client is able to connect to multiple Servers and if necessary, reconnect to these connections at login. For details, see Adding connections.

Note4: Login profiles store different sets of login settings for a specific Client, so you only need to specify them once instead of each time you need them. 

Note5: Login profiles are a security risk in multi-user environments as they specify the login name and password.

Working with graphic form translation

Projects can provide language support, also known as localization, because their graphic forms can be translated into the language(s) required by their end-users.

When graphic forms are created the currently specified Graphic Form Language of the user profile of the user that created them becomes the primary or reference language of this graphic form used when importing other languages and CANNOT BE CHANGED. Any subsequent change to this user profile setting ONLY changes the preview language of the existing graphic forms (the language that used to display or preview the graphic form in the Designer).

By default, this is the language of the Windows operating system. For details on how to configure this user profile setting, see Customizing the primary translation language of new graphic forms and the preview language of new and existing graphic forms.

Note: It is possible to change the language of the Operator via scripting at runtime, so that you can dynamically change the language in which graphic forms are displayed.

SmartUI 10 enhances the existing graphic form localization process and provides data translation or the translation of specific data strings, which if matched exactly are translated in real-time. So now both the graphic form user interface and the data that it displays can be localised. For details, see Globally translating projects.

Each graphic form uses its own local translation table to perform the translation of its configured form components, into the required language(s). For details, see Translating graphic forms. 

A graphic form can import translation(s) from the project translation table, which is global to all the graphic forms within this project.

You can also export the translations created in a graphic form translation table to the project's global translation table. Then import these translations to other graphic forms, as required. SmartUI 10 allows you to directly obtain the strings you want to translate directly from specific graphic forms, without having to manually type them in or export and import translation tables. For details, see Globally translating projects.

This global translation table or ‘phrase book’ of the project provides a central storage area that contains the languages and translated text for the common graphic form components used within any or all of the project’s graphic forms. 

Using this global translation table, while not directly translating the graphic forms themselves, provides the following benefits:

  1. The translations for the common form components only need to be performed once and can then be imported into the necessary graphical forms.
  2. This considerably simplifies the overall management of the translations, in that any changes only needs to this table, which can be imported throughout the project.
  3. This ensures that translations are applied consistently throughout the project.

Note: There is no limit to the number of languages can be added to a translation table.

If special characters are required for the translated language, ensure the required input locale is installed on the operating system. For details, see Adding input locales.

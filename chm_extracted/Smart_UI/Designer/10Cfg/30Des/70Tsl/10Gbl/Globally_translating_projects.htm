Globally translating projects

Although each graphic form is translated using their own translation tables, you can use the global or central translation table provided by each project to assist in this translation process, as follows:

Tip: You can also translate specific data strings, which if matched exactly are translated in real-time. So now both the graphic form user interface and the data that it displays can be localised.

  • It saves time and effort, since the required translations only need to be performed once and then can be imported into any number of graphic forms.

    This is especially the case if you have a large number of graphic forms that share a large number of common controls.

  • It simplifies the process of managing these translations, ensuring that the translations are consistent throughout the graphic forms within this project.
  • From SmartUI 10 onwards the process of obtaining the strings you want to translate is greatly simplified, by obtaining them directly from one or more graphic forms, so that you no longer need to manually type them in or export and import translation tables.

The following translation process is recommended:

After creating and configuring all the graphic forms for the project:

  1. Ensure that theGraphic Form tab of theproject translation table contains all the languages required by the graphic forms within a project. For details, see Adding languages to projects.

Note: Languages are added to both the Graphic Form and Data tabs of the project translation table. So only add languages as required by most graphic forms. If certain languages are graphic form specific, then it may be simpler to only add these languages to these specific graphic form translation tables.

  1. Add the translation strings required by any or all of graphic forms within a project to the Graphic Form tab of the project translation table. By typing them in manually or you can Fetch them from the required graphic forms themselves. For details, see Fetching translation strings from graphic forms.
  2. Translate these strings into the required languages.
  1. Push (copy) translations, either entirely or selectively to the required graphic form/s from the project translation table. This automatically adds any languages to the graphic form translation tables that are missing. For details, see Pushing translations to graphic forms.
  1. You may need to perform translations that are graphic form specific i.e. that may require languages and translations that are not common to other graphic forms in the project. For details, see Editing translations within graphic forms.

After creating and configuring the datasources used by the project, for any string or textual values that are displayed by your graphic forms:

  1. Ensure that the Data tab of the project translation table contains all the languages required by the graphic forms within a project. For details, see Adding languages to projects.
  2. Add the translation keys for all the string data values displayed by any or all of graphic forms within a project. By typing them in manually or clicking the browse button and using the Data Element browser to select them. For details, see Browsing for data translation keys.
  3. Translate these Key strings into the required languages.

Note: Each Key represents the full string value of a data element, this does not do partial string matches. In other words, only textual data elements (from any datasource) whose values EXACTLY match any of the Key column strings will be translated when the graphic form is displayed.

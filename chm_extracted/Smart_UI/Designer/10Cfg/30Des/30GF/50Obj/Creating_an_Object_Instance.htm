Creating an Object Instance

When you have created a template for an object, you can create any number of instances of the object. You can name each instance and specify the process values that uniquely configure it by using the assigned predefined value substitutions.

You can also choose to immediately deploy the instance, fully or partially, or deploy it at a later time.

  • Currently, the Object Model supports the following commonly-used drivers (devices): Modbus Ethernet, Mitsubishi Q, QnA, L, R and iQF Series Ethernet (3E Frames), OPC Client and Siemens Ethernet.
  • If you need to use other drivers, then you simply create the necessary devices yourself before deploying an instance of this object model template.

To create an object instance:

From the Object Model datasource in the Enterprise Manager

Display the Create New Instance configuration dialog for the required object instance:

  1. Select the required SmartUI Server in the Enterprise Manager tab.

  2. Open the Enterprise Manager.
  3. Navigate to Servers > [Server Name].
  4. The connection name is prefixed with the SmartUI Server name.
  5. Expand the remaining category folders Datasources > Object Model > Templates.
  6. Right-click on the required template in the list, then select Create new instance of this template.
  7. The Create New Instance configuration dialog opens.

 

From the Context View window:
  1. Select Context View tab at the bottom of the right-side panel in the Default Layout window.
  2. Select the Default context from the list of contexts in bottom toolbar of this window then click the Edit button.
  3. If required, Add new user node and expand the necessary node .
  4. Right-click the node and select Create new instance.
    • Use the modified Data Element browser dialog to select the required template.
    • Tip:  You could also drag an existing Object Model template from the Enterprise Manager onto this node directly to skip the step where you need to specify the required template.
    • The Deployment Options configuration dialog opens.

For more information about the Default context of the Context View window, see Editing the Default context.

Step 1: Create New Instance

Name the instance and specify any instance-specific attributes

.

  • By default, the New instance name is assigned the name of the template and is prefixed with "INST_" instead of "TPL_".
    • You can edit the name as you prefer.
    • Typically, you edit the name to create a unique and detailed name for this object.
  • To ensure that the specified Template is the template that you want to use to create an instance.
    • Hover the mouse pointer over the template name or any child template that is listed in the Template hierarchy tree.
    • A preview image of each template is displayed.
    • Note:  Only the parent template has the specified instance name, whereas any child templates retain their template names.
  • The table labelled Attributes for displays any attributes specified for the selected template including their default values
    • You may change the value as required, such as its power rating.
    • You can also add additional instance-specific attributes that only apply to or further describe this instance.
  • Any custom attributes that you add are saved in your current profile and are available for future use to all users who use your profile.
  • You can click the Reset the attribute library button to clear the custom attributes that are specified for the current profile.
  • Note:  This only removes the custom attributes from the list, which will no longer be available for selection. It does not remove any custom attributes that you have previously added to deployed objects, so these still appear in the Context View window.

Tip:  Typing in the first letter of an existing attribute immediately inserts the full text of this attribute name.

  • The Object Model datasource then uses the specified attributes to configure the Context View window automatically.

  • When object instances are deployed, each Name of their defined attributes creates a different context (tree-view) in the Context View window and instances that have the same Value of an attribute are grouped in this context.
  • A simple one-level deep tree-view is created for each attribute Name, in which a node is created for every unique value specified for this attribute.
  • Important:  Only the Value and Instance names can be searched in the Context View and not the attribute Name, which is added to the list of contexts at the bottom of the Context View.

Note:  You can only delete the additional instance-specific attributes that you add.

Click Next, once you are satisfied with the instance name and its specified attributes.

Click Cancel, if you selected the incorrect template.

Step 2: SCADA Configuration:

In this step, you specify and configure the agents that are associated with each template referenced by this object instance.

  • The SCADA Configuration dialog displays a table containing the group of agents required for each template referenced by the object. These group names use dot notation to represent the template names as specified in the Template hierarchy tree shown on the first ‘Create New Instance’ dialog.
  • Selecting the INST_<GroupName> group displays the instance details for the template in the Instance tab of the Configuration pane below the Agents table.
  • Note:  The Datasource property indicates the name of the Adroit datasource (Agent Server) that is used to validate, create and configure these agents.
  • If each group heading does not display a list of agents, then click the Expand All button to expand all the groups to display the list of required template agents.
  • If any template row containing a substitution displays a icon, it is an indication that some substitution values require insertion.
    • To correct the value, click either the Substitution Names or Substitution Values cell in the row where a icon is displayed to open the Substitution Values dialog.
    • Type in the Value for each required substitution.
    • Note:  You cannot proceed from this dialog until you have inserted all the required substitution values for each row containing a icon.
  • Use the < and > buttons to navigate to the previous or next substituted value.
  • Note:  Commas separate multiple substitutions and their values in their cells.
  • Tip:  Use the Name cell to determine the eventual format of the entire substituted name.
  • The background colour of the Name cell indicates whether the resultant agent name already exists or is new, as follows:
  • Typically, you specify new tags that do not already exist. However, you can also specify an existing tag, which you want to reuse, such as an AlarmManagement agent.

Configuration pane

Once an agent name is specified, then use the Configuration pane below the table to configure its Scanning, Logging, Alarming, and Slots as predefined in the templates by selecting the relevant tabs.

  • Instead of querying each agent individually for their scan addresses, click the Bulk scan address editing button to configure all the scan addresses associated with this object in a single list view.
  • The Bulk scan address editing dialog displays the list of all the scan addresses that are classified by the Device, Tag and Address columns.
  • You can also change each Address manually, by typing the required entry into each cell in this list.
  • Alternatively, you may use a text file editor of your choice to change these addresses.
    1. Click the Copy addresses to clipboard button.
    2. Tip:  You can also select all or deselect all rows by clicking the top-left cell in the list and use the CTRL+C to copy these to the clipboard.
    3. Open MS Excel or the text file editor of your choice.
    4. Paste the clipboard into it.
    5. Bulk edit the Address column as needed.
    6. Select all of these columns and copy them.
    7. Click the Paste addresses from clipboard button.
  • Click Next, once you have replaced all the icons with valid values and have configured each of the agents appropriately.
Step 3: Device Setup

In this step, you specify and configure the devices that each template uses to scan their values. These devices are listed in the Devices table.

  • The background colour of the Device cell indicates whether the current device already exists or is new, as follows:
  • Important:  If the background colour of the device row is red (Setup required ) for the device, then you must manually add this device-name via the Config Editor first before you can continue. This typically only occurs when a template uses a protocol driver that is not natively supported by the Object Model.
  • For more information using the Config Editor, see Adding a Device to an installed Protocol Driver.
  • Note:   If the device already exists then any specified properties are not applied to it during the deployment of this object.
  • If the Object Model natively supports the specified new or existing device, then you can configure their Primary and Secondary device-specific Properties.
  • Important:  The onus rests on the user, who is adding this instance, to possess the technical know-how to determine which of these device-specific values need to be specified.
  • Note:  If the device already exists then any specified properties are not applied to it during the deployment of this object.
  • Click Next, once all the required devices have been added and have had their required properties specified.
Step 4: DBLogs

This step only applies if one or more DBLog agents are selected for this template.

  • You can configure each of the selected DBLog agents in the DBLogs list.
  • You can also view which slots of the other agents in this object are allocated, to each DBLog agent, in the Tags table below.
  • You can also see if you can configure their Deadband.
  • Click Next, once all the deadbands of the values in the DBLog agents are correctly specified.
Step 5: Graphic Substitutions

This step is typically only required when you have changed the substitution names when creating the instance and the name of the substitution used in the SCADA Configuration step differs from the name used in the referenced wizard.

  • Note:  You cannot proceed from this dialog until you have inserted all the required substitution values for each row containing a icon.
  • Select the required row in the Graphic Form list that contains a icon and then the Value cell in the Substitutions table below and type in the required value.
  • Note:  The background colour of the Result cell shows whether the specified value is .
  • Tip:  If you keep the same substitution names as those used in the wizard, this makes it easier to implement your instances, since you only need to configure these substitutions once; otherwise you must specify substitutions both during the SCADA Configuration and Graphical Substitution stages.
  • Click Next, once you have replaced all the icons with their required substitution values.
Step 6: Deployment Options

This is the final step, which lets you deploy the instance of this object using the settings that you have specified.

  • Important:  When deploying a template, the following rule is applied. If a referenced agent exists then none of its properties are changed. The reason is if the template is currently in use on a running plant, it is critically important that it does not affect any existing values for safety reasons.
  • The following two options are provided:
    • Deploy now: After creating and saving the instances, the instances are deployed to the relevant Agent Server.
    • Deploy later (the default option): Only create and save the instances, but deploy later by right-clicking on the saved instance. For example, you may want to create the instance of an object at another site.
  • If you select the Deploy now option, then the On deployment group is displayed.
  • When deployed, this object and all of its configuration are created immediately, such as:
    • Any new agents.
    • Any new devices and their scanning.
    • The specified alarming, logging and DBLog agents.
    • Important:  When the global destinations (i.e. the Output / Event Logs categories) of the specified alarm routes contain agents that do not exist in the Agent Server then the deployment is not created as these agents could cause potential issues.
    • The Save Agent Server checkbox is also selected by default which saves this configuration to the Agent Database file of the Agent Server of the specified Adroit datasource.
  • To run the script defined for this object, select the Run Script checkbox as this is not selected, by default.
  • Note:  If the Run Script checkbox is disabled (greyed out), then the script was not defined or did not compile successfully.
  • Note:  Currently only the script defined for this object may be run. Any scripts defined for child objects are ignored, even when no script is defined for the parent object.
  • Tip:  Use the View button to display the associated script action before it is run.
  • Perform a partial deployment at this time, by clearing some of the following checkboxes:
    • Create agents
    • Create devices and scanning
      • Start devices
    • Create alarming
    • Important:  When the global destinations (i.e. the Output / Event Logs categories) of the specified alarm routes contain agents that do not exist in the Agent Server then the deployment is not created as these agents could cause potential issues.
    • Create data logging
    • Create DB logging
  • Note:  This configuration is only saved to the Agent Database file of the Agent Server of the Adroit datasource when you select the Save Agent Server on deployment completion checkbox.
  • Click the Finish button.

In the case of a partially deployed or non-deployed instance, you can deploy it fully or partially at a later stage.

For more information about later deployment, see Deploying an Object Instance.

  • If you selected any of the deployment checkboxes, then the Object Model Deployment Status progress dialog appears.
  • For more information about the deployment status, see the Object Model Deployment Status dialog.
  • When you create an instance of an object template, you can view the template- and object-specific attributes that you defined along with their configured values for the object.
  • For more information about defined attributes, see Viewing the defined attributes of an Object Instance.

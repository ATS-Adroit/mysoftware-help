Creating or Editing an Object Template

To start, use a wizard instance on a graphic form that you have already configured, which is working as required and is already configured with the necessary SCADA configuration (i.e. the scanning, logging, and alarming) plus any other agents that the object needs.

Important:  Take the necessary time to test that the wizard has been correctly configured and is working optimally. Ensure that it can be scanned, logged and alarmed correctly. Be aware that any mistakes or omissions will be duplicated.
So, take care!

Tip:  If you keep the identical substitution names as those you have used in the wizard, this makes it easier to implement your instances, as you will only need to configure these substitutions once. If you don’t use the same substitutions, you should specify unique substitutions during both the SCADA and Graphical Substitution stages.

Next, create a template from the wizard, which incorporates the graphical components of the wizard (and any substitutions that it uses), along with the SCADA configuration that you specify. Now, you can create numerous instances of each that will create unique tags and can be scanned, logged and alarmed, as specified by the template.

Best Practice:  Always alarm agents from route 2 onwards never use routes 0 and 1. These routes are used internally by Adroit for reporting the system alarms and events.

Note:  To create an object template, you need to be fully aware of how your SCADA system (Agent Server) is configured.

Once you have created an object template, and any other instances that you create using this template, the referenced wizard will provide the graphical components and uniquely configure the SCADA configuration for the process values that you have specified for each object.

Click on each of steps below to learn how to create an object template:

Create an object template
  • Open the SmartUI graphic form that contains your wizard instance with all the necessary SCADA scanning, logging, and alarming configuration and any other agents that the object requires and is working correctly.
  • Right-click this wizard instance in the Designer and select Create Object Template.

  • This displays the first page of the Create Object Template configuration dialog.
  • Important:  if you Cancel the configuration dialog then you will lose all configuration that you have done. You can navigate between the steps using the Previous and Next buttons, which retains the current configuration of each step.
Editing an existing object template

Select the required SmartUI Server in the Enterprise Manager tab, as follows:

  1. Open the Enterprise Manager.
  2. Navigate to Servers > [Server Name].
  3. Tip:  The connection name is prefaced by the SmartUI Server computer name.
  4. Expand the remaining category folders Datasources > Object Model > Templates.
  5. Right-click on the required template in the list, then select Edit.

The first step of the Edit Template configuration dialog is displayed:

Important:  if you Cancel the configuration dialog then you will lose any configuration that you have done. However, you can use the Previous and Next buttons to navigate between the steps, which retain the current configuration of each step.

Step 1 of 12: Validate Wizard Data Elements

By default, the Template Name box uses the name of the selected wizard instance prefixed with "TPL_". You may change the name as required.

Template Descriptor

  • You can also specify a Template Descriptor, which is the last portion of the default deployed object name and relates to the object itself but not its context.

  • Typically, this is a standardised abbreviation for this object, such as MOT for Motor, after which you typically need to provide the unique, detailed name for this object e.g. MOT_PUMP_01.
  • By default, a number of predefined descriptors are available to you. You can, however, create new custom descriptors.
    1. Click the selection list button adjacent to the Template Descriptor box, then click Add new.

    2. Select the required Category then type in a Description and the required Descriptor, ensuring that the new descriptor can be easily identified in the list of predefined descriptors.
    3. Click OK to save.

Wizard Data Elements

The Data Elements table should contain the valid names of the specified data elements used for the substitutable values of this primary wizard, so no further configuration should be required.

  • The table displays all the data elements from the datasources that apply to the specified wizard.
    • Only the Adroit-specific data elements will be processed.
    • The purpose of a template is to assign the necessary SCADA configuration for this primary wizard.
  • If necessary, click the Associated wizards tab to select related wizards that use the SAME substitutable values as this primary wizard (or LESS of these substitutable values).
  • Caution:  Another wizard can ONLY be associated when it has the SAME or LESS substitutions as the Primary wizard.
  • Examples of valid Associated wizards:
    • If you have created different graphical orientations for the same item of equipment, like a left or right or top or bottom view, which use the same substitutable values.
    • If you have a simpler view of the primary wizard, in other words a wizard that uses less of the substitutable values.
  • Click Next, when you are satisfied with the template name and any associated wizards.
Step 2 of 12: Select Agents

The Agent tree displays the list of Adroit tags directly referenced by the wizard.

  • Important:  Currently the Object Model only supports the following agent types: alarm, alarmmanagement, alarmlist, analog, beeper, counter, dblog, digital, eventoutput, expression, icmp, integer, marshal, maxdemand, oee, pid, real, shift, snmpmgr, statistical, string, stringlist, text and timer.
  • Executing this action is best done by a user who has an in-depth knowledge of how their SCADA system (Agent Server) has been designed.
  • If an agent is used by (i.e. referenced within) another agent, such as an expression, the relevant agent is added to the Related Agents list.
  • Note:  Only DBLog agents that have been enabled and are referencing one of the selected agents will appear in this list.
  • The template designer decides which of the agent relationships are required by the template.
    • These intra-agent relationships may become complex depending on how deeply nested they are.
    • Only the first level of agents are linked by default.
  • You may also manually add any agents that are not directly linked to the agents in this wizard, but are required.
    • Agents such as Script agents, the AlarmManagement agent and others, may be added by clicking the Add agent button.
    • Any added agent, both existing or created at this time, is displayed in blue.
  • Note:  Do not include the agents used to directly alarm, log or scan the agent.
  • Tip:  If necessary, you can also create agents at this stage.
  • Click Next, once all the required agents have been selected.
Step 3 of 12: Assign Agent Substitutions

You can use this step to assign portions of an agent name for substitution, or to be variable, when creating instances of this object. This ensures that they adhere to tag naming conventions that are applicable.

  • Typically, the substitutions for all the values used within the referenced wizard are listed here and are prefixed by the Adroit datasource name.
  • Tip:  If you keep the same substitution names as those used in the wizard, this makes it easier to implement your instances, because you will only configure these substitutions once, otherwise you will need to specify substitutions both during the SCADA Configuration and the Graphical Substitution stages.
  • Unless the substitution includes the datasource name and any manually added agents, the tag name is used instead.
    • You will have to manually add any required substitutions.
    • You may also modify existing substitutions at this point.
  • Important:  Any tag that is not substituted will be referenced by all the instances of this template.
  • Note:  Templates do not support obtaining tags from two different Adroit datasources. All the specified tags must exist on the same Agent Server.
  • To insert a substitution, click the Insert Substitution button containing the agent and specify each required substitution within curly brackets {...} in the Substitutions dialog.
  • To modify any substitution, double-click the row containing the agent and specify each required substitution within curly brackets {...} in the Substitutions dialog.
  • For example, if a plant area code and an equipment code is required: {PlantAreaCode}_{EquipmentCode}.value
  • Alternatively, you can use a single substitution for both the agent name and slot value, such as {AnalogTag}
  • Note:  It is not possible to substitute the Adroit datasource name. However, you can specify which Adroit datasource (Agent Server) you want to use when creating an instance of this template.
  • Tip:  When you click the Remove button, this removes all the specified substitutions of the current row (i.e. if only one has been selected) replacing these substitutions with the name of the specified agent.
  • Click Next, once all relevant substitutions have been specified.

Step 4 of 12: Configure Slots

Each agent that is selected for use in this template provides a filtered list of values (slots) that a user may configure.

  • Select the row containing the agent you want to configure. The Slots table below displays a filtered list of available agent slots and their values.
  • Note:  Any agent, such as DBLog and AlarmManagement, used to scan, log or alarm is not configured at this point
  • The underlying purpose of the object template is to create specific objects that simplify the SCADA objectives of your users.
    • You must determine how complex your objects need to be.
    • Also which values should be configured by using one of the following four configuration states:
      • Agent Default (Not displayed): these values are preconfigured for this object and are hidden from your users.
      • User Default (Read-only): these values are preconfigured for this object and are displayed for information purposes so that your users can still see them, even though they cannot edit them (like alarm limits or set points).
      • Editable with a default value: a recommended or suggested value is provided, which a user may change when adding an instance. This is the default option.
      • Editable with NO default value: users must specify these values when creating each instance.
      • Note:  This only applies to values that are not of type String (a blank string can be valid).
  • Click Next, once you have appropriately configured the slots of each agent referenced by this object.
Step 5 of 12: Configure Scanning

This step lists all the slots values of the selected agents that are scanned and also their commonly configured scanning settings:

  • The selected device and its scan address for the device.
  • The scan rate and the alarm deadband setting.
  • The four scanning IO settings that affect how this value is scanned.
  • For more information about the IO settings, see IO Flags.
  • Note:  If you want to update these scanning settings on all listed devices, then select the Update all devices on edit checkbox.
  • Click Next, when you are satisfied with how each of these slots are being scanned.
Step 6 of 12: Configure Devices

This step lets you configure the properties of each device that will be scanned.

  • These properties specify the default settings used when you create an instance of this object.
    • Currently, the Object Model supports the following commonly-used drivers (devices): Modbus Ethernet, Mitsubishi Q, QnA, L, R and iQF Series Ethernet (3E Frames), OPC Client and Siemens Ethernet.
    • If you need to use other drivers, then you simply create the necessary devices yourself before deploying an instance of this object model template.
  • Note:  This step may or may not be required, depending upon the requirements of your site and how you intend deploying the instances of this template.
  • Select the row containing the device you want to configure.
  • The protocol driver-specific primary property settings  are listed in the Primary tab of the Properties table below.
  • Select a property value box and type in a default value or you may leave these values blank. These values will be applied when creating an instance.
  • Click Next, once you have appropriately configured the primary settings for each of the required devices.

This step lists all the slot values of the selected agents that are logged and also their commonly configured logging settings:

  • You may modify one or more of these logging settings, where necessary.
  • Click Next, once you are satisfied with how each of these slots are being logged.
Step 8 of 12: DBLogging Summary

This step lets you configure each of the selected DBLog agents:

  • Select the row containing the DBLog agent you want to configure in the DBLogs list.
  • For information purposes only, the Tags table, below the DBLogs list, displays the slots of the other selected agents.
  • Click Next, once you have appropriately configured the DBLog agents.

Step 10 of 12: Add Attributes

This step lets you to add one or more attributes, searchable strings or identifiers that you can use to filter or classify the objects that you create in the Context View window.

  • Each attribute applies to all the object instances and requires both a Name and a Value.
  • Note:  You cannot edit the Name once you create it. If you need to change the Name then delete the attribute and add it again.
  • These attributes provide user-friendly terms that can be used to identify this object, such as the equipment Type, containing a value of ‘motor’, or ‘valve’, etc. or perhaps even a power specification, such as 'kWh'. You can then specify the required value for each object attribute.

  • The Object Model datasource then uses the specified attributes to configure the Context View window automatically.

  • When object instances are deployed, each Name of their defined attributes creates a different context (tree-view) in the Context View window and instances that have the same Value of an attribute are grouped in this context.
  • A simple one-level deep tree-view is created for each attribute Name, in which a node is created for every unique value specified for this attribute.
  • Important:  Only the Value and Instance names can be searched in the Context View and not the attribute Name, which is added to the list of contexts at the bottom of the Context View.

To add an attribute:

  1. Click the button.
  2. Type in a new attribute or click the drop-down selection list button then select one of the existing attributes.
  • Tip:  Typing in the first letter of an existing attribute immediately inserts the full text of this attribute name. The following general attributes always appear in this list: Manufacturer, Description, Model, and Type
  1. Click the Finish button.
  • Any custom attributes that you add are saved in your current profile and are available for future use to all users who use your profile.
  • You can click the Reset the attribute library button to clear the custom attributes that are specified for the current profile.
  • Note:  This only removes the custom attributes from the list, which will no longer be available for selection. It does not remove any custom attributes that you have previously added to deployed objects, so these still appear in the Context View window.
  • As these attributes and their values are displayed on the first page when creating an instance, you can add the default Description attribute to provide a detailed description of this template, so that a user can know that they are adding the required object instance.
  • Note:  The Delete button deletes the recently selected attribute, which by default is the last attribute in the list.
  • Tip:  In addition to these attributes and when adding an instance, your users can specify additional instance-specific attributes too.
Step 11 of 12: Add Child Templates

You can add specialised sub-folders and move your templates into these folders.

  • You can do this within the Enterprise Manager, or you can use Windows Explorer.
  • When next the SmartUI Server loads it acquires the folder structure as you have created it. You can, therefore, create a workflow that suits your project best.
  • If you do choose to use Windows Explorer, these templates are stored in the following physical location on the SmartUI Server computer: C:\ProgramData\Adroit Technologies\Adroit\SmartUI\Configurations\Default\ObjectModel\Templates
  • Note:  This path assumes that you are using the Default configuration, otherwise replace "Default" with the name of your currently active Configuration, which you can retrieve from the Configurations page of the SmartUI Config Editor.

 

  • When you create an object template.
    • Any instance that you create using this template will provide the referenced wizard to provide the graphical components.
    • It  will also uniquely configure the specified SCADA configuration with the process values that you specify for each object.
  • For detailed steps to creating on Object instance, see Creating an Object Instance.
  • You can also use the Object Model Template Export and Import utility to export one or more of your existing Object Model Templates to a proprietary .TEF (Template Export File) file and also to import Object Model Templates from a .TEF file.
  • For more details, see Object Model Template Export Import Utility.
Step 12 of 12: Run A Script

This step lets you to define a script for the Object Model Template. When deploying an instance your users could run this script but only if it compiles successfully.

  • Note:  Currently only the script defined for the template can be run. Therefore any scripts defined for child templates will be ignored, even if no script is defined for the parent template.
  • The Include script in this template checkbox is not selected, by default.
    • If selected then click the Launch Script Editor button to open the Script Editor with the default (sample) script.
    • You may edit and compile the script.
    • When you are done, close the Script Editor window to save the script.
    • Note:  A warning is displayed when the script did not compile successfully or did not execute. To clear any errors, click the Launch Script Editor button again to edit and compile the script.
    • Important:  This does not prevent you from clicking the Finish button, but be aware that when an instance of this template is deployed, the script will not run until it has been edited in the interim to successfully compile.
  • When deploying an instance of a template, a additional checkbox is displayed labelled Run Script, which is not selected by default and will be greyed out if a script was not specified or when the specified script does not successfully compile.
  • Click Finish, once you are satisfied with the configuration of this object template.
  • Tip:  You can navigate between the steps using the Previous and Next buttons to edit any of the steps before clicking Finish.

Deploying an Object Instance

If you chose not to deploy an instance of an object once it was defined or you performed a partial deployment by selecting only some of the available operations, then you can perform a full or partial deployment of an instance at any later time.

  • Currently, the Object Model supports the following commonly-used drivers (devices): Modbus Ethernet, Mitsubishi Q, QnA, L, R and iQF Series Ethernet (3E Frames), OPC Client and Siemens Ethernet.
  • If you need to use other drivers, then you simply create the necessary devices yourself before deploying an instance of this object model template.

Note:  Your Agent Server Type must be set to "Stand-alone / Distributed Server" mode in the Config Editor (Restart your Agent Server to change this setting) before you can deploy object instances.

To fully or partially deploy a created object instance:

Display the Deployment Options configuration dialog for the required object instance:

From the Object Model datasource in the Enterprise Manager

Select the required SmartUI Server in the Enterprise Manager, as follows:

  1. Open the Enterprise Manager.
  2. Navigate to Servers > [Server Name].
  3. Tip:  The connection name is prefixed by the SmartUI Server computer name.
  1. Go to the Enterprise Manager category folders Datasources > Object Model > Instances
  2. Right-click the required instance and select Deploy.
  3. The Deployment Options configuration dialog opens.

From the Context View window
  1. Select the Context tab at the bottom of the SmartUI Designer window.
  2. Select the required context from the list, which is typically the Default context.
  3. Expand the necessary node .
  4. Right-click the node and select Deploy instance(s).
  5. The Deployment Options configuration dialog opens.

    For more information about the Context View window, see the Context View tool window.
Deploying the object instance

By default, most of the On deployment checkboxes of the Deployment Options configuration dialog are selected:

  • When deployed, this object and all of its configuration are created immediately, such as:
    • Any new agents.
    • Any new devices and their scanning.
    • The specified alarming, logging and DBLog agents.
    • Important:  When the global destinations (i.e. the Output / Event Logs categories) of the specified alarm routes contain agents that do not exist in the Agent Server then the deployment is not created as these agents could cause potential issues.
    • The Save Agent Server checkbox is also selected by default which saves this configuration to the Agent Database file of the Agent Server of the specified Adroit datasource.
  • To run the script defined for this object, select the Run Script checkbox as this is not selected, by default.
  • Note:  If the Run Script checkbox is disabled (greyed out), then the script was not defined or did not compile successfully.
  • Note:  Currently only the script defined for this object may be run. Any scripts defined for child objects are ignored, even when no script is defined for the parent object.
  • Tip:  Use the View button to display the associated script action before it is run.
  • Perform a partial deployment at this time, by clearing some of the following checkboxes:
    • Create agents
    • Create devices and scanning
      • Start devices
    • Create alarming
    • Important:  When the global destinations (i.e. the Output / Event Logs categories) of the specified alarm routes contain agents that do not exist in the Agent Server then the deployment is not created as these agents could cause potential issues.
    • Create data logging
    • Create DB logging
  • Note:  This configuration is only saved to the Agent Database file of the Agent Server of the Adroit datasource when you select the Save Agent Server on deployment completion checkbox.

Tip:  In the case of partial deployment, only the steps that have not yet been deployed are processed.

In addition to these checkboxes, the dialog provides a list of agents both new and existing that the object references and a Remove current deployment button.

  • Important:  Only the agents that are not being used by (subscribed to) other agents will be removed.
  • Note:  The Remove current deployment button is only enabled if one or more of the referenced agents exist (i.e. they have a green background, and the instance has already been partially or completely deployed).

Finally, click Deploy to perform the currently selected deployment operations or Cancel to quit.

  • If you selected any of the deployment checkboxes, then the Object Model Deployment Status progress dialog appears.

  • For more information, see the Object Model Deployment Status dialog.

Working with SmartUI Templates

SmartUI Templates are reusable graphic forms that can be used at run-time.

The fundamental difference between a graphic form and a SmartUI Template is that a SmartUI Template has aliases, some of which are automatically created, which allow data elements within Behaviours and/or spiders to be dynamically driven.

Typically SmartUI Templates are used for graphic forms that are displayed as pop-ups or within TemplateGOa Template Graphic Object control that displays a graphic form and connects data elements to any aliases of this graphic form. controls. For more details about using aliases, see Working with aliases.

IMPORTANT: The default action for values entered into the Aliases tab of the Advanced View has been changed to always specify the text that is either manually entered or browsed in, unless the Use Tag Value checkbox is checked, at which time it will try to resolve the required data element value from the entered (typically browsed in) text.

Therefore when passing substitutions or aliases, in curly {} brackets, ensure that the Use Tag Value checkbox is NOT checked, which is its default setting.

When launching child SmartUI Templates from a parent SmartUI Template, you can automatically use the alias values of the parent SmartUI Template, instead of manually assigning values to the aliases of each child. For details, see Passing alias values from parent to child.

IMPORTANT: When dragging or copying a SmartUI Template onto a graphic form ONLY use the Graphic Form by Reference option as this is the ONLY option that creates TemplateGO controls so that you can configure its aliases. For details on configuring this option, see Adding a graphic form to another graphic form.

Automatic alias creation

Aliases can be automatically created for you, by using {} notation, in the following instances:

  • in the Properties tool window: for any String or Text properties, you can specify the required name enclosed in { } braces.
  • when configuring Behaviours: for any data element field, you can specify the required name enclosed in { } braces.
  • when configuring a charting control, for the applicable Series values specify the required name enclosed in { } braces.
  • when configuring an Adroit Alarm Viewer control, specify the required name enclosed in { } braces for the Alarm List / Alarm Agent value.

Use {} notation to specify aliases, as follows:

  • if you require the alias to specify the ENTIRE value/data element to be substituted then specify the single {requiredAliasName} - this is most typical.
  • if you require multiple parts of the value/data element name to be separately replaced then specify multiple aliases, such as {DataSource}.{Structure}.{DataName}.{Value}.

For example: {tag} or by concatenating a number of hierarchical levels for this data element , for instance: {AS}.{tag}

Manual alias creation

If you need to expose any other property of the graphic form or its configured form components, then you need to manually add the required alias to a graphic form and then manually assign them to the required properties of this graphic form and/or its added form components via the Spider Configuration tool window. For details on how to configure aliases in this manner, see Working with aliases.

 

A typical example of how to use SmartUI Templates as run-time reusable graphic objects:

  1. Create a SmartUI Template with 2 aliases using 4 labels.

  1. Create a normal graphic form with 3 buttons.

  1. For each button, add an Execute Command behaviour that opens the SmartUI Template that you created.

  1. Click the Advanced View button and the Aliases tab to browse in the appropriate data element for each Alias. Repeat this step for each Button.

  1. Once you’ve configured each button, clicking on each button in the Operator to display the same SmartUI Template but with different data element values.

SmartUI Templates can also be used when creating wizards that contain a pop-up that needs to “inherit” or use the tag data that is substituted when the user drops the wizard down on the form. For an example of configuring this, see How to create a Wizard that contains a Template pop up.

Tip: Wizards that display one or more SmartUI Templates can use their substitutions to drive the values of the aliases of these child SmartUI Templates. For details, see Driving aliases with wizard substitutions.

For more information and detailed procedures for this and other methods of re-using graphical components to speed up the process of creating graphic forms, see How to reuse graphical components.

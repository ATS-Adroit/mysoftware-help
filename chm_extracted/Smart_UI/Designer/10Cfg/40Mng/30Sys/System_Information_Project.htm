System Information Project

The sample project ‘System Information’ provides a number of sample graphic forms, which demonstrates various generic functionality

Note: This project does not exist if you unchecked the Include default projects i.e. Navigation Templates, Shapes Wizards and Examples, and System Information etc. checkbox when creating a new Configuration in Adroit Config Editor.

Tip: Examine the spider configuration of this project to determine how to use the functions and obtain the information provided by this datasource.

System Management graphic form: this is the main graphic form of the ‘System Information’ project, which demonstrates how to use the System datasource to obtain the troubleshooting data that you require from each SmartUI Server and/or Clientrefers to either the Designer or the Operator, both of which are client applications of the Server..and provides the following tabs:

  • General System Information: this tab provides the commonly used SmartUI Server and/or Client information and functions that are of interest to most users, as follows:
  • General System: this default vertical tab provides the following tables and their associated buttons:
  • The Server Information table provides the SmartUI Server-specific information. See Server Information.
  • The buttons below this table provides the SmartUI Server-specific functions (performable actions). See Server Actions.
  • The Client Information table provides the SmartUI Client-specific information. See Client Information.
  • The buttons below this table provides the SmartUI Client-specific functions (performable actions). See Client Actions.
  • Advanced : this vertical tab provides ADVANCED troubleshooting information and functions, which should ONLY be used by TECHNICAL personnel, since the misuse of the functions provided by this tab can cause the SmartUI Server and its Clients to stop working!

For this reason, this tab is NOT documented as it should ONLY be used by those “in the know” – if you are unsure as to what this tab does – then DO NOT USE IT!

IMPORTANT: The following tabs (in part or in full) rely on an Adroit datasource called "Adroit" to function.

  • System Alarms: this tab, only applies when you have Adroit installed, in which case this displays the alarms logged to the Adroit system alarm routes (0 and 1).
  • PC Performance Monitor: this tab displays the current CPU and memory using statistics and, if you have you have Adroit installed, this displays the Agent Server applicable statistics.
  • Active Cluster Control: this tab, only applies when you have Adroit installed and in particular if you are using a clustered Agent Server, in which case it can be used to manage your clustered Agent Servers.
  • Datalog catch-up Management: this tab, also only applies when you have Adroit installed and in particular if you are using a clustered Agent Server, in which case it can be used to synchronise, unsynchronised sections of logged data between the two Agent Server partners in the cluster.

Global Alarms and Events graphic form: this graphic form provides an AlarmViewer control that lists the Adroit alarms and events of the defaultAlarmAgent, so that they can be viewed and/or acknowledged. For more details on using this control, see Operating AlarmViewer controls.

The Auditing folder contains the following sample graphic forms that pertain to auditing operations.

The following graphic forms show you how to use different methods for reporting the audited entries logged to the audit database:

  • Audit Report Example (Script): this graphic form uses a graphic form script to filter the available audit entries according to a specific (initiating) user and a specific date/time range, which are then displayed in a standard DataGridView control.
  • Audit Report Example (Spiders): this graphic form uses spiders (the visual programming language) to filter the available audit entries according to a specific date/time range, which are then displayed in a DevExpress Grid control.

The sample Authorise Deferred Writes graphic form (in the Data Element Authorization folder), to obtain a list of the currently deferred changes made to data elements, so that these can be authorised by the applicable user, as follows:

The authorizing user:

  • needs to be an allowed user (or a member of an allowed user group) of the SmartUI Server
  • requires write access to a data element to authorise its change in value.
  • CANNOT be the initiating user (the user who made the change)

If necessary, click the Refresh button to populate the list with all the currently deferred data element writes (changes to values).

Select which value change/s you want to authorise in the list.

Specify the User Name and Password and, if required a Comment , typically the justification for granting the requested change/s.

Click the Authorise button.

Note1: Only the last change made to the value is authorised, when more than one deferred change is made or requested for the same value (data element),

Note2: Any data elements that the authorizing user does NOT have write access to will remain in this list.

Repeat this as often as needed.

For more details about specifying which data elements can be audited and/or have their value changes authenticated, see Configuring the auditing and/or authorizing of value changes.

Working with policies

Policies are configurable sets of rules, which provide a general (large-scale) level of control to safeguard the services and data that the SmartUI Server provides. 

In other words, policies control the access to a SmartUI Server and to each datasource plugina generic type of data supplier that interfaces between the Server and this specific type of data, so that it is exposed to the Server in the format of data elements. See data element. for the allowed groups and/or users, as follows:

  1. Each policy represents a specific service or activity that can be performed by this SmartUI Server. Certain policies are datasource plugin-specific. For details on the provided services, see Available policies.
  1. By associating the allowed users and/or groups with each policy, you are able to determine the extent of their access to this SmartUI Server and its datasource plugins.  For details, see Associating policies with allowed users and groups.
  2. Any allowed user and/or group not associated with a policy is unable to perform the service that it represents.

In this way, whenever a SmartUI Server receives a request for a service, it first determines whether the currently logged in user is part of the allowed users or groups that are able to perform this request, and then denies or grants access based on this result.

Policies are configured per Server connection in the Enterprise Manager, by using its Security component within the Management category.

  • Any group(s) and/or user(s) that have been assigned global security access to this SmartUI Server, is automatically associated with every policy. For details, see Assigning global security to groups and users.
  • Additional groups, over and above those that are assigned global security access, may initially be associated with every policy. For details on configuring this security setting, see Server security settings.
  • Once a datasource plugin is secured using a policy, this security will be applied to all of its existing and future configured datasources. 
  • In order to secure a specific datasource, data element security needs to be employed instead. For details, see Working with data element security.

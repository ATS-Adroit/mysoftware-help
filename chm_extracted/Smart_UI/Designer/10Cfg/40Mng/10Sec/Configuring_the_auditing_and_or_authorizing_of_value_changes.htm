Configuring the auditing and/or authorizing of value changes

The SmartUI Server includes the following data element security functionality:

Note: This functionality is part of the SmartUI Server and is available even when one does not want to use 21 CFR 11 mode.

  • auditing functionality: to audit ANY data element by completely tracking changes made to its value through the SmartUI.
  • change authorizing functionality: when enabled this requires an additional user to provide authorization before a change can be made (written) to a data element.

Tip: If you are employing a 21 CFR 11 compliant project then ensure that you have enabled 21 CFR 11 mode. For more details, see Working with 21 CFR 11 mode.

Before your Windows user accounts and/or groups can participate in the auditing and/or authentication of value (data element) changes, they need to be added as "allowed" users and groups on each SmartUIServer.

  • Since these users are required to access the SmartUI Server computer directly then to preserve the integrity of the 21 CFR 11 functionality, these users must only be given minimal rights (from a Windows security context). Only administrative users may be given extended rights.

IMPORTANT: Therefore ONLY specify your system administrator users and/or groups in this the Security Settings page of the SmartUI Server in the Adroit Config Editor, since these users and/or groups have immediate GLOBAL access to every aspect of your project, which includes the ability to write to all of the data elements. For details, see Server security settings.

For this reason, you should rather configure your allowed users and groups within the SmartUIDesigner, as you can then manually configure the extent of their access. For details, see Adding allowed users and groups.

  • Since, you need to know beforehand exactly which values to audit and/or authorise, you can only configure specific, individual data elements and not entire groups of data elements. In other words, the Apply To Children setting is NOT supported

For instance, when used with the Adroit datasource and you apply it to an Analog agent it does nothing, you need to manually select and configured the value slot security. Although a default (the most commonly used) slot for each agent type, may be implemented later.

In the SmartUI every value is known as a data element of a datasource, so you use data element security to configure the auditing change of values (data elements) and/or their authorization, as follows:

IMPORTANT: Unlike the data element security permissions, the auditing and authorizing settings are data element specific and NOT user or group specific. So they are enabled or disabled for ALL the selected users and/or groups.

However, ONLY users or groups with the Write Data security permission can authorise changes to a data element.

Note: Currently these security options can only be applied to data elements and not to special functions of a datasource.

  1. Right-click the required datasource or data element in the Enterprise Manager and select the Security menu option: 

In the Security configuration dialog, ensure that the Security For Data Element field, beneath the Data Element Information group, specifies the required data element.

  1. Use the Groups And Usersgroup to select the allowed user(s) and/or groups to be assigned security permissions for this data element.

Either by clicking the << button or double-clicking the required entry in the Available list to immediately add it to the Selected list.

  1. Assign security settings to allowed users and groups, as follows:
  1. Select a user or group from the Selected list.

Tip: Select multiple users or groups, if more than one is to have the same security permissions assigned to them.

  1. Empty the checkboxes that do not apply to the currently selected user(s) or group(s).

Tip: Clicking on the name will check or empty its checkbox. 

  1. Repeat this until all of the selected users or groups have been assigned the correct security settings for the selected data element.
  1. Use the Data Element Securitygroup to assign the required security permissions to the selected users and/or groups. For details, see Available data element security permissions.
  2. Use the Auditing group to assign the required value auditing and/or authorizing settings to this data element, as follows:

IMPORTANT: Unlike the Data Element Securitygroup, the settings of the Auditingare data element specific and NOT user or group specific. So they are enabled or disabled for ALL the selected users and/or groups.

Note1: These settings IGNORE the Apply To Children and Inherit From Parent settings as they ONLY apply to specific data elements and NOT to groups of data elements and therefore cannot be inherited from data element groups.

Note2: BOTH these settings need to be applied to the applicable data elements for 21 CFR 11 compliance.

  • Audit Writes: when checked any change made to this data element is recorded to an auditing database with the user who initiated the change and if applicable the user who authorised this change. For further details, see Working with audited data element values.

These recorded (logged) changes include: the timestamp of the change; the change made; the initiating user and, if applicable the authorizing user, and a computed hash of all these fields to detect tampering.

  • Requires Authorization: when checked any change made to this data element needs to be authorised by one of the selected user/s and group/s. Once set, then any change made to this data elements needs to be authorised by a DIFFERENT allowed user or group, than the user or group who makes the change (the initiating userthe currently logged on user or group that changes the value (data element) that requries authorization; See authorizing user). For details, see Authorizing changes made to values.

IMPORTANT: If a data element is marked as requiring authorization then no single individual may change the value of this data element.

Note: ONLY users or groups with the Write Data permission can authorise changes.

Furthermore, the authorizing user is recorded along with the other details of this change in value, when the writes of this data element are audited.

The system responds to write requests made to this data element, as follows:

User Access Authorization Required Response to Write Attempt
Read No Prompt for credentials
Read Yes Prompt for credentials
Write No Write operation carried out unchallenged
Write Yes User prompted to provide authorizing user credentials OR to defer the operation for later authorization OR to cancel the write.
Authorise No N/A
Authorise Yes User prompted to provide authorizing user credentials (other than this user) OR to defer the operation for later authorization OR to cancel the write

Working with security

The SmartUI security system is user-centric and operates on top of the traditional Windows operating system security.

This uses a configurable sub-set of the existing users and groups that are "allowed" on each SmartUI Server computer and are hence known as the Allowed users and groups.

SmartUI Server security is configured in the Enterprise Manager, by using the Security component within the Management category.

  • The ONLY mandatory SmartUI Server security configuration are the Allowed users and groups, which provides the first or foundational level of ALL user security and management within the SmartUI. For details, see Configuring Server security.

Note: SmartUI Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. applications also provide security to control the access of the Allowed users and groups within these applications, amongst other functions. For details, see Working with Client security.

Security should typically be implemented during deployment, so that the initial allowed users and groups can be configured on each SmartUI Server. Then the access of these allowed users and groups should be specified within each Server and Client application.

However, security configuration should continue throughout the life of the project to secure new datasources; limit the access of new users and modify the access levels of existing users, as required etc.

Note: The lowest level to which SmartUI Server security can be applied is the data element. It is therefore useful to determine the available data elements. For details, see About datasources and data elements.

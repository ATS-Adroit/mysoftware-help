The DumpConfig agent

The DumpConfig agent is used for reporting purposes only and is a special report that exists in the Adroit Pack of our Adroit Report Suite.

  • The sole function of this agent is to periodically record a snapshot (or a dump, or a record) of the current configuration of certain agent types.
  • The snapshot record is saved to specific tables in an OLE DB database that will allow reports to be generated.
  • An example of its use is to report on agents in the context of their configuration at the time of the report, or it may be used to audit changes made to specific agents.

Warning:  You can only add ONE DumpConfig agent.

This agent is located in the following file: T_DUMPCONFIG.DLL

How it works

When the agent is enabled, the agent will wait for one of three events to happen before performing a snapshot:

  1. The occurrence of the next hourly period.
    • The very first period is synchronised to midnight, meaning that if you specify an hourly interval of 8, the first snapshot will occur at 08h00 or 16hoo or at 00h00, whichever occurs first.
    • After that, the snapshot will occur every subsequent 8 hours.
  1. A  manual snapshot can be requested via the dumpNow slot
  2. A non-zero value trigger event of a selected trigger tag, when one is specified.

Configuration

Configuring this agent provides the following options:

  1. Select the agent types to be recorded.
    • For each agent, you can specify CSV strings of specific and also which instances are to be recorded.
    • By default, these entries are specified as [*] to indicate all slots and all instances are selected.
    • Should you want to select only A1 and A2 agent instances, for example, then the entry would read A1, A2
  2. Optionally enable snapshots for the alarming and scanning configurations.
  3. Set the hourly interval at which these snapshots should be recorded.
  4. Specify a trigger tag for snapshot recording.
  5. Enter the database connection string where these snapshot tables are to be created.

Configuring the DumpConfig agent

You can set up the DumpConfig agent to specify the configuration of specific agents that you want to save to the OLE DB database, including the interval and triggers.

  1. To create a new agent or find an existing agent:
    • To add a new DumpConfig agent, see To Add a New Agent.
    • To open an existing agent, see To Select an Agent.
  2. To begin, open the Edit DumpConfig Agent dialog.
  1. Select the Edit menu item to display the Edit DumpConfig Agent dialog.
  2. Select the Enable option to activate the agent.
  3. Add the Agent configurations you want to save to the OLE DB database:
    • Click the + button to add a row to the Agent type configuration table.
    • Type in the name of the required Agent Type, ensuring that you spell this name correctly.
    • By default, all the Agent slots of the specified agent type, indicated by an [*], are included in each configuration, and all are saved to the database.
      • However, you can enter a comma-delimited list of slots to explicitly include the slots that you want to be saved.
      • This will reduce the size of each configuration and the processing time taken to log this data.
    • If you do want to use a comma-delimited list of the header slots that you want to save, enter the list in the following format:
      • agentName.headerSlot1, agentName.headerSlot2, agentName.headerSlot3, and so on.

Important:  The optional comma-delimited list of Agent slots or Agent instances for the specified Agent type cannot exceed 79 characters!

  1. You may optionally enable recording of the alarming or scanning configuration.
    • Select the Dump full Alarming configuration option.
    • Select the Dump full Scanning configuration option.
  2. Specify the time interval or event that will save the specified agent configurations to the database.
    • If required, enter the required Dump interval (in hours, 0 to disable).
    • If set to a number greater than 0, then this number indicates an hourly interval used to trigger this agent.
    • If set to 0, this will disable this method of triggering this agent.
  3. If required, enter the required Dump trigger tag.
    • Type in the required tag (agent.slot) or select the ... button to browse for the required tag containing a Boolean, integer or real value.
    • Whenever the value of this slot changes to a non-zero value, the specified agent configurations are saved to the database.
  4. Alternatively, you can manually save the specified configurations to the database by clicking the Dump now button.
  5. Specify the target OLE DB database to save the agent configurations.
    • In the Connection string box, type or select the ... button to browse for the connection details of the required OLE DB database.
    • You may also use an existing (or create) a SQL Server database to save your agent configurations.

    Note:

    • If you configure this DumpConfig agent from remote computers, it is safer to use SQL Server authentication (Use a specific user name and password) when creating this connection.
    • Avoid using Windows authentication (Use Windows NT Integrated Security) unless you are certain that the logged on users at the remote computers have the necessary access rights to this SQL Server database.
    • If the SQL Server connection string in the DumpConfig agent has been configured using Windows authentication, it will more than likely not work, and agent configurations will not be saved
    • Occurs if the Windows User on this remote computer has not been given access rights to the SQL Server database.

Provider TAB

The Data Link Properties dialog specifies the location and the security credentials required to connect to this database.

Double-click the Microsoft OLE DB Provider for SQL Server item in the Provider tab of the Data Link Properties dialog.

Important:  If the computer, on which SQL Server was installed, was renamed, then SQL Server may need to be re-installed.

If the computer was renamed after installing SQL Server, then SQL Server must be re-installed, to function correctly.

Run the following check:

  • Execute the following T-SQL (Transact-SQL) script in SQL Server Management Studio: SELECT @@SERVERNAME
  • If the resulting server name is different to the actual name of the computer, then the name of the computer has been changed after SQL Server was installed, so you need to reinstall SQL Server.

Advanced Tab

The Advanced tab of this dialog allows you to specify access permissions for this connection string.

Dump Output

Configurations will be saved to tables named Adr_Dump_AgentTypeName  in the specified database, for example: Adr_Dump_Analog.

  • The available agent slots that are saved to these tables depend upon whether the table exists or not in the specified database.
  • If the Adr_Dump_xxxxx table does not exist it will be created with the specified Agent slots in the Agent type configuration table for this Agent type.
  • If the Adr_Dump_xxxxx table already exists then the configurations will be saved using the existing slots specified by this table, to allow users to manually remove columns of unwanted data from this table.
 

The status bits of this agent can be used for diagnosing the status of its connection to the database and/or the process of saving agent configurations to this database.

  • For details, see Specific Status Bits of the DumpConfig Agent.

Agent Slots

The DumpConfig agent contains various slot categories. Click on the options below to view more information on each category.

DumpConfig Agent Configuration slots

The following slots are used for configuration and are saved to the .WGP file:

Slot name Slot type Slot description
addType VARSTRING Add agent type to list.
connection VARSTRING Define the connection string to the database.
dumpAlarm BOOLEAN Set to [1] to dump alarm configuration on each snapshot.
dumpNow BOOLEAN

Set to [1] to create immediate snapshot.

  • Agent will reset this value to [0] after every snapshot.
dumpScan BOOLEAN Set to [1] to dump scanning configuration on each snapshot.
enable BOOLEAN Enables the agent to create snapshots.
Interval INTEGER

Set the number of hours to define the intervals for creating snapshots.

  • Set to [0] to disable interval snapshots.
trigger TAGNAME Optional boolean, integer or real trigger tag that will create a snapshot, if the value changes to any non-zero value.
list LIST List of agent types to snapshot.
DumpConfig Agent Status slots

The following status bits of this agent can be used for diagnosing the status of its connection to the database and/or the process of dumping agent configurations to this database.

Note:  These slots are of type BOOLEAN only.

Bit Number Name Function

status bit 16

ConnectionError

Set to [1] when the connection with OLE DB source cannot be established. Used for troubleshooting.

status bit 17

TransactionError

Set to [1] when any transaction error with SQL occurs. Used for troubleshooting.

status bit 18

DumpBusy

Set to [1] when a snapshot begins and set to FALSE when snapshot is complete. Used for monitoring.

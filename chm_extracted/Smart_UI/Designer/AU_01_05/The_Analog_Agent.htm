The Analog Agent

An Analog agent stores a real (floating point) value that provides the following functionality:

  • Scaling its value according to user defined minimum and maximum scaling settings. These scaling parameters are typically only specified, when a front-end device contains this value.

    The Analog agent provides support for up to 51 bit numbers, in that the new maximum range is 2,000,000,000,000,000 for unsigned numbers or -1,000,000,000,000,000 to 1,000,000,000,000,000 for signed numbers.

    Note: To reduce the loss of accuracy in scaling caused by IEEE conversion issues, the Analog agent bypasses the scaling calculation, when the scaling is 1:1.

  • Monitoring its value against one or more of the following value-specific alarm limits: low-low, low, high, high-high and/or rate of change.

    Any infringement of these alarm limits causes the agent to set its corresponding status bits, which can be alarmed.

  • Specifying the engineering units used to measure this value.
  • Monitoring its value for changes, where any change in value causes the agent to log an event and set a status bit, which can be alarmed.
  • Calculating statistics from the value slot every second, for a specific rolling period (specified in minutes). For details, see Calculating statistics from Analog values.
  • Recording the time this value changes, which is saved to the time slota value (attribute) or field within an agent that can be retrieved and/or set. of this agent
  • Reverse polarity scaling and the remote configuration of the alarm limits
  • Square root extraction for the linearization of flow signals,
  • Alarm deadband settings for the high and low alarm limits
  • A cold start value initialization option when starting the Agent Server.

For details on how to configure some or all of this functionality for an Analog agent, see Configuring Analog Agents.

IMPORTANT CHANGE FOR ANALOG AGENTS: Changed the default method of handling what happens when the rawvalue slot goes out of range (either exceeds the rawMax value or is lower than the rawMin value), from now this causes the Analog agent to set the new OutOfRange status bit (which can be alarmed if needed).

This is to prevent the entire agent from being marked at as being bad, as happened previously, which causes all the instances of this value to be greyed out (disabled) on the mimics which display them.

Note: If you prefer the legacy method of marking the agent bad (setting the statusAgentBad condition bit) when the rawvalue slot goes out of range, then you need to add the OutOfRangeEqualsAgentBad registry setting.

Typically Analog agents should be used for tank levels or any process value stored in a front-end device that needs to be scaled (converted) to and from its engineering value and/or that needs to be closely monitored and/or alarmed.

If you ONLY want to store a real (floating point) value then use the Real agent instead.

Note: For those of you running a clustered Agent Server, this agent supports real-time catch-up so even if the master Agent Server fails, the standby will seamlessly continue with the current configuration settings including its scaling and alarm limit settings.

For details of the specific status bits of this agent that represent the agent-specific conditions that can be alarmed or directly displayed on a mimic to indicate when these conditions occur, see Specific Status Bits of the Analog Agent.

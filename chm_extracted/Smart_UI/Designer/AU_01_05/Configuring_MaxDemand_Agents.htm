Configuring MaxDemand Agents

This describes how to configure each of the configurable fields provided by the MaxDemand agent.

Edit an agent of type: MaxDemand.

If necessary, add an agent of the required type, as follows:

In the SmartUI Designer:

Select the required SmartUI Server in the Enterprise Manager, as follows:

  1. Open the Enterprise Manager.
  2. Navigate to Servers > [Server Name].
  3. Tip:  The connection name is prefixed by the SmartUI Server computer name.

  2. If necessary, expand the required Adroit datasource or its icon .

In the Enterprise Manager window: right click this agent and select Configure.

In the Edit MaxDemand Agent dialog:

To enable this agent during periods of high electricity consumption: since your electricity provider only calculates maximum demand during high consumption periods, this agent should only be enabled at these times.

This agent can be selectively enabled as follows:

  • Check the Enable OR use tag checkbox (the enable slot) to browse in a Boolean or Real tagA fully qualified named value in Adroit (agentName.slotName). that turns this agent on during maximum demand periods. For example, you could create a Scheduler agent to define these high consumption periods. This is the recommended approach, since the Scheduler agent is designed to specify time periods that take weekends and holidays and other non-essential times into account OR
  • leave the Enable OR use tag checkbox unchecked, do NOT browse in a tag and use Script or Expression agent to drive the Boolean enable slot OR
  • leave the Enable OR use tag checkbox unchecked, do NOT browse in a tag and scan the Boolean enable slot of this agent to a PLC that has knowledge of the maximum demand periods.

WARNING! A scanning overrunthis occurs when the scan task takes longer than the required scan rate due to an overloaded or defective scanning subsystem. will affect the accuracy of the periods in which this agent is enabled. Since this would cause the enabling pulse to arrive late, so that the measuring block period will be out by a couple of seconds or more.

To synchronise the block periods with your electricity provider: it is important to ensure that the block periods are synchronised with the SAME duration as those used by your electrical provider to ensure that the predicted and actual maximum demands calculations are the same.

Use ONE of the following methods to ensure this:

  • Time-based block periods: The block period duration is specified and each block period is synchronised with the local system time of the computer. In this case:
    • specify the required block period, in minutes, in the Block period (mins) edit box (the blockPeriod slot) and
    • CLEAR the Enable block pulses checkbox (the blockPulseEnable slot).

    Note: If this method is used, it is essential that the system time of the computer reflects the actual time; otherwise, the predicted values may not be the same as those calculated by your electricity provider.

  • Pulse-based block periods: Your electricity provider sends a pulse (signal) to you to synchronise the start of each block period. In this case:
    • specify the Block period (mins) edit box,
    • check the Enable block pulses checkbox, and
    • ensure that the BOOLEAN blockPulse slot of this agent is scanned to this external pulse, preferably at 1 second to maintain accuracy.

    WARNING! Any scanning overruns will affect the accuracy of the predicted and actual maximum demands calculations due to timing differences between the Agent Server and your electricity provider.

Use the 'PulseError’ alarm type for this agent to warn you when this occurs.

To specify the maximum kVA demand limit for this agent: if this limit is exceeded an alarm can be generated.

Use the Max demand limit edit box (the mdLimit slot).

Tip: If may be useful to specify a value slightly LESS THAN the actual maximum demand limit imposed by your electricity provider, so that there is time for counteractive measures to be taken when this is exceeded.

To set the MaxDemand status bit when the limit is exceeded: this will set the MaxDemand status bit when the predicted maximum demand exceeds this specified maximum demand limit. By alarming the ‘MaxDemand’ alarm type for this agent, you can be warned when this occurs.

Check the Enable max demand alarm checkbox (the enableMDAlarm slot).

 

To reset the monthly maximum demand calculation: since this agent stores the largest maximum demand calculated over any block period for the current billing period (month), you need to specify when this billing period ends to reset this value.

Both the day of month and time of day can be specified, as follows:

  • Day of month (0 denotes the last day of month) (the resetDay slot): This edit box specifies the required day at which the monthly values are reset, the default is 0 (the last day of the month).
  • Time of day (the resetTime slot): This spin control specifies the time (hours:minutes:seconds) of the specified day (in 24 hour format) at which the at which the monthly values are reset, the default is 12 am (midnight).

Note: The BOOLEAN resetNow slot, if set to one, resets all the calculated values to zero.

To specify the instantaneous kVA (apparent power) input: this is required to calculate maximum demand for the current block period and for the current monthly billing period.

Specify this input as follows:

  • Either scan the REAL kVA slot of this agent to a PLC that measures the total instantaneous kVA usage and leave the kVA edit box empty.
  • Or specify a REAL tag (agent.slot) value in the kVA edit box (the kVATag slot) that specifies the total instantaneous kVA usage.

Tip: Use the browse button to the right of the kVA edit box to locate this tag. For details, see Selecting a Tag Using the Built-in Agent Explorer.

To specify the instantaneous kW (real power) input: this is required if you also want this agent to calculate the instantaneous reactive power and/or power factor.

Specify this input as follows:

  • Either scan the REAL kW slot of this agent to a PLC that measures the total instantaneous kW usage
  • Or specify a REAL tag (agent.slot) value in the kW edit box (the kWTag slot) that specifies this value.

If necessary, you can also display your instantaneous kVAr (reactive power) input (the kVAr slot) for information purposes only.

 

Current Block Period Information: this describes the information provided by the MaxDemand agent for the current block period.

Last pulse time (the blockPulseTime slot): This value depends upon the method used to determine the block period, as follows:

  • Time-based block periods: The time at which this block period was synchronised with the local system time of the compute.
  • Pulse-based block periods: The time at which the scanned pulse started the current block period.

Tip: Alarm the error alarm type for this agent to warn you when the timing of these external block pulses is compromised.

Time left (mins) (the blockTimeLeft slot): The available time-in-hand (in minutes) to the end of this block period. In other words, this specifies the available time in which the maximum demand for this block period can still be controlled.

Current demand (the demand slot): The actual power that has been used (kVA demand) for this block period.

Predicted max demand (the mdPredict slot): This estimates the total power use (kVA demand) for this block period, by using the Current demand (the demand slot) against the remaining time for this block period.

Note: If this value exceeds the specified Max demand limit(the mdLimit slot) then the MaxDemand status bit is set if the Enable max demand alarm checkbox (the enableMDAlarm slot) is enabled. Then alarm the ‘MaxDemand’ alarm type for this agent to warn you when this occurs. 

Tip: It is possible to use the MaxDemand status bit in a Script agent to control the maximum demand by using it to turn off non-essential equipment.

Predicted over/under (the mdOverUnder slot): This displays the difference between the Predicted max demand (the mdPredict slot) and the Max demand limit(the mdLimit slot) for this block period.

Time to max demand (mins) (the timeToMD slot): This indicates how long, in minutes, before the Max demand limit(the mdLimit slot) will be reached before the end of the block metered period, at the current demand.

Note: If you are running safely, this will ALWAYS indicate the end of the current block period.

Optimal KVA (the kVAOptimal slot): The recommended kVA consumption to meet (and NOT EXCEED) the Max demand limit(the mdLimit slot) for this block period.

Spare KVA (the kVASpare slot): The spare kVA capacity for current period, which is the difference between the Current demand(the demand slot) and the Optimal KVA(the kVAOptimal slot).

This either specifies a negative amount of kVA that needs to be shed (removed) or a positive amount of kVA that can be added to meet (and NOT EXCEED) the Max demand limit(the mdLimit slot) for this block period.

MaxDemand Agent Calculations: the MaxDemand agent only performs these calculations when correctly licensed and provided with the necessary inputs.

Note: This agent needs a separate OEMa component in Adroit that requires a SEPARATE license BEFORE it can be used, which is added to the Agent Server license by means of an appropriate textual description of this component. license before performing background calculations.

Tip: To determine if this agent is correctly licensed, ensure that its Unlicensed status bit is NOT set.

kVAr* (the kVArCalc slot): This calculates the instantaneous kVAr (reactive power) value, which requires both the mandatory kVA input (the kVA slot) and optional kW input (the kW slot).

PF (the pf slot): This calculates the instantaneous power factor, which requires both the mandatory kVA input and optional kW input. For details on how this can save you money, see About Power Factor.

TotalKWh (the kVAhTotal slot): This calculates the total real power in KWh (kilowatt-hours) consumed for the maximum demand periods of the current month.

TotalKVArh (the kVArhTotal slot): This calculates the total reactive power in KVArh (Kilo Volt Amps Reactive Hours) consumed for the maximum demand periods of the current month, either from the calculated kVAr* value or the optional kVAr input.

Current month MD (the mdActual or value slot): This is the highest recorded maximum demand for any block period of the current month.

Note: When the monthly values are reset this becomes the Last month MD value.

Last month MD (the mdPrev slot): This specifies the previous month’s actual maximum demand for comparison purposes only.

 

This also provides the following additional slots: kVAOptimal, mdOverUnder and timeToMD. See MaxDemand Agent - Slot Details.

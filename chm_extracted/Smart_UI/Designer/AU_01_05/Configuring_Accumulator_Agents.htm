Configuring Accumulator Agents

You are typically required to configure an Accumulator agent to analyse an accumulating process value and to calculate its difference in value (or change) between successive events or over a specific time (interval).

To do this, click on and read each of the following options:

1. Open the Accumulator agent dialog

First, open the Edit Accumulator Agent dialog as follows:

  1. Select the name of this agent. For details, see To Select an Agent.
  2. If an agent does not exist, you may add an Accumulator agent. For details, see To Add a New Agent.
  3. Right-click and select the Edit option to display the Edit Accumulator Agent dialog.
2. Define the accumulating value

In the Edit Accumulator Agent dialog, you can specify the accumulating process value that you want to monitor and assess, in one of the following two ways:

  1. Find the inputTag property, click the browse button then select the slot which represents the ever-increasing process value. In this case, the selected value of this tag will be assigned to the inputValue slot.
  2. If the inputTag slot is NOT specified, then you need to drive the inputValue slot, typically by scanning this to the required accumulating process variable stored on the front-end device or using a script or expression.
3. Specify how you want each period to be defined

Typically, you define a constant interval of time over which the differential increases in value is calculated. The agent provides you with the ability to select the method you’d prefer to use.

You do this on the intervalMode slot property, as follows:

Note:  The triggerNow slot (and button) performs a manual end of period, which is effective in any mode selected by this intervalMode slot.

IntervalMode options 0 - 2

These first three interval options use the intervalTag, which is a tag you can browse to set when the end of an interval has occurred:

0 = Interval tag value goes to zero The end of the interval occurs when the value of the intervalTag changes from any non-zero value to a value of zero [0].
1 = Interval value goes (from zero) to non-zero The end of the interval occurs when the value of the intervalTag changes from a value of zero [0] to any non-zero value.
2 = Any interval tag value change The end of the interval occurs when the value of the intervalTag changes in value to any other value (a different value from its current value).

IntervalMode options 3 - 4

The next two options let you to define the required interval by making use of the system time (the time of the Agent Server computer) and the interval slot, which specifies the duration of each period in minutes:

3 = Synchronised (to clock - default)
  • The agent forces the periods to be synchronised with the system time (i.e. the time of the Agent Server computer). Therefore, the initial period of the current hour always begins at the start of the current hour (0 seconds or 0 minutes) which is how the current period is calculated when this agent is enabled.
  • As an example, if you have an interval of 10 minutes, the first period of this hour starts on the current hour to 10 minutes past the hour; the second period of this hour starts at 10 minutes past the hour and end at 20 minutes past the hour, and so on.
  • A further example, if the agent is set to use the intervalMode of 3 with an interval of 10 minutes and the agent is enabled at 10:02, then the first period will end at 10:10 for this mode (a partial interval of only 8 minutes to enforce the ending time of this period, which began at 10:00 even though the agent was only enabled at 10:02).
  • However, if this same agent is enabled at 10:45, then the first period will end at 10:50 for this mode (a partial interval of only 5 minutes to enforce the ending time of the current period, which began at 10:40).

Important:  If you are using this method, then you need to ensure that the specified interval is divisible into 60 or is a multiple of 60 otherwise period timing errors will occur.
4 = Not synchronised (to clock)
  • The agent sets the starting time of the periods to the exact time that this agent is enabled and calculates all the successive periods by adding the specified interval number of minutes to this starting time.
  • For example, if the agent is set to use the intervalMode of 4 with an interval of 10 minutes and this agent is enabled at 10:02, then the first period will end at 10:12 for this mode (a full interval from the starting time) and the next period will end at 10:22, and so on.

IntervalMode option 5

If you choose the final option then you typically need to devise a method of driving the triggerNow slot via a script or expression or this agent can calculate the differential value whenever you choose to.

5 = Manual trigger The rate of change and its alarm limits only applies when using periods that have regular intervals.
4. Configure the required alarm limits and if necessary their deadband

If necessary, you can configure the alarm limits and the deadband when required, for this differential value, and the rate of change of this differential value over the specified period.

Tip:  The deadband slot is used to desensitise these alarm limits and prevent unnecessary alarms if the value is oscillating. In other words, this specifies the ‘band’ (size of) the ‘dead’ area outside these alarm limits, which the value must reduce by before the alarm is cleared.

Important:  The deadband slot ONLY applies to the alarm limits for the differential value and NOT to the rate of change alarm limits.

Alarm limits

The following alarm limits can be defined for the differential value in the Value alarm levels section of the properties dialog:

  • The valueHiHi alarm limit specifies the second alarm limit for a high value, which if reached, should typically require urgent and immediate corrective action.
    • When the value reaches or exceeds this alarm limit, the VHighHigh status bit is set to [1] (enabled), which can be alarmed using the VHighHigh default alarm type.  
  • The valueHi alarm limit specifies the first alarm limit for a high value, which if reached, should require corrective action as soon as possible.
    • When the value reaches or exceeds this alarm limit, the VHigh status bit is set to [1] (enabled), which can be alarmed using the VHigh default alarm type.  
  • The valueLo alarm limit specifies the first alarm limit for a low value, which if reached, should require corrective action as soon as possible.
    • When the value is lower or equal to this alarm limit is reached, the VLow status bit is set to [1] (enabled), which can be alarmed using the VLow default alarm type.  
  • The valueLoLo alarm limit specifies the second alarm limit for a low value, which if reached, should typically require urgent and immediate corrective action.
    • When the value is lower or equal to this alarm limit is reached, the VLowLow status bit is set to [1] (enabled), which can be alarmed using the VLowLow default alarm type  

Note:  Whenever the Low-low alarm is on, the Low alarm must, by definition also be on. Similarly, whenever the High-high limit is reached, the High limit will already have been passed.

Rate of change

The following alarm limits can be defined for the rate of change of this differential value over the specified period in the Rate alarm levels section of the properties dialog:

Note:  The deadband slot does NOT apply to these rate alarm limits.

  • The rateHiHi alarm limit specifies the second alarm limit for a high rate, which if reached, should typically require urgent and immediate corrective action.
    • When the rate reaches or exceeds this alarm limit, the RHighHigh status bit is set to [1] (enabled), which can be alarmed using the RHighHigh default alarm type.  
  • The rateHi alarm limit specifies the first alarm limit for a high rate, which if reached, should require corrective action as soon as possible.
    • When the rate reaches or exceeds this alarm limit, the RHigh status bit is set to [1] (enabled), which can be alarmed using the RHigh default alarm type.  
  • The rateLo alarm limit specifies the first alarm limit for a low rate, which if reached, should require corrective action as soon as possible.
    • When the rate is lower or equal to this alarm limit is reached, the RLow status bit is set to [1] (enabled), which can be alarmed using the RLow default alarm type.  
  • The rateLoLo alarm limit specifies the second alarm limit for a low rate, which if reached, should typically require urgent and immediate corrective action.
    • When the rate is lower or equal to this alarm limit is reached, the RLowLow status bit is set to [1] (enabled), which can be alarmed using the RLowLow default alarm type.
5. Configure the SQL Server database to store the values of each period

To maintain a history of the differential values for each period you must specify the SQL Server database and table that is used to store these records:

  • Specify the connection string to this SQL Server database in the connection field by using the Data Link Properties dialog.
  • For more details, see Creating a SQL Server database connection string.

    • Note:

    If you specify global, the Global OLE DB connection string of the Agent Server is used, which is specified in the Adroit Config Editor.

    • Typically, you can launch this tool from the Desktop shortcut.
    • Select the Agent Server Configuration Welcome menu item.
    • Select the Advanced Agent Server Configuration option.
    • At the bottom of the dialog, the Global OLE DB connection field is available for you to specify this connection string.
  • Specify the required table name in this database to store these records in the tableName field. By default, this table name is set to the name of this Accumulator agent.
  • When you are using a clustered Agent Server, then the standby clustered partner will, by default, not log these records to this database, thus preventing duplicate records. However, you can change this, if required, by configuring the disableOnStandby slot setting.
  • Each record specifies a unique index (idx); the date and time at which the period ended (dt); the differential value(value) and the inputValue - the value of the accumulating process variable (accumulator) at this time.

If a valid connection and table is specified, the History table will be created as follows:

Column name Type Description
idx Int Auto incrementing index
dt datetime Period end date and time
value float Calculated value for period
accumulator float The accumulator reading (inputValue) at the end of the period

If you want automatic management of this data, then specify how many days worth of data you want this table to store in the housekeepDays field, to ensure that you keep the most relevant (most recent) records only.

Note:  The default value of 0 disables this functionality.

6. Enable the agent

To start analysing the accumulating process:

  • You should enable this agent to start analysing the accumulating process value and calculate its differential value for each period and its rate of change and, if required, also log the values of each period to the specified history table in the SQL Server database.
  • To enable this agent, set the enable slot of this agent (in the General section of this properties dialog) to True.
7. Values calculated by the agent for each period

At the end of every period:

  • The differential value of the previous period is saved to lastValue.
  • The differential value of the current completed period is calculated as: inputValue - startValue.
  • The rate of change of the previous differential value and period is calculated as: lastValue * 60 (minutes per hour) / (last period length in minutes) = value per hour.
  • A new record is added to the tableName (in the database by connection, if specified) containing the period start and end times, values and differential value and rate for the period.
  • A new period will commence immediately and the startValue will be assigned to the inputValue.

Tip:  You can view the amount of time that has passed (elapsed) from the start of the current period, in minutes, by viewing the elapsedTime slot.

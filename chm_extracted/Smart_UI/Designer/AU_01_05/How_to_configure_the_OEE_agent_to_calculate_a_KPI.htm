How to configure the OEE agent to calculate a KPI

This explains the recommended method of configuring your Adroit system to calculate a KPIKey Performance Indicator, a quantifiable measurement that measures how well something is accomplishing its goals and objectives.  for specific equipment (machine/s) and/or an entire plant (process).

KPIs are either:

  • simple : some production value over time such as ton/hr, total produced or actual run-hours, etc. [KPI% = (Total input1/Run time)/Target KPI] OR
  • complex: one production value against (divided by) another production value, such as kWh/ton. [KPI% = (Total input1/Total input2)/Target KPI]

Note: If the SECOND variable is not specified, then the FIRST variable is automatically divided by time.

The KPI can either compare actual performance with benchmark (optimum) figures or compare shift performances. For instance you could compare today’s total performance with that of the previous day and/or today's shifts with those of the previous day.

Before you can calculate a KPI, you may need to do the following:

  1. Ensure that the OEE Count parameter of your Adroit license has specified the required number of OEE agents (these are specified in groups of 10). This enables the background engine of the OEE agent to update the monitored KPI in real-time.

Note: WITHOUT specifying the licensed number of OEE agents, only one instance of an OEE agent has its background engine enabled. All other agents will appear not to be running.

  1. Ensure that you can access and communicate the variable/s used to calculate the KPI to Adroit.

    Scan the primary measurement variable to the input1 slot.

    IMPORTANT: The OEE agent expects that this input1 slot will ONLY be STATIC if the available and/or running slot is OFF.  If not, then production totals will continue to increment even though running/availability is OFF.

    If you are calculating a complex KPI, then also scan the secondary or dividing measurement variable to the input2 slot.

  2. Create the necessary Shift agent (for instance called OEE_SHIFT), which the OEE agent uses to specify the required shift patterns and to determine the current shift number. For details, see Configuring the Shift agent.

    Use the Shift tag field of the edit dialog (shiftAgent slot) to specify this Shift agent.

  3. Since we only calculate a KPI during time that the monitored equipment or process is running, the associated BOOLEAN running slot (or the optional BOOLEAN tag reference runningTag) should only be ON when the machine/process is supposed to be running.

    Note: The OEE agent expects that this slot will be OFF if the available slot is OFF.  If not, runtime will continue to increment even though availability is OFF.

    Therefore you could create a Scheduler agent that is configured with the applicable OFF times for the monitored machine/process - such as maintenance/lunch/tea times etc. For details, see Configuring the Scheduler agent.

    Then browse in the BOOLEAN value slot of this Scheduler agent as the Running tag (the runningTag slot) for this OEE agent to drive the running slot of this OEE agent directly. This is configured using the Advanced OEE options dialog of the OEE agent.

  4. An optional OLE DB connection to a SQL database, configured using the SQL connection string field.

    5. Note:

    If you specify global, the Global OLE DB connection string of the Agent Server is used, which is specified in the Adroit Config Editor.

    • Typically, you can launch this tool from the Desktop shortcut.
    • Select the Agent Server Configuration Welcome menu item.
    • Select the Advanced Agent Server Configuration option.
    • At the bottom of the dialog, the Global OLE DB connection field is available for you to specify this connection string.

  5. If the connection string is specified then this agent logs shift data, manually triggered snapshots and 1 minute sample data to a table called ADR_OEE. 

    Alternatively, the OEE agent can support database transactions to a table for the purposes of data warehousing. This requires specifying the required Data warehouse sample rate from 1-60 minutes. By default this is 0 = DISABLED.

To calculate a KPI:

  1. Edit an agent of type: OEE.

If necessary, add an agent of the required type, as follows:

In the SmartUI Designer:

Select the required SmartUI Server in the Enterprise Manager, as follows:

  1. Open the Enterprise Manager.
  2. Navigate to Servers > [Server Name].
  3. Tip:  The connection name is prefixed by the SmartUI Server computer name.
  1. If necessary, expand the Datasources category.
  2. If necessary, expand the required Adroit datasource or its icon .
  3. If necessary, expand the AgentGroup tree.
  4. Right click the required agent type , which are listed alphabetically, and select Create Tag.
  5. Specify the required Tag Name or agent name.

The following rules apply when naming agents:

  1. Agent names have a maximum of 27 characters.
  2. Agent names cannot be the same as the names used for Agent Types or for Agent Groups.
  3. Agent names cannot use the following characters:

Space

%

  1. If necessary, provide an optional Description that describes the purpose or describes the value of this tag (agent) for ease of reference.
  2. Click the Finish button.

 

If necessary, locate the required agent, as follows:

In the SmartUI Designer:

Select the required SmartUI Server in the Enterprise Manager, as follows:

  1. Open the Enterprise Manager.
  2. Navigate to Servers > [Server Name].
  3. Tip:  The connection name is prefixed by the SmartUI Server computer name.
  1. If necessary, expand the Datasources category.
  2. If necessary, expand the required Adroit datasource or its icon .
  3. If necessary, expand the AgentGroup tree.
  4. If necessary, expand the required agent type , which are listed alphabetically.
  5. Locate the required agent , which is also listed alphabetically beneath their applicable agent type.

 

In the Enterprise Manager window: right click this agent and select Configure.

In the Edit OEE Agent dialog:

  1. Check the Enable agent checkbox (the enable slot).

  2. Click the browse   button to the left of the Shift tag checkbox and select the Shift agent you created to specify the required shift patterns and to determine the current shift number. For details, see Selecting a tag using the Agent Explorer.

    By default the OEE agent resets the recorded OEE at the end of each shift.

    If you want to use the agent for recording the OEE or KPI on a “per batch” basis, then uncheck the Shift auto-reset checkbox and programmatically reset the agent at the end of every batch. 

  3. For a simple or complex KPI, scan the primary measurement variable to the input1 slot of this OEE agent (OR use the input1Tag optional tag reference for the input1 slot - Advanced OEE options dialog, Input 1 tag).

    ONLY for a complex KPI - scan the secondary or dividing measurement variable to the input2 slot of this OEE agent (OR use the input2Tag optional tag reference for the input2 slot - Advanced OEE options dialog, Input 2 tag).

  4. Specify the type of input signal of the primary measurement variable, from the Input 1 type list, as follows:

    Note: Select the method that is used to add up this value.

    • Accumulator: The input1 slot is interpreted as an accumulated production count over time e.g. 123 bags.

    Note: This Input 1 type must be reset to 0 at the end of every shift using the ShiftEnd status bit as a trigger.

    • Total: The input1 slot is interpreted as an accumulated production count over time e.g. 123 bags.

    Note: This Input 1 type is never reset to 0.

    • Rate/hr: The input1 slot is interpreted as a per hour production rate which will be integrated by the agent over time to produce a totalised value.
    • Rate/min: The input1 slot is interpreted as a per minute production rate which will be integrated by the agent over time to produce a totalised value.
    • Rate/sec: The input1 slot is interpreted as a per second production rate which will be integrated by the agent over time to produce a totalised value.

  5. ONLY if you are calculating a complex KPI (where one measured variable is divided by another) then change the Input 2 type list from the default setting of Unused and specify the type of input signal of the secondary or dividing measurement variable, as follows:

    • Accumulator: The input2 slot is interpreted as an accumulated production count over time e.g. 123 bags.

    Note: This Input 2 type must be reset to 0 at the end of every shift using the ShiftEnd status bit as a trigger.

    • Total: The input2 slot is interpreted as an accumulated production count over time e.g. 123 bags.

    Note: This Input 2 type is never reset to 0.

    • Rate/hr: The input2 slot is interpreted as a per hour production rate which will be integrated by the agent over time to produce a totalised value.
    • Rate/min: The input2 slot is interpreted as a per minute production rate which will be integrated by the agent over time to produce a totalised value.
    • Rate/sec: The input2 slot is interpreted as a per second production rate which will be integrated by the agent over time to produce a totalised value.

    6. IMPORTANT: If calculating a simple KPI whose measured variable should be divided by time and NOT another variable, then ensure that the Input 2 type list is ONLY set to Unused, the default setting.

  6. If necessary, specify the units for the primary measured variable input1 in the top Totalised units edit box (the units1 slot) and ONLY if you are calculating a complex KPI then also specify those of the secondary or dividing measurement variable input2in the bottom Totalised units edit box (the units2 slot).

  7. Since KPI calculations are calculated against the time that the Machine/process running checkbox (the running slot) is ON - this should ONLY be ON when the machine/process is supposed to be running.

    Note: The OEE agent ALSO expects that this slot will be OFF if the available slot is OFF.  If not, runtime will continue to increment even though availability is OFF.

    Therefore instead of manually checking this checkbox:

    • Create a Scheduler agent that is configured with the applicable OFF times for the monitored machine/process - such as maintenance/lunch/tea times etc.
    • Click the Advanced button of this edit dialog and in the Optional tag references section, browse for BOOLEAN value slot of this Scheduler agent as the Running tag (the runningTag slot).

    In this way, this Scheduler agent will drive the running slot of this OEE agent directly.

  8. If necessary, specify an activity "deadband" or an acceptable level of inactivity for the monitored machine or process, in seconds, in the Inactive Period (secs) field (INTEGER inactivityPeriod slot).

    Note: To disable the inactivity period alarming, specify a value of 0.

    If the primary measurement variable (the input1slot) remains inactive for a longer time than this period, then the OEE agent will stop incrementing the running time and the Downtime status bit is activated. Click for more details:

    As long as the input1slot is changing AND is not zero, the agent assumes that the process/machine is active and increments the running time.

    Therefore the actual production time is determined by a combination of the running slot and an active input1slot.

  9. If necessary, you can use the Setpoints section of the Advanced OEE options dialog (displayed by clicking the Advanced button) to define the Target value, the Low alarm and/or Low-low alarm values for the overall KPI% calculation.

    Note: These alarms are calculated in real time.

  10. If necessary, you can also use the Advanced OEE options dialog to specify an optional OLE DB connection to a SQL database, to:

    • EITHER log shift data, manually triggered snapshots and 1 minute sample data
    • OR log data warehouse records to a table called ADR_OEE.

    In this case you can use: 

    The Batch ID field to manually specify an optional batch ID that is recorded with these database entries (the batchID slot) OR use a tag value instead, which you specify using the Batch ID tag in the Advanced OEE options dialog (batchIDTag slot).

    The Product field to specify an optional product name that will be recorded with database entries (the product slot) OR use a tag value instead, which you specify using the Product tag in the Advanced OEE options dialog (productTag slot).

    For more details on configuring the Advanced OEE options dialog (display this by clicking the Advanced button of the edit dialog), see Advanced OEE agent configuration options.

  11. Once OEE agent has been configured and working, you can:

    • Check the Auto-refresh checkbox, to view the real-time calculation of the production factors and the resultant OEE for the monitored machine or process.

    If you are logging this data to an OLE DB database, then you can:

    • Click the Reset... button to reset the current OEE data.
    • Click the Reset all... button to reset ALL the recorded OEE data.

    WARNING! Since these buttons cannot be secured, it is recommended that you ensure that your operators NOT have access to the dialog!

    Note: You ONLY need to perform these functions if there is “rubbish” in the shift data caused by faulty sensors etc.

  12. The following slots provide the calculated KPI, which you may want to display or use elsewhere:

    Slot Name Type Function

    kpiPercent

    REAL

    calculated KPI as a percentage.

    kpiCurrShift

    REAL

    calculated KPI for the current shift as a percentage.

    kpiPrevShift

    REAL

    calculated KPI for the previous shift as a percentage.

    kpiToday

    REAL

    calculated KPI for the current day as a percentage.

    kpiTodayShiftn

    REAL

    calculated KPI for the current day's shift n as a percentage where n = 1 to 6.

    kpiYesterday

    REAL

    calculated KPI for the previous day as a percentage.

    kpiYesterShift

    REAL

    calculated KPI for the current (same) shift on previous day as a percentage.

    kpiYesterShiftn

    REAL

    calculated KPI for the previous day’s shift n as a percentage where n = 1 to 6.

    In addition to these calculated values, the following slots are also provide useful information concerning this OEE agent and the monitored process or machine:

    Slot Name Type Function

    statusStr

    STRING

    The status of the OEE agent, as follows: Not available(A=0,R=0), running (A=1,R=1), stopped (A=1,R=0)

    total1CurrShift

    REAL

    The totalised value of the input1 slot for the current shift. 

    Note: This agent allows putslots to this slot to correct the integrated totals.

    total1Predicted

    REAL

    The predicted total of input1 for the shift

    total1PrevShift

    REAL

    Total value of the input1 value for previous shift

    totalToday

    REAL

    Total value of input1 for the day.

    totalTodayShiftn

    REAL

    Total value of input1 for today’s shift n where n = 1 to 6

    totalYesterday

    REAL

    Total value of input1 for yesterday

    totalYesterShiftn

    REAL

    Total value of the input1 value for shift n on previous day where n = 1 to 6.
    If calculating a complex KPI, then you can also refer to these slots:

    total2CurrShift

    REAL

    The total value of the input2 slot for the current shift. 

    Note: This agent allows putslots to this slot to correct the integrated totals.

    total2Predicted

    REAL

    The predicted total of input2 for the current shift.

    total2PrevShift

    REAL

    Total value of the input2 value for previous shift

    total2YesterShift

    REAL

    Total value of input2 for the same shift yesterday.

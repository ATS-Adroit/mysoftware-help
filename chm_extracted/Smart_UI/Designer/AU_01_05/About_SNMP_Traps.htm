About SNMP Traps

SNMP traps are unsolicited SNMP messages that devices send to notify an SNMP manager of significant events. Each message is known as 'a trap of the event', hence the term SNMP traps.

IMPORTANT: NEVER run the Windows SNMP Trap (listener) service because it conflicts with the Adroit SNMP trap functionality!

Note: This agent does NOT require the Windows SNMP Service to function, this service is ONLY required on each computer that this agent monitors.

Using SNMP traps can reduce the number of SNMP managed objectsmanagement data exposed by SNMP managed devices that might be hardware, configuration parameters, performance statistics, and any other data that directly relates to the operation of this device. (values) that you need to monitor (poll) for each device. In other words, instead of monitoring every OID value on every device, by using SNMP traps, a device can simply inform its SNMPMgr agent of the important values, which are then pushed to the SNMPMgr when an event occurs.

Note: This will also increase your required scan pointa scan point licence that is consumed from your Adroit license when information is being manipulated. allocation, since one scan point is consumed for every unique OIDSNMP managed Object IDentifier, which describes the exact location of this value in the SNMP structure for its device. value that is polled, written to and/or trapped.

To enable the receipt of traps for an SNMPMgr agent:

Check the Enable traps checkbox (BOOLEAN trapEnabled slot), in the Connection settings section of the Edit SNMPMgr Agent dialog, which is cleared (disabled) by default.

Note1: You also need to Enable polling (the start slot) before you will receive traps.

Note2: Adroit relies on the SNMP Trap Service to receive traps, which is installed with the SNMP Service.

 

By definition a trap can either be simple - one OID (unique or not) OR complex- multiple OIDs (unique or not). Click for how to handle traps:

  • you need to create a script to process non-unique OIDs
  • you can manually add unique OIDs to the OID list, so that the value of its associated Tag is updated when this trap is fired.

 

The SNMP Manager provides the following two trap handling Queues (which are FIFO in nature i.e. First In, First Out):

Note: The trap queues are processed from the oldest to the newest trap.

  • the first or main trap queue collects all the incoming traps

  • the second or work queue is used to hold the remainder variable sets (described below) for external parsing. This queue ensures that the trap handling scripts no longer need to ensure stack integrity.

    So now the script ONLY needs to monitor the following two size slots to ensure correct operation:

  • trapCount (INTEGER): The number of OIDs traps (and their sub-traps) contained in the main trap queue (for simple traps this is 1, for complex traps this is the number of OIDs [sub-traps] in this trap).
  • trapWorkCount (INTEGER): The number of remainder OIDs sub traps contained in the working trap queue (for simple traps this is NOT used, for complex traps this is the number of remainder OIDs [sub-traps] in this trap, minus the first one which was passed through to the trap slots directly).

One trap event may consist of one or more trap variable sets, and one trap variable set consists of the following set of slots:

  • trapGeneric (INTEGER): An Integer value of the generic code or identification of this trap OID.
  • trapSpecific (INTEGER): An Integer value of the specific code or identification of this trap OID.
  • trapOID (VARSTRING): The OID, in numeric format, which identifies the SNMP managed object for this event.
  • trapValue (VARSTRING): The value of the OID specified by trapOID.
  • trapTime (TIME): The time that the value, specified by trapValue, occurred.
  • trapType (INTEGER): An Integer indicator of the return type of the value, specified by trapValue, for information purposes only. For details, see OID Return Type Indicators.

This indicator can help you to determine which tag you should use to store this value.

These slots are marked as empty when there is no trap to parse, so triggering trapPop is this case does nothing.

Once the SNMPMgr agent receives the traps for the device that it is managing:

  • the Traps status bit is enabled (set)
  • these incoming SNMP messages are stored in the main trap queue

Triggering the trapPop will transfer the trap variable set to the slots above for use by a domain specific script.

  • trapPop (BOOLEAN): Set this slot to 1 (via a script or button etc.) to read the first trap off the main trap queue, which reduces the trapCount slot by the number of OIDs in this trap (for simple traps this is 1, for complex traps this is more than 1).

Simple traps (only one set) are therefore pushed directly to the set slots and not stored in the work queue at all, which is only of the remainder sets.

WARNING! Once a trap has been read off a queue it is discarded and cannot be accessed again.

Note1: You also need to Enable polling (the start slot) before you will receive traps.

Note2: Adroit relies on the SNMP Trap Service to receive traps, which is installed with the SNMP Service. (It is advisable to add these two services to the Agent Server dependencies list if running the Agent Server as a service.)

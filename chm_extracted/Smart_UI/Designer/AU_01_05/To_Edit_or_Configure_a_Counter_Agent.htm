Configuring a Counter Agent

  1. Edit an agent of type: Counter.

The Edit Counter Agent dialog box is displayed.

  1. Enable Counter agent persistence: This GLOBAL setting prevents the loss of the statistical values calculated by Counter agents.
    Use this method instead of saving the Agent database (.WGP) file frequently. 

WARNING! If there are large numbers of Counter agents, this setting can increase the CPU load of the Agent Server computer. For further details, see Agent Persistence Files.

  1. In the Input Tag box, enter the Input agent and slot. If the Input Tag field is left empty, the agent can use a value supplied from an Operator Action Behaviour linked to its inputValue slot, or directly using the Scheduler to run a PutSlot command, which inserts a new value into the inputValue slot.

  2. Trigger contains the triggering agent name and slot and the Triggered checkbox must be checked to permit external triggering.

    External triggering is used to update the On/Off time calculations regularly, if the Input Tag is changing at infrequent intervals, then triggering is required at faster intervals. If Trigger is blank, the agent defaults to using each toggling of the input tag’s value to trigger the next count calculation, or in the case where Input Tag is blank, it uses each change in its inputValue slot to do this.

  3. Enter the Time Format using the syntax described under the Date agent. The time slots are reported in this format, which can be changed at any stage, whether the agent is running or stopped.
  4. The percentage of time spent On and Off for the Last and Total times is shown next to the relevant boxes.
  5. Click the Alarms button.

The Alarms dialog will appear.

  1. Enter the alarm limits, or use the default limits.
  2. Click OK when finished defining the Alarm limits.
  3. Being event based, the counters are updated only in the event of one of the following slots changing: inputValue, refresh or trigger (if triggered is set).
  4. Toggling the Pause/Continue button temporarily causes the agent to ignore subsequent possible updates to the computed values.

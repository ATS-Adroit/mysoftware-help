How to chart and/or report data from a database

This document describes the procedure for trending/charting and/or reporting/displaying data that has been logged:

  • by using the DBLog agent of Adroit - although this how can be adapted for ANY data logging method.
  • to a MS SQL database that is connected to a SmartUI Server via an OleDB datasource

Prerequisites

Note: This document assumes that the reader has a basic working knowledge of using SQL databases and using databases in SmartUI.

Have Adroit 8 (MAPS 3) or later installed.

Note: If you are using a version later than this then this how to will probably also apply to your version too, although some dialogs and/or commands may have changed slightly.

Configuring the DBLog agent

The DBLog agent is a bulk OLE DB logging agent for typically logging Analog and/or Digital values to a specific table in a database for later retrieval. This provides various different logging methods, such as “log on change”, “log on interval” etc. For a detailed description of configuring the DBLog agent, see Configuring DBLog Agents.

Tip: Typically you need to separate the Analog and Digital tags that you want to log into different DBLog agents, due to their unique logging requirements.

Once the DBLog Agent has been configured and enabled, it creates table/s in the specified database with the following fields:

  • id: a unique indexing identifier
  • dt: the Timestamp of the logged value
  • Tagname: the name of the tag being logged
  • Value:– the value of the tag being logged
  • Quality: an indication of whether value of this logged tag was good or baddata has a bad status when data is missing, incorrectly reported or extrapolated..

This agent ALSO creates the Adr_DBLog_AgentDetails table, which contains all the agents referenced by all DBLog agents to provide more details about these referenced agents, which can be used to provide more context about them for reports.

This table is updated when: the agent is started; or when its tag list is changed; and unconditionally every morning at 01h00 and this table contains the following fields:

  • ID – integer key: a unique indexing identifier
  • Owner – varchar(255): the DBLog agent name for future use to remove entries owned by the agent
  • AgentName – varchar(255): the name of the agent of the tag being logged
  • AgentDescription - varchar(255): the description of the agent being logged
  • AgentType – varchar(255): the agent type of the tag being logged
  • TagName – varchar(255): the tag being logged
  • TagDescription – varchar(255): a description of the tag being logged; always equal to AgentDescription unless agent type is Marshal whereupon it contains the description of the bit
  • Units - varchar(255): for Analog agents only
  • OffText - varchar(255): for Digital and Marshal agents only
  • OnText - varchar(255): for Digital and Marshal agents only
  • RawMin - float: Raw (device-scale) minimum scaling limit for Analog agents only
  • RawMax - float: Raw (device-scale) maximum scaling limit for Analog agents only
  • EngMin - float: Engineering minimum scaling limit for Analog agents only
  • EngMax - float: Engineering maximum scaling limit for Analog agents only
  • LoLo - float: Low-low alarm level for Analog agents only
  • Lo - float: Low alarm level for Analog agents only
  • Hi - float: High alarm level for Analog agents only
  • HiHi - float: High-high alarm level for Analog agents only

Note: If you do not intend to make use of this table then you can prevent this table from being created by all of your DBLog agents, by adding the following registry value and setting it to 0: DumpAgentDetailsEnabled.

The Adr_DBLog_Housekeeping_Config table is also created, simply contains a list of all DBLog agent tables requiring housekeeping, which is required to perform this housekeeping without affecting the logging operations of the DBLog agents.

Adding an OleDB datasource

Create an OleDB datasource and name it LoggingDB and link it to the required database, which in this case is where the DBLog agent the tags to. For details, see Adding OLE DB datasources.

Create the Select Tags query

The function of this query is to return the names of all tags whose values are being logged by the DBLog agent.

  1. Add a Select Query to this LoggingDB OleDB datasource, called Tag Names, which returns a unique and sorted set of values from the Tagname field of the database table that the DBLog agent logs to. For details, see Select queries.
  2. Select the appropriate table from the database, specified by this OleDB datasource, which is typically called “Adr_DBLog”.

  3. Ensure that the resultant query adheres to the following syntax:

    SELECT DISTINCT [Adr_DBLog].Tagname FROM [Adr_DBLog] ORDER BY [Adr_DBLog].Tagname ASC

Create the Select Tag Values query

The function of this query is to return the values of a specific tag between a specific starting and ending time.

  1. Add a Select Query to this LoggingDB OleDB datasource, called Tag Values, which returns a set of values logged for a specific tag starting from a specific time and ending at a specific time.

This query therefore uses the following three parameters, whose values will eventually be specified by using suitable controls on the graphic form:

  • tagname: this parameter specifies the required name of the tag, whose values should be returned,
  • startdate: this parameter specifies the date and time at which the required values of the specified tag should be retrieved from
  • enddate: this parameter specifies the date and time at which the required values of the specified tag should be retrieved to
  1. Ensure that the resultant query adheres to the following syntax:

SELECT [Adr_DBLog].[dt], [Adr_DBLog].[Value] FROM [Adr_DBLog] WHERE  [Adr_DBLog].[Tagname] = '<!!tagname!!>' AND ([Adr_DBLog].[dt] between '<!!startdate!!>' and '<!!enddate!!>')

Note: You can simply copy and paste this query as-is into the Custom Query dialog, you do not need to specifically add parameters and/or constraints by using the Select Query Builder dialogs. The required parameter data type is specified by its specific formatting in the query string, whether this is typed in manually or selected from the right click menu.

Add and configure a LineChart control to chart the tag data

By default the LineChart is configured to chart real-time values, so you need to change its properties as you are charting historical (logged) data from a database.

  1. If necessary, add the required project and/or graphic form to this project.
  2. Add a LineChart control to this graphic form, from the Data category of the Toolbox window.
  3. Click Cancel to close the chart configuration dialog that is automatically displayed.
  4. In the Properties window, ensure the (Trendline) UseTrendLines Boolean property of this LineChart control is set to False, from the default value of True, so that this linechart control will only use Line and not Trendline series to chart the logged values.
  5. Click the glypha glyph is a specific graphic symbol, for instance employed by form components, which when clicked launch alternate configuration dialogs., in the top left corner of the LineChart control, which lists its commonly-used properties and configuration tasks.

In the Data Settings section of this task list:

  • Uncheck the Realtime checkbox, which is checked by default and not required since this chart is trending data from a database and not real-time data
  • Uncheck the Extrapolate Data checkbox, to ensure that only the logged values are charted and no interpolation will occur between successively logged values - this is the most accurate method of trending data, although it may be not as visually appealing as extrapolated data.

In the Configuration Dialogs section of this task list:

  • Click the Edit Time Details... link to display the Time Detail Settings dialog:

Change the Period Type to Start DateTime to End DateTime from the default of End Datetime - Timespan, since in this example the start and end date times define the charting value range.

  • Click the Edit Chart... link to display the LineChart configuration dialog.

In the Series Setup page, change the Datasource column of the initial series from Values to DataSet.

This displays the DataSet tab beneath the series table, which you need to configure as follows:

  • In the Data Element field, browse in the required table of the configured OleDB datasource, in this case: the Adr_DBLog table of the LoggingDB datasource, so theshould be: LoggingDB.Tables.Adr_DBLog.
  • In the YValue Member field, specify the value field (row) of this table, in this case this is the Value field.
  • In the XValue Member field, specify the datetime field (row) of this table, in this case this is the dt field.

Note: In this case only a single value is being trended at a time so only one series is required.

Add the other controls required by this graphic form

Add the following controls to this graphic form, from the Windows Forms category of the Toolbox window:

  5. One Button control to populate the DataGridView control with the values of the selected tag between the specified starting and ending times, so change its Text property to Fetch data and change its (Name) properties to btnFetch.

Add and configure a Query spider to run the Select Tags query

Note: Query spiders can perform queries and execute statements provided by any OLE DB datasource.

  1. Right click the spider workspace and select Create New Spider and select the Query spider from the Databasing category.
  2. Double click the spider icon to display its spider configuration dialog.
  3. Double click the default name, for instance Query1 and type in the new name: Tag Names.
  4. Configure the Inputs section of this spider to specify the Select Query created for the LoggingDB OleDB datasource, which is called Select Tags, as follows:
  5. Set the Server input to Default Server; the OLEDB Data Source input to LoggingDB; and the Query Type input to Select Queryand the Query Name input to Select Tags
  6. Configure this Query spider to perform this query when the graphic form is opened, by configuring the Event Trigger section, to select Form as the Event Object and Load as the Event Name.

Troubleshoot query and link the Return Object output to the ComboBox control

  1. Right click the Spider header (bar at the top of this Tag Names spider) and select Trigger Now! to get the initial dataset for this Query spider.

Note: Ensure that the Success output is True (i.e. the query ran successfully), if this is False then there is either a problem with the query syntax or another problem preventing this query from running.

Tip: The Rows Exist output is only True when the query returns data and is False if an empty dataset is returned.

  1. In the graphic form, click the comboBox control to display this control's properties in the Objects tree on the right of the spider workspace.
  2. In the Outputs section of the Tag Names Query spider, drag the Return Object output onto the Data property group (to expand it) and then onto the Datasource property of the comboBox control to connect them with a Silk.

Add another Query spider to run the Select Tag Values query

  1. Similarly add another Query spider called Selected Tag values and specify the Select Tag Values query of the LoggingDB OleDB datasource.

You will notice, that once this query is selected that the names of its 3 parameters, namely tagname, startdate and enddate are also added to the Inputs section.

Link the applicable control properties to supply the values of the 3 parameters of this query

Linking the Text property of the ComboBox to the tagname parameter

  1. In the graphic form click the comboBox ComboBox control to display this control's properties on the right of the spider workspace.
  2. In the Objects tree on the right of the spider workspace, expand the Appearance property group and right click the Text property and select Show property spider.
  3. Right click the Spider header (bar at the top of this comboBox.Text spider) and, if necessary, disable the default Silk triggering method (remove the tick from the Enable Silk Triggering option) and enable Event triggering instead (add a tick to the Trigger Spider From Event option).
  4. In the Event Trigger section of this comboBox.Text spider, configure this Value property of the comboBox control to update when its selected index changes, by selecting SelectedIndexChanged from the Event Name list, since the Event Object should already specify comboBox.
  5. Drag the Text output (in the Outputs section of this comboBox.Text spider) onto the tagname input of the Selected Tag values Query spider to connect these spiders by a Silk.

Linking the Value properties of the DateTimePickers to the startdate and enddate parameters

  1. In the graphic form click the dtStart DateTimePicker control to display this control's properties on the right of the spider workspace.
  2. In the Objects tree on the right of the spider workspace, expand the Behaviour property group and right click the Value property and select Show property spider.
  3. Right click the Spider header (bar at the top of this dtStart.Value spider) and, if necessary, disable the default Silk triggering method (remove the tick from the Enable Silk Triggering option) and enable Event triggering instead (add a tick to the Trigger Spider From Event option).
  4. In the Event Trigger section of this dtStart.Value spider, configure this Value property of the dtStart control to update when its value changes, by selecting ValueChanged from the Event Name list, since the Event Object should already specify dtStart.
  5. Drag the Value output (in the Outputs section of this dtStart.Value spider) onto the startdate input of the Selected Tag values Query spider to connect these spiders by a Silk.
  6. Similarly configure and connect the Value property of the dtEnd DateTimePicker control to the enddate input of the Selected Tag values Query spider.

How to write and or read database data from a control

This document briefly explains how to use the Data Binding functionality to write and read data to and from a DataGrid or edit control to a SQL Server database table.

Data binding facilitates the selecting, adding, updating, deleting and inserting of rows to and from a SQL Server database table from any control that supports data binding.

The requires the following main steps:

  1. Adding an OLEDB datasource
  2. Creating a DataBinder for this OLEDB datasource
  3. Adding and Configuring a VIZNETDataBinder Component on the relevant Graphic Form
  4. Using the added VIZNETBindingNavigator control to interface to the specified table/s
  5. Important post configuration Tasks provided by the VIZNETDataBinder component

Adding an OLEDB datasource

To configure data binding, we first need to create an OLEDB datasource which will connect to our SQL Server database:

For this example we will add an OLEDB datasoure that will connect to our Northwind database on our SQL Server.

  1. Launch and login to the Designer and then right-click on the Datasources node of the Enterprise Manager tree and select Add Datasources, then select OLE DB and click Finish.

Example:

  1. In the Add A New OLEDB Datasource dialog, specify a name for your OLEDB datasource, in this case Northwind and click the browse (...) button to the right of the Connection String edit field to display the Connection Properties dialog.

  2. In the Connection Properties dialog select Microsoft OLE DB Provider for SQL Server from the OLE DB Provider list and click the Data Links… button.

    Typically do NOT change the Data source from the default of .NET Framework Data Provider for OLE DB, unless you are connecting to a SQL Compact database. More details: in which case, click the Change... button and choose the datasource that corresponds to the correct version of SQL Compact and then the dialog will change so that you only need to browse in the required database file and specify the required password, if any.

Example:

  1. In the Data Link Properties dialog enter the required details to connect to your SQL Server database and then click Finish.

Example:

  1. In the Connection Properties dialog click Test Connection to verify that the connection details are correct and that we can connect to the SQL Server database and then click OK.

Example:

  1. Click Finish in the Add A New OLEDB Datasource dialog to add this new OLEDB datasource to the Server.

Our newly added OLEDB datasource, in this case Northwind, should be listed under the Datasources node in the Enterprise Manager tree listing all the tables, views and stored procedures for this SQL Server database that you are connected too.

Creating a DataBinder for this OLEDB datasource

In order to bind controls to data in a specific table in our database we first need to create a server-side DataBinder in the OLEDB datasource, as follows:

  1. Right-click on the DataBinders node of this OLEDB datasource in the the Enterprise Manager tree and click Add DataBinder.

Example:

  1. In the Add DataBinder dialog provide a descriptive name for your DataBinder as below, in this case CustomersDB, and click Next.
  2. Select the tables and fields you wish to write and/or read data to and from.

IMPORTANT: If you are writing data back to the database you need to make sure the primary key field of the selected table is also selected. This is mandatory as data binding requires a primary key field so that it is able to distinguish which rows in your table need to be updated or deleted.

Example:

  1. Click Next and then click Finish as for this example we are not going to do any further configuration.

Tip: The Add DataBinder dialog allows you to configure multiple table relationships, constraints on rows and ordering of certain fields and adding custom views. For more information, see Adding DataBinders.

Your newly added DataBinder, in this case CustomersDB, should now be listed under the DataBinders node of your OLEDB datasource tree.

Adding and Configuring a VIZNETDataBinder Component on the relevant Graphic Form

In order to data bind to controls on your graphic form, you need to add a VIZNETDataBinder component to the relevant graphic form:

  1. Drag this component from the Data category of your Toolbox window onto your graphic form.

Example:

This displays the VIZNET Data Binder Configuration dialog, in which you need to select the OLEDB datasource you are using as well as the you just configured and you need to select (check) the table you wish to write and/or read data to and from.

For this example we are connecting to our OLEDB datasource called Northwind and using our DataBinder called CustomersDB and binding to the Customers table in the Northwind database.

Example:

This VIZNETDataBinder component can create and bind controls for you to your tables and their fields on your graphic form which will allow your users to read and edit the data from your tables.

We will now configure the VIZNETDataBinder component to create edit controls and a DataGrid on to your graphic form which will be bounded (linked) to the selected table and fields.

  1. On the right-side tab control, in the Required Field Controls tab, check Select All Field Controls, which in this case, ensures that you will create and bind (link) edit controls on your graphic form to each selected field, although you can also manually select which fields you want.
    You can also specify the order of the fields by moving the fields up and down in the specific order you want with the up/down arrow buttons on the right hand side.

Example:

  1. In the Required DataGrid Columns tab, check the Select All DataGrid Columns, which in this case, ensures that you will display all the fields as columns on the DataGrid control that will be created on your graphic form and bounded (linked) to the selected table and fields, although you can also manually select which DataGrid columns you want.
    Again you can also specify the order of the columns by moving the columns up and down in the specific order you want with the up/down arrow buttons on the right hand side.

Example:

  1. Click Finish and the VIZNET DataBinder component will create all the necessary edit controls and DataGrids to your graphic form and bind them to the selected table and fields of your DataBinder.

Using the added VIZNETBindingNavigator control to interface to the specified table/s

This will also create a VIZNETBindingNavigator control on your graphic which allows you and your end-users to navigate through rows, add new rows, delete or update existing rows in the table/s you specified when creating this DataBinder and commit or load any changes to and from the selected database table/s.

Example:

  1. Click the Run button of your graphic form to enter Run Mode in the Designer
  2. Click the Load button in your VIZNETBindingNavigator to load the data into the edit controls and DataGrid.
  3. Click the Save button to commit any changes made in the edit controls or DataGrid back to the database table.

Important post configuration Tasks provided by the VIZNETDataBinder component

The VIZNETDataBinder component does provide some additional post configuration options, accessed by clicking the glyph of this component (at the bottom of the graphic form) to display its VIZNETDataBinder Tasks menu.

Example:

The following Tasks menu options are important:

  • Auto Load – to automatically load data from the selected tables into their bounded controls when the graphic form runs. This Auto Load functionality can also be accomplished by using the DataBinder Trigger spider. For more details, see Updating changes made to a DataBinder table or Fetching data from a DataBinder table.
  • Max Records – this specifies how many records to fetch at a time per page.
  • Refresh Data – this specifies how to handle refreshing of the data on the edit controls and DataGrid when data is changed in the selected table in the SQL Server database. You can select one of the following three settings:
  • Selecting the Manual setting will prompt the user if he wishes to refresh all edit controls and DataGrids with the new data.
  • Selecting the Auto setting will automatically refresh all edit controls and DataGrids with the new data without prompting the user (you will lose any changes that have not been committed).
  • Selecting the Ignore setting will not refresh all the edit controls and DataGrids with the new data (this has the potential of overriding any new data in the database table if someone has made a change to data in the table before you have committed your changes.)

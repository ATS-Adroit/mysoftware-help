How to optimise performance for remote clients over slow networks

Introduction

This document aims to describe how SmartUI users can configure each SmartUI Server and Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. to ensure the best user experience.

This document aims to describe the three COMMUNICATION mechanisms and two CONNECTION mechanisms that SmartUI provides, each intended to optimise the use of a specific network infrastructure:

Minimum requirements

  • Graphic form size: 50-100 kb.
  • Computer: Pentium IV with 512MB RAM.
  • Bandwidth: 512KB/sec [slower GPRS/3G links may still provide acceptable response times]
  • Install the latest available version of SmartUI
  • Start your SmartUI Server and SmartUI Designer and log in to the SmartUI Server.

Communication mechanisms

Subscribe

  1. A LAN based communication mechanism where the SERVER will PUSH data to the CLIENT.
  2. This mechanism is the fastest and the CLIENT will receive changes as they happen on the SERVER.
  3. This mechanism does not optimise bandwidth usage, but is the fastest.

Subscribe-Poll

  1. A communications mechanism that can be used on a LAN/WAN or the Internet.
  2. This mechanism does NOT PUSH any data to the CLIENT, but relies on the CLIENT to POLL for the data.
  3. ALL the changes since the last POLL cycle will be retrieved from the SERVER.
  4. This mechanism attempts to reduce latency by minimising round-trips to the SERVER.

Poll

  1. A communications mechanism that can be used on a LAN/WAN or the Internet.
  2. This mechanism does NOT PUSH any data to the CLIENT, but relies on the CLIENT to POLL for the data.
  3. Only the LAST change will be retrieved from the SERVER for each interested data point e.g. if there has been 5 changes to a set point, only the last change will be fetched (the most recent change).
  4. This mechanism attempts to reduce latency by minimising round-trips to the SERVER. It will also try to optimise bandwidth usage by retrieving as little data as possible.

TIP: On slower networks, opt to use the SUBSCRIBE-POLL mechanism first and then the POLL mechanism.

Configurable settings:

The following settings can be applied to the communication mechanisms on the SmartUI Client applications (Designer and/or Operator):

  1. ClientPollTime: The time (in seconds) which will be used to POLL the SERVER for any changes.
  2. ClientPingInterval: An “IsAlive” period in which the CLIENT will determine whether the SERVER is still available.

Connection mechanisms:

SmartUI offers the following TWO connection mechanisms that can be used with some or all of the communication mechanisms, as follows:

MAINDATAPROVIDER

  1. A direct, binary connection to the SERVER using a proprietary protocol.
  2. The channel can be encrypted using some of the configuration options discussed below.
  3. The communication to the SERVER is normally on port 9000.
  4. All three communication mechanisms may be used.

WEBSERVICEDATAPROVIDER

  1. An indirect, Web Service (XML) connection to the SERVER via IIS.
  2. Packets are compressed before they are made available to the CLIENT.
  3. The communication to the SERVER is normally via IIS on port 80 and then from IIS to the SERVER on port 9000.
  4. Only the SUBSCRIBE-POLL and POLL mechanisms may be used.

Configurable settings:

The following settings can be applied to the connection mechanisms on BOTH the SmartUI Server and Client applications (Designer and/or Operator):

  1. NetworkBindAddress: This setting determines which subnet the SERVER and CLIENTS communicate on and is required for computers with multiple network cards or IP ranges .

Note: ALL CLIENTS and SERVERS that need to communicate must have this setting specified in order to communicate with each other.

Example: SERVER has TWO IP’s: 10.10.10.9 and 196.248.23.1; Client has TWO IP’s: 10.10.10.101 and 192.168.1.2; If both need to communicate set the SERVER NetworkBindAddress to: 10.10.10.9 and the CLIENT’s NetworkBindAddress to: 10.10.10.101;

The following settings can ONLY be applied to the connection mechanisms on the SmartUI Server:

  1. BroadcastEnabled: This setting causes the SERVER application to broadcast it’s availability to the subnet and is ONLY required for clustered systems, so DISABLE this setting if not in a clustered SmartUI environment..

This setting only applies to the local subnet and does NOT apply to Internet/WAN connected CLIENTS.

Note: This setting INCREASES general network traffic.

  1. ServerPort: This setting specifies the port that the SERVER listens for incoming connections.

Note: If this port is changed, make sure it is changed on the CLIENT as well.

Caching:

Caching can optimise the transfer of data between the CLIENT and the SERVER. For instance, if a graphic form that has been cached is opened by the Client, this graphic form is loaded from the local cache instead of retrieving it from the Server via the Internet/LAN so it opens quickly.

There are TWO main caching techniques, both of which are configured on the CLIENT:

  1. Using the DataElementCachingEnabled setting: This method determines whether the SERVER contains a more recent version of an object than the CLIENT:
  2. If it does, the CLIENT cache will be updated.
  3. If it does not, the CLIENT will simply use the object from it’s local cache.

In other words, a cached graphic form will ONLY be loaded by the Client if it remains unchanged when it is opened again. In other words, no further design changes have been made to this graphic form that is stored on the Server.

Note: This method requires a roundtrip to the SERVER.

  1. Using the DataElementCachingRetrieveRegardless setting: This method retrieves the cached object (if it exists) regardless of whether a more recent version exists on the SERVER.

Note: This method is faster as it does NOT require a roundtrip to the SERVER.

This greatly improves the user experience but requires the additional administrative overhead of ensuring that the local cache is updated to include any changes made to the graphic forms of the project/s that it displays AND then copy this updated local cache to all the Operators that use this project/s.

Steps to optimise bandwidth:

STEP 1: Update the local cache of all your projects

  1. Open the SmartUI Designer;
  2. Right click on the project that should be cached and select “Update Local Cache”;

Note: This may take a while but wait for the message box to appear once the operation is complete.

This updates the CACHE files in the Caching sub-folder of the SmartUI ProgramData folder (typically C:\ProgramData\Adroit Technologies\Adroit\SmartUI\Caching) with the latest versions of all the forms of the selected projects.

This Caching subfolder can now be transferred to all your SmartUI Operators.

STEP 2: Copy the updated local cache to all your SmartUI Operators

  1. Copy the Caching subfolder from the SmartUI ProgramData folder (typically C:\ProgramData\Adroit Technologies\Adroit\SmartUI), that was updated in STEP 1.
  2. Paste this subfolder into your SmartUI ProgramData folder (typically C:\ProgramData\Adroit Technologies\Adroit\SmartUI) of each SmartUI Operator, so that it overwrites its previous files.
  3. Run “VIP Config.exe”
  4. Open the Advanced, SmartUI Operator page of settings.
  5. In the “Caching” section enable (set to “true”) the following properties
  6. CachingSecurity
  7. DataElementCachingEnabled
  8. DataElementCachingRetrieveRegardless

Note: Setting DataElementCachingRetrieveRegardless to true will FORCE the Client to fetch the graphic form from the local cache instead of from the Server REGARDLESS of whether this form has changed on the Server.

In other words, although this setting requires the least amount of network bandwidth, care needs to be taken when enabling this property. Since it requires the additional administrative overhead of ensuring that the local cache of each Client is up to date.

Enabling only the CachingSecurity and DataElementCachingEnabled properties may suffice on their own.

  1. If necessary, change the ClientPollTime to 2 seconds, this is the default setting.
  2. Connect to the SERVER using the POLL mechanism (STEP 3 explains how to install the Web Service)

STEP 3: Setting up the SmartUI WebService

Note: This step is optional but recommended if communication is still too slow; since the SmartUI WebService allows your CLIENTS to make use of compressed XML packets from the SERVER.

  1. On the SERVER computer, run the SmartUI installation and install the SmartUI Web Service.
  2. Typically this installs the SmartUI Web Service into the /VIP virtual directory.
  3. The CLIENT can then access this WebService in the connection dialog using the http://serverip/VIP URL.
  4. To test whether the Web Service installation works, try it from a local operator first using the http://localhost/VIP URL.

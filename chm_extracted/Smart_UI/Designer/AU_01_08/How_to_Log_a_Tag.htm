How to Log a Tag

Adroit allows the value of a tagA fully qualified named value in Adroit (agentName.slotName). (agent.slot) to be recorded or logged to either proprietary log files or an OLE DB-compliant database.

The logging to ADO (SQL) databases by the Datalog agent is disabled by default (the SQL... button of the Datasource field is hidden in the Edit Datalog agent dialog). This is to force users to use the DBLog agent instead, which logs data to SQL more efficiently.

Although if the Agent Server loads a legacy WGP file that ALREADY contains an ADO datalogging configuration, then the SQL... button of the Datasource field will be visible in the Edit Datalog agent dialog.

Hence the Datalog agent should only be used for proprietary logging and the datalog period (Length...) should not exceed what is required for operational trending purposes. In other words, should an operator only need to see 24 hours of trend data to properly monitor and control his plant then the datalog period should only be set for 1 day. Historical data (i.e. data outside of the datalog period), if requested, will be retrieved from the backup files, if required.

Note1:Disable logging on standby is now configured PER datalog SET. So you can disable an OLE DB logging set WITHOUT disabling any proprietary logging sets, which typically do not require this setting as each Agent Server logs to their own datalog files.

Note2: The Flush lazily setting has moved from the main Edit Datalog Agent dialog to the Advanced Datalog Configuration (global settings) dialog, by pressing the Advanced… button.

To Log a process value:

 

Open the Agent Configuration dialog, as follows:

Tip: This also opens the Adroit Classic UI in the SmartUI Designer, which provides agent-specific menu functions, such as importing and exporting agents.

In the SmartUI Designer:

Click the Open Configurator tool in the Agent Server group of the Home tab of the SmartUI Designer ribbon.

Note: When there is more than one Adroit datasource available, a list is provided to select which Agent Server to configure.

The Agent Configuration dialog is displayed within the Classic UI.

Select the required agent in the Agent Configurator, as follows:

  1. Ensure that the Basic, Advanced and/or System checkbox is checked to display the required agent type in this list. These checkboxes use these default agent groups to help you select the required agent quickly.

Tip: If no checkboxes are selected, then all the available agent types will be displayed in the Type list box. This is useful if the required agent type has not been categorised.

  1. Click the down arrow in the Type drop down list
  2. Locate the required agent type, using the scroll bar and click on it.
  1. In the Agents list, click on the name of the required agent (if necessary scroll down to locate this).

Tip: Right-click to display a menu of commands to perform upon the selected agent(s).

  1. Click the Log... button to display the Edit DataLog Agent for dialog.

Tip: You can also right-click the agent and select the Log… menu item.

  1. Select the value of this agent that you want to log from the Slot list box. Click for more details:This must be a REAL, INTEGER, BOOLEAN or a 7 character STRING (the 8th character will be forced to 0). For example, the value slot of an Analog agent.
  2. Select the required data-logging Mode, as follows:
    • Continuous:Adroit logs data values when the value changes, provided the value does not change more frequently than the configured Time deadband ( see below).
    • Demand:Adroit only logs a data value when the LogNow or Trigger slots of this Datalog agent are activated.

    This can be used if you want to avoid logging every change during a batch process, and only want to log the values at the end of the batch.

    The Trigger tag may be browsed in here and a Log Now button is provided for manually triggering the logging.

    If necessary, use the Datalog compression algorithm when using Demand logging, by adding the SupportCompressionOnDemand registry value.

    • Both: This uses both the Continuous and Demand data logging modes.
  1. The DataLog agent can accommodate multiple log sets for a given agent and slot, which allow you to log a given tag (agent.slot) using different sample and/or logging destination settings etc.

Note: Multiple log sets are no longer required as Adroit provides the DBLog agent that should make SQL logging via the Datalog agent redundant. Also you no longer need multiple proprietary sets with increasing periods and larger time deadbands, since Adroit provides a new datalog backup feature with full trend-retrieval support.

Add a Set number if more than one log set is required, and configure the following per set:

  • The Datasource field, allows you to select a proprietary data file - enter or browse in the name of the file you wish to log to, using the … browse button.

    This defaults to the same name as the current agent file loaded, and has a .LGD extension. If a new filename is specified, it will only be created when the DataLog agent has its Start radio button activated.

    Note: If the specified file path does NOT exist, Adroit will attempt to create it - if this path cannot be created (because the drive does not exist or file security disallows this etc) then this value will NOT be logged.

    Typically the legacy SQL… button ONLY appears when the Agent Server loads a legacy WGP file that ALREADY contains an ADO datalogging configuration to allow it to be configured. But even in this case you are encouraged to use the DBLog agent instead, which logs data to SQL more efficiently.

  • Select Disable logging on standby, when a clustered Agent Servers log to the same OLE DB compatible database to prevent the duplication of database entries by only logging entries from the master server. The default state is unchecked.

Note: This setting is now configured PER datalog SET. So you can disable an OLE DB logging set WITHOUT disabling any proprietary logging sets, which do not require this setting as each Agent Server logs to their own datalog files.

  • Click the Length button and enter the Log Length in the time units of your choice for this set. The default setting is 10 days BUT this should not exceed what is required for operational trending purposes. Click for more details:

    In other words, should an operator only need to see 24 hours of trend data to properly monitor and control his plant then the datalog period should only be set for 1 day. Historical data (i.e. data outside of the datalog period), if requested, will be retrieved from the backup files, if required.

    Note1: A rule of thumb is that the Log Length should not exceed 500000 x Shortest Logging Interval (this factor is true only when using the same time units).

    Note2: If Adroit proprietary logging is selected and the logging period is increased ensure that the WGP file is saved and the Agent Server is restarted, at least once to allow the necessary LGD file compressions to occur. For details, see Increasing Logging Periods.

  • Specify the required logging Deadbands (methods to reduce the number of records logged for this value) as follows:
    • Time deadband: click the Time... button and specify the Shortest Logging Interval (how often this value must be logged). The default setting is 10 seconds. This setting can reduce the amount of logging required for this value, as follows:if this value changes more than once during this period then the specified Compression Method is used to determine what value is actually recorded.  
    • Value deadband: specify the MINIMUM Value which the value being logged must EXCEED for it to be logged. This reduces the amount of logging for this value, as follows:if the change in value is LESS than this value then the value will NOT be logged.

    Note: When logging DIGITAL values, ensure that this Value deadband is 0, otherwise NO values will be logged.

Tip: The Time deadband setting actually specifies the required logging rate of this value.

The Datalog agent allows for a maximum of 53000000 records. This means that the specified datalog Length... (or period) and Time... deadband combination may not exceed 53000000 records. This corresponds to a maximum of 1010.9 MB of data at 20 bytes per record, which means 613 days at 1 second or 30 days at 50 ms.

Note1: The minimum Time... deadband allowed is 10 ms which only provides a maximum Length... (or period) of 6.13 days of logged data.

Note2: When retrieving data from classic (legacy) trends the maximum number of datapoints that can be trended is 99999 therefore, for example, only 27.77 hours of data can be retrieved at 1 second on a classic (legacy) trend.

  1. If necessary, configure the Out of limit logging to immediately log out of limit values (values that are not within their specified operating range). For details, see Out of limit data logging.
  • Choose the required Compression Method for the value to be logged. For details, see Available Logging Compression Methods.

Tip: To facilitate data compression it is RECOMMENDED to use a non-zero Deadband Value. The units are the same as for the slot being logged.

  • If necessary, the Options section provides the following options that apply to ALL Datalog agents:
    • Select Clear at Start to clear any records from memory or disk each time logging commences.
    • Select Interpolate if you are logging continuously changing values. Leave unselected if the values are discrete and change in a stepwise fashion.
    • Select Double entries to log both the old and new value of a step change at the same time. This is necessary if you want to export the data to an Excel spreadsheet and avoid interpolation when plotting the data.
    • Use the Backup period list etc., when the Datasource is a proprietary data (.LGD) file, to configure when and how this logged data should be backed up using .LGB files, when the LGD file wraps. This backed up historical data can then be retrieved by the datalogging system when needed. For details, see Datalog backup and retrieval.

IMPORTANT: .LGB files are used when backing up datalogs as these can have their stored historical data seamlessly retrieved for trending and reporting. For details, see Datalog backup and retrieval.

Note: To disable datalog backups for a particular Datalog, set the backupPeriod slot of this Datalog agent to 0.

  1. If necessary, click the Advanced button to configure the Flush lazily setting and other GLOBAL DATA LOGGING SETTINGS. For more details on when and how to configure each of these settings, see Advanced Datalog Configuration (global settings).

Note: The logged values are immediately queued to a global buffer, and then a separate, asynchronous thread reads the data and sends it to the correct datalog file. It is possible to change the size of the queue by clicking the Advanced button.

  1. Click the Start radio button to begin logging.

Note: It is also possible to log multiple tags simultaneously i.e. to log multiple agents of the same type, using the most recently specified logging configuration. For details, see Bulk Logging Tags Using the Same Configuration.

Advanced Datalog Configuration (global settings)

This dialog provides global settings that affect the operation of the data logging sub system.

To display this dialog:

  1. If necessary, launch the Classic User Interface, as follows:click the Start menu, Programs, Adroit 10 and select the Classic User Interface item).
  2. Click on the Configurator  toolbar button to display the Agent Configuration dialog box.

Ensure that the System checkbox is checked to display the Datalog agent type in this list.

  1. Click the down arrow in the Type drop down list
  2. Click the Datalog agent type.
  3. Click any of the agents in the Agents list.
  4. Click the Edit button.
  5. Click the Advanced… button in the Edit Datalog Agent dialog.

Note: This dialog can only be displayed, once you have logged an agent and have thereby created a Datalog agent.

 

These settings are divided into the following three main sections:

Note: The settings in the General and SQL logging sections require the Agent Server to be RESTARTED before applying the configured setting/s.

Tip: Click the section headings to show or hide their settings.

General:

Datalog system buffer size (Kb)

This setting specifies the size of the global "datalog change queue", which is 500 Kb, by default. Click for more details:

All changes arriving at the data logging subsystem are added to a "datalog change queue". This ensures that these historical updates do not affect the throughput of any real-time updates. These changes are stored in this queue until Adroit reads them off.

Therefore, the size of the queue must be able to handle the maximum spike of changed values that a plant can expect. This maximum number of changes is generally proportional to the number of tags logged.

The default size of 500Kb, allows for approximately a spike of 11000 changes.

It is possible that the sustained (not the instantaneous) rate of plant changes will exceed the rate at which the data logging subsystem is able to operate. In this case, the Agent Server is simply not capable of handling the data logging requirement and the computer will require upgrading or the data logging task musts be split over separate Agent Servers OR less tags need to be logged.

For this reason we recommend that you use the PerfMon agent to monitor "SubManQueueLen" performance counter of the Agent Server to ensure that it always tends towards 100%, as this counter indicates the free datalog buffer queue. If this value is steadily decreasing, then the rate of datalogging is exceeding the rate at which the values can be committed to disk and the Flush lazily global logging setting should be turned ON.

Note: The default value is big enough to handle short term spikes in putslot rates and should not need to be changed.

Tip: When specifying the required buffer queue size, use the provided buttons to increase/decrease this value in 64 KB increments/decrements.

 

Disable legacy file compression of 5:1 (LogCompressionFactor =1)

This setting removes the legacy default 20% datalog compression setting when using the proprietary logging of Adroit and is ON (checked) by default for new installations. This setting is removed as it unnecessarily misleads users when configuring logging periods and has been outmoded by the newer hardware. Click for more details.

 

Flush lazily (LazyFlushing = 1)

This setting determines how Adroit writes logged values to disk, which is ON (checked) by default, so that Adroit logs its values to the file cache of the Windows operating system. If you uncheck this option (turn it OFF) then logged data is immediately written to disk. Click for more details:

  • If checked (the default option), this results in a DELAY before this cache saves the data, due to the amount of file I/O activity on the computer. Therefore, if the computer is not on a UPS and there is a power failure, ALL datalog values that have not been committed to disk by Windows will be LOST.
  • If unchecked, all logged values are IMMEDIATELY written to disk but this increases the CPU load and slows the Agent Server down. 

Therefore we recommend that you use the PerfMon agent to monitor the CPU load for very high values and also monitor the "SubManQueueLen" performance counter of the Agent Server, which indicates the free datalog buffer queue and should remain around 100%.

If this value is steadily decreasing, then the rate of datalogging is exceeding the rate at which the values can be committed to disk and flush lazily should be turned ON. In this case a UPS is highly recommended to allow operators to effect a controlled shutdown of the Agent Server computer, thereby preserving all datalogged values.

 

Disable first datalog entries on startup of agent server (SuppressLogAtStartup = 1)

This setting determines whether a value is logged at startup for each value that you have logged (the Post_Startup_ValueFor every session (the period between the startup and shutdown of the Agent Server), Adroit will always denotes the first and last entries in the log as the Post_Startup_Value and Last_Known_Value. All intermediate values will be marked as normal or bad. :), which is OFF (unchecked) by default, so that this ‘Post_Startup_Value’ is logged by the Agent Server. However, if you have logged a large number of values (this amount is site-dependant) to SQL, then the logging of these Post_Startup_Values can significantly increase the time the Agent Server takes to startup.

Note: ONLY suppress the logging at startup IF there IS a real issue with startup times when logging to SQL.

In this case, you can check this setting (turn it ON), which stops the Agent Server from retrieving any logged values to reduce the time taken by the Agent Server to startup.

Note: When this setting is ON, then you are unable to determine from the logged data, where an Agent Server was restarted. 

 

Support compression algorithm on demand logging (SupportCompressionOnDemand = 1)

This setting enables the use of Datalog compression algorithms when using the Demand Mode of datalogging, by default, this setting is OFF (unchecked) so you are unable to use compression algorithms when Demand logging. Click for more details about Demand logging:

The Demand mode of data-logging, unlike the default Continuous mode, only logs a data value when the LogNow or Trigger slots of the Datalog agent are activated. This allows you to decrease the size of your log files by using a script (or some other external intelligence) to drive the logging of a datalog.

For instance, by only triggering the log when the value is between certain limits or at particular times of the batch, instead of logging every change in value. For further details, see Demand Logging.

To further reduce the size of your datalogs, you can check this setting (turn it ON), so that you can specify a Time deadband and employ one of the datalog Compression Methods. For details, see Data Logging Compression Methods.

Settings that affect the operation of the data logging system that are typically applied irrespective of the selected Datasource (the Adroit proprietary log files or SQL logging)

SQL logging:

Check for existence of database tables on startup (CreateTablesOnStartup =1)

This setting causes the Agent Server to attempt to create the necessary tables in SQL at startup, for each value that is being logged to a SQL database, which is ON (checked) by default. This can increase the time the Agent Server takes to startup, especially if you have a large number of values that are being logged to SQL.

If this option is UNCHECKED (turned OFF):

  • Adroit creates the necessary tables when creating NEW datalogs (from the Configurator).
  • Adroit does NOT check for the existence of these tables when the Agent Server starts up. This means that datalogs will NOT write if their tables do not exist.

Therefore, if you have a large number of values that are being logged to SQL and you have ensured that the datalogs for these EXISTING values have their necessary tables, then UNCHECK this option (turn it OFF) to reduce the time taken by the Agent Server to startup. 

 

Disable database table name prefixes (DisableADOTableNamePrefix = 1)

This setting causes the Agent Server to create tables for each value that is being logged to a SQL database, by using the following table name format AdroitRawLog_[tablename], which is OFF (unchecked) by default.

If you prefer Adroit to ONLY specify the table name and hence create shorter table names, then check this setting (turn it ON). This removes this "AdroitRawLog_" table name prefix, so that Adroit only uses the specified table name.

 

Add normal timestamp fields to database tables (LogADODataTimes = 1)

This setting causes the Agent Server NOT to log readable timestamps for values that are logged to SQL databases, which is OFF (unchecked) by default. So that ONLY the Adroit timestamp of the change in value is provided, this is not ‘readable’ in SQL as this does not conform to the DateTime value type.

If you want Adroit to provide an additional column containing readable timestamps to the database table, then you can check this setting (turn it ON). However, then you must DELETE all your existing database tables and allow Adroit to re-create them with an added timestamp column.

Tip: We recommend that you check this setting (turn it ON) before logging values to the SQL database.

 

Use only proprietary logged data for trends (ProprietarySetPreference =1)

This setting prevents Adroit from using data from SQL for trending, regardless of the circumstances, this is OFF (unchecked) by default.

Typically you would turn this setting ON if you use at least 2 log sets to log ALL your values, one that logs to Adroit’s proprietary log files and another that logs to SQL. In this case, by enabling this setting Adroit will ONLY trend data from the log set that logs values to Adroit’s proprietary log files and NEVER trend data from a log set that logs values to SQL. This ensures that your trends quickly retrieve and display their historical data.

Settings that ONLY apply when using OLEDB Data Logging or the SQL Datasource.

IMPORTANT: Although reference is only made to SQL in these settings, they apply to any OLEDB compatible database.

UI settings (no restart required):

Create datalog agents automatically (AutoCreate = 1)

This setting causes the Agent Server to immediately create a Datalog agent when you log an agent from the Configurator, which is ON (checked) by default.

Since each agent has a default logging slot that is automatically selected, you can uncheck this option (turn it OFF) if you usually need to log another slot. In this case, a confirmation dialog is launched, asking the user whether a new Datalog agent should be created, before a slot of an agent can be logged.

Settings that ONLY apply to the Configurator dialog within the Classic User Interface.

Datalog backup and retrieval

Previously, when logging to the Adroit proprietary datalog (.LGD) files, the Adroit datalogging system only provided the historical logged data existing in the .LGD file and was unable to provide historical data from the SystemDatalog-created .CSV datalog backup files.

Now each Datalog agent can create their own backup (.LGB) files, when their associated .LGD files wrap, as follows:

  1. these .LGB backup files are created in a “backups” sub-folder that is automatically added to the folder containing the .LGD file;
  2. these .LGB backup files are created on a per tag basis, so if you log 10 tags to the same .LGD file, then 10 backup files are created and maintained;
  3. each .LGB backup file contains a month of data, so the current .LGB file is updated with new data (each time the .LGD file wraps) and a new .LGB file is only added once a month has passed and
  4. each .LGB backup file adheres to the following naming convention: log$agent$slot M-yyyy-mm, where yyyy is the year and mm is the month of the year.

In Adroit 10, the naming convention of these backup files have improved compared to Adroit 8.4 to significantly reduce the number of files that are created. More details:

When creating monthly datalog backup files in Adroit 8.4, a separate file was created for each day of the month that had data logged, since the file name also included the day that the data was logged.

For instance:

1. A data value with a timestamp of 2017-11-21 10:00:00 would go to a backup file called 2017-11-21-m-11

2. A data value with a timestamp of 2017-11-22 10:00:00 would go to a backup file called 2017-11-22-m-11

In Adroit 10, the name of the backup file only specifies the year and month so that now only one file is created for the month.

For instance:

1. A data value with a timestamp of 2017-11-21 10:00:00 would go to a backup file called 2017-11

2. A data value with a timestamp of 2017-11-22 10:00:00 would also go to a backup file called 2017-11

This feature can also extend the potential amount of logged data without creating larger log files, since larger log files have the side effect of causing the Agent Server to take longer to start up. In this case, while the active log (LGD) file can remain small, the log backup (.LDB) files can store historical data for much longer time periods.

Note: By using this backup feature, you no longer need multiple proprietary sets with increasing periods and larger time deadbands.

Once created, the datalogging subsystem automatically retrieves the data from these .LGB files, if required by trends (charts) or other requests for historical data. This .LGB file-data retrieval process may slightly increase the time required to obtain and view this historical data. More details:

In addition to creating .LGB files for Adroit to retrieve historical data, you can also create the associated .CSV files to enable third party applications to trend or report this data too.

IMPORTANT: If .CSV files are being created, Adroit ONLY only looks for and uses the data in the .LGB files. Therefore if you have deleted a .LGB file but still has the .CSV file for the same period, Adroit is unable to retrieve the historical data for this time period.

Since multiple backup files are created, a housekeeping feature ensures that the files older than a specified number of days (default 90 days) are deleted from this backup folder.

Note: If you want to keep data older than the specified housekeeping period, for future retrieval, then ensure that you have a MANUAL backup procedure in place that moves the old .LGB files are the required folder.

This new datalog feature makes the existing backup capability of the Systemdatalog agent redundant, which is configured in the Options section, when logging a tag, by checking the Enable (system datalog) backups checkbox. We recommend that this legacy method of backing up datalogs is no longer used as it may be deprecated in a future version of Adroit.

Note: To disable this new backup feature, select Disabled from the Backup period list, which is also configured in the Options section at the bottom, of the Edit Datalog agent dialog.

Configure the backup portion of the Options section, at the bottom, of the Edit Datalog agent dialog, as follows:

  1. The Backup period is by default set to Monthly.

So the naming convention of these .LGB (and .CSV) files will be: log$agent$slot M-yyyy-mm, where yyyy is the year and mm is the month of the year

Note: The associated .CSV files, if created for third party use, adhere to this same naming convention but have a .CSV extension instead of .LGB.

  1. Since multiple backup files are created, use the Delete backup files older than (days)housekeeping feature to ensures that the .LGB (and .CSV) files older than a specified number of days (default 90 days) are deleted from the backup folder.

Note: If you want to keep data older than this specified housekeeping number of days, then ensure that you have a MANUAL backup procedure in place to ensure that you move these old .LGB files to the required folder.

  1. If necessary, check the Enable CSV backups checkbox to also create associated .CSV files. This will allow third party applications to trend or report this historical data too,

IMPORTANT: If .CSV files are being created, Adroit ONLY only looks for and use the data in the .LGB files. Therefore if you have deleted a .LGB file but still has the .CSV file for the same period, Adroit is unable to retrieve the historical data for this time period.

Note: Each .CSV file stores the logged data by using the following 3 column file structure: Date (yyyy/mm/dd HH:mm:ss), Value and Quality.

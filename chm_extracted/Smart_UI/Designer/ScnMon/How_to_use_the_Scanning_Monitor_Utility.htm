How to Use the Scanning Monitor Utility

The Scanning Monitor utility is particularly useful in tuning polled driver's polling intervals. However, OPC Server devices not in "sync-poll mode", and telemetry applications will find this utility less useful. For details of the user interface of this utility, see Scanning Monitor Utility.

Tip: The Scanning Monitor utility can generate a report of your current scanning configuration of an Agent Server to indicate how well it has been configured. For details, see Creating and using the Scan Configuration Report.

After understanding the user interface of the program and selecting the required device from the Device List, one really needs to only look at 2 things, the "effective" scan rate (rate at which the driver actually returns data), and the polling rate you intended it to use, these 2 values are in column 5 and 6 of the Scan Job List.

If the effective rate is consistently greater than the intended rate, you have a scanning backlog.

Find the scan jobs with the shortest scan-times, as you select each one, check how many tags (scan points) are scanned in that task in the Tag List, which is immediately below the scan job list.

Consider the communications bandwidth cost of having a task with only one I/O point; at this point one can make the scan-interval of an expensive point longer to remedy this.

If all tasks are responding slower than their intended intervals, then a re-evaluation of all the scan-times is needed. For further details concerning the scanning optimization benefit of grouping scanned data, see Scanning Optimization Tips.

Since the right-click commands within the Scan Job List that change scan rates are not permanent (in other words saving the Adroit agent database will not save these online changes), it is necessary to perform the following procedure to make any changes permanent:

To make permanent scan rate changes:

  1. Backup your Adroit agent database file (.WGP). For details, see Backing Up Agent Database Files.
  2. Stop the required device agent, and wait a few seconds for any backlogged polling to cease.
  3. Export the Device agent type, i.e. click the No button for all the other preceding agent type message boxes.
  4. In the Choose file to contain conversion dialog, select the location to save the Device agent files, it is recommended to leave this as the default location of the Adroit system folder, typically C:\Program Files\Adroit Technologies\Adroit and save the ‘Device.CSV’ file, then save the scan files for each of the device agents, of the name format DeviceName-SCAN.CSV, where DeviceName is the name of the Device agent.
  5. When the next agent type message box is displayed, click Cancel, to stop the exporting process.
  6. In either a CSV or text editor, open the DeviceName-SCAN.CSV, where DeviceName is the name of the Device agent that the tags have been scanned to. This file will contain four columns or comma-separated values, from left to right as follows: Address, agent.slot, Scanning Interval (period), Deadband
  7. Increase the scan-times on all I/O points, particularly those that are not fast moving within your process. You will want to increase all of your tags poll rates up until the average "effscanrate" value, or increase most of them to double that value and leave just a few scanning quickly.
  8. Save and close this CSV file.
  9. In the User Interface, edit the required Device agent.
  10. Remove all the scan points from this device (unscan them).
  11. Click Import… button and browse in the edited Devicename-SCAN.CSV file, where DeviceName is the name of the selected Device agent from step 4.

Note: If messages are displayed during the importing of this scanning configuration, see Common Reasons for Scanning Import Failure for the possible reasons.

  1. Start this device agent.
  2. Verify that the communications are still fine and all I/O tags work as expected.
  3. Save your Adroit agent database file (.WGP) again and finally perform a full test by restarting the Agent Server to verify proper loading etc.

If going through all of the above does not help, you may have a stuck continuous output. For details on using the Scanning Monitor to locate this, see Troubleshooting Continuous Writing.

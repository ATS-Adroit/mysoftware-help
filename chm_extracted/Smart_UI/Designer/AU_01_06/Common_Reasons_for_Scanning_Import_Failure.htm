Common Reasons for Scanning Import Failure

When importing scanned tags (agent.slot) from the CSVComma Separated Value file containing data, which consists of a number of fields in one or more rows, in which the different fields (values) are typically separated by commas. file, the following messages may be displayed: "Invalid device address" or "slot already scanned". For details on importing scanned tags, see Bulk Scanning.

These messages appear in either of 4 known cases:

  1. The scan-tag you wanted to scan does not exist (the slot may be missing or the tag may not exist). Ensure that the tag already exists.
  2. The scan-address is not recognised/interpretable by the driver. Try a different address or read the driver documentation that was installed with the driver.
  3. The slot you tried to scan is already scanned. Edit the tag, click on header, and then click Advanced, select the desired slot from the list; to see if the "scanned" header bit is on for any specific slot.
  4. The operation timed out! The operation may still succeed however, close and re-open the Configurator to check. This occurs only after about 10 seconds of waiting with an hourglass mouse cursor. Stopping the device or reducing scan backlog helps reduce this occurrence. Also try increasing the Advanced Agent sever remote timeout value of 10 seconds to about 20 seconds.

In all the above cases, an alarm is generated on route 0 of the defaultAlarmlist, simply create a new Alarm Viewer, to see the alarm for more detail, as to determine which of the 4 cases is relevant.

Scanning Troubleshooting FAQ

This topics provides answers to commonly experienced problems/issues associated with scanning:

 

Q: When the Agent Server is started, 3 beeps are heard and the Agent Server disappears. Why does this happen?

A: The 3 beeps are produced when a driver is NOT loaded by the Agent Server, which can occur because of the following reasons:

  • the driver has not been configured and therefore cannot load properly
  • the port is already in use or does not exist
  • some other resource has run out.

Look for the devices in the Adroit Setup drivers tab, and check the amount of free disk space. Make sure you do not have a folder in your installation directory with the same name as the device.

 

Q: When writing to a register, the value does not change, why?

A: This can be due to writing to an input; a driver automatically disallows writing values to inputs, since they are most likely not supported in that protocol.

In the Modbus driver, for instance you cannot write to digital input 1XXXXX registers, nor to the analog input 3XXXX registers.

A driver in most cases does not generate an error/alarm, but simply fails the transaction. This is noticeable by the tag greying out in the mimic, and then becoming healthy on the next scan.

Note: Whenever you perform a write using any polled (not telemetry) driver, Adroit automatically queues that item/task for reading afterwards

 

Q: The driver software does not run, and I do not get any messages explaining what is wrong. Where do I look now?

A: The first place to look in event of an error is the Windows event log. Look at the last few entries in the Application and System event logs for more details on a problem. Often a problem is the result of an error reported a little further back in the log.

 

Q: An error message appears about a buffer overrun in the protocol driver monitor just before the comms dies. What does this mean?

A: Buffer overruns and underruns are caused when the buffer on the serial card overflows. This is because character reception and transmission relies on the CPU emptying the buffer as the computer receives characters in the line.

If the computer is busy with some other task (which happens all the time in windows), the buffer is not serviced often enough. The solution is to use a card with a buffered UART (FIFO buffer). This provides a 16-byte buffer as opposed to the 1-byte buffer common in older cards.

 

Q: I have a serial card with a Buffered UART of FIFO but I still get overruns, why?

A: The serial card driver for Windows may not have detected the FIFO. Use the Ports applet in Control Panel to enable the use of the FIFO.

Delete the affected ports, and re-boot. The operating system will auto-detect the FIFO on the port and add it in. If it is not added in, you may edit the port settings and go to the advanced dialog which allows changing IRQ’s etc. Check the box at the bottom of the dialog, in order to enable the FIFO.

 

Q: I get error messages such as parity error or framing error in the driver monitor window, followed by communications failure.

A: In this case, characters on the line are being corrupted or badly sent. To correct the problem, lower the baud-rate on both devices.

 

Q: The (any serial) driver is not running. When I run the Agent Server, the message "Error load completion agent [BOILER1]." appears. Although no driver or hardware configuration was changed, there is no longer any communication.

A: Make sure the mouse is plugged into the correct port. If the mouse is on the port the driver would use, the mouse will work but the Adroit driver will not. To correct this problem, either swap the mouse back and re-boot, or re-configure the driver to use the free port, and re-start Adroit.

 

Q: Why does scanning not work for certain Analog agents?

A: Please ensure that you scan the raw value slot and NOT the Engineering value as this can cause scanning to fail because the scanned value is out of range.

 

Q: When I access a device agent, all I receive are event log entries about the failed device and the need to restart the Agent Server.

A: This indicates that a device has not been attached at startup and as a result, its scanning configuration is not loaded. This occurs for intermittent Windows/PC resource/device unavailability/conflict at the time of Agent Server startup.

The Agent Server needs to be restarted to gain access to these resources or to sort out a resource conflict; for example, your RAS connection (or other software) is still active which is using the same COM port as your device configuration.

 

Q: When I install a protocol driver, it is copied without errors but does not appear in the "Available protocol drivers" list.

A: A number of our Adroit drivers rely on 3rd party components being installed, if they are not, then you get the above symptoms. This is because the driver available list in setup uses the driver, which also uses the missing 3rd party component.

Examples are: Allen Bradley RSLINX, Eagle, Lonworks, Modbus plus (+), Siemens H1, Siemens L2 and Siemens S7 Functions among others. In such cases, the required hardware and accompanying software must be installed (preferably before the driver).

Note: Many network (Ethernet, H1 and TCP/IP) drivers also require the installation of the Windows TCP/IP protocol. If in doubt, open the relevant driver documentation file found in your Adroitsystem folder for more information.

 

Q: Communication to the PLC is lost intermittently.

A: This is a possible driver device failure. Reinstall or update with a new driver.

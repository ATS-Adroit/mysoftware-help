Catch-up

When a new server is added to the cluster, it must become a mirror image of the active member of the cluster.

The new server must restore its historical data (historical catch-up) that it lost during the down time.

This historical synchronization or Datalog catch-up is facilitated by a new agent called the SystemDatalog agent.

Note: For performance reasons, the SystemDatalog agent ONLY provides the Time datalog catchup method, of catching up the data between two specified date/times.

Note: Datalog catch-up is not supported when OLE DB logging is being used as this would only further delay a task which is already time consuming and CPU intensive. As OLE DB logging is logging to a database, this database could be equipped with the querying/replication tools required to fill any holes that exist.

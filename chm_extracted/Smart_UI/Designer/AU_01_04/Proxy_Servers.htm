Proxy Servers

A proxy server is an Agent Server that creates proxy agents for agents that exist on remote Agent Servers on the same project because it itself does not contain any configured agents. Since it only contains Proxy agents, it will not support scanning, alarming or datalogging. Proxy servers generally use an empty WGP file.

IMPORTANT: If your proxy Agent Server is running as a service, then ensure that the user profile that the Agent Server service uses to log onto the computer HAS the necessary rights to browse the network and connect to the other Agent Servers. This should NOT be the default Local System account. See Configuring Agent Server Service User Profile. 

Note: A Proxy Server (an Agent Server that is licensed for ZERO scan points) can proxy an unlimited number of agents, whereas a normal Agent Server is only able to create as many proxy agents as it has scan points and therefore must be licensed for AT LEAST the same number of scan points as the remote Agent Server.

Proxy servers are used in environments where one or more clients need information from multiple Agent Servers. A client can only connect to one Agent Server so this server must have the capability to create proxies where needed. Proxy servers are also useful in environments where a user wishes to remove the burden of servicing multiple clients from an Agent Server. Those clients are connected to a proxy server and the remote server(s) then only services the proxy server leaving it more processor and network time for it's SCADA functions.

Note: If your proxy server needs to proxy information from a remote Agent Server that is on a DIFFERENT domain or on DIFFERENT sides of a router/switch, then ensure that you are using an explicit connection to connect to this remote agent server. See Agent Server Connection Methods.

All Agent Server types (Standalone, Cluster aware and cluster servers) have the capability to create proxy agents for agents that exist on remote agents servers on the same project.

Cluster and Cluster Aware servers acting as proxy servers, have the unique feature of creating proxy agents even if there are more than one agent of the same name in a network of clustered Agent Servers. Therefore cluster proxy servers must be used if there are cluster servers on the same project.

A Standalone server acting as a proxy server will not create proxies agents if two or more agents of the same name are found on a network. Therefore standalone proxy servers should only be used where there are no cluster servers on the same project.

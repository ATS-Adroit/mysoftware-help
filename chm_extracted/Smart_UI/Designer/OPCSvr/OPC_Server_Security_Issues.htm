OPC Server Security Issues

Note: If you still experience issues even after following this procedure, then consult the Configuring OPC DCOM Settings.pdf document in the Adroit Documentation folder of the Adroit DVD, which provides a clear description of the configuration of all the required DCOM settings.

OPC client applications are generally unable to connect to remote OPC servers due to DCOM and Windows security reasons. We therefore recommend that both the OPC clients and OPC server computers reside within the same domain to reduce the possible security issues. 

If this is not possible then please:

  • ensure that the required user accounts (and their passwords) are configured on all OPC client and server computers and
  • ensure that any change to these access details (a user name and/or password) are replicated to all these computers.

We also recommended that you configure the lowest or minimum level of DCOM security for both OPC client and server computers, as follows:

These settings prevent the domain configuration and the login user names and passwords of each computer from affecting the OPC client to OPC server connection.

Note1: In very rare cases, some 3rd party OPC Servers or Clients may enforce security, which overrides the following settings and not allow them to work.  This is not a problem with the Adroit OPC components.

Note2: Your network administrator may need to perform these settings.

On OPC Client computers:

  • Set the Default Authentication Level to (None), as follows:
  1. Click the Start menu and select the Run… option.
  2. Type in DCOMCNFG.EXE and press ENTER.

The Component Services dialog is displayed - locate My Computer in the left hand pane.

(Console Root > Component Services > Computers > My Computer)

Right-click this and select Properties to display the My Computer Properties dialog.

Example screenshot:

  1. Select the Default Properties tab in the displayed dialog.
  2. Ensure that the Default Authentication Level list box is set to None.

Example screenshot:

  1. Select OK and close any opened dialogs.

 

On OPC Server computers:

  • Set the Default Authentication Level to (None) ), as per the explanation above [except do NOT close the open dialogs at the end of this procedure]
  • Add the "Everyone" group to both the Default Access Permissions and Default Launch Permissions, as follows:

Select the COM Security tab of the My Computer Properties dialog.

  1. Click the Edit Default… button in the Access Permissions group
  2. Select the Everyone group in the list and click the OK.
  3. Click the Edit Default… button in the Launch and Activation Permissions group.
  4. Select the Everyone group in the list and click the OK.
  5. Select OK and close any opened dialogs.

 

If an OPC client application is unable to browse OPC servers on some remote computers

Perform the following procedure on each of these remote computers:

  1. Click the Start menu and select the Run… option.
  2. Type in DCOMCNFG.EXE and press ENTER.

The Component Services dialog is displayed - locate DCOM Config in the left hand pane. (Console Root > Component Services > Computers > My Computer >DCOM Config)

Locate OpcEnum in the right hand pane, right-click this and select Properties.

Example screenshot:

Select the Application tab, browse for OpcEnum in the list and double-click it.

  1. Select the Identity tab in the OpcEnum Properties dialog.
  2. Select This user and specify the user and password of an administrator.

Note: Specify domain user names as "domainname\username".

  1. Click the OK and close all the open dialogs.

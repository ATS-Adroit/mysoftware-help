The OPC Server item-address Browser Window

This Adroit OPC Server item-address browser window displays all the agent.slot combinations, which the AdroitOPC Server is currently connected to.

Note: Enabling the browser-populating feature, adds a number of items, by default, which are used to monitor the state of the Agent Server.

The OPC Server graphically displays the status of connection to the specified Agent Server (node), as follows: all the added items are displaying all tags in red

  1. Disconnection: a red font is used for each tagA fully qualified named value in Adroit (agentName.slotName). displayed by this window.
  2. Connection: a green font is used for each tag that is connected to an OPC clientan application that uses the data provided by an OPC server. and all other tags are displayed using a grey font.

Note: To optimise tag browsing tags are greyed out in the Adroit OPC Server window until an OPC client connects to a tag.

Each tag (OPC itema string, uniquely describing an individual data element residing in an OPC server. It may be up to 80 characters long, and structured hierarchically typically using a period "." to separate each level.) displayed by this window adheres to the following addressing: nodename.agenttype.agentname.slotname. Click for more details:

  1. nodename, specifies the node, which is like an Agent Server, but transparently provides redundancy (especially for Agent Server clustering).For details, see Working with Nodes.
  2. agenttype is the agent type (e.g. Analog or Digital),
  3. agentname is the name of the applicable agent (e.g. MYANALOG or AIRCON01_SP) and
  4. slotname is the slot of the value that is required (e.g. Value).

Automatically Populating the OPC Server Item Browser Window : in addition to enabling this feature, this allows you to configure which agent.slot combinations populate this item-address browser.

The following columns provide additional information concerning the update activity of values from the Agent Server:

  1. Update: which specify the number of good updates i.e. correct values.
  2. Bad updates: which specify the number of bad updates received.

Note: If OPC connectivity is not required, then this OPC Server item-address browser can still be used to visually monitor specific tags.

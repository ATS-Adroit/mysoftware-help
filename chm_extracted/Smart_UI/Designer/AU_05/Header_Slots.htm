Agent Header Slots

All agents types, regardless of their function, have header attributes that are assigned and managed by the Agent Server. These slots are identifiable by the fact that their names are all prefixed with word agent.

Note1: The overall status of an agent can be determined from its status slot, which is common to all agent types. For details, see Agent Status.

Note2:The first bit in the status word, statusBit00 (statusBad), is the only bit an application needs to monitor to determine the integrity of this agent. For details, see Agent or Slot Integrity Monitoring (Bad Handling).

Note2: The remaining slots for each agent are specific to the agent type. For details, see Agent Type and Slot Reference.

status

INTEGER

The 32-bit status word discussed below, shows the status as determined by the status of the individual slot, for instance if one of the agent slots is scan bad, then the agent status slot will show scan bad.

Each individual bit can be accessed by the agentStatusBitxx slots.

agentStatus

 

statusBit00

 

BOOLEAN

Bad - This is set when at least one of the following bits is on: statusScanBad, statusConnectionBad (a.k.a. statusRemoved) or statusAgentBad. It is a condition bit and fans in.

agentStatusBit00, statusBad

statusBit01

 

BOOLEAN

Global Inhibit - Equivalent to Scan Inhibit plus Log Inhibit plus Alarm Inhibit. This is a control bit and fans out.

agentStatusBit01, statusGlobalInhibit

statusBit02

 

BOOLEAN

Operator Inhibit - Disallows an operator from changing any slot in the agent. This is a control bit and fans out.

agentStatusBit02, statusOperatorInhibit

statusBit03

 

BOOLEAN

Log Inhibit - Disables any configured data logging for the agent or slot. This is a control bit and fans out.

agentStatusBit03, statusLogInhibit

statusBit04

 

BOOLEAN

Alarm(s) Unacknowledged Agent has one or more unacknowledged alarms. This is a condition bit and fans in.

agentStatusBit04, statusAlarmsUnacked

statusBit05

 

BOOLEAN

Alarm Inhibit - Disables any configured alarming on the agent. This is a control bit and fans out.

agentStatusBit05, statusAlarmInhibit

statusBit06

 

BOOLEAN

Alarm(s) Active Agent has one or more active alarms. This is a condition bit and fans in.

agentStatusBit06, statusAlarmsActive

statusBit07

 

BOOLEAN

Alarmed Agent is configured for alarming. This is a configuration bit and doesn’t fan in or out.

agentStatusBit07, statusAlarmed

statusBit08

 

BOOLEAN

Scan Inhibit - Disables any configured scanning of the agent from occurring. This is a control bit and fans out.

Note: To Scan Inhibitvalues when scanning, this needs to be added to their IO Flags bit mask . For details, see IO Flags.

agentStatusBit08, statusScanInhibit

 

statusBit09

 

BOOLEAN

Legacy - used to be Output Enable - this is now being stored within the IO Flags bit mask for each scanned value.

 

statusBit10

 

BOOLEAN

Scan Bad - Communications with the front-end device are not happening successfully. This is a condition bit and fans in.

agentStatusBit10, statusScanBad

statusBit11

 

BOOLEAN

Legacy - used to beOutput Initialise - this is now being stored within the IO Flags bit mask for each scanned value.

 

statusBit12

 

BOOLEAN

Connection Bad - Proxy agent link to real agent has failed. It could also mean that an agent has been removed. Set this bit to delete an agent! This is a condition bit and fans in.

agentStatusBit12, statusRemoved, statusNetBad, statusConnectionBad

statusBit13

 

BOOLEAN

Scanned - This is usually set per slot, and it means that a slot is scanned. A slot may not be scanned more than once. This is a configuration bit and doesn’t fan in or out.

agentStatusBit13, statusScanned

statusBit14

 

BOOLEAN

Agent Bad - is set if the agent is unable to perform an operation or calculation due to invalid (out of range) data. For example syntactically incorrect Expressions will set this bit. This is a condition bit and fans in.

agentStatusBit14, statusAgentBad

statusBit15

 

BOOLEAN

Subscriptions active - is set when the agent is actively being subscribed to or not, and all agents that are alarmed, logged or subscribed to by any other agent will have this bit set. This is a condition bit and fans in.

Note: This status bit in the agent header dialog only works if global demand scanning is enabled. In other words if global demand scanning setting is NOT enabled, this status bit is ALWAYS off.

agentStatusBit15, statusSubscribed

statusBit16 to
statusBit31

BOOLEAN

Agent type dependent. These are condition bits and fan in (the specific names of the agent type’s status bits will also suffice as slot address).

agentStatusBit16 to agentStatusBit31

statusRaw

INTEGER

The same as the status word, except that all fan-ins from the same and lower levels (i.e. the slot statuses and the bad bit) are discounted.

In other words, the agent raw status word shows the status of the agent, without any regard for the status of the individual slots. For instance, if one of the agent slots is scan bad, the agent status slot will not necessarily show scan bad unless the agent itself has been marked as scan bad.

agentStatusRaw

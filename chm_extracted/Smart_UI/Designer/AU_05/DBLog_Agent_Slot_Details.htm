DBLog Agent - Slot Details

The DBLog Agent allows you to typically log Analog and/or Digital values to a specific table in a database for later retrieval.

This agent is located in the following file: T_DBLOG.DLL

Slots:

Slot Name Type Function
addItem VARSTRING

This allows you to remotely add or remove tags to and from the DBLog agent list, as follows:

To add a tag to the DBLog agent list, use the following syntax: tagA fully qualified named value in Adroit (agentName.slotName).,deadband

To remove a tag from the DBLog agent list, use the following syntax:-tagname
catchupData RAWBYTES For internal use during real-time catch-up.

connection

VARSTRING

The OLE DB connection string for logging data. 

Note:

If you specify global, the Global OLE DB connection string of the Agent Server is used, which is specified in the Adroit Config Editor.

  • Typically, you can launch this tool from the Desktop shortcut.
  • Select the Agent Server Configuration Welcome menu item.
  • Select the Advanced Agent Server Configuration option.
  • At the bottom of the dialog, the Global OLE DB connection field is available for you to specify this connection string.

disableOnStandby

BOOLEAN

Disable SQL logging on standby cluster node – default is TRUE
housekeepDays INTEGER

Specifies the maximum number of days to keep records for.

Note: A value of 0 disables this housekeeping functionality.
housekeepFolder VARSTRING

Specifies an OPTIONAL folder to backup the data (OLDER than the number of days specified by the housekeepDays slot) that the housekeeping functionality deletes.

Note: Leave this slot empty to disable this backup functionality.

interval

INTEGER

ONLY used by the interval logging method (method=0) . Specifies the required interval (in seconds) at which the logging of all tags occur.

lastError

VARSTRING

The last OLE DB transaction error.

lastErrorQuery

VARSTRING

The query that caused the last OLE DB transaction error.

method

INTEGER

Logging method:

0 – Log all tags at configured interval, specified by the interval slot.
1 – Log individual tag on change
2 – Log all tags on change of any one tag
3 – Log all tags when trigger tag value goes to zero
4 – Log all tags when trigger tag value leaves zero
5 – Log all tags when trigger tag value changes

Default value is 0.
queuesize INTEGER The number of items in the queue waiting to be logged to the database, which you can use to determine how close the agent is to dumping these logging transactions to a SQL file (this occurs when there are >= 1000 items). Since this value should always tend to zero.

start

BOOLEAN

To stop or start (enable) this agent.
strLog BOOLEAN

Enable string logging only - this setting changes the data type of value column in the specified database table from a real to a string - so that you can also log

other string slots (ONLY their first 79 characters).

tableName

STRING

The name of the table to which data should be logged – the default is ‘Adr_DBLog’.

tagList

LIST

The list of tags that are logged by this agent.

trigger

TAGNAME

The trigger tag ONLY for trigger methods (method = 3-5).

Specific status bits: 

Note: These are of type BOOLEAN.

Bit Number Name Function

status bit 16

ConnectionError

 

OLEDB error – either connection string is invalid OR  a transaction error has occurred - in this case use the lastError and lastErrorQuery slots to troubleshoot this further.

status bit 17

TransactionError

 

When an error occurred during the last transaction to the specified OLE DB database.

status bit 18

QueueFilling

 

When there is more than 1 item in queue, which could be indicative of a slow database link.

status bit 19

QueueDump

 

This is pulsed On, when the number of items in the queue (waiting to be logged) exceeds a 1000 and these items are dumped to a SQL file, which requires manual intervention to "catch-up" this lost data.

Note1: If this occurs it is usually indicative of a problematic connection to the specified database and so this condition can also be alarmed.

Note2: An audit entry is also generated when the queue is dumped, if you have implemented Agent Server auditing.

Methods of creation:

Manual.

Agents created by default:

None

The AlarmManagement Agent

Alarm Management is an important aspect of process control required to counteract inefficient alarming.

Alarm management allows you to create an alarming system that alerts the operator to the most relevant alarm for the current incident. In this case fewer alarms are more effective as the human mind can only focus on a few things at a time. For details, see About Alarm Management.

The AlarmManagement agent logs all incidentssignified by AgentName.AlarmType, which indicate that this agent has gone into the condition or state specified by this alarm type. Each incident can either be an alarm (requiring action) or an event (not requiring action). and their details, including their time of occurrence, their time of acknowledgement and the time at which they were cleared to a database. This repository of incidents allows you to:

  • generate statistics from the data produced by the alarming system. This allows you to have efficient and meaningful incident reviews to identify and remove nuisance alarms by analysing the counts, frequencies, durations and acknowledgement times of alarms.
  • measure KPIs to improve your alarming configuration. For details, see Obtaining KPI Values.

Note1: You can only add ONE AlarmManagement agent.

Note2: Ensure that your Adroit license is licensed to enable your AlarmManagement agent to function.

Tip: An unlicensed AlarmManagement agent can log your historical acknowledged alarms. For details, see Historical Alarm mode.

Multiple Agent Servers may log incidents to the same database thereby unifying alarm management for the enterprise. However, in this case please ensure that your AlarmManagement agent is uniquely named as each incident is logged using the name of its assigned AlarmManagement agent.

Repeating this process at regular intervals will eventually create relevant alarms, which result in the following benefits:

  • Improves the operator environment, workload and efficiency
  • Avoids unplanned outages
  • Improves plant reliability

The review process must be a repetitive and cyclical process, for the following reasons:

  • Alarms are generally added without prior forethought
  • Your process changes over time
  • Your equipment changes and degrades over time
  • Seasonal changes

The AlarmManagement agent is designed to help you implement the first 3 of the following 5 phases of ongoing Alarm Management:

  1. Alarm and Event Archiving: although already accomplished by Adroit, this is improved by the new AlarmManagement agent.
  2. Alarm and Event Analysis: this is main function of the new AlarmManagement agent
  3. Alarm Rationalisation: this exercise is performed by the user after the analysing the alarms/events.
  4. Dynamic Alarm Management: this is the automated tuning of alarms, currently not supported by the AlarmManagement agent.
  5. Predictive Alarming: the ability to predict what is going to happen based on past alarm/event patterns, currently not supported by the AlarmManagement agent.

Making SmartUI Operators cluster-aware

SmartUI Servers can be clustered to handle their combined workload evenly and to provide continued operation in the event that one or more fail. For details on configuring a clustered Server (cluster partnera Server that belongs to a particular cluster. See Cluster.), see SmartUI Server clustering.

Cluster partners are only able to service SmartUI Operator clients that have been made aware of their cluster, by configuring a number of their Operator-specific settings. For details on accessing these settings, see Advanced SmartUI Operator settings.

Example:

ClusterName=Cluster1

ClusterServers=Cluster1~Machine1~9000~MAINDATAPROVIDER~SUBSCRIBE;Cluster1~Machine2~9000~MAINDATAPROVIDER~SUBSCRIBE;Cluster1~Machine3~9000~MAINDATAPROVIDER~SUBSCRIBE

This will make this SmartUI Operator aware of a cluster named "Cluster1", and allow it to connect to the cluster partners that are running on Machine1, Machine2 and Machine.

Each of these Servers are communicating by means of Subscribe, via the default Server Port 9000 and will have "Cluster1" as their ServerName setting.

Also, the default connection settings for this Operator are:

DefaultConnection = Machine1

DefaultConnectionType = MAINDATAPROVIDER

DefaultCommunicationMode = SUBSCRIBE

Note: That these settings match those used for the first Server, specified in the ClusterServers setting.

Tip: It is recommended that this configuration be performed once and then copied to all the Operators that need to be made aware of the cluster(s).

Simply copy the two sections of this .CONFIG file, ConnectionSettings and ClusterSettings, to the other SmartUI Operator .CONFIG files.

To configure an Operator to become cluster-aware:

  1. ClusterNames: This setting lists the names of all the clusters that this SmartUI Operator should be aware of, where each cluster name identifies the SmartUI Servers within each cluster.

Note: The cluster names should be separated by semicolons “;” in this list.

  1. ClusterServers: This setting lists the connection details of each SmartUI Server within each of the clusters, specified in the ClusterNames setting, that this SmartUI Operator is able to connect to. The required communication details depend upon the method by which the SmartUI Operator connects to the SmartUI Server, as follows:

Directly over the LANLocal Area Network: Clustername~MachineName~Port~CommunicationType~CommunicationMode, where:

  1. Clustername: This is the name of the required cluster, which is ALSO the name of this SmartUI Server. For details on configuring this setting, see General SmartUI Server settings.
  2. MachineName: This is the network name of the computer on which this Server is running; this can also be its IP address.
  3. Port: This is the port used to communicate with this Server, which is specified by the ServerPort setting for this Server. By default this is 9000. For details on accessing this setting, see Advanced SmartUI Server settings.
  4. CommunicationType: This specifies the type of connection that is made by this Operator to this Server, which currently will always be: MAINDATAPROVIDER.
  5. CommunicationMode: This specifies the manner in which the data is communicated between this SmartUI Operator and Server, this should typically be: SUBSCRIBE. For details of the various methods of communicating data, see Communication methods.

For instance, Cluster1~Machine1~9000~MAINDATAPROVIDER~SUBSCRIBE.

On the Internet via the Web service: Clustername~WebServiceURL~Port~CommunicationType~CommunicationMode, where:

  1. Clustername: This is the name of the required cluster, which is ALSO the name of this SmartUI Server. For details on configuring this setting, see General SmartUI Server settings.

  2. WebServiceURL: This is the Internet location of the SmartUI Web Service responsible for providing a gateway between this SmartUI Operator and Server.

    By default this is http://machineName/SmartUI. This can also be the IP address of this computer.

  3. Port: This is the port used to communicate with this SmartUI Server, via the Internet. By default this is 80.
  4. CommunicationType: This specifies the type of connection that is made by this Operator to this Server, in this case it will always be: WEBSERVICEDATAPROVIDER. [Is this true?].
  5. CommunicationMode: This specifies the manner in which the data is communicated between this SmartUI Operator and Server, this should typically be: SUBSCRIBE. For details of the various methods of communicating data, see Communication methods.

For instance, Cluster1~http://webservice/folder~80~WEBSERVICEDATAPROVIDER~SUBSCRIBE_POLL 

Note1: The connection settings for each SmartUI Server should be separated by semi colons “;” in this list.

Note2: Ensure that the default connection settings for this SmartUI Operator, match those used for the first SmartUI Server, specified in the ClusterServers setting.

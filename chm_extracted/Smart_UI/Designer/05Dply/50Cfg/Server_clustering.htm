SmartUI Server clustering

How to cluster SmartUI Servers

SmartUI Servers can be clustered to provide both load balancing and redundancy.

Any number of SmartUI Servers can belong to the same cluster, in which case, they are known as cluster partners.

Essentially, all cluster partners (SmartUI Servers within a cluster), act as if they were a single Server, which means that certain characteristics of ALL the cluster partners in a cluster must be IDENTICALLY configured, as follows:

  1. Server name: this also becomes the name of the cluster to which these cluster partners belong, for instance, all the SmartUI Servers whose Server Name is "MyCluster", belong to the "MyCluster" group of cluster partners. For details on configuring this setting, see General SmartUI Server settings.
  2. Server configuration: this configuration encompasses the profiles, security, projects and all datasources that have been configured. For details on configuring the locations for these items, see SmartUI Server directory settings.

Tip: It is recommended that you specify a shared network folder on RAID (failsafe disk) in which you provide the license and configuration files for all the cluster partners to refer to.

Alternatively, these locations can be identically configured on each cluster partner, so that the required configuration is performed on one cluster partner and then copied to the other cluster partners.

  1. System time: cluster partners need to be time synchronised, so that the same timestamp will be set regardless of which cluster partner performs the operation.

Tip: Use time synchronizing software to do this, such as the NET TIME command, provided by the Windows operating system, which sets the time of the local computer to that of a specified remote computer. Example of use:

The following example will set the time of the local computer to that of Computer1 (providing that it is in the same domain): NET TIME \\Computer1 /SET /Y

The /Y option allows this command to be performed automatically without needing to be confirmed first, so that this command can then be added to a command (.CMD) file that could be run on startup or as often as needed.

  1. Microsoft Windows security configuration: this means that any user who logs in to a specific clustered SmartUI Server, must be able to log in to all the other cluster partners, using the same user name and password.

  2. Network location of users and groups: this means that all the cluster partners must be either be physically located in the same network domain or else must be members of a Workgroup that has the same security configuration on each of the cluster partners.

    This allows the same users and groups to secure these SmartUI Servers. For details of configuring this settings, see Server security settings.

IMPORTANT: For clustering to work correctly, only one Server can run on a specific machine at any point in time.

Currently cluster partners ONLY share the workload (load) generated by their SmartUI Operator clients that are cluster-aware, in which case they handle their combined load evenly and to provide continued operation in the event that one or more fail.

Each SmartUI Server uses UDP broadcasts to inform each SmartUI Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. of its availability and/or load. The load of each SmartUI Server is determined by the number of SmartUI Clients that are currently connected to it.

This broadcast system can be disabled and both the range of UDP ports used for this broadcast and the frequency of broadcasts can be configured, as follows:

  • The BroadcastEnabled SmartUI Server setting enables (the default setting) or disables these UDP broadcasts.
  • The BroadcastTimePeriod SmartUI Server setting specifies the time, in milliseconds, between broadcasts, which is 2 seconds (2000 milliseconds) by default. Although decreasing this setting reduces the network traffic it also prevents the SmartUI Operators from quickly responding to changes in Server load and/or availability.
  • The BroadcastPortRange SmartUI Server setting specifies the UDP port range which the Server uses for its broadcasts, by default this is 11000-11010.

IMPORTANT: If you CHANGE this setting for a SmartUI Server then you need to change the BroadcastPortRange setting of each SmartUI Client that you want to receive these broadcasts from this Server.

Each cluster aware SmartUI Operator maintains a list of SmartUI Servers for ALL the clusters that it connects to. The list is periodically updated by the SmartUI Operator, which obtains the availability and load of these Servers from their broadcasts.

Cluster aware SmartUI Operators automatically switch over to the SmartUI Server with the lightest load.

Upon login, if the default SmartUI Server (cluster partner) is NOT available then a cluster aware Operator will search for an available cluster partner.

For details on how to make an SmartUI Operator aware of one or more clusters, see Making SmartUI Operators cluster-aware.

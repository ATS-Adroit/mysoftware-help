About .NET installations

The .NET framework, in addition to making across the Web inter-operability simpler and easier also provides the a number of advantages when it comes to deploying and maintaining applications when compared to conventional software in the past.

Advantages of .NET installations over conventional software installations:

  1. In the past one of the greatest headache with installing (deploying) applications, were shared DLLs (dynamic-link libraries), which has been termed "DLL Hell" for the following reasons:
    1. Firstly, these files needed to be dispersed across hard disk in common folders, such as System32. This both complicated the process of backing up and removing these applications and caused the hard drive to become cluttered with these files.
    2. Secondly, these files could easily be overwritten by newer versions that were not backward compatible with the version already on the computer. Which could cause one or more of the existing applications to either work incorrectly or stop working completely.

.NET applications, however, prevent potential conflicts between applications by isolating their assembliesformerly known as a dynamic linked libraries (.DLL files), which is externally compiled and contains a collection of properties or methods that can be implemented within a script. in their individual installation folders. For this reason, multiple versions of an assembly can be installed and run simultaneously on the same computer.

 

Furthermore .NET applications record the version information of its component assemblies and verify these versions before it is run. Any version differences detected prevent the application from running and display an appropriate warning instead. Therefore .NET applications always load the components with which they were built and tested.

  1. In the past applications were forced to use the registry to store their user-configurable settings and any other application-specific information, which in many cases complicated the process of replicating and backing up these applications effectively.

.NET applications are no longer tied to using the registry to save its user-customizable settings. Instead these settings are saved in .CONFIG files (a type of .INI file), which reside within the application’s installation folder and can be opened and edited in any text editor.

 

In short by making .NET applications entirely self-contained the major hiccups that previously complicating the process of installing, copying, backing up and removing conventional software, have been removed.

This means that the installation folder of a .NET application now contains:

  1. All of its dependent assembliesformerly known as a dynamic linked libraries (.DLL files), which is externally compiled and contains a collection of properties or methods that can be implemented within a script., with each assembly having the specific version that this application was built and tested with.
  2. All the user-customizable settings for the application, contained within its .CONFIG fileThis .NET file is similar to an .INI file, in a single .CONFIG file is used per application to contain its user-configurable settings. This text file is located in the installation folder and has the same name as its application..

Although this does mean that it is no longer essential to install a .NET application, an installation is still preferred, since it does still makes it easier to manage the copied files and to perform any further configuration, such as the setting up of services etc.

Note: If you do not install the product, then you will need to run the .NET framework’s InitExe application to install the required .NET services, yourself.

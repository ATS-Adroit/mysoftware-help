Deployment considerations

The SmartUI has been designed to be as open as possible and as such there is no limitation or restriction to the number of different deployment scenarios that are possible. Since any number of Clients are able to connect to any number of Servers. For details about the function of the SmartUI and a description of its component applications, see Working with the SmartUI.

Note1: Servers can also be clustered to provide both load balancing and redundancy. For details, see Server clustering.

Note2: Click Once allows a user to use a fully fledged SmartUI Operator in Internet Explorer without requiring an initial installation. For details, see Working with Click Once.

Possible Client connections:

Although there are no restrictions to the number of SmartUI Servers that any one Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. can connect to, the following two constraints determine the maximum number of Clients that any one Server can be connected to:

  1. The operating system that is running on the Server computer i.e. any Server that is not running on a Windows Server operating system, e.g. Windows Server 2003, is only able to allow 5 Clients to connect to the Server, over the Internet, at any one time.

    Also if more than 10 Clients are required to connect to the Server, over the LAN, at any one time, it is also recommended to use a Server operating system, as otherwise this may cause performance problems. 

  1. The licencing of the SmartUI Server i.e. this will determine the total number of possible Clients that can connect to a Server at any one time.

Note: The licencing of the Server also determines if the Server has access to any additional components, such as datasources, spiders etc. For more information on licensing the SmartUI Server, see Licensing the Server.

Network topology used for Client connections:

When connecting Clients to Servers, the most important decision is what network topology should be used to connect the Client to the Server i.e. whether to use the LAN or the Internet.

Note: By default, the SmartUI Launcher can be used to deploy and update the Operator application via the selected network topology. Although this can also be used to deploy and update the Designer and additional components, such as datasources, spiders etc. if necessary. For details, see Working with the Launcher. 

  1. It is recommended that only the SmartUI Operator application be connected to the Server over the Internet, unless you are using a high bandwidth Internet connection. This is because the Designer, unlike the Operator, requires a two-way flow of data between itself and the Server, when designing graphic forms.
  2. If one or more Clientrefers to either the Designer or the Operator, both of which are client applications of the Server. can connect to the Server over the Internet, then the SmartUI Server needs to communicate to IIS and the firewall, if present, will also need to be configured, so that the Server can communicate to IIS and the Clients. For details, see Firewall configuration.

Tip: For a detailed step-by-step procedure of connecting Operators to a Server over the Internet, see How to Connect to the Server over the Web.

Note1: The SmartUI Web Service needs to be installed on the web server (IIS computer) to facilitate the communication between the Client and the Server. For details, see SmartUI Installations.

Note2: Since the SmartUI Server only needs to communicate to IIS, these applications can be on different computers, which can even be in different domains, providing the necessary trust relationships exists between these computers.

Note3: IIS is also required when exposing Web services to the Internet.

Usage Guidelines for DbAccess Agents

Note: All DbAccess Agents require a scan point license to run. This license is checked prior to actually doing a DbAccess transaction for the first time (on a per agent basis) and is only returned when the agent is deleted. For details of licensing, see Adroit Licensing.

This is an alternative method to datalog agents by sending slow moving production and batch data values from the AS to OLE DB Servers.

Whereas one datalog agent is required per value that is logged to an OLE DB Server, the DbAccess agent can transfer multiple tags in a single transaction and is therefore a more efficient mechanism.

The DbAccess agents have the added functionality of retrieving data from OLE DB Servers. This is not intended for high speed logging i.e. data that changes within a minute. Instead, it is ideally suited to applications where data is periodically written to a database (such as at the end of a batch job or shift) for reporting reasons.

These agents require careful consideration in terms of both the number of agents to be used and the amount of work that they are to do, as they are resource "hungry".

Hence, both the Agent Server memory and overall memory usage should be monitored during configuration to avoid the excessive usage of these resources. The CPU usage should be monitored while during operation to ensure that the computer is able to handle the additional load.

Note1: You CANNOT export DBAccess agents that contain single quotes (‘) in their format strings.

Note2:The DBAccess agent encloses SQL statements field names in square brackets if the field names contain spaces.

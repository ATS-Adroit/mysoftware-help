Basic Principles of DbAccess Agents

Each DbAccess Agent represents a transaction on a row, in a table, in a database.

Before any transactions can take place, a connection to a database has to be established and a table in this database has to be identified, that requires or contains the information necessary for a transaction.

IMPORTANT: If you are connecting to a database across the network and your Agent Server is running as a service, then ensure that the user profile that the Agent Server service uses to log onto the computer HAS the necessary rights to browse the network and connect to the remote database. This should NOT be the default Local System account. See Configuring Agent Server Service User Profile. 

The table will consist of a number of fields or columns; and each field may be linked to a tagA fully qualified named value in Adroit (agentName.slotName)..

Note1: Table names and field names should not contain spaces as each database vendor supports spaces differently.

Note2:The DBAccess agent encloses SQL statements field names in square brackets if the field names contain spaces.

The following transactions are supported: insert, update, delete and retrieve:

  1. An insert or an update transaction is used to transfer information from Adroit into the table, as follows:
  1. An insert transaction simply takes the values of tags and inserts a new entry into the end of the table, this is useful for accumulating a history of information on tags.
  2. An update transaction is responsible for keeping a record or a row in a table updated with the values of tags.
  1. A delete transaction can be used to remove a number of rows in a table.
  2. A retrieve transaction is used to transfer information from the table to Adroit. This is useful for applying a recipe management system or for updating Adroit with the results obtained from a 3rd party application.

These database transactions can be executed in the following ways:

  • On demand by poking a one into the agent's runNow slot, or, by clicking the "Trigger now" button, when editing the agent.
  • By scheduling , based on a simple schedule; e.g. to transact every three seconds, or, to transact every twenty-four hours synchronised at six 'o clock in the morning.
  • By triggering , based on a list of tags e.g. when the digital tag PUMP.value switches on, or, when the analog tag DAM_LEVEL.value changes.
  • By using a combination of triggering and scheduling.

For instance, using scheduling on condition that triggering has occurred, will apply a time dead band to the triggering of the transactions, e.g. to transact every five seconds but only if the tag DAM_LEVEL.value has changed.

This prevents a flood of triggers initiating multiple transactions.

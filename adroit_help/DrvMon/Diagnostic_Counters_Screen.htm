Diagnostic Counters Screen

The "Diagnostic Counters" Protocol Driver Monitor screen provides a comprehensive list of counters maintained by Protocol Driver.

Example screenshot:

These counters are all zeroed when the Agent Server starts, and for some drivers, also when the device agent starts.

These diagnostic counters can be used to troubleshoot your device communication problems, by providing the following information:

  • “Transactions” increment every-time a transaction succeeds. A transaction fetches one or more data points.
  • “Retry's” increment every-time a transaction is retried.
  • xxx errors increment when there is a problem communicating. For example, Write errors increment when DTR signaling is configured but not received; by device failure or the cable not having that line wired in.
  • xxx timeouts increment when no or too little data has been received on the port in the time allotted for a transaction, resulting in a retry.

The following describes all the available counters:

  1. Transactions: The number of successful transactions performed by this device.
  2. Init failures: The number of times this device attempted to initialise or configure the communication hardware and failed.
  3. Retry’s: The total count of retries performed on read or write operations.
  4. Port switches: If a secondary resource is allowed, this count is the number of times the driver switched between primary and secondary channels.
  5. Protocol errors: This counter generally indicates invalid device responses, which are not legal or are unrecognised.
  6. Percent errors: This is an indication of the communication fault frequency, which is expressed as a percentage.
  7. Read errors: The number of times the driver failed to read an expected response.
  8. Read timeouts: The number of times the driver failed to receive a response to a request, within the required time.
  9. Write errors: The number of times the driver failed to send data because of a hardware problem.
  10. Write timeouts: The number of times the driver timed out while waiting to send data because of a hardware problem.
  11. Transactions/sec: This represents the number of successful transactions performed per second.

Note: These default driver performance counters, as well as any driver-specific counters, can also be displayed using the Perfmon agent. This agent is also able to copy the value of these counters into tags, which could then be reported, as required.

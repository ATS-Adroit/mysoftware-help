OLE Server Interface (MISSRVR)

The OLE Server Interface allows third party client applications to interact with standalone or distributed Agent Servers. Because OLE is a programming-language-independent standard, third party applications can be written in any OLE enabled development environment, such as Visual Basic™, (VBA) Visual Basic for Applications™, Borland Delphi™, PowerBuilder™, C++, etc.

Note: The Adroit Server ActiveX Control (adroitx.ocx) is provided as an alternative to this OLE Server interface. See Adroit Server ActiveX Control.

Monitoring Real-time Data describes the steps you need to take to provide continuously updating real-time data for your application. The examples are shown in VBA for ease of understanding.

The Adroit Automation Interface describes the OLE Automation or Programmability Interface for Adroit OLE Server Data Objects, which is a set of OLE Automation methods and properties exposed by the Data Objects. These methods are callable as functions and these properties are settable/gettable as variables by container applications.

Note1:Adroit also provides a scripting interface, namely the Adroit system object. This is not the same as the OLE Server interface; in fact, certain tasks can only be accomplished via the OLE interface, like adding and removing tags. It is possible, however, to use the OLE Server interface within this scripting interface.

Note2: Any pokes performed, using this Adroit OLE Automation Interface will require a scan point license for each unique tag that is "poked". This also applies to the use of functions that use pokes internally, such as AlarmTag, LogTag, and ScanTag.

Note3: Fetching values of logged data (by using the FetchChanges and/or FetchValues functions) does not use scan points.

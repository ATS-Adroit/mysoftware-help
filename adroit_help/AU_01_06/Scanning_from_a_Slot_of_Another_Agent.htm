Scanning from a Slot of Another Agent

Instead of communicating or scanning a tagA fully qualified named value in Adroit (agentName.slotName). to a front-end device, it is also possible to simply link or connect the value of this tag to another tag instead.

This is usually known as @scanning (pronounced at-scanning), where the source address is replaced by another agent's slot, so that the value of the source agent’s slot is copied into the destination agent’s slot.

Note1: To support drivers that use the @ character in scan addresses, @ scanning can be disabled for the required device, by adding the DisableAtScanning registry value. For details, see Registry settings affecting communications.

Note2: The ‘subsCount’ slot of the Device agent displays the number of @scanned tags configured for the device.

PLEASE NOTE: @scanning is not true scanning from a Device, and no Scan agents are involved. It is in fact a slot-to-slot subscription, therefore, the following scan status bits statusScanInhibit(08), statusScanned(13) and statusScanBad(10) will not be affected by @scanning.

To @ scan a tag:

Scan the required tag as normal except for the following details:

  1. Device selection: Although ANY device can be selected, it is good engineering practice to restrict all such agent-to-agent scanning to a single pseudo device rather than mixing genuine front-end device communications with agent-to-agent scanning within a single device.

Either create a pseudo-device using the Adroit simulation protocol driver or use the ALIASSCAN device, which has been created, by default, for this purpose.

  1. Specifying Address field: specify the tag (agent,slot) whose value is required to be copied into the tag that is being scanned, by typing in the required agent name and slot preceded by an @ in the Address field.
  2. The Currently scanned tags list, only displays the following information once this tag is @scanned:
  3. Tag column: destination_agent.slot,
  4. Address column: @source_agent.slot.

Note: When slots are "scanned" from other slots like this there is no concept of scan interval because all change events are continuously reported by the subscription mechanism of Adroit.

WARNING: If a circular @ subscription is defined whereby destination_agent subscribes to source_agent which is already subscribing to destination_agent, even though via a circuitous route, then the performance of the Agent Server will be severely compromised.

Protocol Drivers

Adroit has created a large number of protocol drivers that use Windows device drivers to communicate to a wide range of front-end devices e.g. Programmable Logic Controllers PLCs, RTUs etc.

If necessary, specialised drivers can be developed. Before a protocol can be used to provide communication to a front-end device, it needs to be installed.

Each protocol driver, provides the following services:

  • The configuration of hardware I/O addresses to be scanned from the front-end device.
  • The communication of these configured addresses to and from the hardware I/O.

Note: Protocol Drivers using proprietary hardware adapters will require the relevant Windows driver for the adapter.

Although an installed protocol driver provides the means of communication, the communication to each FEDfront-end device, which is a device that is accessed directly by the user, such as a PLC or RTU. is performed by a deviceadded to an installed protocol driver to communicate using this protocol to a specific front-end device - in other words a logical connection to this FED. that you need to be add to the installed protocol driver.

These devices are essentially logical connections to the front-end devices they communicate to and a total of 65534 devices may be added and used for any one installed protocol driver.

Note1: The protocol driver configuration for each device is saved in the system registry; therefore it is necessary to reconfigure the devices if they are to be run on another computer.

Note2: You may use as many different protocol drivers and devices as you wish, until the sum of their scanned points exceeds your licensed number of scan points. For details, see Scan Points.

NASA, stands for New Adroit Scanning Architecture and describes a sub-class of protocol drivers that are specifically written to take advantage of the scanning improvements and enhancements provided by NASA, such as demand scanning and highly optimised scan tasks. For more details, see Demand Scanning.
